- Milestone: M3.5
- Status: Complete
- Order: 16

## Goal

Build one shared HTTP client and URL policy for every provider, with the required TLS, pooling, timeout, user-agent, and cleartext rules.

## Preconditions

- Domain and contract types exist.
- Do not add provider-specific parsing in this task.
- Do not use OpenSSL or a platform-dependent TLS stack.
- Do not place API keys in query strings or log headers.
- Do not modify `web/`, `android/`, or `contracts/`.

## Deliverables

- A shared `reqwest::Client` configured once and reused:
  - `rustls-tls`;
  - connection pooling;
  - consistent user agent;
  - connect timeout 30 seconds;
  - no total timeout during streaming;
  - redirect policy that does not leak auth headers to another origin.
- URL policy helpers for:
  - HTTPS by default;
  - cleartext allowed only for localhost/private-range hosts with an explicit warning;
  - rejecting keys in query parameters;
  - joining base URLs and paths safely.
- Normalized networking error types for DNS/TLS, timeout, connection, HTTP status, and cancelled.
- Tests for URL policy, client construction, header application, and error mapping.

## Implementation steps

1. Read spec sections 7.7, 7.9, and 10.7.
2. Add `reqwest` with `rustls-tls` and no default OpenSSL feature. Add `url` and `tokio`.
3. Create `build_http_client()` that returns a pooled client with the required settings. Do not set a total request timeout for streaming.
4. Set a user agent such as `ChatUI/<version>` with no personal data.
5. Configure redirects. Do not forward `Authorization`, `x-api-key`, `x-goog-api-key`, or custom secret headers across origins. Prefer refusing cross-origin redirects with auth headers.
6. Implement `classify_url` or equivalent:
   - `https` is allowed;
   - `http` is allowed only for loopback, localhost, `.local`, or approved private ranges;
   - other cleartext URLs produce a warning/error that the UI can surface.
7. Implement URL joining that handles absolute discovery URLs (for example Ollama `/api/tags`) and normal paths.
8. Reject any attempt to put a key in a query parameter.
9. Implement networking errors with retryability metadata and no secret values.
10. Add tests. Use `wiremock` or `httpmock` for connection behavior where practical.

## Handoff notes

- Client builder: `build_http_client()` in `src/http.rs` builds one pooled `reqwest::Client` with `default-features = false` and features `http2`, `json`, `rustls-tls`, and `stream`. It sets `ChatUI/<crate version>` as the user agent, a 30 s connect timeout, a 90 s pool idle timeout, 8 idle connections per host, and a 60 s TCP keepalive. It deliberately sets no total request timeout; streaming uses `HttpClient::execute`/`send`, while `execute_with_timeout` is only for non-streaming calls.
- Redirect policy: `redirect_policy()` refuses every cross-origin redirect (`attempt.stop()`) and errors after 10 redirects. Refusing the redirect is safer than trying to strip individual secret headers, so `Authorization`, `x-api-key`, `x-goog-api-key`, and custom secret headers cannot cross origins.
- URL classification: `classify_url()` allows HTTPS unconditionally. Cleartext HTTP is allowed only for `localhost`, `*.localhost`, `*.local`, loopback, IPv4 private/link-local/CGNAT/unspecified ranges, and IPv6 loopback/unspecified/unique-local/link-local ranges (including IPv4-mapped addresses). Allowed cleartext returns `CLEARTEXT_WARNING`; public cleartext returns `UrlPolicyError::CleartextNotAllowed`.
- Key handling: `ensure_no_key_in_query()` rejects key-like query parameter names (`api_key`, `key`, `x-goog-api-key`, `access_token`, `client_secret`, `authorization`, and similar) and values with known secret prefixes (`sk-`, `sk-or-`, `AIza`, `gsk_`, `xai-`, `hf_`, `Bearer `, `Basic `). `SecretHeader` redacts its value in `Debug` output.
- URL joining: `join_url()` treats a full absolute URL as a replacement, a leading `/` as an origin-relative discovery path (for example Ollama `/api/tags`), and a relative path as appended under the base path (`https://api.example.com/v1` + `chat/completions`). Protocol-relative paths are rejected.
- Errors: `NetworkError` normalizes DNS, TLS, timeout, connection, HTTP status, cancelled, redirect, invalid URL, invalid header, and other failures. Retryability is explicit (`Dns`, `Timeout`, `Connection`, and statuses 408/425/429/5xx are retryable). `to_chat_error()` maps to the shared `ChatError`/`ChatErrorCode` shape without keys, headers, or full URLs. `parse_retry_after()` handles whole-second values; HTTP-date parsing is left to M3.5-05.4.
- Tests: 31 tests cover URL policy, joining, key rejection, client constants, user agent, same-origin and cross-origin redirects, secret header application/redaction, timeout mapping, connection-failure mapping, and error/status mapping. Wiremock is used for transport behavior.
- Platform TLS caveat: `rustls-tls` uses webpki roots, so enterprise or private certificate authorities are not trusted by default. No OpenSSL or platform TLS stack is used. Because default features are disabled, reqwest's system-proxy feature is also off; proxy support is not part of this task.
- Dependency decision: reqwest is pinned to the 0.12 line because 0.13 renamed the `rustls-tls` feature to `rustls`; the task explicitly requires `rustls-tls`. Cargo resolved 0.12.28.
- Verification: `cargo fmt --all --check` passed; `cargo clippy -p chatui-providers --all-targets -- -D warnings` passed; `cargo nextest run -p chatui-providers` passed 31/31 tests.
