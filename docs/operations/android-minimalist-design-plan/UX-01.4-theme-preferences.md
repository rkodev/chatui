# UX-01.4 - Applied theme and feedback preferences

- Phase: UX-01 - Calm foundations
- Status: Not started
- Order: 7
- Depends on: UX-01.1
- Output folder: `docs\operations\android-minimalist-design-plan`
- Parallel-safe: Yes with isolated scaffold work; serialize edits to ChatUiApp.

## Goal

Make the existing stored dynamic-color and haptic choices reach the real
application theme, without changing defaults or adding new preferences.

## Read first

Read the [execution contract](README.md), source-plan sections 2, 5.7,
and 8, `Shell\ChatUiApp.kt`, `DS\Theme.kt`, `DS\Haptics.kt`,
`SettingsStore\AndroidSettings.kt`, `AppTests\MotionHapticsThemeTest.kt`,
`AppTests\ShellThemeTest.kt`, and `DSTests\HapticsTest.kt`.

## Owns

- Preference propagation in `Shell\ChatUiApp.kt` and `DS\Theme.kt`.
- Tightly required haptics-provider fixes in `DS\Haptics.kt`.
- The named app/design-system tests; settings storage is read-only.

## Deliverables

Production-root theme wiring, resolved application-theme information usable
by consumers, and regressions that would fail with the current missing props.

## Implementation steps

1. Trace settings collection to `ChatUiTheme`. Pass the already persisted
   dynamic-color and haptic fields alongside theme/density.
2. Preserve light/dark/system resolution, OS reduced motion, font/density,
   and pre-API-31 dynamic-color fallback. Do not overwrite stored preferences
   when a platform cannot render dynamic color.
3. Ensure any exposed resolved-theme signal describes the applied app theme,
   including an explicit override differing from the system. Reuse existing
   theme locals where available; UX-03.7 will use it for code.
4. Keep dynamic color paired with its correct Material on-colors; do not mix
   a wallpaper accent with a hard-coded unreadable label color.
5. Verify disabling haptics suppresses actual feedback paths, not only the
   settings preview. Keep OS motion handling independent from haptic choice.
6. Add root-composition regressions for stored flags, override/system
   mismatch, supported dynamic color, and unsupported-platform fallback.

## Acceptance criteria

- [ ] Stored dynamic-color/haptic changes affect the production root.
- [ ] API fallback does not reset preferences or crash.
- [ ] Explicit app-theme overrides resolve consistently for consumers.
- [ ] No defaults, settings schema, or security behavior changes.

## Out of scope

Appearance-screen redesign, preference migrations/default changes, code-block
rendering changes, or new haptic patterns.
