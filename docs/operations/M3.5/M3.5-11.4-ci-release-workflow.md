# M3.5-11.4 - Rust CI matrix and tag release workflow

- Milestone: M3.5
- Status: Not started
- Order: 44
- Depends on: M3.5-11.2, M3.5-11.3
- Parallel-safe: none; needs packaging and updater
- Owns: `.github/workflows/rust.yml`, `.github/workflows/rust-release.yml` (or equivalent), `docs/operations/M3.5/ci.md`
- Read first: [M3.5 plan](../M3.5-rust-desktop-implementation-plan.md) sections 3.7 and 6; spec sections 10.11, 16.3, 14.5

## Goal

Add a Rust CI matrix and tag-driven release workflow that enforce fmt, clippy, tests, release builds, deny/audit, packaging, signing, notarization, checksums, and update-manifest publication.

## Preconditions

- Packaging and updater configuration exist.
- Do not commit signing keys or certificates.
- Do not use a debug or self-signed substitute for release signing.
- Do not modify web or Android workflows except for a shared runner/cache if explicitly required.
- Do not modify `web/`, `android/`, or `contracts/`.

## Deliverables

- `.github/workflows/rust.yml` triggered on pull requests, pushes to `main`, and relevant tags:
  - install pinned toolchain;
  - cache Cargo registry and targets;
  - `cargo fmt --all --check`;
  - `cargo clippy --workspace --all-targets -- -D warnings`;
  - `cargo nextest run --workspace`;
  - conformance suite;
  - `cargo build --release --workspace`;
  - `cargo deny check`;
  - `cargo audit`.
- Matrix: Linux x86_64, macOS Apple Silicon, Windows x86_64.
- A tag-driven release workflow that:
  - builds and packages artifacts;
  - signs/notarizes where credentials exist;
  - generates checksums;
  - signs update manifests;
  - publishes a GitHub Release.
- A documented list of required CI secrets (names only).
- `docs/operations/M3.5/ci.md`.

## Implementation steps

1. Read spec sections 10.11, 16.3, and 14.5, plus the existing web/Android workflows for style.
2. Create the CI workflow with a matrix for the required OS/architectures. Use native runners where possible.
3. Install the pinned toolchain from `rust-toolchain.toml`. Install `cargo-nextest`, `cargo-deny`, and `cargo-audit` in CI only.
4. Cache Cargo registry and target directories per OS. Do not cache secrets.
5. Run fmt, clippy, nextest, conformance, release build, deny, and audit.
6. Create the tag release workflow. Build packages, sign/notarize when credentials exist, generate checksums, sign update manifests, and attach artifacts to the GitHub release.
7. Fail the release job when required signing/notarization credentials are absent. Do not fall back to unsigned production artifacts unless the decision record explicitly allows an unsigned preview.
8. Document required secret names and which job uses them. Do not include values.
9. Run the workflow locally with `act` or a dry-run if available; otherwise record the CI-only blocker.
10. Update `docs/operations/M3.5/ci.md` with the matrix, jobs, secrets, and artifact names.

## Acceptance criteria

- [ ] Rust CI runs on PRs, `main`, and tags.
- [ ] Matrix covers Linux x86_64, macOS Apple Silicon, and Windows x86_64.
- [ ] fmt, clippy, nextest, conformance, release build, deny, and audit run in CI.
- [ ] Toolchain and dependency caches are configured.
- [ ] Tag release builds artifacts, checksums, and signed update manifests.
- [ ] Signing/notarization credentials come only from CI secrets.
- [ ] Missing credentials fail the release job.
- [ ] Secret names are documented without values.
- [ ] `docs/operations/M3.5/ci.md` exists.

## Verification

```bash
make rust-fmt
make rust-check
make rust-lint
make rust-nextest
make rust-conformance
make rust-deny
make rust-audit
make rust-build
```

Plus the recorded GitHub Actions run evidence. If CI cannot run locally, record the blocker.

## Out of scope

- Performance and installer-size evidence (M3.5-11.5).
- Web, Android, contracts, or deployment workflows.
- Publishing to package registries outside the desktop release.
