## Goal

Create one buildable Cargo workspace that matches the prescribed layout, pins the toolchain, and contains only the desktop app and the six core crates.

## Preconditions

- M3.5-00.2 is complete and records the platform matrix.
- Do not add Android, iOS, or WASM workspace members.
- Do not implement domain, provider, storage, secret, or UI behavior in this task.
- Do not modify `web/` or `android/`.

## Deliverables

- `rust/Cargo.toml` with `resolver = "3"` and members for:
  - `crates/chatui-domain`
  - `crates/chatui-contracts`
  - `crates/chatui-providers`
  - `crates/chatui-storage`
  - `crates/chatui-secrets`
  - `crates/chatui-ui`
  - `apps/desktop`
  - `tests/conformance`
- `rust/rust-toolchain.toml` pinned to a stable Rust version that supports edition 2024 and `resolver = "3"`, with `rustfmt` and `clippy`.
- Each crate manifest with edition 2024, a package name, and `publish = false` where appropriate.
- Minimal `src/lib.rs` files and a minimal desktop `main.rs` that compile.
- A committed `rust/Cargo.lock`.
- Removal or exclusion of `rust/apps/android`, `rust/apps/ios`, and `rust/apps/wasm`.
- A short note in the task handoff confirming the workspace member list.

## Implementation steps

1. Read the plan's workspace layout and `docs/IMPLEMENTATION.md` section 10.3.
2. Create `rust/rust-toolchain.toml`. Pin an exact stable version, not a floating branch. Example shape:
   ```toml
   [toolchain]
   channel = "1.xx.y"
   profile = "minimal"
   components = ["rustfmt", "clippy"]
   ```
   Choose a version that supports edition 2024 and `resolver = "3"`.
3. Create `rust/Cargo.toml`:
   ```toml
   [workspace]
   resolver = "3"
   members = [
     "crates/chatui-domain",
     "crates/chatui-contracts",
     "crates/chatui-providers",
     "crates/chatui-storage",
     "crates/chatui-secrets",
     "crates/chatui-ui",
     "apps/desktop",
     "tests/conformance",
   ]
   ```
4. Create every member package with edition 2024. Start with `chatui-domain`, `chatui-contracts`, and `chatui-providers` having no dependency on `chatui-ui`.
5. Give `apps/desktop` a minimal `main.rs` that prints a temporary startup line. Do not build UI yet.
6. Give `tests/conformance` a minimal library or test target. It may be empty until M3.5-02.3.
7. Remove the placeholder directories `rust/apps/android`, `rust/apps/ios`, and `rust/apps/wasm`. If a reviewer wants them kept, exclude them from the workspace and document why.
8. Build the workspace once to create `rust/Cargo.lock`, then commit the lockfile:
   ```bash
   cd rust && cargo check --workspace --all-targets
   ```
9. Record the member list and toolchain version in the handoff notes.

### Result (2026-11-07)

Created the buildable Cargo workspace at `rust/` with `resolver = "3"` and
exactly these members:

- `crates/chatui-domain`
- `crates/chatui-contracts`
- `crates/chatui-providers`
- `crates/chatui-storage`
- `crates/chatui-secrets`
- `crates/chatui-ui`
- `apps/desktop` (package `chatui-desktop`)
- `tests/conformance` (package `chatui-conformance`)

Toolchain: pinned `channel = "1.98.1"` in `rust/rust-toolchain.toml` with
`profile = "minimal"` and `components = ["rustfmt", "clippy"]`. Rust 1.98.1
supports edition 2024 and `resolver = "3"`. The toolchain was installed locally
with `rustup toolchain install 1.98.1 --profile minimal --component rustfmt
--component clippy`.

Every package uses edition 2024 and `publish = false`. The six crates and the
conformance package have minimal `src/lib.rs` stubs; `apps/desktop` has a
minimal `main.rs` that prints `chatui desktop starting (skeleton)`. No domain,
provider, storage, secret, or UI behavior was implemented.

Removed the placeholder directories `rust/apps/android`, `rust/apps/ios`, and
`rust/apps/wasm` along with the `.gitkeep` files that were replaced by real
manifests and sources. No Android, iOS, or WASM workspace member exists.

`rust/Cargo.lock` was generated by `cargo check` and is committed. `web/` and
`android/` were not modified.
