# M3-04.5 - Startup orphan-attachment cleanup

- Milestone: M3
- Status: Complete
- Order: 22
- Depends on: M3-04.4
- Parallel-safe: no; shares startup files
- Owns: `android/app/src/main/java/dev/chatui/startup/AppStartup.kt`, `android/app/src/main/java/dev/chatui/di/AppModule.kt`, `android/feature/chat/ChatModule.kt`, `android/core/database/attachment/AttachmentService.kt`, startup tests
- Read first: [M3 plan](../M3-android-depth-implementation-plan.md) sections 2.3, 3.3, and 4.5; spec sections 9.4 and 9.8

## Goal

Remove orphan attachment metadata and bytes at startup, not only when a chat happens to open.

## Preconditions

- M3-04.4 is complete.
- `AttachmentService.cleanupOrphans(before)` already exists; extend its use, do not duplicate file-deletion logic.
- Do not delete attachments created after startup began.

## Deliverables

- `AppStartup` runs attachment cleanup after message recovery and before the shell renders.
- Cleanup uses a startup timestamp so new attachments are safe.
- A DI binding for the cleanup dependency.
- Tests for orphan metadata, orphan bytes, referenced attachments, and new attachments.
- Evidence in the handoff notes.

## Implementation steps

1. Read `AppStartup`, `MainActivity`, `AppModule`, `ChatModule`, `AttachmentService.cleanupOrphans`, `AttachmentStorage`, and `AttachmentDao`.
2. Add an `AttachmentCleanup` interface or use `AttachmentService` directly as the startup dependency. Keep `AppStartup` testable with a fake.
3. In `AppStartup.run()`, after `recovery.recoverInterruptedMessages()`:
   - capture `startedAt` once;
   - call cleanup with `before = startedAt`;
   - keep failures non-fatal but record them without sensitive data.
4. Ensure cleanup runs exactly once per process and remains idempotent with the existing mutex/guard.
5. Add tests:
   - orphan metadata row with no message is deleted;
   - orphan bytes with no metadata are deleted;
   - an attachment bound to a message survives;
   - an attachment created after `startedAt` survives;
   - a cleanup failure does not block the shell.
6. Update the handoff with what is cleaned and what is intentionally kept.
7. Add a line to `M3-verification.md` recording the startup cleanup test.

## Acceptance criteria

- [x] Startup cleans orphan attachment metadata and bytes.
- [x] Attachments referenced by a message survive.
- [x] Attachments created after startup begins survive.
- [x] Recovery still runs before the shell renders.
- [x] Cleanup is idempotent and failure-safe.
- [x] Tests pass.

## Handoff notes

- `AppStartup` now takes an `AttachmentCleanup` interface plus a `Clock`. The
  production binding is `AppModule.provideAttachmentCleanup`, which delegates to
  the shared `AttachmentService.cleanupOrphans`; no file-deletion logic was
  duplicated.
- `AppStartup.run()` captures one startup instant before recovery, runs
  `recovery.recoverInterruptedMessages()`, then calls
  `attachmentCleanup.cleanupOrphans(startedAt)`. The existing mutex/`completed`
  guard makes both steps run exactly once per process.
- Cleanup is best-effort. A failure is recorded as
  `AppStartup.lastCleanupFailure` (exception class name only, no message or
  path) and never blocks the shell. A recovery failure still attempts cleanup
  and then propagates as before.
- Cleaned: attachment metadata rows with no message or a missing message, and
  stored bytes with no metadata row. Kept: attachments bound to an existing
  message and any attachment created at or after the captured startup instant.
  Draft attachment rows (`messageId: null`) are still treated as orphans because
  draft attachments are not persisted across process death.
- Tests: `AppStartupTest` covers ordering, the startup timestamp, once-per-process
  behavior, failure safety, and recovery-failure cleanup. `AttachmentServiceTest`
  covers orphan metadata, orphan bytes, referenced attachments, and new
  attachments. `AppModuleTest` covers the DI binding.
- Evidence is recorded in `M3-verification.md` section 17.
- Verification: `make android-lint`, `make android-test` (953 aggregated tests,
  0 failures), and `make android-assemble` all pass with
  `ANDROID_HOME=$HOME/Android/Sdk`.
