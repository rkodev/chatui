## Goal

Establish controlled, explicitly labeled AVD measurements and agreed comparison
conditions before visual changes, preserving the old build for later physical
comparison. The owner approved this AVD-only baseline gate on 2026-11-17;
physical entry-level/mid-tier acceptance remains mandatory in UX-06.4.

Read the [execution contract](README.md), source-plan sections 7 and 10,
UX-00.2's fixture/build recipe, and
`android\baselineprofile\src\main\java\dev\chatui\baselineprofile\StartupBaselineProfile.kt`.
Profile generation is not a startup/frame timing benchmark.

## Owns

Measurement protocol/results, artifact references, reference-device matrix,
and agreed-budget record in this task's Handoff notes. No production code, scheduling,
SDK, dependency, or provider changes.

## Deliverables

Named and characterized disposable AVD profiles, comparable baseline
startup/frame/feedback/memory results, frozen build/fixture/measurement artifacts,
and a repeatable protocol for UX-06.4. Do not equate AVD resource settings with
physical entry-level or mid-tier hardware.

## Implementation steps

1. Record actual AVD identity, requested/effective RAM, vCPUs, API, renderer,
   host conditions, refresh rate, navigation mode, font
   scale/density, app/build identity, power/thermal conditions, and data reset
   procedure. Do not invent a device or reuse old milestone measurements.
2. Use a release-like baseline and UX-00.2's local fixtures. Separate seeding
   and network delays from measured UI work; record compilation/profile state.
3. Measure at least 30 controlled cold starts and report the distribution/p95
   to first usable local screen. State the actual measurement method.
4. Exercise history scroll, opening chat, typing, streaming, Stop, large code,
   and supported images. Capture frame distribution, frozen frames/ANRs, local
   feedback latency, and steady/peak PSS with the 10,000-message fixture.
5. Record the source plan's proposed targets: <1.5 s mid-tier cold start,
   entry-level p95 <2.5 s, ordinary local feedback <=100 ms, entry-level p95
   frame <=32 ms, no >700 ms frozen frames/ANRs, no OOM, investigate >10% PSS
   growth. Obtain an explicit decision before changing a target.
6. Preserve raw artifact links and exact scenario/build identifiers. Missing
   required AVD measurements leave this task `Blocked`; a proposed protocol or
   screenshots alone do not complete the approved gate. Preserve the physical
   device requirement and unchanged budgets for UX-06.4.

### AVD protocol and measurement boundaries

The private profiles are `ChatUI_UX003_L` (2 vCPUs, requested 4096 MiB)
and `ChatUI_UX003_C` (4 vCPUs, requested 6144 MiB), not named physical
hardware tiers. Both use the installed API 37.0 Google Play x86_64 image,
revision 7, emulator 37.2.13.0 / build 16740729, with WHPX acceleration.
Final-profile geometry is 822 x 1782 px at 320 dpi (411 x 891 dp),
font scale 1.0, 60 Hz requested, and system animations 1.0. Actual guest
memory, display, navigation, IME, power, and thermal reports are captured
before and after each run; requested settings alone are not observations.

The host is Windows 11 Enterprise 10.0.26300, Ryzen AI 7 PRO 350
(8 cores / 16 logical processors), 33,476,071,424 physical-memory bytes,
Balanced power plan, on AC at initial characterization. It is a shared
host: CPU exclusivity, physical-device thermals, and fixed host GPU/CPU
frequencies are not claimed. Total host CPU busy percentage and available
physical memory are sampled every two seconds and tagged by phase.

Each run boots a fresh, private, headless AVD without snapshots, binds
every ADB command to its verified owned serial (5580/5582), installs the
same measurement APKs, seeds/verifies local data outside the timing
window, and verifies airplane mode/Wi-Fi-off. Absent telephony service in
early pilots is recorded as N/A, not a successful mobile-data command.
Owned AVDs are stopped and their private runtime leaves removed, without
stopping the global ADB server or modifying existing user AVDs. Final
profiles run sequentially, not concurrently.

### Pilot findings and exclusions

`avd-l-01` failed preparation because the guest lacked a phone service.
`avd-l-02` exposed an instrumentation-thread Compose setup error, corrected
in the external harness using `compose.setContent`; neither run supplied
accepted performance measurements.

`avd-l-03` captured 30 genuine transcript-and-composer cold starts, then
failed its native history journey. Its startup traces were overwritten
when the next instrumentation invocation reused the output directory.
Those preliminary observations are **excluded**, not the accepted sample
set. The collector now uses separate startup/launcher output directories
and pulls startup traces immediately.

`avd-l-04` preserved a real pre-existing layout defect: at 360 x 640 dp,
fixed drawer header/footer sections nearly eliminate the history viewport.
The screenshot/XML are retained at
`runs\avd-l-04\startup\launcher-failure.png` and
`launcher-failure.xml`. This task does not fix that UI. The 411 x 891 dp
reference window permits investigating full journeys; it does not imply
compact-window acceptance. Carry the defect into scaffold/history and
accessibility acceptance.

`avd-l-05` failed native launch setup at 411 x 891 dp. Saved logcat shows
system/telephony ANRs and no target-package fatal exception. The host
sampler recorded a 0.60 GiB minimum available memory and 52.4% median host
CPU busy percentage across the attempt. The root cause is not established;
it must not be described as a proven application or geometry crash.
Subsequent validation uses host-accelerated graphics and explicitly
configured standard virtual sensors/modem; earlier SwiftShader attempts
are not mixed into its results. This task's verified idle build/compiler
processes were stopped by specific PID to release their memory, and
subsequent builds use a single-use daemon/in-process compiler. Other
users' processes were left untouched.

`avd-l-06` successfully launched the hardware-rendered app and navigated
to the empty chat, then exposed the no-key/offline fixture's disabled
native composer (`enabled="false"` in the saved hierarchy). No draft was
inserted. Native journeys now explicitly measure history, opening the
empty chat, and returning to the long transcript; they record the actual
composer enabled state. They do not label a rejected text-injection
attempt as typing feedback. The separate controlled harness still
requires all 30 typed characters, deterministic streaming, and Stop;
it uses the existing fake context resolver, not real secrets or requests.
Hardware rendering was verified as OpenGL ES 3.0 through the AMD Radeon
860M translator, driver 32.0.31028.1003; it is not a phone GPU.

`avd-l-07` hit a stale accessibility-node query during drawer animation.
Queries now reacquire transiently replaced nodes; required actions and
state assertions remain mandatory. `avd-l-08` completed code/all four
image decodes, deterministic streaming, and Stop with 72 retained
characters, but its history/transcript test encountered a Compose runtime
concurrent-apply error involving test-clock continuation interception.
That failed suite is excluded. The external harness now uses an explicit
Android frame-clock recomposer and real-time platform scroll injection,
without upgrading Compose or modifying production rendering. All four
scenarios must pass under that final protocol before accepting either
profile. Controlled scenarios precede native journeys so an accessibility
tool failure does not prevent investigating the independent harness.

`avd-l-09` confirmed native-clock streaming/Stop, but two subsequent
drawer-closure checks timed out after scrolling. The collector no longer
mixes Compose test-clock clicks with wall-clock gestures: all pointer
actions now use current-uptime platform finger events. Required drawer,
enabled-state, typed-content, and committed-frame checks remain; failed
scenarios also capture a full-window image and semantics tree. Image
checks require the frozen blue, orange, and yellow regions, not merely a
blue placeholder/button. This attempt remains excluded regardless of
subsequent validation.

`avd-l-10` built the unified platform-input harness and completed three
controlled cases before history/repeated navigation stalled. A diagnostic
capture (`runs\avd-l-10\pilot-live.png`) shows the on-screen keyboard
reducing the open drawer's history viewport to effectively nothing.
The target process was deliberately force-stopped before the owner's
deferral; the resulting instrumentation "Process crashed" message is not
evidence of an independently occurring application crash. This interrupted
pilot is excluded. Its private emulator was stopped and its owned AVD
files removed; no connected devices remained at cleanup verification.
