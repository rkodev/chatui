## Goal

Capture a reproducible pre-redesign visual/test baseline using invented data
and the real production shell, not just standalone screen fixtures.

## Read first

Read the [execution contract](README.md), source-plan sections 2, 7, and
10, and UX-00.1's ledger. Inspect `Screenshots\ScreenshotTest.kt`,
`android\app\src\sharedTest\kotlin\dev\chatui\testing\TestFixtures.kt`,
`AppTests\ShellNavigationTest.kt`, and the existing app instrumentation tests.
Existing `ScreenshotSidebar` and standalone chat are not production-shell
coverage.

## Owns

- Test-only fixtures/harness under `android\app\src\test`,
  `android\app\src\sharedTest`, and existing `android\app\src\androidTest`.
- Baseline screenshots/reports and a seeding/capture recipe linked from this

## Deliverables

Deterministic fixtures, actual-shell baseline captures, baseline command
results, and an identified baseline build/revision for later device comparison.

## Implementation steps

1. Reuse existing fakes and fixtures. Cover empty/populated/archived history,
   long titles, model filters/hidden models, code/tables/reasoning, attachment
   warnings, missing configuration, and recoverable errors with fake content.
2. Provide a deterministic local dataset/stream recipe for 10,000 messages
   and representative supported images. Reuse it for UX-00.3 and UX-06.4;
   do not require a paid provider or depend on external catalog latency.
3. Extend the test harness to compose actual shell/navigation surfaces with
   injected services. Capture the current placeholder and closed drawer as
   findings; do not accidentally fix them in a baseline test.
4. Record representative small-window light/dark captures, including 320 dp
   width/large text and one expanded sidebar. Label existing standalone
   goldens separately and preserve them where useful.
5. Run baseline app/design-system checks and screenshot verification. Record
   existing failures separately instead of changing unrelated expectations.
6. Record exact seeding/reset steps, fixture identity, build configuration,
   and baseline revision/artifact checksum for UX-00.3. Keep secret-free
   baseline artifacts available even after UI implementation starts.

## Acceptance criteria

### Dataset and capture contract

- Fixture ID: `android-minimalist-ux-00.2-v1`. Both JSON archives use the
  existing secret-free export/import format. The visual archive has six
  conversations, eight messages, and four image references. The long archive
  has exactly 10,000 messages in conversation
  `019a5520-0000-7000-8000-000000000006`, with 40 references rotating across
  four content-addressed images. Other conversations are empty in that
  archive. Do not merge the visual archive over the long-history seed.
- The synthetic provider is `baseline-provider`, with
  `https://baseline.invalid/v1` and no stored key. Models cover pinned/free,
  vision/paid-metadata, hidden, and long-label states. No provider or external
  catalog request is needed. All conversation and image content is invented.
- Frozen swatches cover PNG 2048 x 1024, JPEG 640 x 480, WebP 320 x 240,
  and GIF 96 x 64. Their bytes, sizes, dimensions, and hashes are defined in
  `BaselineImages.kt`; the importer and native bitmap decoding are exercised.
  The shell image capture waits for decoded swatch pixels, not a placeholder.
- `TEST_NOW` is `2026-11-03T12:00:00Z`; history starts one year earlier, with
  consistent message/conversation timestamps. This deliberately stabilizes
  Pinned/Older history, **not every relative-date bucket**. Fixture preferences
  use comfortable density, MD chat font, token usage on, remote images off,
  and completed onboarding. Production's remote-image default remains true.
- `stream.json` describes success and recoverable-failure events: first event
  after 250 ms, subsequent events every 32 ms, 12-character Markdown chunks,
  reasoning, usage, and a terminal finish/error. `BaselineFixtures.playStream`
  feeds the existing fake adapter. Host captures hold a known partial stream;
  device tests play the complete recipe and check persisted content.
- `actual-shell` contains **28** host captures: light/dark pairs for the
  closed compact root; empty/populated/archived drawers; 840 dp permanent
  sidebar; empty chat; expanded reasoning/code/table; local images; 320 dp
  at 200% font scale; recoverable error; missing configuration; duplicate
  attachment warnings; 10,000-message history; and a controlled stream.
- `standalone-current` contains **four** new light/dark model-filter/hidden
  management captures. Existing tracked `ScreenshotTest` goldens are also
  standalone and were not refreshed. Neither group establishes production
  model-picker reachability. Injected shell coverage here is chat/history,
  not provider/settings/backup destination coverage or connectivity callbacks.
- Host conditions: Robolectric API 34, native graphics, mdpi, US locale, UTC,
  reduced motion, widths 320/360/411/840 dp. Explicit Markdown readiness,
  paused-looper idling for Room continuations, and a fixed large-text scroll
  position avoid capturing intermediate layout states. Absolute Windows
  outputs use Roborazzi's `File` overload.

### Reference-device seed, capture, and reset

Use the frozen APK pair on a **fresh disposable install only**. Never use a
real user's install, supply a real key, uninstall/clear real data, or depend
on a live provider. All host file paths below are Windows paths; the runner
component is Android's package/component syntax.

```powershell
# Start at the repository root, or reuse $A from Frozen artifacts.
$adb = Join-Path $env:LOCALAPPDATA 'Android\Sdk\platform-tools\adb.exe'
$serial = 'YOUR_DISPOSABLE_DEVICE_SERIAL'
$runner = 'dev.chatui.test/androidx.test.runner.AndroidJUnitRunner'
& $adb -s $serial install -r (Join-Path $A 'apks\app-debug.apk')
& $adb -s $serial install -r (Join-Path $A 'apks\app-debug-androidTest.apk')

$phaseArgs = @(
  'shell', 'am', 'instrument', '-w',
  '-e', 'class', 'dev.chatui.BaselineSeedTest',
  '-e', 'baselineDisposable', 'true',
  '-e', 'baselineAction'
)
& $adb -s $serial @phaseArgs seed $runner
& $adb -s $serial @phaseArgs verify $runner
& $adb -s $serial shell am start -W -n 'dev.chatui/.MainActivity'

# Separately: isolated real-shell paging and complete deterministic stream.
& $adb -s $serial shell am instrument -w `
  -e class dev.chatui.BaselineDeviceTest `
  -e baselineCapture true $runner
# /sdcard is a remote Android path, not a Windows host path.
& $adb -s $serial pull `
  '/sdcard/Android/data/dev.chatui/files/android-minimalist-ux-00.2-v1' `
  (Join-Path $env:TEMP "chatui-ux002-device-$PID")

# Remove only the persistent fixture when finished; seed again to repeat.
& $adb -s $serial @phaseArgs reset $runner
```

Require `OK (1 test)` for each seed/verify/reset and `OK (2 tests)` for the
device harness; `am instrument`'s process exit code alone is insufficient.
The manual phase is skipped by ordinary connected runs without its arguments.

Seeding refuses nonempty conversation/provider stores or an already-onboarded
install. It imports the exact long archive, stores its non-secret fixture
preferences, and selects the long conversation. Verification compares all
10,000 messages, the conversation count, and all four stored image hashes.
Reset removes only fixture-owned conversations/provider/attachments/drafts
and clears fixture preference pointers; shared image bytes are retained when
other attachment rows reference them. It refuses a modified fixture endpoint
or a provider with a stored key. On an otherwise empty install, onboarding
returns to incomplete so another seed can reproduce the starting state.

The ordinary launcher was verified to restore/read the persisted long history
offline without a key. Its existing API-key/offline notices are expected.
Wait for actual transcript text (`Local baseline` or `Synthetic local
message`), not merely `am start -W`, UI idleness, or an initial not-found
frame, before capturing or defining a usable-screen boundary.

The separate `BaselineDeviceTest` uses temporary on-disk Room and in-memory
preferences, injects fake provider/connectivity availability, and cleans up
after itself; it does not persistently seed the launcher. With
`baselineCapture=true`, its PNGs go under the target app's external-files
directory named `android-minimalist-ux-00.2-v1`. Frozen native evidence is in
`device-captures\android-minimalist-ux-00.2-v1`; these are informational Android
captures, not host golden comparisons or IME/device-matrix approval.

Executed environment: a new, task-owned API 37 x86_64 Google Play emulator,
720 x 1280 px / 320 dpi, font scale 1, en-US, UTC+03, two configured vCPUs,
WHPX/SwiftShader. The emulator raised the requested 2048 MiB RAM to **4096 MiB**;
this is not entry-level/2-GB hardware evidence. Wi-Fi/mobile data were disabled
and all three animator/window/transition scales set to zero. See
`device-harness-final.log`, the seven `device-seed`/`device-verify`/`device-reset`
logs, `emulator-device-properties.txt`, and the installed-launcher hierarchy.
The emulator was stopped and its specifically owned AVD files removed;
existing AVDs and persistent host environment settings were left untouched.
