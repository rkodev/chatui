## Goal

Persist non-secret settings and store API keys as ciphertext using Tink and the Android Keystore. Secrets and databases must be excluded from backup.

## Preconditions

- Room and `SecretEntity` exist.
- Tink and DataStore dependencies are configured.
- Do not implement provider behavior.

## Deliverables

- `core:datastore`:
  - Preferences DataStore persistence for non-secret settings and defaults
  - a typed settings model matching the shared `Settings` fields that apply to Android
  - no secrets, tokens, or provider keys in DataStore
  - tests for write/read/default behavior
- Secret storage:
  - a `SecretStore` or `SecretRepository` API: `put`, `get`, `delete`, `forgetKey`, `forgetAll`
  - Tink `AndroidKeysetManager` backed by Android Keystore in production
  - AEAD AES-256-GCM encryption
  - ciphertext-only persistence in `SecretEntity`
  - keyset never exported
  - an injectable cipher/keyset interface so JVM unit tests can use a Tink in-memory keyset without a real Android Keystore
  - no plaintext key in logs, DataStore, Room, crash reports, or URLs
- Backup exclusion:
  - `android:allowBackup="false"` where appropriate
  - `android:dataExtractionRules` for API 31+
  - `android:fullBackupContent` rules for API 26-30
  - exclude the database, secret storage, and secret-related shared preferences
  - do not rely on `allowBackup="false"` alone
- Tests:
  - settings persistence
  - secret encrypt/decrypt
  - ciphertext differs from plaintext
  - forget key and forget all behavior
  - wrong or missing keyset fails cleanly
  - backup rule files exist and reference the database/secret exclusions

## Handoff notes

Completion record (2026-11-02):

- DataStore: `dev.chatui.core.datastore.settings.AndroidSettings` is the typed non-secret model. It mirrors the shared `Settings` fields that apply to Android and deliberately omits `rememberKeysOnWeb` (web-only) and `backup` (future, stored in Room `BackupConfigEntity`). Defaults are `Theme.SYSTEM`, `Density.COMFORTABLE`, `ChatFontSize.MD`, `SendKey.ENTER`, empty prompt, streaming `ChatParams`, token usage off, remote images on, and onboarding incomplete.
- DataStore persistence: `SettingsDataStore` wraps `DataStore<Preferences>` and exposes `settings`, `current()`, `save()`, `update()`, and per-field setters. The application store is `Context.settingsDataStore` with file name `settings` under `files/datastore/`. Enum values are stored by enum name; `defaultParams` is stored as JSON via `ChatUiJson`. Missing or corrupt values fall back to defaults. No secret, token, or provider-key field exists in the model or preference keys.
- Cipher abstraction: `dev.chatui.core.datastore.secret.SecretCipher` has `encrypt`/`decrypt`; `SecretCipherException` carries only a safe message and never plaintext. `TinkSecretCipher` uses Tink AEAD AES-256-GCM with associated data `chatui-secret-v1` and Base64 ciphertext envelopes.
- Production keyset: `TinkSecretCipher.androidKeystore(context)` uses `AndroidKeysetManager` with `AeadKeyTemplates.AES256_GCM`, SharedPreferences file `chatui_secret_keyset_prefs`, keyset name `chatui_secret_keyset`, and master-key URI `android-keystore://chatui_secret_master_key`. The keyset is never exported or exposed by the API.
- Test keyset strategy: `inMemorySecretCipher()` in test sources generates a fresh Tink in-memory AES-256-GCM keyset per call. `FailingSecretCipher` simulates a missing keyset. No Android Keystore or device is required for JVM tests.
- Secret persistence: `SecretStore` uses `SecretDao` and stores only `SecretEntity.ciphertext`; `createdAt` is preserved on update and `updatedAt` advances. `put`, `get`, `delete`, `forgetKey`, and `forgetAll` are implemented. `forgetKey` deletes one row; `forgetAll` deletes every secret row. Keyset rotation/reset is intentionally out of scope for this task.
- Backup exclusion: `android/app/src/main/AndroidManifest.xml` keeps `android:allowBackup="false"` and adds `android:dataExtractionRules="@xml/data_extraction_rules"` plus `android:fullBackupContent="@xml/backup_rules"`. Rule files are `android/app/src/main/res/xml/data_extraction_rules.xml` (API 31+, cloud backup and device transfer) and `android/app/src/main/res/xml/backup_rules.xml` (API 26-30). Both exclude `chatui.db`, `chatui.db-shm`, `chatui.db-wal`, `chatui.db-journal`, the `datastore/` directory, and `chatui_secret_keyset_prefs.xml`.
- Tests: `:core:datastore:testDebugUnitTest` ran 21 tests (10 `SecretStoreTest`, 4 `TinkSecretCipherTest`, 7 `SettingsDataStoreTest`) with 0 failures. `:app:testDebugUnitTest` ran 4 tests (3 `BackupRulesTest`, 1 `PlaceholderTest`) with 0 failures. `BackupRulesTest` asserts the manifest attributes and that both rule files reference the database, DataStore directory, and secret SharedPreferences exclusions.
- Verification: `cd android && ./gradlew :core:datastore:testDebugUnitTest` passed; `cd android && ./gradlew :app:testDebugUnitTest` passed; `cd android && ./gradlew :app:assembleDebug` passed; `grep -RniE 'allowBackup|dataExtractionRules|fullBackupContent' android/app/src/main` printed the manifest attributes and rule-file comments.
- Keystore behavior still needing a device or Robolectric check: the production `AndroidKeysetManager` path is not exercised by JVM unit tests because it requires a real Android Keystore. A device/instrumented test should verify first-run keyset creation, decrypt-after-process-restart, and clean failure when the Keystore master key is invalidated.
- Decision: `allowBackup="false"` is kept, but backup exclusion does not rely on it alone; explicit API 31+ and API 26-30 rules are present as required.
- Decision: `forgetAll` clears secret rows but does not rotate the Keystore keyset. Rotation can be added later without changing the `SecretStore` API.
