## Goal

Turn the raw OpenRouter SSE fixtures into shared expected normalized output so web and Android adapters cannot drift. M0 intentionally deferred this work to M1.

## Preconditions

- `make contracts-check` passes on the M0 baseline.
- Do not modify client source in this task.

## Deliverables

- `contracts/fixtures/expected/openrouter-text.json`: expected ordered events and final text for `openrouter-text.sse`.
- `contracts/fixtures/expected/openrouter-keepalive.json`: expected events proving comments and unknown fields are ignored.
- `contracts/fixtures/expected/openrouter-reasoning.json`: expected reasoning and text deltas, with no duplicated reasoning.
- `contracts/fixtures/expected/openrouter-usage.json`: expected prompt, completion, total, and cost values.
- `contracts/fixtures/expected/openrouter-error-200.json`: expected partial text, error event, and no retry.
- `contracts/fixtures/expected/openrouter-key.json`: normalized key metadata from `contracts/fixtures/models/openrouter-key.json`.
- `contracts/fixtures/expected/openrouter-errors.json`: normalized `ChatError` values for 402, 429, 503, auth, model-not-found, and context-length cases.
- Validator support that reads every expected file, validates its shape, and rejects unknown fixture names or missing references.

## Expected file shape

Use a small explicit shape so a smaller implementer can follow it:

```json
{
  "source": "openrouter-text.sse",
  "events": [
    { "type": "start", "responseId": "gen-example-text" },
    { "type": "text-delta", "text": "Hello" },
    { "type": "text-delta", "text": " from" },
    { "type": "text-delta", "text": " OpenRouter." },
    { "type": "finish", "reason": "stop" },
    { "type": "usage", "usage": { "inputTokens": 12, "outputTokens": 4, "totalTokens": 16, "costUsd": 0.000012, "estimated": false } }
  ],
  "text": "Hello from OpenRouter.",
  "reasoning": "",
  "retryAllowed": false
}
```

Adjust the final ordering only if the real fixture requires it. Keep the shape consistent across files.

## Implementation steps

1. Read every OpenRouter SSE fixture and the key fixture.
2. Write one expected JSON file per stream scenario using the shape above.
3. For reasoning, define the rule explicitly in the file or a sibling note: prefer structured `reasoning_details` text, emit `reasoning` only when the same text has not already been emitted for that turn.
4. For `openrouter-error-200.json`, include the partial text `Partial answer`, the normalized error code, and `retryAllowed: false`.
5. For `openrouter-errors.json`, map 402 to `quota`, 429 to `rate_limit` with `retryAfterSeconds: 2`, 503 to `provider`, 401 to `auth`, 404 to `model_not_found`, and 400 context messages to `context_length`.
6. Extend `scripts/validate-contracts.mjs` to validate expected files against a small inline schema or a new Draft 2020-12 schema. Fail on missing source references, invalid event types, or malformed usage.
7. Run the contract gate and inspect the failure messages by temporarily breaking one file.

## Handoff notes

- Final stream shape: `{ source, events, text, reasoning, retryAllowed }`.
  Events use the spec 7.2 union. `usage` always carries all five fields.
- Reasoning precedence: structured `reasoning_details` wins when both fields
  appear in one delta; across deltas, each distinct reasoning text is emitted
  once per turn and later duplicates are suppressed. In the reasoning fixture
  the plain `reasoning` delta arrives first, so the emitted text is identical
  and the later `reasoning_details` duplicate is suppressed.
- `ChatError` vectors intentionally omit the runtime `at` timestamp so the
  vectors stay deterministic. Adapters still set `at` at runtime.
- The M0 fixture set has no 401, 404, or 400 context-length envelopes. Those
  cases are marked `"synthetic": true` in `openrouter-errors.json` and must be
  constructed inline by adapter tests. 402, 429, and 503 reference the existing
  raw envelopes.
- In-stream 502 is covered by `openrouter-error-200.json`; it emits `start`,
  `text-delta`, and `error` with `retryAllowed: false` and no `finish` event.
