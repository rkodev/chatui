# M5-01.3 - Android envelope codec and crypto tests

- Milestone: M5
- Status: Not started
- Order: 4
- Depends on: M5-01.1
- Parallel-safe: yes, with `M5-01.2` and `M5-01.4`
- Owns: `android/core/backup/` (new module), `android/settings.gradle.kts`, `android/gradle/libs.versions.toml`
- Read first: [M5 plan](../M5-backup-and-sync-implementation-plan.md) sections 3.2 and 5.3; spec sections 13.4 and 21.5; `contracts/fixtures/backup/vectors.json`

## Goal

Implement the `CHATUI1\n` backup envelope on Android using a passphrase-derived
AES-256-GCM key. The codec must match the shared vectors and must not reuse the
device-bound Tink key used for secret storage.

## Preconditions

- `M5-01.1` is `Complete` and the schemas and vectors exist.
- `android/core/datastore` already provides Tink for secret storage. Do not
  change it.
- Do not add a cloud SDK in this task.

## Deliverables

- New Gradle module `android/core/backup/` with:
  - `build.gradle.kts` and registration in `android/settings.gradle.kts`.
  - `BackupEnvelope.kt` with encode/decode and encrypt/decrypt functions.
  - `BackupCrypto.kt` with PBKDF2-HMAC-SHA256 key derivation and AES-GCM.
  - `BackupEnvelopeException.kt` with typed failures.
- Header JSON with `v`, `formatVersion`, `alg`, `kdf`, `iterations`, `salt`,
  `objectType`, `objectKey`.
- AAD construction from `objectType` and `objectKey`.
- Gzip via `GZIPOutputStream`/`GZIPInputStream` for conversation payloads; no
  gzip for attachments.
- Unit tests in `android/core/backup/src/test/`:
  - Round trip for manifest, conversation, and attachment.
  - Shared vector comparison.
  - Fresh IV per write.
  - Wrong passphrase fails.
  - Tampered magic, header, IV, ciphertext, and AAD fail.
  - Gzip round trip and attachment no-gzip.
  - Unknown `v`/`formatVersion` handling.

## Implementation steps

1. Read the existing `android/core/datastore` secret code and the shared vectors.
2. Create the `android/core/backup` module. Add it to `settings.gradle.kts` and
   the version catalog if new dependencies are needed.
3. Use JDK crypto, not Tink, for the backup envelope:
   - `SecretKeyFactory.getInstance("PBKDF2WithHmacSHA256")` with
     `PBEKeySpec(passphrase, salt, 600_000, 256)`.
   - `Cipher.getInstance("AES/GCM/NoPadding")`.
   - `GCMParameterSpec(128, iv)` and `updateAAD(aad)`.
4. Implement the byte layout exactly as frozen:
   - magic 8 bytes, big-endian `uint32` header length, UTF-8 header JSON,
     12-byte IV, ciphertext with the 16-byte tag appended.
5. Implement `encodeEnvelope`/`decodeEnvelope` with bounds checks on the header
   length and a maximum object size.
6. Implement `encryptObject`/`decryptObject` with optional gzip. Use
   `java.util.zip.GZIPOutputStream` and `GZIPInputStream`.
7. Add a passphrase verification token helper consistent with the web choice.
8. Add tests using JUnit and the shared vectors. Use synthetic data only.
9. Run the Android gates and fix failures.

## Acceptance criteria

- [ ] The new module builds and is registered in `settings.gradle.kts`.
- [ ] Envelope encode/decode matches the frozen byte layout.
- [ ] Header JSON contains every required field.
- [ ] AAD binds `objectType` and `objectKey`; tampering fails.
- [ ] A fresh 12-byte IV is used for every write.
- [ ] PBKDF2 uses 600,000 iterations, 16-byte salt, and a 32-byte key.
- [ ] Conversation payloads are gzipped; attachment bytes are not.
- [ ] Wrong passphrase and tampered ciphertext fail safely.
- [ ] Shared vectors pass.
- [ ] Secret-storage behavior and tests are unchanged.
