## Goal

Deploy the static app to a real staging tenant using the M6 templates and
templates/config, then prove the complete user flow with synthetic data: load,
configure a provider, chat, export, and optionally restore an encrypted backup.

## Preconditions

- Every dependency is `Complete`.
- The external operator supplies a staging tenant, subdomain, custom-domain test
  path, TLS access, edge access, and a disposable storage bucket or MinIO.
- The privacy copy is approved by `M6-04.3`.
- Do not record real keys, prompts, responses, passphrases, storage credentials,
  IP addresses, or user data. Use synthetic data and disposable credentials.
- If the staging tenant or operator access is unavailable, mark this task
  `Blocked` and record the blocker in `Handoff notes`.

## Deliverables

- `docs/operations/M6/evidence/README.md` with an index of M6 evidence and a
  statement that all data is synthetic.
- `docs/operations/M6/evidence/staging/README.md` recording:
  - Date, commit, operator, tenant URL, custom-domain URL, release version,
    artifact digest, and config hash.
  - Deployment steps using `deploy/roksky/README.md`.
  - Raw output of `scripts/verify-hosted-deployment.mjs` for the subdomain and
    custom domain.
  - Browser smoke steps and results:
    - Load the tenant and confirm the app shell.
    - Configure an OpenAI-compatible or OpenRouter test provider with a
      disposable key. If a real test key is unavailable, use a local
      OpenAI-compatible mock reachable at `http://localhost` and document it.
    - Send a synthetic prompt and confirm streaming/response handling.
    - Confirm no analytics/telemetry or third-party requests appear.
    - Export all data (JSON) and confirm the download.
  - Optional BYO storage smoke:
    - Configure MinIO or a disposable S3-compatible bucket with synthetic
      credentials.
    - Run the connectivity test.
    - Run a backup, then restore into a clean profile or a second browser
      profile.
    - Confirm the restore merges by default and the encrypted object names/
      contents are opaque.
  - Failure-state checks: invalid credentials, unreachable endpoint, and a
    CORS-negative case if practical.
  - A note on what was not exercised and why.
- Supporting artifacts under `docs/operations/M6/evidence/staging/`:
  - `verification-subdomain.txt` and `verification-custom-domain.txt`.
  - `smoke-checklist.md` or `.txt` with pass/fail results.
  - `network-audit.txt` listing request origins only, with no secrets or
    personal data.
  - `byo-storage.txt` if the optional storage smoke was run.
- Update the README task status if the task completes.

## Implementation steps

1. Confirm all dependencies and external access.
2. Build `web/dist` at the pinned commit.
3. Deploy to the staging subdomain using the template, then attach the custom
   domain.
4. Set the public config with the exact staging origin and validate it with the
   validator.
5. Run the hosted verification script against both URLs. Save raw output.
6. Run the browser smoke with synthetic content and disposable credentials.
7. Run the optional BYO storage backup/restore smoke with MinIO.
8. Record the network origins and confirm no hidden destinations.
9. Write the staging evidence README and update the evidence index.
10. If anything fails, record the failure as a blocker; do not mark complete.

## Acceptance criteria

- [ ] The staging tenant and custom domain are live and pinned to a recorded
      release and config hash.
- [ ] The hosted verification script passes for both URLs.
- [ ] The app loads and a synthetic chat succeeds.
- [ ] Export all data succeeds.
- [ ] The optional encrypted backup/restore smoke is recorded as pass or a
      documented not-run with reason.
- [ ] The BYO storage connectivity/failure checks are recorded if storage is in
      scope for the staging run.
- [ ] The network audit shows only expected origins.
- [ ] Evidence contains only synthetic data and no secrets or personal data.
- [ ] The evidence index is updated.

## Verification

```bash
make web-build
node scripts/validate-tenant-config.mjs <staging-config.json> --origin <staging-origin>
node scripts/verify-hosted-deployment.mjs <staging-url> --origin <staging-origin>
node scripts/verify-hosted-deployment.mjs <custom-domain-url> --origin <custom-domain-origin>
```

Plus the browser smoke, optional MinIO backup/restore, and network audit saved
under `docs/operations/M6/evidence/staging/`.
