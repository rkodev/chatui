# M5-01.1 - Contracts: envelope, manifest body, conversation payload, fixtures

- Milestone: M5
- Status: Complete
- Order: 2
- Depends on: M5-00.1
- Parallel-safe: no; blocks all client codecs
- Owns: `contracts/schema/`, `contracts/fixtures/backup/`, `scripts/validate-contracts.mjs`
- Read first: [M5 plan](../M5-backup-and-sync-implementation-plan.md) sections 3.1 and 5.3; spec sections 13.3, 13.4, and 21.5; `contracts/schema/backup-manifest.schema.json`

## Goal

Turn the frozen decisions from `M5-00.1` into versioned JSON Schemas and
fixtures. This task is the single source of truth for the backup format. Client
tasks must not invent fields or layouts.

## Preconditions

- `M5-00.1` is `Complete` and `M5-decisions.md` records the envelope layout,
  header fields, AAD, and manifest contents.
- Do not modify client source in this task.
- Do not change existing export or settings schemas in a breaking way.

## Deliverables

- Updated `contracts/schema/backup-manifest.schema.json`:
  - Add `formatVersion`.
  - Keep `contractVersion` and `v`.
  - Keep the existing header fields and `objectType` enum.
- New `contracts/schema/backup-envelope.schema.json` describing the header JSON
  and the byte layout metadata (magic, header length, IV, tag).
- New `contracts/schema/backup-manifest-body.schema.json` with:
  - `formatVersion`, `createdAt`, `updatedAt`, `deviceId`;
  - `conversations` index: `id`, `storageKey`, `revision`, `updatedAt`,
    `deletedAt`, `deviceId`, `objectKey`;
  - `attachments` index: `sha256`, `size`, `objectKey`, `createdAt`;
  - `tombstones`: `conversationId`, `deletedAt`, `deviceId`.
- New `contracts/schema/backup-conversation.schema.json` with:
  - conversation metadata (id, title, systemPrompt, providerId, modelId,
    modelLabel, params, pinned, archived, temporary, timestamps);
  - all messages (id, sequence, role, parts, status, usage, timestamps,
    `deletedAt`);
  - attachment references (id, sha256, mimeType, name, size, storageKey).
- Fixtures under `contracts/fixtures/backup/`:
  - `manifest.json` (valid manifest body);
  - `conversation.json` (valid self-contained conversation);
  - `envelope-header.json` (valid header);
  - `invalid/` cases for missing fields, wrong `alg`, wrong `kdf`, bad
    `objectType`, and bad `formatVersion`.
- `scripts/validate-contracts.mjs` updates:
  - Add the new schemas to `REQUIRED_SCHEMA_FILES`.
  - Validate every fixture in `contracts/fixtures/backup/`.
  - Add broken-vector self-tests for the new schemas.
- `contracts/fixtures/backup/README.md` documenting the vectors and that they
  are synthetic.

## Implementation steps

1. Read `M5-decisions.md`, the existing `backup-manifest.schema.json`, and the
   export schema for entity shapes.
2. Update `backup-manifest.schema.json` additively. Do not remove existing
   fields. Add `formatVersion` with `const: 1` for v1.
3. Create `backup-envelope.schema.json`. Model the header JSON, not the binary
   bytes. Document the byte layout in `description` fields.
4. Create `backup-manifest-body.schema.json`. Use `additionalProperties: false`
   and explicit `required` lists. Use `format: date-time` for timestamps.
5. Create `backup-conversation.schema.json`. Reuse the entity field names from
   spec section 6.2 and the export schema. Do not include secrets or provider
   API keys.
6. Add valid fixtures with synthetic IDs and content. Use UUIDv7-shaped IDs and
   RFC 3339 timestamps.
7. Add invalid fixtures under `contracts/fixtures/backup/invalid/`. Each file
   must fail for exactly one documented reason.
8. Update `scripts/validate-contracts.mjs`:
   - Add the new schema filenames to `REQUIRED_SCHEMA_FILES`.
   - Add a `validateBackupFixtures` function that loads each fixture and
     validates it against the matching schema.
   - Add a self-test that mutates a valid fixture and asserts validation fails.
   - Call the new function from the main validation sequence.
9. Run `make contracts-check` and fix every error.
10. Record the schema version and any deviations in `Handoff notes`.
