# M6-06.3 - Exit-gate verification and milestone closure

- Milestone: M6
- Status: Not started
- Order: 20
- Depends on: M6-06.1, M6-06.2, all prior tasks
- Parallel-safe: no; final gate
- Owns: `docs/operations/M6/M6-verification.md`, `docs/operations/M6/README.md`, `contracts/parity.md`, `docs/milestones/M6-managed-hosting.md`
- Read first: [M6 plan](../M6-managed-hosting-implementation-plan.md) sections 8, 9, 10, and 13; [M6 milestone](../../milestones/M6-managed-hosting.md) "Exit gate" and "Verification"; every M6 evidence file; [contracts/parity.md](../../../contracts/parity.md)

## Goal

Close M6 with a truthful verification record, evidence links, updated task and
milestone status, and an explicit statement that no backend, proxy, key custody,
plaintext storage, or support data-access path was introduced.

## Preconditions

- Every prior task is `Complete`, or a deferral is approved and recorded.
- `M6-04.3` is approved.
- `M6-06.1` and `M6-06.2` are complete and their evidence exists.
- Do not close the milestone if the staging tenant, privacy review, or
  portability proof is missing. Mark the milestone blocked instead.

## Deliverables

- `docs/operations/M6/M6-verification.md`:
  - Header: milestone, date, commit, outcome, evidence links, privacy review
    link, decisions link, and plan link.
  - Exit-gate table with pass/fail and evidence for every item in the M6
    milestone "Exit gate".
  - Commands and results:
    - `make contracts-check`
    - web gates if config/schema/scripts changed
    - `node scripts/validate-tenant-config.mjs` on deployed/template configs
    - `node scripts/verify-hosted-deployment.mjs` on staging and self-hosted
    - optional `make release-check`
  - Staging tenant summary: URL, custom domain, release digest, config hash,
    header/CSP/SPA/health result, chat/export/restore result.
  - Config review result and rollback drill result.
  - Privacy/legal approval and support-access review result.
  - Security/no-hidden-destination result.
  - Self-host/export portability result.
  - Teardown/export result or approved blocker.
  - A "no backend, no proxy, no key custody, no plaintext storage, no managed
    storage" statement verified by the security review.
  - Known limitations, if any, with owner and whether they block release.
- Update `docs/operations/M6/README.md`:
  - Set the milestone status to `Complete` only when everything passes.
  - Mark each task Complete or record an approved deferral.
- Update `contracts/parity.md` only if a hosting row is added by decision. Do not
  invent a parity row solely for M6.
- Update `docs/milestones/M6-managed-hosting.md` status from `Future` to the
  delivered status when complete, and update the milestone index if required.
- Update the plan status if a completion note is needed.

## Implementation steps

1. Confirm every dependency is Complete and every evidence file exists.
2. Run the full repository gate relevant to the files changed.
3. Re-run the tenant validator, hosted verifier, and self-host verifier.
4. Compile the exit-gate table from the actual evidence.
5. Record every failure as a blocker; do not mark the milestone complete.
6. If all items pass, write the verification record and update the statuses.
7. If a hosting parity row was approved, update it with evidence.
8. Update the milestone file and index, then re-read the final docs for
   consistency.
9. Confirm no secret, real key, passphrase, prompt, chat content, or personal
   data is in the evidence.

## Acceptance criteria

- [ ] `docs/operations/M6/M6-verification.md` exists and maps every exit-gate
      item to evidence.
- [ ] All required commands are recorded with real results.
- [ ] Staging, config review, rollback, privacy, security, and portability
      evidence are linked.
- [ ] The no-backend/no-proxy/no-key-custody/no-plaintext/no-managed-storage
      statement is verified.
- [ ] The README task statuses are updated.
- [ ] The milestone status and index are updated only if the gate passes.
- [ ] Any missing or failed item is an explicit blocker, not an unchecked box.
- [ ] No secret or real user data is present.

```bash
node scripts/verify-hosted-deployment.mjs <self-host-url> --origin <self-host-origin>
```

Plus the evidence links and manual review recorded in `M6-verification.md`.

- M5 or M4 behavior changes.
