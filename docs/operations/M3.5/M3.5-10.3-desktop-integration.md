# M3.5-10.3 - Native menus, shortcuts, window state, dialogs, and deep links

- Milestone: M3.5
- Status: Complete
- Order: 39
- Depends on: M3.5-08.1, M3.5-09.1, M3.5-09.3
- Parallel-safe: yes, with M3.5-10.1 and M3.5-10.2

- Read first: [M3.5 plan](../M3.5-rust-desktop-implementation-plan.md) sections 3.6 and 4.12; spec sections 10.8, 11.10, 11.11

## Goal

Implement the desktop-only integration layer: native menus, keyboard shortcuts, window-state persistence, native dialogs, clipboard, drag-and-drop, system theme, and `chatui://chat/<id>` deep links with single-instance behavior.

## Preconditions

- The shell and chat runner exist.
- Do not add hidden network destinations.
- Do not add multi-window unless it is low-risk and tested.
- Do not modify `web/`, `android/`, or `contracts/`.

## Deliverables

- Native menu bar with File, Edit, View, Conversation, and Help actions that map to real commands.
- Keyboard shortcuts from section 11.10:
  - `Ctrl/Cmd+K` search;
  - `Ctrl/Cmd+Shift+O` new chat;
  - `Ctrl/Cmd+/` shortcuts help;
  - `Esc` stop/close;
  - `Ctrl/Cmd+Shift+C` copy last response;
  - `Alt+Up/Down` navigate conversations.
- Window-state persistence for size and position.
- Native file dialogs for attachments and export/import.
- Clipboard copy for messages and code.
- Drag-and-drop file handling into the composer.
- System theme following.
- Deep link registration and routing for `chatui://chat/<id>` on cold and warm starts.
- Single-instance forwarding on platforms that support it.
- Optional multi-window only if tested and explicitly enabled by the decision record.
- Tests and a manual Linux smoke; record macOS/Windows blockers.

## Implementation steps

1. Read spec sections 10.8, 11.10, and 11.11, plus the framework-decision notes for native integration support.
2. Implement the menu model as commands over the same view models used by the shell. Do not duplicate business logic.
3. Implement the shortcut map. Do not steal text-field input. `Escape` first stops streaming, then closes the top layer.
4. Persist window size and position through the settings/state layer. Avoid storing sensitive content.
5. Wire native dialogs for attachment picking, export, and import.
6. Wire clipboard copy with exact text. Do not copy secrets or hidden metadata.
7. Wire drag-and-drop to the composer attachment flow.
8. Follow the system theme when the setting is `system`.
9. Implement deep-link parsing. Validate scheme/host/path and ID. If onboarding is incomplete, finish onboarding first or show a safe not-found state.
10. Implement single-instance forwarding where supported. Test cold and warm starts.
11. Add tests for command mapping, shortcut dispatch, deep-link parsing, invalid IDs, and window-state serialization.
12. Record manual OS results and blockers.

## Handoff notes

### Modules

- `menu.rs` owns the framework-independent menu model, stable command IDs,
  section 11.10 shortcut mapping, and the `CommandHandler`/`CommandOutcome`
  executor contract.
- `shortcuts.rs` owns the key map, modifier normalization, text-input guard,
  `Escape` precedence, dispatch actions, and the help-overlay lines.
- `window_state.rs` owns geometry serialization, clamping, file/memory stores,
  the Slint read/apply helpers, and system theme/motion probes.
- `dialogs.rs` owns the `rfd` native pickers, text read/write, dropped-file
  validation, and the composer attachment path.
- `clipboard.rs` owns exact message/code payload construction and the `arboard`
  system clipboard.
- `deep_link.rs` owns `chatui://chat/<id>` parsing, ID validation, onboarding
  routing, and cold/warm state.
- `single_instance.rs` owns the local Unix-socket listener/forwarder and the
  unsupported-platform fallback.
- `main.rs` wires the modules to the Slint shell and owns the startup, close,
  theme-poll, and single-instance timers.

### Menu and command mapping

| Menu | Item | Command ID | Shortcut |
| --- | --- | --- | --- |
| File | New Chat | `new-chat` | Ctrl/Cmd+Shift+O |
| File | Attach File… | `attach-file` | none |
| File | Export… | `export` | none |
| File | Import… | `import` | none |
| File | Quit | `quit` | Ctrl+Q (Slint binding only) |
| Edit | Search | `search` | Ctrl/Cmd+K |
| Edit | Copy Last Response | `copy-last-response` | Ctrl/Cmd+Shift+C |
| View | Toggle Sidebar | `toggle-sidebar` | none |
| View | Keyboard Shortcuts | `shortcuts-help` | Ctrl/Cmd+/ |
| Conversation | Previous Conversation | `previous-conversation` | Alt+Up |
| Conversation | Next Conversation | `next-conversation` | Alt+Down |
| Conversation | Stop | `stop-or-close` | Esc |
| Help | Keyboard Shortcuts | `shortcuts-help` | none |
| Help | Documentation | `open-docs` | none |
| Help | About ChatUI | `about` | none |

- The Slint `MenuBar` and the Rust `MenuBar` model use the same command IDs.
  `Command::id`/`Command::from_id` round-trip, and `command_for_id` rejects IDs
  that are not present in the active menu.
- `Command::shortcut` only exposes section 11.10 shortcuts. Quit has an extra
  native `Ctrl+Q` binding in Slint but is intentionally absent from the
  section 11.10 map.
- Commands route through `DesktopContext::execute`, which navigates the shell,
  toggles `ShellState`/`ShellWindow` properties, or shows a status notice. No
  menu item is a dead control.
- No menu label or command ID contains a URL; the only user-visible endpoint is
  the already-documented `DOCS_URL` notice.

### Shortcut behavior

| Shortcut | Action |
| --- | --- |
| Ctrl/Cmd+K | Search / History |
| Ctrl/Cmd+Shift+O | New chat |
| Ctrl/Cmd+/ | Toggle shortcuts help |
| Esc | Stop streaming, then close the top layer |
| Ctrl/Cmd+Shift+C | Copy the last response |
| Alt+Up | Previous conversation |
| Alt+Down | Next conversation |

- `Control` and `Meta` are normalized to the same primary modifier, so the map
  works on Linux/Windows (`Ctrl`) and macOS (`Cmd`).
- When a text field has focus, unmodified keys are left to the field. Modified
  shortcuts still resolve, so typing `k` or `/` is never stolen.
- `Esc` is stateful: while streaming it stops the stream; otherwise it closes
  the shortcuts-help overlay or the narrow drawer; with neither open it does
  nothing. This is implemented by `ShortcutMap::dispatch` and covered by tests.
- The help overlay lines are generated from `ShortcutMap::help_lines`, so the
  displayed list cannot drift from the dispatch table.

### Window state

- `WindowState` stores `width`, `height`, `x`, `y`, and `maximized` as camelCase
  JSON. Values are clamped to 480–7680 × 360–4320 logical pixels and ±10,000
  offsets; non-finite sizes fall back to 1024 × 720.
- `FileWindowStateStore` writes
  `$XDG_CONFIG_HOME/chatui/window-state.json` (or `$HOME/.config/...`, then the
  temp directory). It contains geometry only; no conversation, prompt, key, or
  other sensitive content is stored.
- The saved state is loaded before window creation and applied to the Slint
  window. It is saved on `on_close_requested`, after the event loop exits, and
  from the `--smoke` timer.
- The headless Slint testing backend does not apply window positions, so the
  x/y round-trip is covered by serialization tests; size is covered by the
  Slint read/apply test.

### Native dialogs, clipboard, and drag-and-drop

- `NativeDialogService` uses `rfd` with the GTK3 backend on Linux and the
  native backend on macOS/Windows. It provides attachment picking, export
  destination picking, import source picking, and UTF-8 read/write.
- `MemoryDialogService` is the test/headless double with queued paths and an
  in-memory file map.
- Dropped paths are filtered to regular files, converted to
  `AttachmentFileInfo`, validated with the shared `validate_attachment_file`,
  content-addressed through `AttachmentStore`, and added to the real
  `ComposerState`. Rejections produce user-safe messages and never mutate the
  composer.
- Clipboard copy is exact: message text is joined from text parts only.
  Reasoning, tool calls, tool results, and attachment metadata are excluded.
  Empty payloads are rejected instead of clearing the clipboard. Code blocks
  copy their exact source.
- `--copy-test` exercises the native clipboard headlessly; `--print-menu`,
  `--print-shortcuts`, and `--smoke` exist for unattended verification.

### System theme and motion

- Linux probes
  `gsettings get org.gnome.desktop.interface color-scheme` and
  `enable-animations`, with `GTK_THEME` as the dark fallback.
- macOS probes `defaults read -g AppleInterfaceStyle` and
  `com.apple.universalaccess reduceMotion`.
- Windows probes
  `HKCU\Software\Microsoft\Windows\CurrentVersion\Themes\Personalize\AppsUseLightTheme`.
- The probe is polled every 2 seconds and only syncs the shell when the theme or
  motion value changes. `ShellState::theme` still controls whether the app
  follows the system or a fixed light/dark selection.
- Probes run only local OS commands; they do not add a network destination.

### Deep links

- Accepted form: `chatui://chat/<id>`, where `<id>` is 1–128 characters from
  `[A-Za-z0-9_-]`.
- Rejected forms: non-`chatui` schemes, non-`chat` hosts, missing or extra path
  segments, query strings, fragments, encoded/unsafe IDs, and overlong IDs.
- Routing: valid link with onboarding complete → open Chat; valid link with
  onboarding incomplete → `OnboardingRequired`; invalid link → safe `NotFound`.
- Cold start scans process arguments; the first `chatui://` argument wins.
  `--deep-link <url>` and `--deep-link=<url>` are also accepted for testing.
  `--onboarding-incomplete` forces the onboarding branch.
- Warm starts arrive through single-instance forwarding and follow the same
  routing. The parsed link is retained in `DeepLinkState::take_pending` for the
  app composition to load the conversation; the current shell shows a status
  notice because the conversation view model is not yet hosted by the shell.
- No deep link can reach an unknown host or inject a path; invalid input only
  produces the not-found notice.

### Single instance

- Unix (Linux and macOS) uses a Unix-domain socket at
  `$XDG_RUNTIME_DIR/chatui-<user>.sock`, falling back to the temp directory.
  The first instance binds it and a listener thread forwards messages to the
  Slint loop through a 250 ms poll. Later launches connect, write the deep link
  (or `focus`), and exit without touching the database or secret store.
- A stale socket that cannot be connected to is removed and rebound.
- Windows uses `NoopSingleInstance`, which reports `Unsupported`; the app then
  starts normally instead of failing. This is a recorded per-OS blocker, not a
  hidden network fallback. The endpoint is local IPC only.

### Multi-window

- Multi-window is off, matching DEC-11. The desktop app creates one
  `ShellController`/`ShellWindow` and forwards links into that window.

### Blockers and limitations

- Windows single-instance forwarding is not implemented; it reports
  `Unsupported` and the app starts normally. macOS uses the Unix-socket backend
  but was not manually smoked.
- macOS and Windows manual smoke, screen-reader checks, and OS deep-link
  registration are unavailable locally. Installer registration and packaging
  remain M3.5-11 scope.
- The desktop binary still composes only the shared shell. Menu commands use
  shell navigation and status notices; export/import currently select and read
  or write files without invoking the repository-backed `DataController`,
  previous/next conversation point to History until the conversation view model
  is hosted, and copy-last-response reads a `last_response` cache that the app
  composition must fill from the chat runner. This matches the integration
  boundary recorded by M3.5-10.2.
- When `XDG_RUNTIME_DIR` is unavailable, the single-instance socket falls back
  to the shared temp directory. It remains local IPC, but permissions hardening
  for multi-user hosts is deferred.
- `rfd` requires a desktop session and a GTK3 runtime on Linux; headless runs
  use `MemoryDialogService` in tests and rely on the `--print-*`/`--copy-test`
  helpers instead of opening dialogs.
