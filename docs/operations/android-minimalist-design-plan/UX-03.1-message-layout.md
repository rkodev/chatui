# UX-03.1 - Content-first message geometry

- Phase: UX-03 - Chat readability and resources
- Status: Complete
- Order: 13
- Depends on: UX-01.5
- Output folder: `docs\operations\android-minimalist-design-plan`
- Parallel-safe: Yes with isolated shell/forms; no with other message-item edits.

## Goal

Give answers more reading space, remove avatar gutters, and keep role/content
distinctions without reducing supported message rendering.

## Read first

Read the [execution contract](README.md), source-plan sections 3, 5.1,
6, and 8, `Chat\ChatMessageItem.kt`, `Chat\ChatMessageList.kt`,
`Chat\ChatMarkdown.kt`, `Chat\ChatCodeBlock.kt`, and existing
`ChatMessageItemTest.kt`/`ChatMessageListTest.kt`.

## Owns

Message geometry in `ChatMessageItem.kt`, strictly needed list grouping/
container-width call sites, and corresponding item/list regressions.
Markdown parsing, actions, and attachment ingestion are not redesigned here.

## Deliverables

Near-full-width assistant responses, restrained right-aligned user bubbles,
and accessible role grouping with responsive transcript width.

## Implementation steps

1. Remove the assistant's 78% width cap and decorative avatar gutter. Use
   available narrow-window space while bounding wide transcript content to
   roughly 680-760 dp.
2. Keep user messages right-aligned on a subtle surface, generally up to
   about 88% width. Avoid hard fixed heights, tails, or stacked shadows.
3. Retain speaker grouping and restrained labels. System/tool roles and
   screen-reader role identity must remain explicit when an avatar disappears.
4. Preserve Markdown/GFM, links, tables, reasoning, code selection/wrap/copy,
   attachments, errors, partial content, and raw-source math fallback. Pass
   realistic content constraints to child renderers rather than clipping them.
5. Keep existing typography choices, lazy keys/content types, and stream-row
   isolation. Do not animate bubble height for each streamed token.
6. Add cases for long user/assistant text, grouped roles, long code/table
   content, 320 dp/200% text, and wide-window bounds.

## Acceptance criteria

- [x] Assistant reading width is meaningfully wider without horizontal clipping.
- [x] User bubbles, roles, system/tool labels, and selection remain clear.
- [x] All content types and partial/error states still render.
- [x] Layout is responsive without changing stored messages or list identity.

## Out of scope

Message-footer/action eligibility changes, composer work, new Markdown/math
features, or deleting content to improve layout.
