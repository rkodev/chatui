## Goal

Implement the local database, versioned migrations, and repositories. No UI may touch IndexedDB directly.

## Preconditions

- Domain types and config exist.
- `idb` and `fake-indexeddb` are installed.

## Deliverables

- `web/src/storage/db.ts`:
  - database name `chatui`, version `1`
  - typed `ChatUiDB` schema
  - `openDatabase()` using `idb`
- `web/src/storage/migrations.ts`:
  - versioned migration functions
  - v1 creation from an empty database
  - a test that creates and upgrades a v1 database
- Object stores and indexes:
  - `conversations` keyed by `id`; indexes `updatedAt`, `lastMessageAt`, `archived`, `pinned`
  - `messages` keyed by `id`; indexes `[conversationId+sequence]`, `conversationId`, `createdAt`
  - `attachments` keyed by `id`; indexes `sha256`, `messageId`, `createdAt`
  - `providers` keyed by `id`; indexes `presetId`, `enabled`
  - `models` keyed by `id`; unique `[providerId+remoteId]`, plus `providerId`
  - `settings` keyed by `key`
  - `secrets` keyed by `id`
  - `backupConfig` keyed by `id`
  - `syncQueue` keyed by `id`; indexes `conversationId`, `attempts`
  - `attachmentBlobs` keyed by `sha256`, used only as the OPFS fallback byte store; document this small extension to spec 8.5
- Repositories:
  - `ConversationRepository`: create, get, list paginated, update, delete
  - `MessageRepository`: get, list by conversation with a default limit of 50 and older-page pagination, append message plus conversation metadata in one transaction, count
  - `AttachmentRepository`: metadata create/get/list/delete
  - `ProviderRepository`: CRUD
  - `ModelRepository`: CRUD and unique `(providerId, remoteId)` enforcement
  - `SettingsRepository`: get, set, list
  - `SecretRepository`: ciphertext record get/put/delete
  - `BackupConfigRepository`: get/put
  - `SyncQueueRepository`: enqueue, list, update attempts, delete
- All write paths are async and use transactions where multiple records change.
- Tests for every repository and the migration path.

## Handoff notes

- `attachmentBlobs` is a documented extension to spec 8.5. It is keyed by `sha256` and stores `{ sha256, blob, size, createdAt }`. M0-02.4 owns writing and reading it as the OPFS fallback; this task only creates the store.
- Message pagination cursor shape: `MessageRepository.listByConversation` returns `nextCursor` as the oldest loaded `sequence` number, or `null` when no older page exists. Pass it back as `beforeSequence` (exclusive upper bound) to load the previous page. The default limit is 50 and results are returned in ascending sequence order.
- Conversation pagination cursor shape: base64-encoded JSON `{ updatedAt, id }`. `id` breaks ties for conversations sharing an `updatedAt`. Results are newest-first.
- Message append transaction boundary: `MessageRepository.appendMessage` opens one `readwrite` transaction over `messages` and `conversations`. It reads the existing message and conversation, writes the message, then updates `lastMessageAt` (max of existing and message time), `messageCount` (incremented only for a new message id), and `updatedAt` (append time). Any error aborts the transaction, so the message and metadata cannot diverge.
- IndexedDB cannot index booleans. `ConversationRecord.archived`/`pinned` and `ProviderRecord.enabled` are persisted as `0 | 1` so the required indexes are functional; repositories map them back to booleans. This matches Room's INTEGER representation.
- `ConversationRepository.delete` removes the conversation and its messages in one transaction. Attachment metadata/bytes are left for the orphan-cleanup path.
- `ProviderRepository.delete` cascades to the provider's models and referenced secret in one transaction, matching spec 6.4.
- `SecretRecord` is `{ id, iv, ciphertext, key?, createdAt, updatedAt }`. M0-02.5 may store the non-extractable device key in `key` and ciphertext records in `iv`/`ciphertext`; plaintext must never be written.
- `SyncQueueItem` is a documented placeholder for M5. `BackupConfigRepository` uses the fixed id `default` unless a caller supplies another id.
- The migration harness is `runMigrations(db, oldVersion, newVersion, transaction, migrationList?)`. Production has only v1; the optional list lets tests exercise a v2 upgrade without adding a production migration.
