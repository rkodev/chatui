## Goal

Replace the placeholder body in `ShellWindow`'s content area with host
containers for the real feature views, driven by `active-destination`, without
constructing services or controllers.

## Preconditions

- `M3.6-01.1` is complete and its decision is available.
- If the decision is no-go, follow its fallback plan instead of
  `ComponentContainer`.
- Do not construct services, controllers, or database connections in this task.
- Do not modify `web/`, `android/`, or `contracts/`.

## Deliverables

- `ShellWindow` properties:
  - `chat-messages-factory`, `chat-composer-factory`, `history-factory`,
    `providers-factory`, `settings-factory`, `data-factory`, `models-factory`
    of type `component-factory`;
  - `show-models` for the Models overlay;
  - any onboarding host flag required by the embedding decision.
- `MainContent` hosts:
  - Chat as a vertical stack of message list and composer containers;
  - History, Providers, Settings, and Data as full-area containers;
  - Models as an overlay container.
- Destination switching keeps containers instantiated and toggles visibility so
  embedded handles remain valid.
- Component tests with the Slint testing backend proving a factory product is
  embedded and updated, and that destination switching does not panic.

## Implementation steps

1. Read the embedding decision and copy its proven pattern.
2. Add the factory properties to `ShellWindow`.
3. Replace the placeholder `Text` block in `MainContent` with a content area.
4. Add one `ComponentContainer` per feature. For Chat, add two stacked
   containers with the messages area stretching and the composer at a bounded
   height.
5. Gate visibility by `active-destination`; keep the components instantiated.
6. Add the Models overlay gated by `show-models` with a close action.
7. Keep the title, notice, and error chrome visible above the content.
8. Add tests using a small test component and `ComponentFactory::new`.
9. Update `sync_window` only if new shell-level state is required. Do not set
   factory properties from `sync_window`.

  - Enabled `SLINT_ENABLE_EXPERIMENTAL_FEATURES=1` in
    `rust/crates/chatui-ui/build.rs` via `cargo:rustc-env`, as required by the
    embedding decision.
  - Added `component-factory` properties to `ShellWindow` and `MainContent` and
    embedded the feature views with `ComponentContainer`.

    `MainContent.body`, and `content-max-width` are gone; `sync_window` no
    longer pushes placeholder copy.
  - Destination switching uses conditional containers (`if`) rather than
    `visible`. The Slint `visible` property on `ComponentContainer` does not
    hide the embedded item tree because the embedded root has no parent link to
    the host clip; the spike only proved handle survival, not hiding. The
    feature components stay instantiated in Rust and the factory returns the
    same handle, so embedded handles remain usable across switches. The new
    test proves this.
  - The Models overlay is a conditional full-area container with a
    "Close models" button that clears `show-models`.
  - No onboarding host flag was added: the embedding decision does not require
    one and the task deliverables list no onboarding factory. Onboarding
    composition remains with `M3.6-06.1`.

## Handoff notes

- `M3.6-06.1` property names and expected component types on `ShellWindow`:
  - `chat-messages-factory` → `MessageListWindow`
  - `chat-composer-factory` → `ComposerWindow`
  - `history-factory` → the History view from `M3.6-04.1`
  - `providers-factory` → `ProviderManagementWindow`
  - `settings-factory` → `SettingsWindow`
  - `data-factory` → `DataWindow`
  - `models-factory` → `ModelManagementWindow`
  - `show-models` (`bool`, in-out) opens the Models overlay.
  - `active-destination` (`int`) selects Chat 0, History 1, Providers 2,
    Settings 3, Data 4.
- Factories must return the controller's own handle, for example
  `slint::ComponentFactory::new(move |_| Some(handle.clone_strong()))`. Do not
  create a fresh component in the factory.
- `sync_window` deliberately does not set factory properties. `M3.6-06.1` must
  install factories once when it creates the feature controllers.
- Embedding decision impact: the go decision selected
  `ComponentContainer` + `ComponentFactory`; the experimental builtins are
  enabled for `chatui-ui` in `build.rs`. The decision's `visible`-over-`if`
  recommendation could not be followed for destination switching because
  `visible` does not hide embedded content. Focus traversal and popups for the
  real feature views still need verification in `M3.6-06.1`; this task only
  embeds a test component and verifies its accessibility-tree presence.
- The shell keeps its own `MenuBar`; feature views must not add one.
