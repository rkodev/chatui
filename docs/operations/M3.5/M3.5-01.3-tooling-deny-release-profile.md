# M3.5-01.3 - Developer tooling, dependency policy, and release profile

- Milestone: M3.5
- Status: Not started
- Order: 5
- Depends on: M3.5-01.1
- Parallel-safe: yes, with M3.5-01.2 and M3.5-02.1
- Owns: `Makefile` (Rust targets only), `rust/deny.toml`, `rust/Cargo.toml` (`[profile.release]` skeleton), `docs/operations/M3.5/tooling.md`
- Read first: [M3.5 plan](../M3.5-rust-desktop-implementation-plan.md) sections 3.1, 3.7, and 6.1; spec sections 10.9, 15.3, 16.3

## Goal

Make the Rust gate enforceable from the repository root and define the dependency, advisory, and release-profile policy before substantial dependencies are added.

## Preconditions

- The workspace exists and compiles.
- Do not change web or Android Makefile targets.
- Do not add CI workflows in this task; M3.5-11.4 owns them.
- Do not install global tooling without user approval.

## Deliverables

- Root Makefile targets:
  - `rust-fmt`
  - `rust-nextest`
  - `rust-deny`
  - `rust-audit`
  - `rust-conformance`
  - `rust-ui-test`
  - `rust-package`
- Updated `.PHONY` and `make help`.
- `rust/deny.toml` with advisories, licenses, bans, and sources policy.
- A `[profile.release]` skeleton in `rust/Cargo.toml` using thin or fat LTO, `codegen-units = 1`, `strip = "symbols"`, and `panic = "abort"` where compatible. Final tuning is M3.5-11.1.
- `docs/operations/M3.5/tooling.md` documenting the commands, required tools, and how to install them.

## Implementation steps

1. Read the current `Makefile`, especially the existing Rust targets at lines 122-140.
2. Add the new targets without changing existing web/Android targets. Every target should require `rust/Cargo.toml` and fail with an actionable message when it is absent.
3. Use these commands as the baseline:
   ```make
   rust-fmt:        cd rust && cargo fmt --all --check
   rust-nextest:    cd rust && cargo nextest run --workspace
   rust-deny:       cd rust && cargo deny check
   rust-audit:      cd rust && cargo audit
   rust-conformance: cd rust && cargo nextest run -p chatui-conformance
   rust-ui-test:    cd rust && cargo nextest run -p chatui-ui
   rust-package:    run the packaging command chosen in M3.5-11.2
   ```
4. Update `.PHONY` and the `make help` Rust section. Keep the wording explicit that Rust is optional and parallel.
5. Add `rust/deny.toml`. Start with a conservative policy: deny known vulnerabilities, deny unknown registries or git sources unless approved, and allow the licenses used by the selected crates. Do not disable a check to make the gate pass.
6. Add the release profile skeleton to `rust/Cargo.toml`. Do not finalize symbol artifacts or packaging here.
7. Document local tool installation separately from CI installation. Do not commit installed binaries.
8. Run the targets that are locally available. If `cargo-nextest`, `cargo-deny`, or `cargo-audit` is missing, record the blocker in the handoff notes rather than faking a pass.

## Acceptance criteria

- [ ] All seven Rust targets exist and are in `.PHONY`.
- [ ] `make help` lists the new targets.
- [ ] Existing web and Android targets are unchanged.
- [ ] `rust/deny.toml` exists with advisories, licenses, bans, and sources.
- [ ] The release profile skeleton exists.
- [ ] `make rust-fmt`, `make rust-check`, and `make rust-lint` pass when the workspace is present.
- [ ] Missing nextest/deny/audit tools are recorded as blockers, not silently ignored.
- [ ] `docs/operations/M3.5/tooling.md` documents the commands and prerequisites.

## Verification

```bash
make help
make rust-fmt
make rust-check
make rust-lint
make rust-nextest || true
make rust-deny || true
make rust-audit || true
```

Only mark the task complete when the available checks pass and missing tools are documented.

## Out of scope

- Adding dependencies beyond the workspace skeleton.
- CI workflows and release artifacts.
- Final release-profile tuning, symbols, packaging, and performance evidence.
