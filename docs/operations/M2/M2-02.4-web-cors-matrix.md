## Goal

Classify browser CORS failures actionably, verify every provider endpoint where possible, and record truthful `browserCors` values.

## Preconditions

- Web adapters for OpenRouter, OpenAI-compatible presets, Anthropic, Gemini, and Ollama exist.
- Use disposable test keys only; never record keys.

## Deliverables

- `cors` error classification when a network failure matches a known provider.
- Provider-specific actionable copy that suggests Android or a future self-hosted proxy, never a hidden proxy.
- CORS matrix results for `/models`, key validation, and chat streaming where applicable.
- Updated `browserCors` values in `contracts/providers.json`.
- Tests for CORS classification and non-CORS network failures.
- Documented unsupported/provider limitations.

## Implementation steps

1. Review the M1 OpenRouter CORS evidence and the new provider adapters.
2. Add a classification helper that distinguishes aborted, offline, CORS-shaped, and generic network failures.
3. Add provider-specific error copy without exposing internals.
4. Build the CORS matrix with endpoint, method, origin, preflight, status, conclusion, timestamp, and evidence.
5. Run browser checks with disposable keys and record only status/conclusion data.
6. Update `browserCors` for every preset.
7. Add tests for classification and copy.
8. Run web gates and contract validation.

## Acceptance criteria

- [x] CORS-shaped failures map to `cors` and show actionable copy.
- [x] Generic offline failures remain `network`, not `cors`.
- [x] No proxy is added.
- [x] Every preset has a truthful `browserCors` value.
- [x] Unsupported providers are documented with a fallback path.
- [x] Evidence contains no keys or prompts.
- [x] `make contracts-check` and web gates pass.
