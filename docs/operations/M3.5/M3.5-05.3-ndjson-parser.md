## Goal

Implement a bounded NDJSON line reader for Ollama's native streaming endpoint without parsing provider payloads in the transport.

## Preconditions

- Domain and conformance scaffold exist.
- Do not parse Ollama JSON in this module. The Ollama adapter owns JSON.
- Do not use an unbounded line buffer.
- Do not modify `web/`, `android/`, or `contracts/`.

## Deliverables

- An async NDJSON line reader over an async byte stream.
- A configurable maximum incomplete-line buffer.
- Handling of final lines without a trailing newline.
- Blank-line tolerance.
- Abort/cancellation support.
- Tests against `contracts/fixtures/streams/ollama-ndjson.txt` and chunk-boundary/property tests.

## Implementation steps

1. Read `web/src/providers/ollama.ts` and the Ollama stream fixture.
2. Define an async API such as `read_ndjson(stream, on_line, cancel, max_line_bytes)`.
3. Read bytes, split on `\n`, and strip a trailing `\r` if present.
4. Ignore empty lines. Do not emit blank lines as records.
5. Enforce a maximum incomplete-line buffer. Return a typed overflow error.
6. Flush the final line when the stream ends without a newline.
7. Support cancellation promptly.
8. Add tests with chunk boundaries, CRLF, split multi-byte UTF-8, blank lines, oversized lines, and the final line.
9. Do not parse JSON in the parser; adapters parse lines.
10. Document the buffer limit and error type.

## Acceptance criteria

- [x] NDJSON lines are emitted in order.
- [x] CRLF and LF are handled.
- [x] Blank lines are ignored.
- [x] The final line flushes without a trailing newline.
- [x] The line buffer is bounded and overflow is a typed error.
- [x] Cancellation stops reading promptly.

## Handoff notes

- Completed 2026-11-07.
- Public API: `chatui_providers::ndjson::read_ndjson(stream, on_line, cancel, max_line_bytes)` where `stream` is any `futures_util::Stream<Item = Result<B, E>>` with `B: AsRef<[u8]>`, `on_line` is `FnMut(&str)`, `cancel` is a `tokio_util::sync::CancellationToken`, and `max_line_bytes` is the incomplete-line byte limit. Re-exported from the crate root as `read_ndjson`, `NdjsonError`, and `DEFAULT_MAX_NDJSON_BUFFER_BYTES`.
- Buffer limit: `DEFAULT_MAX_NDJSON_BUFFER_BYTES = 1024 * 1024` (1 MiB). The limit applies only to an incomplete line; complete lines are drained before the check, so a complete line larger than the limit is still delivered. Overflow returns `NdjsonError::BufferOverflow { max_bytes }`.
- Error type: `NdjsonError::{BufferOverflow, Cancelled, Stream, InvalidUtf8}`. `Stream` carries the underlying error's display message; `InvalidUtf8` is returned for a complete line that is not valid UTF-8.
- Framing: bytes are split on `\n`; a trailing `\r` is stripped so LF and CRLF both work, including a CRLF pair split across chunks. Empty and whitespace-only lines are ignored. The final line is flushed at end of stream, including a final line that ends with a lone `\r`. Lines are passed through raw; the module never parses JSON or interprets Ollama's `done` flag.
- Cancellation: checked before every read and raced against the pending stream read with `tokio::select!` (`biased`), so a cancelled token returns `NdjsonError::Cancelled` without polling the stream again.
- Fixture tests: `rust/crates/chatui-providers/tests/ndjson.rs` loads `contracts/fixtures/streams/ollama-ndjson.txt` through `chatui_conformance::ConformanceFixtures` and compares the raw line sequence against an independent oracle.
- Chunk-boundary tests: every split point of the Ollama fixture, one-byte chunks, and every fixed chunk size from 1 through the fixture length. Additional cases cover CRLF split across chunks, blank and whitespace-only lines, final-line flush with and without a newline, a final lone `\r`, UTF-8 split across chunks, overflow, complete-line-larger-than-limit, cancellation, stream errors, invalid UTF-8, and raw non-JSON passthrough.
- Verification: `cargo fmt --all --check` passed; `cargo clippy -p chatui-providers --all-targets -- -D warnings` passed; `cargo nextest run -p chatui-providers` passed 84/84 (22 NDJSON tests).
- Decisions: the parser accepts a generic byte stream rather than a `reqwest::Response` so it stays transport-agnostic and testable; `CancellationToken` is required rather than optional so callers cannot accidentally ignore cancellation; the buffer limit is measured in bytes, matching the SSE parser. Lone `\r` is not treated as a line ending because the task specifies splitting on `\n` and stripping a trailing `\r`; only a trailing `\r` before `\n` or at end of stream is removed.
- Known framing edge case: a complete line larger than `max_line_bytes` is allowed because the limit is on the incomplete-line buffer, matching the web transport. A single stream chunk can therefore allocate up to the chunk size before the post-chunk overflow check; the HTTP client's chunking bounds this in practice.
- No `web/`, `android/`, or `contracts/` file was modified. `lib.rs` declares and re-exports the module.
