## Goal

Prove on a second target that backup and device transfer do not restore keys, provider secrets, the database, or the DataStore.

## Preconditions

- M3-01.1 proved the sentinel encrypt/decrypt path.
- Use a disposable test key only; never a real provider key.
- Do not weaken `allowBackup` or the XML rules to make a test pass.

## Deliverables

- A documented backup/transfer procedure using two emulators or two devices.
- Case 27 evidence: after restore, no provider/key returns, and a fresh install requires onboarding/key entry again.
- Evidence for both API 26-30 (`fullBackupContent`) and API 31+ (`dataExtractionRules`) rule paths where available.
- Confirmation that `BackupRulesTest` still passes.

## Implementation steps

1. Read `AndroidManifest.xml`, `backup_rules.xml`, `data_extraction_rules.xml`, and `BackupRulesTest`.
2. On the first target, install the app, complete onboarding with a disposable sentinel key, and create one conversation.
3. Run the backup or transfer path available in the environment:
   - `adb shell bmgr backupnow dev.chatui` plus a restore on a second emulator; or
   - Android device-to-device transfer; or
   - the platform backup tooling available on the test device.
4. On the second target, install/restore the app and inspect:
   - onboarding state;
   - provider list;
   - secret store;
   - conversations.
5. Assert the key/provider data is absent. If conversations are also absent, record that as expected because the database is excluded.
6. Repeat or document the API 31+ data-extraction path. If only one API level is available, record the limitation.
7. Add the exact commands, API levels, targets, date, and result to `M3-verification.md`.
8. If a defect is found, fix only the manifest/rules or a targeted test; do not redesign storage.

## Acceptance criteria

- [ ] Manifest still has `android:allowBackup="false"` and references both rule files.
- [ ] Both XML files still exclude database, DataStore, and secret keyset.
- [ ] A second target cannot restore a provider key or secret.
- [ ] The evidence states the API levels and transfer method used.
- [ ] `BackupRulesTest` passes.
- [ ] No real key or personal data is recorded.

## Verification

```bash
make android-test
cd android && ./gradlew :app:connectedDebugAndroidTest
```

Plus the recorded two-target backup/transfer evidence.

## Out of scope

- Implementing backup/sync.
- Changing database or secret storage layout.
- Biometric or key-reveal behavior.
