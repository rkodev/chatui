# UX-03.2 - Message actions and metadata footer

- Phase: UX-03 - Chat readability and resources
- Status: Not started
- Order: 14
- Depends on: UX-03.1
- Output folder: `docs\operations\android-minimalist-design-plan`
- Parallel-safe: No with message-item/list footer edits.

## Goal

Consolidate secondary rows into one wrapping footer while keeping actions,
historical attribution, and the user's token-usage preference discoverable.

## Read first

Read the [execution contract](README.md), source-plan sections 5.1 and
6, `Chat\ChatMessageItem.kt`, `Chat\ChatMessageActions.kt`, existing
`ChatMessageActionsTest.kt`/`ChatMessageItemTest.kt`, and
`MessageModelSnapshotTest.kt` in the providers test root.

## Owns

Message footer/action presentation and corresponding item/action regressions.
Read service eligibility/snapshot APIs; do not rewrite runner/history logic.

## Deliverables

A visible Message actions entry, direct Copy for the latest eligible assistant
response, compact metadata, and preserved action safeguards.

## Implementation steps

1. Merge redundant timestamp/model/action rows into one wrapping footer.
   Keep a visible accessible Message actions control; long press is optional.
2. Retain direct Copy for the latest eligible assistant answer. Put existing
   regenerate/edit actions in the appropriate message menu using the current
   eligibility helpers, not new presentation-derived eligibility rules.
3. Preserve exact-text copy, regenerate-last-assistant behavior, edit/resend-
   last-user behavior, and the existing truncation warning/confirmation.
4. Keep historical model/provider attribution available from the message's
   stored snapshot, never the current header or renamed current model.
5. When Show token usage is enabled, display a readable wrapping summary
   beneath responses. Do not move all usage behind Details. Put genuinely
   additional metadata in a labeled disclosure/menu entry.
6. Keep request Retry/Details beside the affected message and avoid a second
   global copy of the same error.
7. Add focused cases for eligible/ineligible messages, confirmation cancel,
   historical attribution after model switching, usage on/off, and large-font
   footer wrapping with 48 dp menu targets.

## Acceptance criteria

- [ ] Footer is compact without hiding required metadata/preferences.
- [ ] Every action has a visible labeled path and unchanged eligibility.
- [ ] Truncation safeguards and exact copy survive.
- [ ] Historical attribution is independent of the current selection.
