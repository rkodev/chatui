# UX-04.3 - Quiet provider list and truthful status

- Phase: UX-04 - Setup, providers, and models
- Status: Not started
- Order: 22
- Depends on: UX-02.4
- Output folder: `docs\operations\android-minimalist-design-plan`
- Parallel-safe: No with ProviderListScreen/ProviderRoutes form extraction.

## Goal

Give Providers one title, simple status rows, and one Add provider entry while
retaining current create flows for the following form-polish task.

## Read first

Read the [execution contract](README.md), source-plan section 5.5,
`Providers\ProviderListScreen.kt`, `Providers\ProviderRoutes.kt`,
`Providers\ProviderListViewModel.kt`, provider auth/preset model definitions,
and `ProviderListScreenTest.kt`/`ProviderListViewModelTest.kt`.

## Owns

List/title/add-entry presentation in the named list/route files, narrowly
required presentation state, and existing list tests. Preset/credential
validation and transport behavior stay read-only.

## Deliverables

Nonduplicated title ownership, concise growable provider rows, truthful textual
status, and a single labeled entry to existing add-form content.

## Implementation steps

1. Coordinate title ownership with the shell, retaining standalone composition
   support only where necessary. Remove the repeated Providers heading.
2. Replace tall repetitive cards/buttons with tappable rows showing provider
   name and useful configuration/enabled status. Keep visible text and
   accessibility semantics in addition to any status color.
3. Determine "needs key" from the actual auth requirement, not just
   `secretId == null`. A no-auth local provider is not broken for lacking a key.
   A stored key means configured, not verified live connectivity.
4. Put existing add-form content behind one labeled Add provider action,
   preserving its current fields/handlers. Extract privately if needed;
   UX-04.4 owns field reorganization, not reconstruction of lost create flows.
5. Keep loading/error/retry/empty states calm and actionable, preserve cached
   rows during refresh, and avoid automatic usage/catalog refresh on recomposition.
6. Add cases for no-auth provider, missing required key, disabled provider,
   stored-but-unverified key, single title/Add entry, long names/large fonts,
   detail navigation, and retained access to both create flows.

## Acceptance criteria

- [ ] One production Providers title and Add provider entry.
- [ ] Status is textual and truthful for all auth/enabled states.
- [ ] All configured profiles and preset/custom create paths remain reachable.
- [ ] No recomposition-triggered network refresh or new service behavior.
