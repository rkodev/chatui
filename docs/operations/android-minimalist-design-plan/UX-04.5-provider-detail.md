# UX-04.5 - Provider detail and secure key editor

- Phase: UX-04 - Setup, providers, and models
- Status: Not started
- Order: 24
- Depends on: UX-04.2, UX-04.4
- Output folder: `docs\operations\android-minimalist-design-plan`
- Parallel-safe: No with ProviderDetailScreen/ProviderRoutes edits.

## Goal

Make provider detail status-first, move diagnostics out of the main path, and
give Change key a focused secure editor without losing metadata or safeguards.

## Read first

Read the [execution contract](README.md), source-plan section 5.5,
`Providers\ProviderDetailScreen.kt`, `Providers\ProviderRoutes.kt`,
`Providers\ProviderDetailViewModel.kt`, UX-04.2's Models callback,
UX-04.4's key-entry patterns, and detail/route/secure-screen tests.

## Owns

Provider detail/key-editor presentation, necessary route callback plumbing,
and existing `ProviderDetailScreenTest`, `ProviderDetailViewModelTest`, and
`ProviderRoutesTest` cases. Services/secret records are not redesigned.

## Deliverables

A concise status overview, secondary Models/Refresh, Connection details
disclosure, and secure key change/removal paths.

## Implementation steps

1. Lead with provider name, enabled state, truthful key/configuration status,
   model count, and actual reported usage/limits. Keep unknown values unknown,
   not invented zero credit/usage or a false connected badge.
2. Preserve the working Models entry from UX-04.2 and Refresh/Validate actions
   as secondary operations. Do not trigger them merely by recomposition.
3. Put auth type, full endpoint/preset, rate limits, CORS metadata, and other
   diagnostics in Connection details. Preserve key label/limit/free-tier
   metadata, OpenRouter policy notice, and documentation access.
4. Change key opens focused protected input with current show/hide/validation/
   rotation behavior. Never load an existing raw key into a preview or expose
   sensitive headers in diagnostics contrary to existing redaction.
5. Keep Remove key clearly destructive with the existing confirmation and
   explanation that provider/conversations remain. Do not turn it into remove
   provider, clear history, or silently disable unrelated configuration.
6. Preserve errors/entered replacement key after recoverable failure and
   focus/Back after editor dismissal. No raw credentials in saved-state bundles.
7. Add cases for unknown/reported usage, Models/Refresh/Validate, diagnostics
   access, rotation failure, remove cancel/confirm, retained records, secure
   editor, and small/large-font layout.

## Acceptance criteria

- [ ] Overview is concise while all metadata/diagnostics remain reachable.
- [ ] Models and refresh/validation keep their real effects.
- [ ] Key editing/removal retains security, confirmations, and record semantics.
- [ ] No false live-connection/credit claims or automatic request loops.
