## Handoff notes

- Export entry points: `ExportReader` in `android/core/database/.../export/ExportReader.kt`
  reads all data or one conversation. `ExportService` in
  `android/feature/conversations/.../export/ExportService.kt` builds `chatui.export` JSON,
  per-conversation JSON, and Markdown. `ExportModule`/`ExportEntryPoint` expose the service to
  the shell; M2-07.5 owns the settings/data UI wiring. `rememberExportDocumentLauncher` and
  `ExportDocumentWriter` provide the SAF create-document flow, and
  `ExportPlaintextWarningDialog`/`EXPORT_PLAINTEXT_WARNING` provide the plaintext warning.
- Attachment policy: attachment metadata (`id`, `name`, `mimeType`, `sha256`, `size`) is always
  included for the snapshot's attachments. `dataBase64` is omitted unless
  `includeAttachmentBytes` is true; Markdown never embeds bytes. Missing bytes fail the export
  instead of writing a partial archive.
- Ordering decision: conversations export by `createdAt` then id, messages by conversation order
  then `sequence` then id, attachments/providers by `createdAt` then id, and models by
  provider/remoteId/id. `listConversations()` returns newest-updated first for the entry point.
- Secret exclusion: the reader never opens the `secrets` table. Provider `secretId` values remain
  opaque references; no ciphertext or plaintext key can enter an archive.
- Schema validation: `ExportServiceTest` loads the checked-in
  `contracts/schema/chat-export.schema.json` and validates both the shared fixture and generated
  full/per-conversation archives with a test-only JSON Schema validator. Production
  `validateChatExport` performs strict kotlinx.serialization decoding plus contract constraint
  checks.
- Scope note: import and clear-data controls remain for M2-07.4/M2-07.5. The settings data screen
  still shows its M2-07 placeholder; M2-07.5 wires the export entry point.
