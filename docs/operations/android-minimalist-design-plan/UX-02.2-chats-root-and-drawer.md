# UX-02.2 - Real Chats root and adaptive history

- Phase: UX-02 - Navigation and entry points
- Status: Not started
- Order: 10
- Depends on: UX-02.1
- Output folder: `docs\operations\android-minimalist-design-plan`
- Parallel-safe: No with shell/navigation edits; coordinate ChatScreen call sites.

## Goal

Replace the compact Conversations placeholder with real Chats, simplify the
history drawer, and retain the expanded permanent sidebar without duplicate
history work.

## Read first

Read the [execution contract](README.md), source-plan sections 3-5.3,
`Shell\ShellNavHost.kt`, `Shell\AdaptiveShell.kt`, `Shell\ChatUiApp.kt`,
`Shell\ShellDestination.kt`, `Shell\BackPolicy.kt`, UX-02.1's host API,
and `AdaptiveShellTest`, `ShellNavigationTest`, `ShellSidebarTest`,
`ShellInsetsTest`, and the deep-link/intent tests under AppTests.

## Owns

The listed shell files, required history-host call sites, and the named shell/
navigation/inset regressions. Keep route identifiers and external-intent
parsing unchanged.

## Deliverables

A useful compact Chats root, single-CTA history hosts, simplified drawer
footer, and responsive production navigation.

## Implementation steps

1. Render the real existing history route at Conversations below 840 dp.
   Use the compact scaffold API; eliminate the closed-drawer placeholder
   dead end after normal launch or onboarding.
2. Keep no bottom navigation. At 600-839 dp retain compact navigation with
   bounded content; at >=840 dp retain the initially 280 dp permanent sidebar.
3. Use one title and New chat owner per active history host. Remove the
   redundant Conversations navigation row/Library group and duplicate embedded
   New chat action. Keep only Providers and Settings in the drawer footer.
4. Give modal history the available safe viewport rather than placing it
   below large global chrome. Let short/IME-visible layouts reflow/scroll;
   keep search results and footer actions accessible.
5. Prevent unnecessary simultaneous root/drawer/sidebar collectors. On expanded
   widths let the permanent history own history while the main pane shows the
   selected chat or an appropriate empty pane, not a second history list.
6. Preserve route aliases, selected chat, search/tab/scroll state, last-active
   restoration, pending share/deep-link precedence, and system/IME inset
   ownership through rotation and crossing the breakpoint.
7. Add regressions proving compact Chats is real, drawer/root each has one
   CTA, removed shortcuts remain reachable through Settings, expanded hosting
   stays functional, and cold/warm external navigation still reaches its target.

## Acceptance criteria

- [ ] Compact launch reaches useful history/chat, never a closed-drawer prompt.
- [ ] Only one history CTA/title and one necessary active history observer.
- [ ] Providers/Settings and all underlying data/backup screens remain reachable.
- [ ] Resizing, restore, pending intents, and IME/system insets preserve state.
