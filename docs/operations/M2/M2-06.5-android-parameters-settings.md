## Handoff notes

- Settings route wiring: `settings` renders `SettingsRootScreen`; section routes are
  `settings/appearance`, `settings/chat`, `settings/data`, `settings/backup`, and
  `settings/about`. `ShellDestination.Settings.matches` treats every `settings/*` route as
  selected. The old `SettingsPlaceholder` and shell placeholder route were removed.
- Extra JSON namespace: `params.extra[provider.presetId]` via `extraNamespaceForPreset`;
  OpenRouter is `openrouter`, Gemini is `google`, Anthropic is `anthropic`, Ollama is `ollama`.
  `setConversationModel` prunes extras belonging to the previous provider namespace when the
  provider changes; core parameters are preserved.
- Protected fields: `model`, `messages`, `stream`, and `stream_options` are rejected by
  `parseProviderExtras` before persistence; adapters also reject them defensively.
- Unsupported-parameter behavior: values stay stored on the conversation, the sheet shows an
  inline note listing ignored fields, and adapters omit unsupported core parameters.
- Conversation settings sheet: opened from the chat header “Settings” action. It exposes model,
  system prompt, temperature, top P, max output tokens, stop, reasoning effort, streaming,
  provider extras, routing summary, a disabled export entry point, and delete with confirmation.
- Behavior wiring: send key, token usage, and remote images flow from `SettingsDataStore` through
  `ChatRoute` into the composer and Markdown renderer. Defaults seed new conversations through
  `ConversationService`. Opening a chat records the last-active conversation from the shell.
- Deferred settings: data controls/export/import remain M2-07; backup remains a placeholder;
  per-conversation export is a disabled entry point owned by M2-07.3.
