# M5-07.2 - Android Azure Blob, GCS, Google Drive, and WebDAV adapters

- Milestone: M5
- Status: Complete
- Order: 22
- Depends on: M5-03.2, M5-04.2
- Parallel-safe: yes, with `M5-07.1` and `M5-07.3`
- Owns: `android/core/backup/`, `android/feature/backup/`
- Read first: [M5 plan](../M5-backup-and-sync-implementation-plan.md) sections 3.4 and 5.3; spec section 13.6

## Goal

Add the remaining storage backends on Android behind the existing
`StorageAdapter` interface: Azure Blob, Google Cloud Storage, Google Drive, and WebDAV. Enable
them in the backup settings UI. The adapters must only ever receive encrypted
bytes.

## Preconditions

- `M5-03.2` and `M5-04.2` are `Complete`.
- The `StorageAdapter` interface and typed errors exist.
- Do not add a cloud SDK; use OkHttp and the documented REST APIs.
- Do not add a server proxy.

## Deliverables

- `android/core/backup/.../storage/AzureBlobStorageAdapter.kt`:
  - Account name + key or SAS token.
  - Block blob PUT/GET/HEAD/DELETE.
  - ETag/`If-Match` conditional writes.
  - Connectivity test.
- `android/core/backup/.../storage/GcsStorageAdapter.kt`:
  - Service account JSON (JWT -> OAuth2 token) initially.
  - JSON or XML API operations.
  - Generation/`If-Match` conditional writes where available.
  - Connectivity test.
- `android/core/backup/.../storage/GoogleDriveStorageAdapter.kt`:
  - OAuth access token; app data folder or user-selected folder.
  - Drive v3 file create/update/get/delete; no ETag/`If-Match`.
  - Conservative consistency handling; re-read after write and retry on
    conflict.
  - Connectivity test.
- `android/core/backup/.../storage/WebDavStorageAdapter.kt`:
  - URL + username + password (Basic auth).
  - PUT/GET/HEAD/DELETE and `PROPFIND` for list.
  - Conservative consistency handling.
  - Connectivity test.
- Backup settings UI: enable the four backends with backend-specific fields.
- Tests with `MockWebServer`:
  - Auth header construction.
  - PUT/GET/HEAD/DELETE for each backend.
  - Conditional write conflict handling.
  - Connectivity test success and typed errors.
  - No plaintext is passed to any adapter.

## Implementation steps

1. Read the `StorageAdapter` interface, S3 adapter, and backup settings UI.
2. Implement Azure Blob:
   - Build the shared-key signature or SAS URL.
   - Use block blob PUT.
   - Parse `ETag` and send `If-Match` on rewrite.
3. Implement GCS:
   - Build and sign a JWT with the service account key.
   - Exchange it for an OAuth2 access token.
   - Use the JSON API for object operations.
   - Use generation preconditions for conditional writes.
4. Implement Google Drive:
   - OAuth access token; app data folder or user-selected folder.
   - Drive v3 file create/update/get/delete.
   - No ETag/`If-Match`; re-read after write and retry on conflict.
5. Implement WebDAV:
   - Basic auth header.
   - PUT/GET/HEAD/DELETE and `PROPFIND`.
   - Re-read after write; never assume read-after-write.
6. Update the backup settings UI to show backend-specific fields.
7. Add tests with `MockWebServer`. Use synthetic encrypted bytes only.
8. Run the Android gates.

## Out of scope

- Web and Rust additional backends (`M5-07.1`, `M5-07.3`).
- Parity and exit evidence (`M5-07.4`).
- User OAuth for GCS (documented as a later preference).
- Google Drive shared-drive administration and folder sharing UX.

## Handoff notes

- Implemented `AzureBlobStorageAdapter`, `GcsStorageAdapter`,
  `GoogleDriveStorageAdapter`, and `WebDavStorageAdapter` in
  `android/core/backup/.../storage/`, plus shared HTTP/XML helpers in
  `StorageHttpSupport.kt`.
- Azure uses SharedKey or SAS auth, block-blob PUT, ETag/`If-Match`, and
  read-after-write HEAD retries. GCS signs a service-account JWT, exchanges it
  for a cached OAuth2 token, and uses generation preconditions. Google Drive
  uses the Drive v3 API with `md5Checksum` as the logical ETag and re-reads
  after writes. WebDAV uses Basic auth, `PROPFIND`, and conservative
  read-after-write retries.
- Added `BackupBackend.GOOGLE_DRIVE` to `android/core/model/.../Settings.kt`.
  This is the only change outside the task's owned paths; the shared enum had
  no Google Drive value and the UI/config could not represent the backend
  without it.
- Extended `BackupFormValues`/`BackupCredentials` with backend-specific fields,
  added per-backend validation and adapter construction, and enabled all four
  backends in the settings UI.
- Added MockWebServer tests for auth headers, PUT/GET/HEAD/DELETE, conditional
  conflicts, connectivity success/typed errors, and encrypted-byte-only
  uploads.
- Verification:
  - `make android-lint` - passed.
  - `make android-test` - passed.
  - `cd android && ./gradlew :core:backup:testDebugUnitTest :feature:backup:testDebugUnitTest` - passed.
- No cloud SDK or server proxy was added. Adapters only accept `ByteArray`
  bodies; callers must encrypt with the envelope codec first.
