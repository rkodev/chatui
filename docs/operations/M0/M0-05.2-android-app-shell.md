- Parallel-safe: yes, with M0-03.3

- Read first: [M0 plan](../M0-foundations-implementation-plan.md) section 4.6; spec sections 9.3, 9.4, 15.1

## Goal

Wire the Android app shell with Hilt, edge-to-edge, splash screen, and placeholder navigation. This is the final Android gate before CI wiring.

## Preconditions

- The design system and all core modules build.
- No provider, onboarding, chat, or other feature implementation is allowed.

## Deliverables

- Hilt application class and dependency wiring.
- `MainActivity` with Compose, edge-to-edge handling, and SplashScreen support.
- Navigation Compose graph with placeholders for:
  - onboarding
  - chat
  - conversations
  - providers
  - settings
  - backup
- Placeholder composables in feature modules only; they must not implement feature behavior.
- A themed shell that launches to a visible placeholder destination.
- Predictive-back behavior for placeholder shell destinations where applicable.
- Tests:
  - Hilt wiring compiles
  - navigation graph resolves placeholder destinations
  - theme/density can be applied to the shell
- Remove placeholder files superseded by real files.
- Run the complete Android gate and record results.

## Implementation steps

1. Add the Hilt application and DI modules.
2. Add `MainActivity` with edge-to-edge and splash screen.
3. Add the navigation graph and placeholder destinations.
4. Add placeholder feature composables.
5. Add shell/navigation tests.
6. Run `lintDebug`, `testDebugUnitTest`, and `assembleDebug`.
7. Launch on an emulator or device if available and capture evidence. If no emulator is available, record that limitation and rely on the assemble/test gates.

## Acceptance criteria

- [ ] The app launches to a themed shell.
- [ ] All required navigation destinations exist as placeholders.
- [ ] Hilt wiring is valid.
- [ ] Edge-to-edge and splash screen behavior are present.
- [ ] No provider adapter, onboarding, chat, drawer, share target, picker, screenshot, signing, baseline profile, or packaging work exists.
- [ ] `lintDebug`, `testDebugUnitTest`, and `assembleDebug` pass.

## Verification

```bash
cd android && ./gradlew :app:lintDebug
cd android && ./gradlew :app:testDebugUnitTest
cd android && ./gradlew :app:assembleDebug
cd android && ./gradlew :app:installDebug
```

The install command is optional and requires a device or emulator.

## Out of scope

- Feature screens and behavior.
- Release signing, baseline profiles, Play Store packaging, and screenshots.

## Handoff notes

Record the final Android command results, the device/emulator used for the manual check, and any navigation destination left as a placeholder for M1-M3.
