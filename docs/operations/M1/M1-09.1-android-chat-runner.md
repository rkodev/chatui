## Goal

Implement the Android chat ViewModel and runner that drives the adapter, reduces events, persists at a bounded cadence, and supports cancel and regenerate.

## Preconditions

- Adapter and repositories are complete.
- Conversation navigation exists.
- Do not build the full screen in this task beyond state hooks.

## Deliverables

- Chat ViewModel with one immutable `UiState` exposed as `StateFlow`.
- Intent methods for send, stop, regenerate, edit-and-resend, and retry.
- Streaming reducer for start, text, reasoning, usage, finish, and error.
- Persistence about every 1 s and on pause, completion, cancellation, and error.
- One active stream per conversation and a send lock.
- Cancel that cancels the coroutine and OkHttp call, persists partial text, and marks `cancelled`.
- Regenerate last assistant without branching.
- First-token and latency timing.
- ViewModel tests with fake adapters and Turbine.

## Handoff notes

### State shape

`ChatUiState` is immutable and exposed as `StateFlow<ChatUiState>` from
`ChatViewModel`. It holds the conversation, the ordered message list, the
active `StreamingState`, the composer draft, `sending`, `loading`, `error`, and
`notice`. The runner separately exposes
`StateFlow<Map<String, StreamingState>>`; the ViewModel selects the entry for
its conversation so a future screen can subscribe only the streaming message.
`StreamingState` holds text, reasoning, usage, finish reason, error, status,
timestamps, and derived first-token/latency timings. `reduceStream` is pure and
appends text/reasoning deltas in arrival order.

### Persistence cadence

The assistant placeholder is persisted before the provider stream starts. A
runner-scoped loop persists at `DEFAULT_PERSIST_INTERVAL_MS` (1,000 ms) only
when the buffer is dirty, so writes are not per token. Final persistence runs
on completion, cancellation, and error through a single `Mutex`, preventing
overlapping writes. `persistNow` flushes the current partial text on lifecycle
pause. Latency is measured from stream start and first-token time is recorded
on the first text or reasoning delta.

### Cancel semantics

`cancel(conversationId)` sets the run's cancelled flag, cancels the run job
(which cancels the adapter flow/OkHttp call), and waits for the run's final
snapshot. The `finally` block uses `NonCancellable` to mark the message
`cancelled` with `FinishReason.CANCELLED`, preserve partial text, and persist
it before completing the run. `dispose` cancels every active stream when the
ViewModel is cleared. Only one stream may be active per conversation:
`putIfAbsent` returns `ChatRunFailureReason.BUSY` for a duplicate send, and the
ViewModel also guards intents with its `sending`/`isStreaming` state.

### Regenerate and retry

Regenerate reuses the target assistant message id and sequence and replaces it
in place, so history is not branched. Retry only accepts failed or cancelled
assistant messages and delegates to regenerate. Edit-and-resend rewrites the
last user message, deletes later messages, and appends a new assistant row
without branching.
