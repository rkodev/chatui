## Goal

Implement conversation history in the sidebar with date groups, search, pin, archive, rename, delete with undo, new chat, drafts, and last-active restore.

## Preconditions

- Chat runner and conversation/message repositories exist.
- Do not load the entire conversation history in one query.
- Do not expose message content in logs or errors.
- Do not modify `web/`, `android/`, or `contracts/`.

## Deliverables

- Conversation sidebar/history:
  - new chat;
  - date groups (pinned, today, yesterday, older);
  - title, timestamp, pin/archive indicators;
  - search with bounded results and snippets;
  - rename;
  - pin/archive/unpin/unarchive;
  - delete with a short undo window;
  - draft indicator;
  - last-active conversation restore.
- Conversation route/navigation state.
- Empty, loading, and error states.
- Tests for grouping, search, pin/archive, rename, delete/undo, drafts indicator, and last-active restore.

## Implementation steps

1. Read spec sections 3.2, 11.1, and 11.2, plus `web/src/features/conversations/*`.
2. Build the history view model over the conversation repository and search API.
3. Implement grouping: pinned first, then today, yesterday, and older by last-message time.
4. Implement search with a bounded query and snippet. Handle empty and no-result states.
5. Implement rename, pin, archive, and delete. Keep the UI responsive and persist each change.
6. Implement delete with a 5-second undo window consistent with web/Android. Restore messages and attachment references on undo.
7. Show a draft indicator when a conversation has a persisted draft.
8. Persist and restore the last-active conversation on startup.
9. Wire new chat and conversation selection to the shell.
10. Add tests for grouping, search, actions, undo, drafts, and restore.
11. Document the history API and route behavior.

## Handoff notes

- History API: `ConversationHistory` owns the sidebar state and persistence. `load(archived)` loads a bounded page, `refresh()` reloads the current view, `load_more()` grows the bounded window, `new_chat()` creates and selects a chat, `select(id)` persists the last-active ID, `rename`, `set_pinned`, `set_archived`, `request_delete(id, now)`, `undo_delete()`, `commit_delete(now)`, `commit_pending()`, and `restore_last_active()` cover the actions. `state()` exposes `HistoryState { status, error, conversations, groups, archived, active_conversation_id, draft_ids, pending_delete }`. `HistoryStatus` is `Loading`, `Ready`, or `Error`; `HistoryState::is_empty()` covers the empty state.
- Grouping rules: `group_conversations` returns `Pinned`, `Today`, `Yesterday`, `Previous 7 days`, `Previous 30 days`, and `Older` in that order. Pinned conversations are removed from the date buckets so they appear once. Within every bucket rows are newest-first by `last_message_at`, with the conversation ID as a tie-breaker. Empty buckets are omitted. Future timestamps are treated as Today. Calendar days use UTC because `Timestamp` is normalized to UTC. `format_conversation_timestamp` shows `HH:MM` for today, `Mon D` for the current year, and `Mon D, YYYY` otherwise.
- Search bounds: `ConversationSearchService` defaults to 20 hits and clamps to 1..=100. It requests `limit + 1` from FTS to set `truncated`, then resolves only the returned conversation titles. Snippets are whitespace-normalized and bounded to 160 characters. Empty queries return an empty result without touching storage. Failures use the generic `ConversationSearchError` message so message content never appears in an error. `ConversationSearchState` covers `Idle`, `Loading`, `Ready`, `Empty`, and `Error`.
- Undo behavior: deletes are buffered for `DEFAULT_UNDO_WINDOW` (5 seconds), matching web/Android. The row disappears immediately, but `ConversationRepository::delete` only runs on `commit_delete` after the deadline, on `commit_pending`, or when another delete starts. `undo_delete` cancels the buffer, so messages and attachment references are never removed and need no restore path. The active conversation's last-active pointer is cleared on request and restored on undo.
- Drafts: `ConversationHistory` reads the injected `DraftStore` on load/refresh and exposes `draft_ids()` and `has_draft(id)`. The composer's `PersistentDraftStore` remains the source of truth; the sidebar only reads it.
- Last active: `restore_last_active()` reads `Settings::last_active_conversation_id`, returns the conversation when it exists and is not archived, and clears a stale or archived pointer. `select` and `new_chat` persist the pointer through the settings repository.
- New chat: `DefaultConversationFactory` prefers the configured default provider/model, then the first enabled provider and its first visible model. It returns `HistoryError::NotConfigured` when nothing is configured. `ConversationFactory` keeps the history view model testable.
- Route behavior: `ConversationNavigation` starts on `ConversationRoute::History`, `select`/`new_chat` switch to `ConversationRoute::Chat { conversation_id }`, `open_history` returns to the list while keeping `last_active`, and `restore(Some(id))`/`restore(None)` implement startup routing. `destination()` maps to `shell::Destination::Chat` or `History` so the shell can bind without a second route type.
- Loading bounds: `HistoryConfig` defaults to a 100-row page and a 500-row cap. The repository has no cursor API yet, so `load_more` re-reads the bounded window instead of loading the whole table. This satisfies the "do not load the entire history in one query" precondition.
- Deviation: the sidebar uses a separate Pinned group per spec section 11.1, while the web client sorts pinned rows first inside each date bucket. The shell binding is provided through `ConversationNavigation` and `HistoryState`; `shell.rs` was not modified because it is outside this task's owned paths.
