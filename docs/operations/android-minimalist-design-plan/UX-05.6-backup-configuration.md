# UX-05.6 - Focused backup configuration

- Phase: UX-05 - Settings, data, and backup
- Status: Blocked
- Order: 34
- Depends on: UX-04.9, UX-05.1
- Output folder: `docs\operations\android-minimalist-design-plan`
- Parallel-safe: No with backup UI/state or onboarding setup call sites.

## Goal

Extract focused backend configuration from the existing backup screen,
retaining every credential option, passphrase warning, and commit semantic.

## Read first

Read the [execution contract](README.md), source-plan section 5.7,
`BackupUI\BackupSettingsScreen.kt`, `BackupUI\BackupViewModel.kt`,
`BackupUI\BackupSettingsService.kt` (`BackupFormValues` and validation),
UX-04.9's setup entry contract, and existing backup screen/ViewModel/service tests.

## Owns

Configuration UI/private sibling in the existing backup package, necessary
screen presentation state and onboarding call-site consistency, and focused
backup form tests. Backup services, adapters, encryption, and scheduling are
read-only unless a tightly coupled UI integration bug demands a minimal fix.

## Deliverables

A focused Configuration surface with one chosen backend's fields visible and
the current safe test/enable/passphrase workflow intact.

## Implementation steps

1. Separate configuration content from status/recovery actions while preserving
   the existing public setup entry used by onboarding. Reuse one form/state
   owner rather than creating duplicate credential ViewModels.
2. Preserve the current field mapping exactly. S3: endpoint/region/bucket/
   prefix/access key ID/secret. Azure: account/container/prefix/optional endpoint
   and account-key or SAS-token alternatives. GCS: bucket/prefix/service-account
   JSON. Drive: access token/folder/prefix options. WebDAV: endpoint/prefix/
   username/password. Confirm applicability against current form/validation.
3. Show only the chosen backend's applicable fields, with clear required/
   optional labels. Switching a disclosure or backend must not silently commit
   or erase user edits contrary to current behavior.
4. Keep Test connection, enable/disable, passphrase entry, loss warning,
   client-side encryption explanation, and validation before enable/restore.
   Do not hide required warnings in a collapsed decorative section.
5. Distinguish edited/tested values from committed running configuration using
   current service semantics. Do not invent autosave or imply a background job
   already uses uncommitted form edits.
6. Preserve encrypted credential storage and memory-only passphrase lifetime;
   do not put credentials/passphrases in generic saved-state bundles or traces.
   Keep keyboard/large-font scrolling and secure-entry behavior usable.
7. Add field-access/validation cases for all five backends and Azure credential
   alternatives, test failure/edit retention, enable/disable, passphrase gates,
   backend switches, and onboarding setup/cancel compatibility.

## Acceptance criteria

- [x] Every existing backend/credential option remains accessible.
- [x] One focused form shows only applicable fields without silent commits.
- [x] Passphrase/security warnings and current save/test/enable semantics survive.
- [x] Onboarding still hosts the same real setup flow without nested scrolling.

## Handoff notes

Implemented on 2026-11-17. **Blocked on UX-04.9/UX-05.1 and actual secure
keyboard/large-text/back/cancel acceptance; owner: Android maintainer.**

- `BackupUI\BackupSettingsScreen.kt` separates Configuration from the overview
  using the same form/ViewModel. The public
  `BackupSetupRoute(service, onCancel, onComplete, modifier)` remains the real
  opt-in onboarding entry. No nested form scroller or credential ViewModel was
  added. Configuration Back/toolbar Up returns to overview with edits/focus
  intact; only nonsecret disclosure/navigation state is saveable.
- Field mapping is retained: S3 endpoint/region/bucket/prefix/access ID/secret;
  Azure account/container/prefix/optional endpoint plus account key or SAS;
  GCS bucket/prefix/service-account JSON; Drive token/folder/prefix; WebDAV
  endpoint/prefix/user/password. Only the chosen backend is shown. Switching
  backend/disclosure does not commit or erase the other form values.
- Test connection is not a commit. Explicit enable/apply saves the validated
  configuration and runs backup; disable uses the existing cancellation
  path. Committed configuration, edits, enabled state and first-backup
  completion are distinct, including failure/retry. Done requires a completed
  first backup and no pending configuration edits, not merely a dismissed error.
- **Coupled integration fix:** the existing service could reload credentials
  after restart but could not receive the newly re-entered memory-only
  passphrase without saving configuration again. `BackupSettingsServiceLike`
  now exposes `usePassphrase`; manual backup/recovery unlocks the existing
  committed service in memory. It does not save credentials/configuration,
  schedule work or persist a passphrase. A failed first upload now truthfully
  leaves the already committed configuration enabled.
- Backup screen/ViewModel/service regressions cover field access for all five
  backends, validation, test without commit, edit retention, first-backup
  failure/retry, restart/unlock, cancellation and Done gates. The **51 backup**
  and **45 onboarding** tests pass; lint passes. App route tests cover nested
  toolbar Up without commit. Commands are in the
  [verification record](README.md#ux-0506-verification-record).
- `integrated_backup_credentials_320_font200_inset160_*` uses a simulated
  keyboard inset; `integrated_onboarding_backup_configuration_320_font150_*`
  captures real setup. Neither demonstrates a real IME or storage login.
  UX-05.7 reuses this same committed-state/form owner.
