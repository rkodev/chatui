## Goal

Deliver the Android first-run flow: BYOK/on-device explanation, OpenRouter preselected and recommended, key entry, inline testing, actionable errors, and transition to a new chat.

## Preconditions

- Provider/model services and Hilt graph are available.
- Other presets are gated to disabled/coming later.
- Do not build provider management or model picker in this task.

## Deliverables

- Onboarding ViewModel with one immutable `UiState` and intents.
- Welcome screen with BYOK/on-device copy and OpenRouter Recommended.
- Provider picker with OpenRouter enabled and other presets disabled.
- Key entry with optional label, Connect, inline testing, error area, and preserved input.
- Public catalog load before key validation; sending disabled until validation succeeds.
- On success, store provider/key, refresh models, select a default, set onboarding complete, and navigate to chat.
- Compose/unit tests for first run, invalid key, valid key, and preserved form.

## Implementation steps

1. Read `OnboardingPlaceholder`, shell navigation, and service APIs.
2. Build the ViewModel with state for welcome, form, testing, catalog loading, and error.
3. Build composables using Material 3 and existing design tokens.
4. Start catalog loading when the screen opens.
5. On Connect, disable the action, validate, and keep the form on error.
6. On success, update settings and navigate to the new chat flow.
7. Wire the shell start destination or onboarding redirect.
8. Add tests for the three critical onboarding cases.
9. Run the Android gate.

## Handoff notes

### Onboarding-complete semantics

`onboardingCompleted` is set only after the provider, key metadata, refreshed
models, and default provider/model all exist. Any failure before completion
deletes the provider (cascading models and the secret) and restores the
previous default provider/model, so an invalid key stores nothing. The typed
key and label remain in `OnboardingUiState` after a failure.

### Navigation

`shellStartDestination(settings)` returns `onboarding` until
`onboardingCompleted` is true, then `conversations`. `OnboardingRoute` emits a
single `Connected` event; `ShellNavHost` navigates to `chat` and pops
`onboarding`. `MainActivity` collects settings with a null initial value and
composes only after the persisted value arrives, avoiding an onboarding flash
for returning users. M1-08.2 can replace the completed-start destination with
last-active chat restore.

### Error copy

Auth failures say the key was rejected and to check it. Permission, quota,
rate-limit, model, context-length, content-filter, invalid-request, network,
timeout, cancelled, parse, storage, provider, and unknown failures each have
plain-language copy. Raw details are behind a "Details" disclosure and the
typed key is redacted. Catalog failures are non-blocking and still allow
Connect.

### Catalog and provider gating

The public catalog loads immediately with a synthetic preview provider and no
key; it is not persisted until `/key` succeeds. The provider picker shows every
contract preset, but only OpenRouter is enabled. Disabled selections are
ignored by the ViewModel and the service always creates OpenRouter.

### Hilt

`OnboardingService` is bound in the feature module. The shell uses
`OnboardingEntryPoint` with `EntryPointAccessors` instead of adding
`hilt-navigation-compose`; the ViewModel is created with an explicit factory.
