- Read first: [M3.5 plan](../M3.5-rust-desktop-implementation-plan.md) sections 3.6 and 4.10; spec sections 11.1, 11.2, 11.9, 11.11, 11.12

## Goal

Create the shared desktop UI foundation: tokens, themes, density, font size, reduced motion, focus-visible states, and the responsive shell with a persistent sidebar and narrow-window drawer.

## Preconditions

- The framework decision is recorded.
- Domain types exist.
- Do not build onboarding, provider, model, chat, or settings feature screens in this task.
- Do not add hidden network destinations.
- Do not modify `web/`, `android/`, or `contracts/`.

## Deliverables

- Rust token constants matching every semantic name in section 11.12.
- Light, dark, and system theme support.
- Density (`comfortable`, `compact`), chat font size (`sm`, `md`, `lg`), and reduced-motion handling.
- Focus-visible ring behavior and keyboard navigation primitives.
- Responsive shell:
  - persistent sidebar at desktop widths;
  - drawer or navigation stack at narrow widths;
  - placeholders for chat, history, providers, settings, and data areas.
- Minimal desktop app entry point that renders the shell.
- Tests or snapshots for tokens, theme switching, breakpoints, focus, and reduced motion.

## Implementation steps

1. Read the framework decision and spec sections 11.9, 11.11, and 11.12.
2. Implement `tokens.rs` with the shared semantic names. Keep names identical to the web/Android tokens where possible.
3. Implement theme selection for system/light/dark. Follow the OS theme when `system` is selected.
4. Implement density, chat font size, and reduced-motion settings as inputs to the shell.
5. Implement focus-visible rings and keyboard traversal. Every interactive element must be reachable.
6. Implement the responsive shell. Use a width breakpoint from section 11.9. Keep every destination reachable in both layouts.
7. Wire the shell into `apps/desktop`. Use fake or empty view models; do not add feature behavior.
8. Add tests or snapshots for token values, theme resolution, breakpoint behavior, focus, and reduced motion.
9. Document the shell API and any framework-specific constraints.

## Acceptance criteria

- [ ] All section 11.12 token names exist in Rust.
- [ ] System/light/dark themes work.
- [ ] Density, font size, and reduced motion are supported.
- [ ] Focus-visible states and keyboard traversal exist.
- [ ] Desktop widths show a persistent sidebar.
- [ ] Narrow widths use a drawer or navigation stack.
- [ ] All placeholder destinations remain reachable.
- [ ] The desktop app renders the shell.
- [ ] Tokens and shell tests/snapshots pass.
- [ ] No feature screens or hidden network destinations are added.
