## Goal

Make the web app installable and safely offline-capable for conversation history, with an update prompt that never interrupts an active stream, and prove the Cache API never stores API responses, secrets, decrypted content, or user data.

## Preconditions

- `M4-00.1` is `Complete`.
- Do not cache provider/API requests or responses. Do not cache IndexedDB content or exported data.
- Do not register a service worker in development.
- Capacitor remains optional and internal; do not make it the primary Android product and do not let it persist keys unless WebView storage is equivalently protected.

## Deliverables

- A service worker that:
  - precaches the app shell and hashed static assets only;
  - never caches API requests/responses, secrets, decrypted content, or user data in the Cache API;
  - serves the SPA shell offline;
  - prompts when a new service worker is waiting;
  - does not force reload during an active stream;
  - is not registered in development.
- A web app manifest with app name, short name, start URL, display mode, theme/background colors, icons (including maskable), and screenshots where useful.
- `config.json` remains public-only, served no-cache, and validated at startup.
- IndexedDB conversation history remains readable offline; sending is disabled with an offline banner.
- Tests proving: caching allowlist, no API/user-data cache entries, offline history read, offline send disabled, update prompt behavior, and no dev registration.
- Evidence under `docs/operations/M4/evidence/pwa/`.

## Implementation steps

1. Inspect the current build (`web/vite.config.ts`), entry point (`web/src/main.tsx`), storage (`web/src/storage`), and `web/public/config.json`.
2. Choose the service-worker approach already supported by the stack (for example a Vite PWA plugin or a hand-written worker). If adding a dependency, confirm it is acceptable for the release and document the choice.
3. Configure precaching to include only:
   - `index.html`;
   - hashed JS/CSS/font/image assets from the build;
   - the manifest and icons.
   Exclude `/api/*`, provider hosts, `config.json` from cache storage, and anything user-specific.
4. Add explicit fetch handling:
   - navigation requests: network-first or stale-while-revalidate for the shell, falling back to cached `index.html` offline;
   - static assets: cache-first with hashed filenames;
   - all other requests: pass through to the network with no caching.
5. Ensure `config.json` is fetched with `cache: 'no-store'` (or equivalent) and validated at startup; keep it public-only and never cache it in the Cache API.
6. Add an update flow:
   - detect a waiting service worker;
   - show a non-blocking prompt with an update action and a dismiss action;
   - on update, activate only when no stream is active; if a stream is active, defer and tell the user;
   - never call `window.location.reload()` automatically during a stream.
7. Register the service worker in production only (guard on `import.meta.env.PROD` or the project's existing env convention). Add a test that development does not register.
8. Add manifest and icons under `web/public/`; include a maskable icon and at least one screenshot if useful. Link them from `index.html`.
9. Offline UX:
   - verify conversation history loads from IndexedDB offline;
   - disable send and show the offline banner when offline, using section 11.8 copy;
   - restore the online state without reload.
10. Tests:
    - unit/integration tests for the cache allowlist and offline state;
    - a Playwright test that loads the built app, goes offline, reads history, and confirms send is disabled;
    - a service-worker update test if practical (or a documented manual check).
11. Record evidence: cache keys before/after a chat, DevTools Application screenshots or exported storage listing, and offline/update notes.

## Acceptance criteria

- [ ] Service worker precaches only app-shell and hashed static assets.
- [ ] No API response, secret, decrypted content, or user data appears in the Cache API.
- [ ] Conversation history is readable offline from IndexedDB.
- [ ] Sending is disabled offline and an offline banner is shown.
- [ ] A waiting update prompts the user and never force-reloads during an active stream.
- [ ] The service worker is not registered in development.
- [ ] Manifest, theme colors, maskable icons, and optional screenshots are present and installability is verified.
- [ ] `config.json` is public-only, no-cache, and validated at startup.
- [ ] Capacitor is not promoted to the primary Android product and does not persist keys insecurely.
- [ ] Tests and evidence are recorded.

## Out of scope

- Caching conversation content or attachments for offline writes.
- Background sync, push notifications, or M5 backup/sync.
- Deployment container/headers (M4-04.1) except where the app build must expose the service worker.
- Android/iOS Capacitor production packaging.
