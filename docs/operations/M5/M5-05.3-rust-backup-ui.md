# M5-05.3 - Rust backup/restore UI and settings

- Milestone: M5
- Status: Not started
- Order: 17
- Depends on: M5-04.3
- Parallel-safe: yes, with `M5-05.1` and `M5-05.2`
- Owns: `rust/crates/chatui-ui/`, `rust/apps/desktop/src/services/`
- Read first: [M5 plan](../M5-backup-and-sync-implementation-plan.md) sections 3.6 and 5.3; spec sections 13.7 and 21.5; `rust/crates/chatui-ui/src/settings/state.rs`

## Goal

Replace the Rust backup placeholder with a working settings and restore flow:
configure a backend, test connectivity, enable backup, show status, back up now,
restore, and delete the remote backup with typed confirmation.

## Preconditions

- `M5-04.3` is `Complete` and the sync engine works.
- `M5-03.3` provides the S3 adapter and connectivity test.
- Rust is conditional. If Rust is not shipping, mark this task `Cancelled`.
- Do not redesign the settings UI.

## Deliverables

- `rust/crates/chatui-ui/src/settings/`:
  - Backup settings state and actions.
  - Backup settings view replacing the placeholder copy.
  - Status model: last backup, pending changes, last error, storage usage.
- `rust/apps/desktop/src/services/`:
  - Backup service wiring to the sync engine.
  - Credential storage through the existing secret store.
- Settings fields:
  - Backend selector (`s3` first; other backends disabled until `M5-07.3`).
  - Endpoint, region, bucket, prefix, access key, secret key, passphrase.
  - "Test connection", "Enable backup".
  - "Back up now", "Restore from backup", "Delete remote backup".
  - Typed confirmation for delete and replace-on-restore.
  - Client-side statement and passphrase-loss warning.
- Tests:
  - State transitions and validation.
  - Connectivity test success and failure.
  - Enable/disable.
  - Back up now calls the sync engine.
  - Restore defaults to merge; replace requires typed confirmation.
  - Delete remote requires typed confirmation and keeps local data.
  - Credentials are stored as secrets; passphrase is not persisted.

## Implementation steps

1. Read the existing settings state, placeholder copy, secret store, and sync
   engine API.
2. Add backup settings state and actions.
3. Build the settings view with existing UI primitives.
4. Wire "Test connection" to the S3 adapter.
5. Wire "Enable backup" to save the config and start the sync engine.
6. Wire "Back up now", "Restore from backup", and "Delete remote backup".
7. Add typed confirmation dialogs for delete and replace.
8. Add the client-side statement and passphrase-loss warning.
9. Add tests and run the Rust gates.

## Acceptance criteria

- [ ] The placeholder is replaced with a working settings view.
- [ ] Backend, endpoint, region, bucket, prefix, credentials, passphrase, test,
      and enable controls exist.
- [ ] Connectivity test shows success and typed errors.
- [ ] Status shows last backup, pending changes, errors, and storage usage.
- [ ] Back up now, restore, and delete remote work.
- [ ] Restore merges by default; replace requires typed confirmation.
- [ ] Delete remote requires typed confirmation and keeps local data.
- [ ] Credentials are stored as secrets; the passphrase is never persisted.
- [ ] The client-side statement and passphrase-loss warning are visible.
- [ ] Existing settings tests still pass.
