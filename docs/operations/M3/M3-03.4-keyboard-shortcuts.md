## Goal

Support common actions from a physical keyboard without breaking text entry or the existing Enter-to-send behavior.

## Preconditions

- M3-03.3 is complete.
- Do not intercept character keys while a text field is focused.
- Do not add web-only or Rust-only shortcuts.

## Deliverables

- A documented shortcut map for Android hardware keyboards.
- Root-level key handling for shell actions.
- Shortcut help reachable from the UI or settings.
- Tests proving shortcuts fire and text entry still works.

## Shortcut map

Use this map unless M3-00.2 changes it:

| Shortcut | Action |
| --- | --- |
| `Ctrl + K` | Focus/open conversation search |
| `Ctrl + Shift + O` | New chat |
| `Esc` | Stop streaming or close the top overlay |
| `Ctrl + Shift + C` | Copy the last assistant response |
| `Alt + Up/Down` | Move to the previous/next conversation |
| `Ctrl + Enter` | Send when the composer is configured for Mod+Enter |

## Implementation steps

1. Read `ChatComposer.kt` and the shell navigation/drawer code.
2. Add a `KeyboardShortcutController` or root `onPreviewKeyEvent` handler in the shell. Route actions through existing callbacks; do not duplicate navigation logic.
3. Keep the composer's Enter/Shift+Enter behavior unchanged. Add `Ctrl+Enter` only if it does not conflict with the existing `SendKey` setting.
4. Add a shortcut help dialog or a settings section that lists the map. Use accessible labels.
5. Add Compose key tests:
   - each shortcut invokes the intended callback;
   - typing normal characters in the composer is not consumed;
   - `Esc` stops an active stream before navigating;
   - shortcuts do not fire when a dialog/sheet should take priority.
6. Record the manual hardware-keyboard check if no physical keyboard is available; state it clearly.

## Handoff notes

### Android shortcut map

| Shortcut | Action | Implementation |
| --- | --- | --- |
| `Ctrl + K` | Focus/open conversation search | Navigates to Conversations and opens the drawer below 840 dp. The search field is visible in the sidebar/drawer. |
| `Ctrl + Shift + O` | New chat | Calls `ConversationService.createConversation()` and opens the new chat; falls back to Providers when no provider is configured. |
| `Esc` | Stop streaming or close the top overlay | Stops an active response first, then closes shortcut help, then the drawer. Dialogs and sheets are separate windows and keep priority. |
| `Ctrl + Shift + C` | Copy the last assistant response | Routed through the active `ChatScreen` copy callback and the platform clipboard. |
| `Alt + Up/Down` | Previous/next conversation | Uses the ordered `ConversationService.observeConversations()` list and the existing chat route. |
| `Ctrl + Enter` | Send in Mod+Enter mode | Existing composer behavior; no change to `SendKey` handling. |

Shortcut help is reachable from the top-bar keyboard button. The dialog lists the same map with accessible row labels.

### Decisions

- The root handler lives in `ShellScaffold` and is focusable so shortcuts work before a field is touched. It only matches explicit modifier chords and `Esc`; plain character keys return `null` and pass through to text fields.
- Chat-scoped actions use a small `ChatShortcutState` bridge in `feature:chat`. `ChatScreen` registers its existing `onStop` and copy callbacks, so the shell does not duplicate streaming or clipboard logic.
- `Esc` only stops when a response is actually active (`state.canStop`). Otherwise it closes the drawer, so it never swallows the key on an idle chat.
- Shortcuts are refused while an app-owned overlay is open (`shortcutAllowed`). Dialogs and sheets are separate windows and already receive keys first.
- `Ctrl + K` opens the search surface rather than programmatically focusing the field; the field is immediately visible in the sidebar/drawer and the existing search behavior is unchanged.
