## Goal

Provide the plain TypeScript services that onboarding and management UI will call: typed settings, provider creation, key storage, key validation, catalog refresh, and model persistence.

## Preconditions

- Adapter, catalog cache, secret store, and repositories are complete.
- Do not build screens in this task.

## Deliverables

- Typed settings facade over `SettingsRepository` for defaults, onboarding completion, send key, usage visibility, last active conversation, and remember-keys.
- `createOpenRouterProvider({ apiKey, label, rememberKeys })` that stores the secret and provider record without plaintext in the provider record.
- `validateProviderKey(providerId)` that reads the secret, calls the adapter, and stores normalized key metadata on the provider.
- `refreshModels(providerId)` that calls discovery and upserts models, preserving pinned/hidden/manual flags.
- `selectDefaultModel(providerId)` implementing the M1-01.2 fallback rule.
- `rotateKey`, `removeKey`, `setProviderEnabled`, and `deleteProvider` helpers.
- Tests using fake IndexedDB, fake secret store, and MSW.

## Implementation steps

1. Read existing repositories in `web/src/storage/` and `web/src/platform/`.
2. Define service interfaces so UI tests can inject fakes.
3. Implement the typed settings facade with defaults that match the spec.
4. Implement provider creation: generate provider ID, create secret ID, write secret in the chosen mode, write provider with `metadata: null`.
5. Implement validation: load secret, call `validateKey`, write key metadata into `provider.metadata`.
6. Implement catalog refresh: call `listModels`, map to persisted `Model` records, preserve user flags on existing `(providerId, remoteId)` rows.
7. Implement delete/rotate/enabled helpers and tests.
8. Ensure no secret is returned by list/get methods used by UI.

## Completion record

- Added `web/src/features/settings/settingsService.ts` with a typed
  `SettingsService` over `SettingsRepository`, spec-aligned `DEFAULT_SETTINGS`,
  and accessors for onboarding completion, send key, usage visibility, last
  active conversation, remember-keys, and defaults.
- Added `web/src/features/providers/`:
  - `types.ts` defines injectable `ProviderStore`, `ModelStore`,
    `SecretStoreLike`, `ProviderAdapter`, and service option types.
  - `providerService.ts` implements `createOpenRouterProvider`,
    `validateProviderKey`, `rotateKey`, `removeKey`, `setProviderEnabled`,
    `deleteProvider`, `getProvider`, and `listProviders`.
  - `modelService.ts` implements `refreshModels`, `selectDefaultModel`,
    `listModels`, `setModelPinned`, `setModelHidden`, and `addManualModel`.
  - `runtime.ts` builds the adapter context without exposing the key.
- Added tests using fake IndexedDB, a fake secret store, and MSW:
  `settingsService.test.ts`, `providerService.test.ts`, and
  `modelService.test.ts`.
- Verification: `make web-lint && make web-typecheck && make web-test &&
  make web-build` passed. The full web suite ran 33 files and 296 tests.
- Decisions:
  - `rememberKeys` defaults to true and maps to secret mode `remember`; false
    maps to `session`. Passphrase mode is not selected by these services.
  - `/key` metadata is stored under `provider.metadata.key` as
    `ProviderKeyMetadata` with a `validatedAt` timestamp.
  - Adapter failures propagate unchanged so the UI can map `ChatErrorCode`.
    Service failures use `ProviderServiceError` with `not_found`,
    `missing_key`, or `invalid_input`.
  - `refreshModels` forces discovery by default, upserts by
    `(providerId, remoteId)`, preserves `pinned`, `hidden`, and `source`, and
    does not delete models absent from the catalog.
  - Manual models keep their user-provided label and metadata across refreshes.
  - `selectDefaultModel` returns `{ modelId, remoteId, notice }` and does not
    persist settings; the onboarding caller decides when to save the default.

## Handoff notes

- Service interfaces: `ProviderStore`, `ModelStore`, `SecretStoreLike`,
  `ProviderAdapter`, and `SettingsStore`. The concrete repositories and
  `SecretStore` satisfy them structurally, so UI tests can inject fakes.
- Secret-mode defaults: `createOpenRouterProvider` and `rotateKey` default
  `rememberKeys` to true (`remember` mode). Pass `rememberKeys: false` for
  session-only keys. The services never write plaintext to the provider record.
- Error contract: adapter errors (`OpenRouterRequestError`) propagate with
  their `ChatErrorCode`, status, retryability, and redacted message. Service
  errors are `ProviderServiceError` with `code`, `providerId`, and a safe
  message. UI should catch both and render actionable copy.
- Key metadata shape: `provider.metadata.key` contains `label`, `usageUsd`,
  `limitUsd`, `limitRemainingUsd`, `isFreeTier`, `rateLimit`, and
  `validatedAt`. Use `getProviderKeyMetadata(provider)` to read it.
- Default-model selection follows M1-01.2 exactly, including the notice strings
  from `contracts/fixtures/requests/openrouter-default-model.json`. The caller
  persists `defaultProviderId`/`defaultModelId` through `SettingsService`.
- `refreshModels` returns `{ models, created, updated }`. It leaves models that
  disappear from the catalog in place so cached and manual entries remain
  selectable.
- No service file imports React.
