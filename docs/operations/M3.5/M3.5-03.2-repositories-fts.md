# M3.5-03.2 - Repositories, schema mapping, FTS5, and pagination

- Milestone: M3.5
- Status: Not started
- Order: 10
- Depends on: M3.5-03.1
- Parallel-safe: yes, with M3.5-03.3
- Owns: `rust/crates/chatui-storage/src/repositories/`, `rust/crates/chatui-storage/src/search.rs`, `rust/crates/chatui-storage/src/mappers.rs`
- Read first: [M3.5 plan](../M3.5-rust-desktop-implementation-plan.md) sections 3.3 and 4.5; spec sections 6.2-6.4, 9.5, 10.5, 11.9

## Goal

Implement repository APIs over the SQLite schema, including FTS5 search and bounded pagination, so UI and export code never issue SQL.

## Preconditions

- M3.5-03.1 is complete.
- Do not put SQL in `chatui-ui` or `chatui-providers`.
- Do not implement attachments, recovery, or export/import in this task.
- Do not use destructive schema changes.

## Deliverables

- Repository traits and SQLite implementations for:
  - conversations;
  - messages;
  - attachments metadata;
  - providers;
  - models;
  - secret metadata;
  - settings;
  - backup config;
  - sync queue placeholders.
- Mapping between domain types and database rows, including JSON columns.
- FTS5 index over message text, synchronized on insert, update, delete, and conversation deletion.
- Conversation search with bounded results and snippets.
- Message pagination by `(conversationId, sequence)` in both directions.
- Tests for CRUD, ordering, pagination, search, cascade deletion, and large conversation bounds.

## Implementation steps

1. Read the migration schema and the Android Room entities for field parity.
2. Define repository traits in `chatui-storage` so `chatui-ui` can depend on abstractions rather than SQLite types.
3. Implement row mappers:
   - `parts`, `usage`, `error`, `params`, and `sync` as JSON text;
   - booleans as integers;
   - `sequence` as a signed integer;
   - timestamps as RFC 3339 text.
4. Implement conversation and message repositories with:
   - create/update/delete;
   - list with pin/archive filters;
   - newest page and older page queries;
   - message insert/update with sequence ordering.
5. Implement provider, model, settings, secret metadata, backup config, and sync queue repositories. Enforce unique `(providerId, remoteId)` for models.
6. Implement FTS5:
   - create the virtual table in the migration;
   - index message text from text parts;
   - update the FTS row in the same transaction as the message write;
   - remove FTS rows on message or conversation deletion.
7. Implement search results with conversation id, message id, snippet, and order.
8. Implement cursor or offset-free pagination that returns bounded pages.
9. Add a large-conversation test with at least 10,000 messages proving queries stay bounded.
10. Add tests for cascade deletion of messages, attachments metadata, and FTS rows.

## Acceptance criteria

- [ ] Repository traits exist and are injected into callers.
- [ ] CRUD and mapping tests pass for every entity.
- [ ] Model uniqueness is enforced.
- [ ] FTS5 rows stay synchronized on insert, update, delete, and cascade.
- [ ] Search is bounded and returns usable snippets.
- [ ] Message pagination is ordered by `sequence` and bounded.
- [ ] A 10,000-message test passes without loading all rows.
- [ ] No SQL exists outside `chatui-storage`.
- [ ] No destructive migration was added.
