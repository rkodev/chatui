# UX-01.1 - Semantic colors and contrast

- Phase: UX-01 - Calm foundations
- Status: Not started
- Order: 4
- Depends on: UX-00.3
- Output folder: `docs\operations\android-minimalist-design-plan`
- Parallel-safe: Yes with UX-01.2; coordinate shared design-system tests.

## Goal

Correct accent contrast and establish restrained semantic surfaces without
replacing the existing neutral palette or token API.

## Read first

Read the [execution contract](README.md), source-plan section 3 and
section 8, `DS\Color.kt`, `DS\Theme.kt`, and `DSTests\DesignSystemTest.kt`.

## Owns

- `DS\Color.kt` and directly required Material-role mappings in `DS\Theme.kt`.
- Color/contrast cases in `DSTests\DesignSystemTest.kt`.
- This task's contrast table and reviewed component captures.

## Deliverables

Compatible semantic colors with corrected accent/on-accent pairs, targeted
regressions, and evidence for actual text/control combinations.

## Implementation steps

1. Identify current semantic roles and exhaustive test constructions. Keep
   existing names; default any essential additional field.
2. Apply the proposed light accent `#2563EB`/on-accent `#FFFFFF` and dark
   accent `#8AB4F8`/on-accent `#0B1020`, unless an approved decision record
   supplies an equally accessible alternative.
3. Keep canvas/input/grouped/separator distinctions subtle. Do not add
   gradients, glass, new shadows, or a broad neutral-palette rewrite.
4. Check rendered normal/selected/pressed/warning/error/code combinations,
   including alpha-composited colors. Do not treat the plan's four opaque
   contrast calculations as certification of every component.
5. Keep matching dynamic on-color roles intact; UX-01.4 owns activating the
   existing persisted dynamic-color preference.
6. Update meaningful affected token assertions and add focused contrast
   regressions for the changed text/action pairs, not a large constants-only
   test suite.

## Acceptance criteria

- [ ] Changed normal-text pairs meet 4.5:1; large text/essential controls meet
      3:1 where applicable.
- [ ] Both palettes retain existing semantic names and readable on-colors.
- [ ] No screen-specific hard-coded palette or new visual dependency appears.
- [ ] Component evidence distinguishes measured contrast from visual judgment.

Review representative filled buttons, selected rows, warning/error labels,

## Out of scope

Screen placement, density/type changes, new theme settings, or silently
enabling dynamic color.
