# M5-01.2 - Web envelope codec and crypto tests

- Milestone: M5
- Status: Not started
- Order: 3
- Depends on: M5-01.1
- Parallel-safe: yes, with `M5-01.3` and `M5-01.4`
- Owns: `web/src/platform/crypto.ts`, `web/src/features/backup/`, `web/src/platform/crypto.test.ts`

## Goal

Implement the `CHATUI1\n` backup envelope on web using WebCrypto. The codec must
produce and consume the exact bytes defined in `M5-00.1` and pass the shared
vectors. It must never write plaintext to storage.

## Preconditions

- `M5-01.1` is `Complete` and the schemas and vectors exist.
- Existing `web/src/platform/crypto.ts` provides AES-GCM and PBKDF2 primitives.
- Do not change secret-storage behavior or its tests.

## Deliverables

- New `web/src/features/backup/envelope.ts` with:
  - `MAGIC = 'CHATUI1\n'`.
  - `encodeEnvelope({ header, iv, ciphertext })` and
    `decodeEnvelope(bytes)`.
  - `encryptObject({ passphrase, salt, objectType, objectKey, plaintext, compress })`
    returning the full envelope bytes.
  - `decryptObject({ passphrase, bytes })` returning plaintext and header.
  - Header JSON with `v`, `formatVersion`, `alg`, `kdf`, `iterations`, `salt`,
    `objectType`, `objectKey`.
  - AAD construction from `objectType` and `objectKey`.
  - Gzip via `CompressionStream('gzip')` for conversation payloads; no gzip for
    attachments.
  - A passphrase verification token helper.
- `web/src/features/backup/envelope.test.ts` with:
  - Round trip for manifest, conversation, and attachment object types.
  - Shared vector comparison from `contracts/fixtures/backup/vectors.json`.
  - Fresh IV per write and no IV reuse.
  - Wrong passphrase fails without returning plaintext.
  - Tampered magic, header length, header JSON, IV, ciphertext, and AAD fail.
  - Gzip round trip and attachment no-gzip behavior.
  - Header/version handling for unknown `v` and `formatVersion`.
- Exports from `web/src/features/backup/index.ts`.

## Implementation steps

1. Read `web/src/platform/crypto.ts`, its tests, and the shared vectors.
2. Add a small byte helper module if needed for big-endian `uint32` read/write.
   Do not add a dependency for this.
3. Implement `encodeEnvelope`:
   - Write `MAGIC` (8 bytes).
   - Write `headerLength` as big-endian `uint32`.
   - Write UTF-8 header JSON.
   - Write the 12-byte IV.
   - Write ciphertext with the 16-byte GCM tag appended.
4. Implement `decodeEnvelope`:
   - Verify magic.
   - Read and bound-check `headerLength` (reject absurd values).
   - Parse header JSON and validate required fields.
   - Split IV and ciphertext.
5. Implement `encryptObject`:
   - Derive the key with PBKDF2-HMAC-SHA256, 600,000 iterations, 16-byte salt,
     32-byte key.
   - Build AAD from `objectType` and `objectKey` exactly as frozen.
   - Generate a fresh 12-byte IV.
   - Optionally gzip the plaintext before encryption.
   - Call `crypto.subtle.encrypt({ name: 'AES-GCM', iv, additionalData }, key, data)`.
6. Implement `decryptObject`:
   - Parse the header, derive the key from the header salt and iterations.
   - Rebuild AAD from the header `objectType` and `objectKey`.
   - Decrypt and optionally gunzip.
   - Throw a typed error on authentication failure; never return partial data.
7. Add a passphrase verification token: encrypt a fixed marker with the same
   key and AAD, or store a small encrypted `verification` object. Document the
   choice in `Handoff notes`.
8. Add tests for every acceptance criterion. Use the shared vectors for at least
   one byte-for-byte comparison.
9. Run the web gates and fix failures.

## Acceptance criteria

- [ ] Envelope encode/decode matches the frozen byte layout.
- [ ] Header JSON contains every required field.
- [ ] AAD binds `objectType` and `objectKey`; tampering fails.
- [ ] A fresh 12-byte IV is used for every write.
- [ ] PBKDF2 uses 600,000 iterations, 16-byte salt, and a 32-byte key.
- [ ] Conversation payloads are gzipped; attachment bytes are not.
- [ ] Wrong passphrase and tampered ciphertext fail safely.
- [ ] Shared vectors pass.
- [ ] No plaintext is written to storage by the codec.
- [ ] Existing secret-storage tests still pass.
