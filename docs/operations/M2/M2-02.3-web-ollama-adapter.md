## Handoff notes

- Native vs fallback selection rule: the Ollama preset (`modelDiscovery.format === 'ollama-tags'` or id `ollama`) uses native NDJSON at `POST /api/chat` by default. A Custom local server, or a request with `params.extra.ollama.transport` / `mode` set to `openai-compatible`, uses the shared OpenAI-compatible transport at `<baseUrl>/chat/completions` (`/v1/chat/completions` for the contract preset). The control fields are stripped before serialization.
- NDJSON edge cases: the reader handles LF, CRLF, and lone CR split across chunks, joins partial lines, ignores blank lines, flushes a final line without a trailing newline, and bounds the incomplete buffer at 1 MiB. An in-stream `{ "error": ... }` line before any content produces a single terminal `error` event; errors after content are terminal and never retried. `done_reason` maps `stop`/`length`/`content_filter`/`tool_calls`; missing reasons default to `stop`. Usage maps `prompt_eval_count` and `eval_count` after `finish`, matching the shared vector. Ollama duration fields have no field in the normalized `Usage` schema and are not persisted.
- Local cleartext expectations: browser calls need `OLLAMA_ORIGINS` set to the app origin, e.g. `OLLAMA_ORIGINS=http://localhost:5173 ollama serve` (`OLLAMA_ORIGINS=*` only for local development). Browser HTTPS-to-HTTP and private-network policies may still block requests; the adapter surfaces `OLLAMA_ORIGINS_GUIDANCE` and never proxies silently. Native discovery uses the absolute `http://localhost:11434/api/tags` contract path.
