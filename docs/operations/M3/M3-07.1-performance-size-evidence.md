## Goal

Record cold-start, list/streaming, and artifact-size evidence against the M3 budgets.

## Preconditions

- Baseline-profile generation (M3-06.3), release artifacts (M3-06.4), image/size work (M3-06.5), and large-list tests (M3-05.5) are complete.
- Use the actual built artifacts; do not estimate sizes.
- Record the device/API and measurement method.

## Deliverables

- A performance section in `M3-verification.md` with:
  - cold-start runs and median;
  - device/API/build type and profile state;
  - large-conversation composition result;
  - streaming recomposition result;
  - image decode/caching check;
  - debug APK, release APK, and release AAB sizes.
- A clear pass/fail against the 1.5 s, 20 MB, and 15 MB budgets, or a documented miss.

## Implementation steps

1. Read the evidence from M3-06.3 and M3-06.5 and the test outputs from M3-05.5.
2. Re-measure cold start if the artifact changed:
   ```bash
   adb shell am force-stop dev.chatui
   adb shell am start -W -n dev.chatui/.MainActivity
   ```
   Run at least five times and record each total time.
3. Run the large-conversation and streaming recomposition tests and record the bounded-composition result.
4. Verify image rendering uses the sized/Coil path from M3-06.5 on a device/emulator with a large image.
5. Measure the exact artifacts:
   ```bash
   ls -l android/app/build/outputs/apk/debug/app-debug.apk
   ls -l android/app/build/outputs/apk/release/app-release.apk
   ls -l android/app/build/outputs/bundle/release/app-release.aab
   ```
6. Record every number and the methodology in `M3-verification.md`.
7. If a budget is missed, record the cause, the largest contributor if known, and a follow-up owner. Do not remove security or required functionality just to hit a soft budget.

## Completion record

- Added section 20 to `docs/operations/M3/M3-verification.md` with cold-start,
  bounded-composition, streaming-recomposition, image-decode, and artifact-size
  evidence.
- Cold start: release build, baseline profile installed and compiled
  `speed-profile`, five `am start -W` runs on `Medium_Phone_API_36.1(AVD) - 16`
  (API 36, x86_64, 1080x2400). Totals 990, 762, 1098, 693, 1296 ms; median
  990 ms against the 1,500 ms budget. Met.
- Large conversation: `ChatMessageListTest` 4 tests, 0 failures. The
  10,000-message case composes fewer than 100 rows and keeps the newest message
  visible (spec 15.2 case 23).
- Streaming: `token updates recompose only the streaming row` passes.
- Image: unit test proves a `Size(1080, 960)` bounded Coil request. Device check
  rendered a 6000x4000 synthetic PNG at 932x621 px with no OOM; TOTAL PSS
  118,460 KB, Java heap 22,868 KB.
- Sizes: debug APK 18,734,354 bytes (17.87 MiB, under 20 MB); signed release APK
  2,907,246 bytes (2.77 MiB, under 15 MB); unsigned local release APK 2,894,958
  bytes; release AAB 7,042,442 bytes (6.72 MiB).
- Verification: `make android-test` passed with 993 tests, 0 failures;
  `:app:assembleDebug :app:assembleRelease :app:bundleRelease` passed;
  `ChatMessageListTest` passed; five `am start -W` runs recorded.

## Handoff notes

- All three budgets are met on the recorded emulator. No follow-up performance
  task is required.
- The cold-start numbers are sensitive to host CPU contention. Earlier runs at
  host load average about 7.7 produced 1.1-2.3 s totals; the recorded set was
  taken at load average 4.65 after the profile was applied. M3-07.3 should
  repeat the measurement on physical mid-tier hardware.
- The release APK used for cold start was signed with a throwaway local
  measurement keystore outside the repository, then deleted. CI signing remains
  the M3-06.4 blocker; no signing material is recorded.
- The image device check used the debug build and a synthetic seeded
  conversation. The seed's `paramsJson` had to be a valid `ChatParams` JSON for
  the conversation to open; no product code changed.
- No number in section 20 is estimated. The unsigned release APK size was
  measured before the signed measurement build replaced it; the signed size is
  the current artifact.
