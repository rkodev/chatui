# UX-03.3 - Responsive composer and single warning

- Phase: UX-03 - Chat readability and resources
- Status: Blocked
- Order: 15
- Depends on: UX-01.5
- Output folder: `docs\operations\android-minimalist-design-plan`
- Parallel-safe: No with UX-02.3/UX-02.4/UX-03.6 ChatScreen edits.

## Goal

Use one calm composer surface, one attachment-warning owner, and responsive
short-screen input without reducing draft capacity or attachment features.

## Read first

Read the [execution contract](README.md), source-plan sections 5.2, 6,
and 8, `Chat\ChatComposer.kt`, `Chat\ChatScreen.kt`, `Chat\ChatDrafts.kt`,
existing `ChatComposerTest.kt`/`ChatScreenTest.kt`, and shell inset ownership.

## Owns

Composer/empty-state/warning presentation in the two listed chat UI files,
directly needed state/callback plumbing in `ChatRoute.kt`, and focused tests.
Draft stores, attachment validation, and send/stop services remain unchanged.

## Deliverables

A single-boundary composer with one attachment strip/warning, visible Stop,
and usable keyboard-visible layouts.

## Implementation steps

1. Remove the stacked gradient/shadow/border treatment; retain one restrained
   surface/boundary using shared tokens and at least 48 dp Add/Send/Stop targets.
2. Keep pending attachments in one strip with readable names/sizes and
   independently operable remove actions. Show each capability/read error once
   near the strip, removing the current duplicate ChatScreen/composer warning.
3. Preserve the explicit Send anyway/Cancel consent flow and all photo/file/
   paste/drop entry paths. Prepare a small pending/processing presentation
   contract for UX-03.6 without moving URI work in this task.
4. Retain eight-line growth when space permits. With short landscape/IME,
   constrain and internally scroll the input viewport, not the text length,
   draft storage, paste limits, or supported multiline/send-key behavior.
5. Keep Stop at the stable send location and immediate; no animation may delay
   cancellation. Preserve offline drafts/history and explain disabled sending
   without suggesting automatic queued delivery.
6. Simplify empty chat to a short greeting/current suggested prompts that
   fill the draft, never auto-send. Let the header own model selection.
   Keep one actionable setup banner; message failures stay on their message.
7. Add regressions for exactly one warning, send-anyway cancel/confirm,
   multiline/send-key variants, attachment removal, Stop, suggested-draft
   filling, and short-window/large-font input with existing inset ownership.

## Acceptance criteria

- [x] One composer surface and one relevant warning/error presentation.
- [ ] Send/Stop/Add/remove remain usable with keyboard and 200% text.
- [x] Draft/input capacity, eight-line ordinary growth, and consent survive.
- [x] Offline/setup/empty states are truthful and do not duplicate controls.
