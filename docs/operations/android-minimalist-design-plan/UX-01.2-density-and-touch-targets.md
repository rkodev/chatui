# UX-01.2 - Density, spacing, and touch targets

- Phase: UX-01 - Calm foundations
- Status: Not started
- Order: 5
- Depends on: UX-00.3
- Output folder: `docs\operations\android-minimalist-design-plan`
- Parallel-safe: Yes with UX-01.1; coordinate shared test edits.

## Goal

Make existing layout primitives visually compact but readable and operable,
including on 320 dp windows at 200% font scale.

## Read first

Read the [execution contract](README.md), source-plan section 3 and
section 8, `DS\Dimens.kt`, `DS\Typography.kt`, `DS\Buttons.kt`,
`DS\GroupedList.kt`, `DSTests\DesignSystemTest.kt`, and
`DSTests\ComponentsTest.kt`.

## Owns

The four listed production design-system files and their existing
`DesignSystemTest`/`ComponentsTest` cases. No feature-wide widget replacement.

## Deliverables

Consistent density spacing, growing/wrapping rows, readable shared typography,
and guaranteed minimum interactive targets.

## Implementation steps

1. Map comfortable/compact token use. Reduce duplicate visual padding rather
   than shrinking text or making compact density a reduced-function mode.
2. Retain the current chat-size choices and 16/24 default body treatment.
   Use the plan's restrained root/title/secondary scale and system font scaling;
   do not add a font asset or remote font.
3. Make shared row content wrap and grow instead of clipping to a fixed
   56-64 dp height. Keep nonessential secondary content from squeezing labels.
4. Ensure buttons, icon actions, steppers, and selectable rows retain at
   least 48 x 48 dp interactive bounds in both densities even when their
   visible shape/icon is smaller.
5. Centralize only spacing/shape values needed by the forthcoming screens:
   narrow margins, ordinary margins, restrained sections and composer corners.
   Avoid unused token proliferation.
6. Add focused component regressions for long text, 320 dp/200% font scale,
   both densities, and icon hit bounds; preserve descriptions/focus semantics.

## Acceptance criteria

- [ ] Compact mode reduces chrome, not target size or supported controls.
- [ ] Shared rows grow and action labels wrap without overlap/clipping.
- [ ] Existing chat font options and system scaling remain effective.
- [ ] No feature screen needs a new one-off density system.

## Verification

```powershell
Set-Location .\android
.\gradlew.bat :core:designsystem:testDebugUnitTest :core:designsystem:lintDebug
```

Inspect representative grouped rows/buttons at 100%, 150%, and 200% fonts.

## Out of scope

Changing persisted density/font values, redesigning individual feature forms,
or adding an alternate low-RAM UI.
