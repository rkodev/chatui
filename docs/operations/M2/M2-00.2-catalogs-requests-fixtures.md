## Goal

Define shared catalog mappings, request serialization, math/export fixtures, capability inference, fallback model rules, and the CORS evidence plan.

## Preconditions

- M2-00.1 is complete.
- Raw model and stream fixtures already exist in `contracts/fixtures/`.

## Deliverables

- Expected catalog mappings for OpenAI, Anthropic, Gemini, and Ollama tags.
- Request vectors for OpenAI-compatible, Anthropic, Gemini, and Ollama requests.
- Request vectors for system prompts, image/file content parts, provider extras, and protected-field rejection.
- Capability inference rules from preset metadata.
- Fallback model rules or fallback model lists for blocked discovery.
- Math fixtures covering inline, block, invalid, and streaming-incomplete input.
- A shared `chatui.export` fixture with IDs, ordering, snapshots, and optional attachment data.
- A CORS matrix template and verification plan for every preset.
- Validator support for all new fixtures.

## Implementation steps

1. Add expected model catalogs derived from the existing raw model fixtures.
2. Add request vectors in the same format as the M1 OpenRouter request vectors.
3. Define and document how provider-specific extras are namespaced.
4. Define protected fields: `model`, `messages`, `stream`, and `stream_options`.
5. Document capability inference defaults for missing modalities, capabilities, context, and supported parameters.
6. Define the fallback model rule and represent it in a schema-compatible way.
7. Add math and export fixture inputs.
8. Add a CORS matrix template with provider, endpoint, preflight, status, conclusion, and evidence columns.
9. Extend the validator and add failure cases.
10. Run the contract gate.

## Handoff notes

- Extra JSON namespace decision: `params.extra[<presetId>]`. Only the active
  namespace is read; non-protected keys merge into the provider body at the top
  level. OpenRouter keeps its existing curated `openrouter` namespace.
- Fallback model representation: `contracts/fixtures/expected/fallback-models.json`
  holds per-preset `fallbackModelIds` lists and executable cases. When discovery
  is blocked and the catalog is empty, the first fallback id is selected with
  the notice `Discovery unavailable; using fallback model <id>.` No client
  constants are required.
- Capability inference defaults: missing modalities and supported parameters
  use preset defaults; missing context and output limits are `null`; missing
  capabilities are derived in the order `text`, `vision`, `files`, `tools`,
  `reasoning`, `streaming`. Raw provider values win.
- CORS evidence location: `docs/operations/M2/M2-cors-matrix.md`. It is a
  template only; M2-09.1 records live evidence and updates `browserCors`.
- Request vector attachment shape: normalized parts reference attachment ids;
  the vector supplies resolved bytes in an optional `attachments` map. File
  parts append `\n\n[File: <name>]\n<utf-8 content>`.
- Provider serialization decisions: Anthropic always emits `max_tokens`
  (default `1024` when unset); Gemini streaming is endpoint-selected and uses
  `generationConfig`; Ollama native uses `options` and `images`.
- Catalog mapping decisions: OpenAI embedding models and Ollama embedding
  models are marked `hidden`; Gemini uses `baseModelId` and token limits;
  Anthropic uses `display_name`; OpenAI uses the raw id as label.
