## Goal

Provide application-scoped Android services for settings, provider creation, secret storage, key validation, catalog refresh, and default model selection, and wire them into Hilt.

## Preconditions

- Adapter and repositories are complete.
- Do not build screens in this task.

## Deliverables

- Hilt providers for `ChatUiDatabase`, `SecretStore`/`TinkSecretCipher`, shared `OkHttpClient`, clock, repositories, provider registry, and provider/model services.
- Typed settings access through `SettingsDataStore`.
- `createOpenRouterProvider`, `validateProviderKey`, `refreshModels`, `selectDefaultModel`, `rotateKey`, `removeKey`, and `setProviderEnabled`.
- No secret stored in Room provider rows.
- Hilt wiring tests and service unit tests.

## Implementation steps

1. Read `AppModule`, `ChatUiDatabase`, `SecretStore`, and `SettingsDataStore`.
2. Add Hilt providers with correct scopes. Use `@ApplicationContext` and `@Singleton`.
3. Build a shared OkHttp client with the timeouts and no logging of secrets.
4. Implement provider creation using the secret store and provider repository.
5. Implement validation and model refresh using the adapter and model repository.
6. Implement default model selection using the M1-01.2 rule.
7. Add tests for provider creation, validation, refresh, and delete behavior.
8. Run the Android gate.

## Handoff notes

### Hilt scopes

Every binding in `AppModule` is `@Singleton` in `SingletonComponent`:
database, settings store, clock, secret cipher/store, HTTP client, registry,
adapter, gateway, repositories, and both services. DAOs are not exposed; the
repositories are the feature-facing API.

### Secret IDs

`createOpenRouterProvider` and `rotateKey` generate a UUIDv7 secret ID with
`newId()`. The provider row stores only `secretId`; the plaintext key is
written to `SecretStore` (Tink AEAD ciphertext in Room). `rotateKey` writes the
new secret first, updates the provider, then removes the old ciphertext.
`removeKey` deletes the ciphertext and clears `secretId` plus
`metadata.key`. `deleteProvider` cascades models and the referenced secret.

### Service interfaces

- `ProviderService`: `observeProviders`, `getProvider`,
  `createOpenRouterProvider(apiKey, label)`, `validateProviderKey`,
  `rotateKey`, `removeKey`, `setProviderEnabled`, `deleteProvider`.
- `ModelService`: `refreshModels`, `selectDefaultModel`, `listModels`,
  `getModel`.
- `ProviderGateway`: `validateKey`, `listModels(context, forceRefresh)`.
  `OpenRouterGateway` forces `refreshCatalog` and surfaces a stale refresh
  error instead of silently accepting last-known-good data.
- Settings remain the typed `SettingsDataStore`/`AndroidSettings` facade; no
  duplicate settings service was added.

### Key metadata

`provider.metadata.key` stores `label`, `usageUsd`, `limitUsd`,
`limitRemainingUsd`, `isFreeTier`, `rateLimit`, and `validatedAt`. Read it with
`getProviderKeyMetadata(provider)`. The key itself is never written to the
provider row, headers, or metadata.

### Default model rule

`selectDefaultModel` uses the preset `defaultModelId` when present (even if
hidden), otherwise the first non-hidden text-output model ordered by
`remoteId` ascending, otherwise `null` with the M1-01.2 notice strings.

### Decisions and scope

- Added a `core:providers` Android library so `feature:onboarding` and
  `feature:providers` can depend on the services without depending on `app`
  or creating a `core:database`/`core:datastore` cycle. This required adding
  the module to `settings.gradle.kts` and `app/build.gradle.kts`.
- Added `androidx.room.runtime` to `app` because `AppModule` exposes
  `ChatUiDatabase`, whose supertype is `RoomDatabase`.
- The shared HTTP client uses connect 30 s, read 30 s, and call 60 s. The
  adapter's dedicated streaming client still overrides read/call to 0 and
  enforces the 120 s inactivity watchdog. No logging interceptor is installed.
- OpenRouter attribution headers are not wired yet because Android has no
  public runtime config; the adapter accepts `null` attribution. M1-10 or a
  later config task can supply `OpenRouterAttribution`.
- `refreshModels` does not delete models missing from the catalog, matching
  the web service and keeping cached/manual entries selectable.
