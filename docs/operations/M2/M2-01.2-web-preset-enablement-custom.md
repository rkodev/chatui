## Goal

Enable the launch OpenAI-compatible presets and Custom provider creation on web without exposing unsupported providers or bypassing contract validation.

## Preconditions

- M2-01.1 generic transport works.
- Contracts already contain every preset.

## Deliverables

- M2 preset enablement replacing the M1 OpenRouter-only gate.
- Runtime config that lists enabled presets and allows Custom provider creation.
- Registry availability labels for enabled, disabled, and coming-later presets.
- Custom provider form and service: base URL, auth type, optional non-secret headers, label.
- Validation for http(s) URLs, auth fields, duplicate labels, and forbidden secret headers.
- Secret storage remains separate from provider records.
- Tests for config validation, preset selection, Custom creation, and rollback on failure.

## Implementation steps

1. Read the current M1 gating in `registry.ts` and `config.ts`.
2. Replace `M1_ENABLED_PRESET_IDS` with an M2 enablement contract.
3. Update `web/public/config.json` to enable the launch presets.
4. Add a validated Custom provider path that does not mutate `contracts/providers.json`.
5. Add UI copy for disabled/coming-later presets if any remain.
6. Ensure Custom headers cannot contain secrets or overwrite auth headers.
7. Add tests for valid and invalid Custom providers.
8. Run web gates.

## Acceptance criteria

- [ ] All launch OpenAI-compatible presets can be enabled without source edits.
- [ ] Custom providers require base URL and auth style.
- [ ] Non-secret custom headers are stored separately from keys.
- [ ] Empty or invalid Custom input is rejected with actionable copy.
- [ ] Provider record writes roll back when secret writes or persistence fail.
- [ ] OpenRouter remains the default and required preset.
- [ ] No native adapters or attachment work is added.
- [ ] Web gates pass.

## Verification

```bash
make web-lint && make web-typecheck && make web-test && make web-build
```

## Out of scope

- Anthropic, Gemini, and Ollama adapters.
- Custom provider import from a file.
- Attachment and conversation data work.
