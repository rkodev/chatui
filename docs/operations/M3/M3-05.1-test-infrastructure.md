# M3-05.1 - Android test infrastructure and fake provider harness

- Milestone: M3
- Status: Not started
- Order: 3
- Depends on: M3-00.2
- Parallel-safe: no; shares the app build file with M3-06.1
- Owns: `android/app/src/androidTest/`, `android/app/build.gradle.kts` test dependencies, shared test fixtures under `android/app/src/test/` and feature test sources
- Read first: [M3 plan](../M3-android-depth-implementation-plan.md) sections 3.4 and 4.6; spec sections 9.5, 15.1, 15.3

## Goal

Create a repeatable Android test setup so later tasks can add instrumentation, Compose, and lifecycle tests without re-inventing runners and fakes.

## Preconditions

- M3-00.2 is complete and records the instrumentation environment.
- Do not add production behavior in this task.

## Deliverables

- An `android/app/src/androidTest/` source set with a runner configuration that compiles and runs on the chosen device/emulator.
- A minimal instrumentation smoke test proving the test harness works.
- Shared fake provider/stream/context fixtures usable by ChatViewModel and Compose tests.
- A documented command for `:app:connectedDebugAndroidTest`.
- If no device is available, a precise blocker in the handoff notes instead of a false pass.

## Implementation steps

1. Confirm the instrumentation dependency set in `android/app/build.gradle.kts`. Add missing `androidTestImplementation` entries such as Compose UI test, AndroidX test runner/rules, and Hilt testing only if the chosen harness needs Hilt.
2. Add `android/app/src/androidTest/java/dev/chatui/M3SmokeTest.kt` using `AndroidJUnit4` and a Compose test rule. Render a small `ChatUiTheme` surface and assert one node exists.
3. Add or reuse a `FakeProviderAdapter` that emits a controlled flow of `StreamEvent` values. Keep it in test sources; do not add a production fake.
4. Add a shared `FakeChatContextResolver`/message source if the existing feature test fakes are not reusable from the app test source set. Prefer moving reusable fakes to a small test-fixtures package rather than duplicating them.
5. Add a short `docs/operations/M3/instrumentation.md` with the exact command and device prerequisite.
6. Run the smoke test on the selected device/emulator. If none exists, record the blocker in the handoff notes and leave the task `Blocked`.

## Acceptance criteria

- [ ] `./gradlew :app:compileDebugAndroidTestKotlin` succeeds.
- [ ] The smoke test passes on the configured device/emulator, or the environment blocker is recorded.
- [ ] Fake provider/stream/context fixtures are available for later tasks.
- [ ] No production source or manifest behavior changes.
- [ ] `docs/operations/M3/instrumentation.md` states the exact command.
