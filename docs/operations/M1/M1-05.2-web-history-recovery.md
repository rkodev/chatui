## Handoff notes

### Recovery scan scope

`MessageRepository.listByStatus(status, { conversationIds? })` scans the
`messages` store with a cursor because the v1 schema has no status index. The
optional `conversationIds` filter is available, but startup recovery omits it
so every conversation is covered. Recovery runs once in
`ConversationHistoryProvider` before the routed content renders, so chat
interaction cannot start first.

Each recovered message keeps its id, sequence, parts, usage, and timestamps.
Recovery sets `status: 'cancelled'`, `finishReason: 'cancelled'`, updates
`updatedAt`, and attaches a `cancelled` `ChatError` whose message is
`INTERRUPTION_NOTE` ("The app closed before this response finished. Partial
content is preserved."). The existing chat message UI renders the cancelled
state and preserves the partial text. Per-message write failures are collected
in `RecoveryResult.failed` and do not block the rest of the scan. Re-running
recovery is idempotent.

### Undo behavior

Delete always opens a confirmation dialog. On confirm, the conversation is
removed from the sidebar immediately, the last-active pointer is cleared when
the deleted conversation is active, and the storage delete is buffered for
5000 ms. Undo cancels the timer, restores the row, and restores the last-active
pointer. Starting another delete or unmounting the sidebar commits the pending
delete. After a committed delete of the active conversation, the sidebar
navigates to `/`, which creates a fresh chat.

### Redirect fallback

`/` checks onboarding first. Incomplete onboarding shows the onboarding screen.
Complete onboarding restores the last-active conversation through typed
settings. A missing or stale pointer creates a new conversation from typed
defaults, records it as last active, and navigates with `replace: true`. If no
provider/model is configured, the route shows `NoConversationState` with a link
to `/settings/providers/new`.

### Other decisions

- New chat always calls `createConversation`, so it never reuses a conversation
  that is currently sending.
- The sidebar loads every conversation page on mount and refreshes when the
  pathname changes, so a chat created by the root redirect appears immediately.
- Offline history remains readable from IndexedDB; the sidebar shows an offline
  notice and the existing composer disables sending through `useOnlineStatus`.
- No search, pin, archive, export/import, or PWA caching was added.
- Known limitation: a title change caused by the first user message appears in
  the sidebar on the next pathname change or reload; the sidebar does not
  subscribe to live conversation metadata.
