# M3.5-04.2 - Encrypted fallback, session mode, and key lifecycle

- Milestone: M3.5
- Status: Complete
- Order: 14
- Depends on: M3.5-04.1
- Parallel-safe: yes, with M3.5-03.* and M3.5-05.*
- Owns: `rust/crates/chatui-secrets/src/encrypted_file.rs`, `rust/crates/chatui-secrets/src/session.rs`, `rust/crates/chatui-secrets/src/lifecycle.rs`
- Read first: [M3.5 plan](../M3.5-rust-desktop-implementation-plan.md) sections 3.4 and 4.6; spec sections 10.6, 12.1, 12.6

## Goal

Provide an explicitly chosen encrypted-file fallback when the OS credential store is unavailable, a session-only mode, and complete key lifecycle operations.

## Preconditions

- `SecretStore` and `KeyringStore` exist.
- Do not make the encrypted file fallback automatic or silent.
- Never store plaintext keys.
- Do not log passphrases, keys, derived keys, salts, or ciphertext internals.
- Do not modify `web/`, `android/`, or `contracts/`.

## Deliverables

- Encrypted-file backend using AES-256-GCM or XChaCha20-Poly1305.
- Argon2id key derivation with a random salt and documented parameters.
- Explicit fallback selection and a user-facing explanation string.
- Safe file permissions where the platform supports them.
- Session-only mode that holds keys in memory and clears them on exit.
- Key lifecycle operations: rotate provider key, forget key, forget all keys.
- Tests for encrypt/decrypt, wrong passphrase, tamper detection, session clearing, and no plaintext on disk.

## Implementation steps

1. Read the decision in `M3.5-decisions.md` for the fallback UX and algorithms.
2. Add `argon2`, `aes-gcm` or `chacha20poly1305`, `rand`, and `zeroize` dependencies.
3. Define an encrypted-file format with:
   - a format version;
   - a random salt;
   - a nonce;
   - ciphertext;
   - KDF parameters.
   Do not include the passphrase or derived key.
4. Derive the key with Argon2id. Use a random 16-byte or stronger salt. Record the parameters in the file header or a versioned config.
5. Encrypt/decrypt with authenticated encryption. On authentication failure, return a clear error and do not fall back to plaintext.
6. Store the encrypted file under the app-data directory with restrictive permissions on Unix. Do not put secrets in filenames.
7. Implement explicit fallback selection:
   - OS store available: use it by default;
   - OS store unavailable: require the user to choose the encrypted fallback;
   - never silently write a plaintext file.
8. Implement session-only mode. Clear keys on exit and on explicit lock. Use `zeroize` for buffers.
9. Implement provider-key rotation, forget key, and forget all keys through the `SecretStore` trait.
10. Add tests using a temporary directory:
    - round-trip;
    - wrong passphrase fails;
    - tampered ciphertext fails;
    - no plaintext sentinel appears in the file;
    - session mode clears keys;
    - rotation and forget flows work.
11. Document the fallback and session behavior for the UI task.

## Acceptance criteria

- [x] Wrong passphrase and tampering fail closed.

  `serde_json`, and the `tempfile` dev-dependency.
- Added `SecretError::Fallback` and `SecretError::FallbackRequired` so the
  fallback can fail closed with a clear, non-secret error.
- Verification:
  - `cd rust && cargo fmt --all --check` - passed.
  - `cd rust && cargo clippy -p chatui-secrets --all-targets -- -D warnings` -
    passed.
  - `cd rust && cargo nextest run -p chatui-secrets` - 45 passed, 0 failed.
- Decisions:
  - AES-256-GCM with a 12-byte random nonce and a 16-byte random salt.
  - Argon2id v1.3 with 19 MiB memory, 2 iterations, and 1 lane by default;
    parameters are stored in the header and bounded on read.
  - The header is authenticated as AEAD additional data, so salt, nonce, KDF
    parameters, and length tampering fail closed.
  - One encrypted file holds the whole secret map; the file name is fixed and
    never contains a secret ID or value.
  - Unix files are written atomically with mode `0600`; the parent directory is
    created with mode `0700`. Other platforms rely on app-data ACLs.
  - `select_store` uses the OS store when available and otherwise requires an
    explicit `FallbackChoice`; no choice returns `FallbackRequired`.
  - Session mode clears on `lock()` and on `Drop`; values use `SecretValue`
    zeroizing buffers.

## Handoff notes

- File format: magic `CHUIENC1`, version `1`, KDF id `1` (Argon2id), then
  little-endian `m_cost_kib`, `t_cost`, `p_cost`, a 16-byte salt, a 12-byte
  nonce, a 4-byte ciphertext length (including the 16-byte tag), and the
  AES-256-GCM ciphertext.
- Default location: `default_path()` returns
  `<platform app-data>/chatui/secrets.enc`; the UI should use it unless the
  caller has a reason to pass another path.
- KDF parameters: Argon2id v1.3, 19 MiB memory, 2 iterations, 1 lane, 32-byte
  output. Readers accept 8 MiB-1 GiB memory, 1-16 iterations, and 1-16 lanes.
- Fallback prompt text: `ENCRYPTED_FALLBACK_EXPLANATION` and
  `SESSION_ONLY_EXPLANATION` in `encrypted_file.rs`; `FallbackChoice::explanation`
  returns the matching string for the UI.
- Test names: `encrypt_decrypt_round_trip`, `wrong_passphrase_fails_closed`,
  `tampered_ciphertext_fails_closed`, `tampered_header_fails_closed`,
  `salt_and_nonce_are_random_per_write`, `no_plaintext_appears_on_disk`,
  `encrypted_file_has_restrictive_permissions`, `store_round_trip_and_forget_flows`,
  `selection_requires_an_explicit_choice_when_os_store_is_unavailable`,
  `explicit_choice_is_honored_when_the_os_store_is_available`,
  `default_path_is_under_app_data`, `lock_clears_every_key`,
  `rotate_replaces_the_existing_value`, `forget_all_keys_removes_every_key`.
- Platform limitation: restrictive permissions are enforced on Unix only. On
  Windows and macOS the fallback relies on the app-data directory ACLs; backup
  exclusion is owned by M3.5-04.3.
- UI task (M3.5-08.3) should call `select_store` with `None` first, show the
  explanation when it returns `FallbackRequired`, and pass the user's explicit
  `FallbackChoice` on retry. Session mode should call `SessionStore::lock` on
  the explicit lock action.
