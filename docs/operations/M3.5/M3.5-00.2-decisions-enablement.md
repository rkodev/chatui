## Implementation steps

1. Read the plan's section 5 decision table and the milestone's risks and decisions.
2. Decide the enablement question first: `proceed`, `defer`, or `decline`.
   - If `proceed`, record that the full exit gate applies and M4 must include Rust if it ships.
   - If `defer` or `decline`, record that M3.5 is not complete and parity stays honest.
3. Record the platform matrix:
   - Windows x86_64 required?
   - macOS Apple Silicon required?
   - macOS Intel required, manual, or future?
   - Linux x86_64 required?
   - Linux aarch64 required, manual, or future?
4. Record the SQLite decision. Prefer `sqlx` with bundled SQLite if it preserves FTS5 and offline builds; otherwise choose `rusqlite` with bundled FTS5. Record how FTS5 will be proven.
5. Record the contract-loading decision. Prefer compile-in `providers.json` via `include_str!` plus runtime fixture loading. Record strict export validation and tolerant catalog fields.
6. Record the SSE parser decision. Prefer a hand-written bounded parser that matches the shared fixtures, not an opaque dependency.
7. Record the secrets decision. OS credential store first; explicit passphrase-based encrypted-file fallback; session-only mode; no silent plaintext.
8. Record the updater decision: manifest hosting, pinned public keys, stable/beta channels, and no update during an active stream without asking.
9. Record the math decision. Prefer a sanitized raw-source fallback for the first release unless a Rust typesetter is proven safe and renderable.
10. Record multi-window, deep-link single-instance behavior, and desktop backup-exclusion expectations.
11. Record the parity policy: Rust stays `Optional` until enabled; if enabled, required rows must meet the web/Android bar.
12. Update this task's handoff notes with the decisions and any decision still blocked by missing information.

### Result (2026-11-07)

Created [M3.5-decisions.md](M3.5-decisions.md) with 18 decisions (DEC-01 through
DEC-18), each naming a recommendation, an owner, and the task it unblocks. Added
section 8 to [M3.5-verification.md](M3.5-verification.md) and marked B-09
resolved.

Enablement decision: **`defer`** for the current release. The preflight baseline
records macOS/Windows runners, notarization, code-signing, and update-key
ownership as `unknown` (B-01 through B-05), so the full exit gate in plan
section 6.4 cannot be satisfied. M3.5 is not complete, `contracts/parity.md`
stays `Required when enabled` with no Rust implementation claim, and M4 does not
depend on Rust. Implementation may continue as a parallel preview; the decision
is revisited when the missing access is provisioned.

Other recorded decisions:

- Platform matrix: Windows x86_64, macOS Apple Silicon, and Linux x86_64 required
  when enabled; macOS Intel and Linux aarch64 manual/future pending owner
  approval or runners.
- Storage: `sqlx` with bundled SQLite if FTS5 and offline builds hold; otherwise
  `rusqlite` with bundled FTS5. FTS5 proven at startup and in migration/search
  tests.
- Contracts: `include_str!` for `providers.json`, runtime schemas/fixtures,
  tolerant catalog fields, strict export fields.
- SSE: hand-written bounded parser against shared fixtures.
- Secrets: OS credential store first, explicit passphrase encrypted-file
  fallback, session-only mode, no silent plaintext.
- Updater: signed manifests on GitHub Releases or a dedicated HTTPS endpoint,
  pinned keys, `stable`/`beta`, no update during an active stream without asking.
- Math: sanitized raw-source fallback first.
- Desktop: single window first; `chatui://chat/<id>` with single-instance
  forwarding; backup exclusion where the OS supports it.
- Parity/M4: Rust stays `Optional` until enabled; if enabled, required rows meet
  the web/Android bar; M4 does not depend on Rust while deferred.
- `rememberKeysOnWeb` and `browserCors` round-trip for compatibility but do not
  govern desktop secret policy or transport.

Unresolved items remain with their owners: B-01/B-02 runners, B-03/B-04 signing
and notarization credentials, B-05 update-key ownership, B-06 local `libsecret-1`
package, and owner approval for the macOS Intel/Linux aarch64 narrowing. The UI
framework decision remains with M3.5-01.2.
