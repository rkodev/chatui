## Handoff notes

- Usage calculation: `DataControlsService.getUsage()` in
  `android/feature/settings/.../DataControlsService.kt` counts conversations,
  messages, attachments, stored keys, providers, and models. Conversation,
  message, provider, and model bytes are estimated from stored string fields.
  Attachment bytes come from attachment metadata `size`, deduplicated by
  SHA-256; attachment file contents are never read. Secret bytes are the stored
  ciphertext length. `formatBytes()` renders the table.
- Clear-all scope: `DataControlsService.clearAll()` clears conversations,
  messages, FTS rows, attachments, providers, models, secrets, and the sync
  queue in one Room transaction, then calls
  `AttachmentStorage.cleanupOrphans(emptySet())` to remove attachment bytes.
  Appearance and chat preferences are intentionally kept so the app remains
  usable after a reset. The UI requires typing `DELETE ALL DATA` before the
  button enables and shows an irreversible warning.
- Per-key deletion path: `DataControlsService.listProviderKeys()` lists
  providers with stored keys and `removeProviderKey()` delegates to
  `ProviderManagementService.removeKey()`. That deletes the secret and clears
  cached key metadata while keeping the provider and its models. The UI uses a
  two-step removal confirmation.
- Entry points: `DataSettingsScreen` renders usage, stored keys, clear-all,
  export, import, and the backup placeholder. `DataSettingsDestination` in the
  shell wires the SAF export/import launchers, the plaintext export warning,
  the replace-import confirmation, and the backup route. Import is merge by
  default; replace is explicit and confirmed.
- Shell route wiring: `SettingsDestination.DATA` now renders
  `DataSettingsDestination`; the settings root, appearance, chat defaults,
  backup, and about routes continue through `SettingsRoute`. The settings
  entry point exposes `dataControlsService()` for the shell.
- Tests: `DataControlsServiceTest` covers usage counts, metadata-only
  attachment sizing, SHA-256 deduplication, clear-all across all stores and
  attachment bytes, key listing, and per-key delegation.
  `DataSettingsViewModelTest` covers confirmation gating, clear-all, two-step
  key removal, and load failures. `DataSettingsScreenTest` covers usage/key
  rendering, confirmation gating, per-key removal, and export/import/backup
  entry points. `ShellNavigationTest` covers the data and backup routes.
- Verification: `make android-lint && make android-test && make android-assemble`
  passed on 2026-11-06 with `ANDROID_HOME=$HOME/Android/Sdk`.
