## Goal

Add a CI workflow that runs the Android lint, unit-test, and debug-assemble gates on pull requests.

## Preconditions

- `android/gradlew` is committed and executable.
- The Android gates pass locally.
- No release signing material is committed.

## Deliverables

- `.github/workflows/android.yml`:
  - triggers on pull requests and pushes to the default branch
  - JDK 21 setup with a stable distribution
  - Android SDK setup using the runner's installed SDK or an explicit setup action
  - Gradle dependency and wrapper caching
  - `./gradlew lintDebug testDebugUnitTest assembleDebug` from `android/`
  - upload the debug APK artifact with bounded retention
  - `permissions: contents: read`
  - concurrency group per branch/PR with cancel-in-progress
  - bounded timeout
- Use `gradlew` from the repository, not a system Gradle.
- No signing secrets, Play Store publishing, emulator matrix, or release build.
- Do not echo environment secrets.

## Implementation steps

1. Write the workflow with the JDK and caching steps.
2. Confirm the Gradle wrapper path and working directory are correct.
3. Confirm the SDK/compile version matches the repository configuration.
4. Push a draft PR or use the repository's CI mechanism and run the workflow.
5. Fix CI-only failures such as a missing SDK component, a non-executable wrapper, or an incorrect cache path.
6. Record the run result in the handoff notes.

## Handoff notes

Outcome: added `.github/workflows/android.yml` and updated the M0 index.

Workflow details:

- Triggers on `pull_request` and pushes to `dev`, the repository's actual default branch (`origin/HEAD -> origin/dev`).
- Uses `permissions: contents: read`, a per-ref concurrency group with `cancel-in-progress: true`, and a 45-minute timeout.
- Sets up Temurin JDK 21 with `actions/setup-java@v4`.
- Sets up the Android SDK with `android-actions/setup-android@v3` and explicitly installs `platforms;android-37.0` and `build-tools;37.0.0`, matching `compileSdk = 37` and the local SDK.
- Uses `gradle/actions/setup-gradle` for Gradle dependency and wrapper caching. The action is pinned to the `v4.4.4` commit (`748248ddd2a24f49513d8f472f81c3a07d4d50e1`) because `act` 0.2.94 cannot resolve the annotated `v4` tag; the pin also makes the workflow reproducible.
- Runs `./gradlew --no-daemon lintDebug testDebugUnitTest assembleDebug` from `android/`, using the committed wrapper rather than a system Gradle.
- Uploads `android/app/build/outputs/apk/debug/app-debug.apk` as `android-debug-apk` with 7-day retention and fails if the APK is missing.
- No signing secrets, Play Store publishing, emulator matrix, release build, or secret echoing.

Verification results:

- `make android-lint && make android-test && make android-assemble` -> all three Gradle builds succeeded.
- `python3 -c "import yaml; yaml.safe_load(...)"` -> workflow parsed.
- `actionlint .github/workflows/android.yml` -> exit 0.
- `act pull_request -W .github/workflows/android.yml -P ubuntu-latest=ghcr.io/catthehacker/ubuntu:act-latest --artifact-server-path ...` -> job succeeded; `lintDebug`, `testDebugUnitTest`, and `assembleDebug` completed, and the `android-debug-apk` artifact uploaded (15,981,147 bytes).
- `git status --short` -> only the workflow and task/index documentation changes.

CI-specific differences and decisions:

- The task runner cannot push branches or open a PR, so no GitHub-hosted run link exists yet. The workflow was executed end-to-end with `act` (local GitHub Actions runner) and passed. The first push/PR will produce the hosted run link; record it here when available.
- Maven Central returned HTTP 429 for `org.robolectric:nativeruntime-dist-compat:1.0.19` during the local `act` runs. The successful run used a local-only Gradle init script that resolves Maven Central through Google's mirror; this script is not committed and does not change the workflow. GitHub-hosted runners use Maven Central directly.
- Local toolchain: Temurin JDK 21.0.2, Android SDK platform 37.0, build-tools 37.0.0, Gradle wrapper 9.8.1. CI uses Temurin JDK 21, the same SDK platform/build-tools, and the same wrapper. The only local difference is `android/local.properties` (`sdk.dir`), which is gitignored; CI uses `setup-android` instead.
