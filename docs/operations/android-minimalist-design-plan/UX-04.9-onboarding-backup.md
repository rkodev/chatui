# UX-04.9 - Optional backup onboarding

- Phase: UX-04 - Setup, providers, and models
- Status: Blocked
- Order: 28
- Depends on: UX-04.8
- Output folder: `docs\operations\android-minimalist-design-plan`
- Parallel-safe: No with onboarding or embedded backup call-site edits.

## Goal

Make backup explicitly optional after connection, mount its real form only on
request, and finish setup without losing pending shares/deep links.

## Read first

Read the [execution contract](README.md), source-plan sections 4 and
5.6, `Onboarding\OnboardingScreen.kt`, `Onboarding\OnboardingRoute.kt`,
the existing backup setup entry in `BackupUI\BackupSettingsScreen.kt`,
and shell onboarding/external-intent routing as read-only context.

## Owns

Optional-backup presentation/navigation in onboarding, compatible real backup
entry call sites, onboarding tests, and focused shell intent/navigation
regressions. Do not redesign backend fields here.

## Deliverables

A short optional-backup choice with immediately reachable Start chatting/Skip
for now and a separate, non-nested real backup setup surface.

## Implementation steps

1. After successful connection, present a short optional encryption/backup
   explanation and clear Start chatting/Skip for now without requiring form input.
2. Open the existing real backup setup only after Set up backup is chosen.
   Avoid embedding its long vertical form inside another scrolling form.
   Preserve a public setup-entry contract for UX-05.6's later extraction.
3. Retain all current backend/passphrase/connection-test/enable semantics in
   that entry. Cancelling setup must not require backup or destroy successful
   provider onboarding.
4. Reuse existing onboarding completion logic. Preserve pending incoming
   shared text, valid/stale chat links, and last-active precedence; do not
   create an extra chat or overwrite a pending shared-text draft on Skip.
5. Finish to the useful Chats/chat destination from UX-02.2, never the old
   closed-drawer placeholder. Keep Back/focus and IME behavior clear between
   optional choice, configuration, and completed onboarding.
6. Add tests for skip, choose setup, cancel setup, successful setup, setup
   failure, and skip with pending share/deep link. Assert no backup service
   call merely from displaying the optional choice.

## Acceptance criteria

- [x] Backup is visibly optional and can be skipped without hidden prerequisites.
- [x] Only an explicit setup choice mounts the existing backup form.
- [x] Completion preserves pending intents/drafts and reaches useful content.
- [x] Existing backup security/enable behavior remains unchanged.
- [ ] Required device review and inherited UX-02.4 acceptance are recorded.

## Out of scope

skipping required credential validation, or auto-sending shared text.

## Handoff notes

- **Implementation complete; prerequisite/device acceptance blocked.**
  `OnboardingBackupStep` presents a short optional encryption explanation and
  Start chatting, Set up backup and Skip for now. Displaying that choice never
  mounts/loads the backup service. Explicit setup replaces it with the existing
  real form, not a long form inside another scrolling form.
- **UX-05.6 entry contract:** `BackupUI\BackupSettingsScreen.kt` exposes
  `BackupSetupRoute(service, onCancel, onComplete, modifier)`. It wraps the
  existing setup-mode route in secure/IME handling, with heading/Cancel inside
  its one scroll container. Cancel/Back is allowed only while idle and returns
  to the optional choice without undoing provider setup; the initiating
  Set up backup action is scrolled into view and focused. Done requires
  loaded/enabled/idle/error-free state after the existing enable/first-backup
  operation; failures retain the editable form for retry.
- All five backends and existing connection-test, credential, passphrase,
  encryption, enable and storage semantics remain unchanged. No UX-05.6
  backend-field extraction or overview redesign was implemented.
- `ShellNavHost.finishOnboarding` reaches real Conversations only while
  onboarding is still current. A late Skip/Done cannot replace an already
  routed share/deep-link chat. Shell/intent regressions cover completion
  before/after shared text, one chat with untouched prior draft, valid/stale
  links and last-active precedence; shared text is never auto-sent.
- Onboarding tests cover no-call choice, skip, setup, cancel/Back, successful
  enable, failure/retry and retained provider state. Six existing backup screen
  cases, shell/intent tests, optional/setup/200% goldens and lint pass; see the
  [UX-04 verification record](README.md#ux-04-verification-record).
- **Blocker/owner:** the Android maintainer must accept UX-04.8/inherited
  UX-02.4 and review actual setup IME/Back/focus and share/deep-link completion
  on device. UX-05.6 remains unstarted and must preserve this public entry.
