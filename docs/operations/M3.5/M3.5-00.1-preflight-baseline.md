## Goal

Confirm that the shared contracts and M0/M1 baseline are healthy, capture the local toolchain and OS environment, and make every blocker visible before any Rust implementation starts.

## Preconditions

- Do not create or change Rust application code.
- Do not modify `web/`, `android/`, `contracts/`, or `.github/`.
- Do not record API keys, signing material, prompts, or personal data.
- Record only `available`, `unavailable`, or `unknown` for credentials and device access.

## Deliverables

- A new `docs/operations/M3.5/M3.5-verification.md` with:
  - environment section: host OS, architecture, Rust and Cargo versions, toolchain support, available targets, nextest/deny/audit availability;
  - contracts baseline: `make contracts-check` result and contract counts;
  - M0/M1/M2 completion references and known deferrals relevant to Rust;
  - CI runner, macOS, Windows, signing, notarization, and OS credential-store availability;
  - blockers with owners and next actions.
- A handoff note in this task file with the exact commands run and their results.

## Implementation steps

1. Read `docs/milestones/M3.5-rust-desktop.md`, `docs/operations/M3.5-rust-desktop-implementation-plan.md`, `docs/milestones/README.md`, `contracts/parity.md`, and the M1/M2 verification reports.
2. From the repository root, run:
   ```bash
   make contracts-install
   make contracts-check
   git status --short
   ```
   Record the result and whether the working tree is clean apart from known unrelated changes.
3. Record contract inventory without editing it:
   ```bash
   find contracts -maxdepth 3 -type f | sort
   node -e "const p=require('./contracts/providers.json'); console.log(p.length)"
   ```
   Expect 14 provider presets, 5 schemas, 11 stream fixtures, 6 model fixtures, 28 error fixtures, 22 request vectors, and 21 expected vectors. If a count differs, record the difference instead of changing contracts.
4. Record the local Rust environment:
   ```bash
   command -v cargo || true
   command -v rustc || true
   cargo --version || true
   rustc --version || true
   rustup show || true
   rustup target list --installed || true
   ```
5. Record optional tooling availability without installing anything globally:
   ```bash
   command -v cargo-nextest || true
   command -v cargo-deny || true
   command -v cargo-audit || true
   command -v sqlite3 || true
   command -v pkg-config || true
   pkg-config --exists libsecret-1 && echo libsecret-present || echo libsecret-missing
   ```
6. Record OS and desktop-environment facts relevant to `keyring`, packaging, and screen readers. On Linux, note the desktop environment and whether a Secret Service provider is present. Do not inspect or print secret values.
7. Record external environment availability:
   - macOS Apple Silicon runner or machine: available/unavailable/unknown
   - Windows x86_64 runner or machine: available/unavailable/unknown
   - macOS notarization credentials: available/unavailable/unknown
   - Windows code-signing certificate: available/unavailable/unknown
   - update-signing key ownership: available/unavailable/unknown
8. Create `docs/operations/M3.5/M3.5-verification.md` with the sections listed in Deliverables. Keep it factual and evidence-oriented. Do not claim OS or signing checks that were not performed.
9. Update this task's `Handoff notes` with the results, blockers, and the exact environment used.
