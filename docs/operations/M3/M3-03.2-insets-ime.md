## Goal

Ensure content is not obscured by system bars, display cutouts, or the keyboard, and that edge-to-edge behavior is deliberate rather than accidental.

## Preconditions

- M3-03.1 adaptive shell is complete.
- Do not change navigation or add new controls in this task.

## Deliverables

- Explicit safe-drawing/system-bar inset handling in the shell.
- IME padding around the chat composer so the input and send/stop button remain visible.
- No double padding when a parent already consumes insets.
- Tests or documented device checks for keyboard and gesture navigation.

## Implementation steps

1. Read `MainActivity.kt` (`enableEdgeToEdge`), `ShellScaffold`, `ChatScreen`, `ChatComposer`, and any bottom-sheet usage.
2. Choose one inset policy:
   - consume `WindowInsets.safeDrawing` at `Scaffold` and pass only the needed inner padding to content; or
   - apply specific `statusBarsPadding`/`navigationBarsPadding` at the shell boundaries.
   Do not apply both at the same boundary.
3. Apply `Modifier.imePadding()` to the chat screen/content so the composer moves above the keyboard. Keep the message list scrollable.
4. Ensure dialogs, bottom sheets, and the drawer use their own platform inset behavior and do not receive duplicate padding.
5. Add Compose tests where possible; otherwise record a manual device/emulator check with the keyboard open and gesture navigation enabled.
6. Verify landscape and tablet configurations if a device/emulator is available.
7. Record the result in the task handoff.

## Acceptance criteria

- [x] Composer stays visible with the keyboard open.
- [x] System bars and display cutouts do not cover content.
- [x] Insets are consumed once; no visible double padding.
- [x] Drawer, sheets, and dialogs still render correctly.
- [x] Phone and tablet configurations are checked or a blocker is recorded.

## Completion record

- Status: Complete on 2026-11-06.
- Chose one inset policy: `ShellScaffold` consumes `WindowInsets.safeDrawing`
  once. `TopAppBar` receives the top and horizontal sides; the content receives
  the remaining bottom and horizontal sides through `innerPadding`.
- The shell content applies `padding(innerPadding)` followed by
  `consumeWindowInsets(innerPadding)` so descendants do not add the same
  padding again.
- `ChatScreen` applies `windowInsetsPadding(WindowInsets.ime)` (default
  `imeInsets`) so the composer and send/stop button stay above the keyboard.
  The shell has already consumed the navigation-bar inset, so the IME padding
  is not doubled.
- `ModalDrawerSheet` in `AdaptiveShell` uses zero window insets because the
  shell already consumed safe-drawing before rendering the drawer. Dialogs and
  `ModalBottomSheet` remain separate windows and keep their own platform inset
  behavior.
- Tests: `ShellInsetsTest` verifies safe-drawing padding at phone (411 dp) and
  tablet (840 dp) widths and that the drawer does not add a second top inset.
  `ChatScreenTest` verifies the composer moves above a simulated 300 dp IME
  inset and returns to the bottom when the keyboard is closed.
- Verification: `make android-lint`, `make android-test`, and
  `make android-assemble` all passed.
