## Goal

Wire the Android app shell with Hilt, edge-to-edge, splash screen, and placeholder navigation. This is the final Android gate before CI wiring.

## Preconditions

- The design system and all core modules build.
- No provider, onboarding, chat, or other feature implementation is allowed.

## Deliverables

- Hilt application class and dependency wiring.
- `MainActivity` with Compose, edge-to-edge handling, and SplashScreen support.
- Navigation Compose graph with placeholders for:
  - onboarding
  - chat
  - conversations
  - providers
  - settings
  - backup
- Placeholder composables in feature modules only; they must not implement feature behavior.
- A themed shell that launches to a visible placeholder destination.
- Predictive-back behavior for placeholder shell destinations where applicable.
- Tests:
  - Hilt wiring compiles
  - navigation graph resolves placeholder destinations
  - theme/density can be applied to the shell
- Remove placeholder files superseded by real files.
- Run the complete Android gate and record results.

## Implementation steps

1. Add the Hilt application and DI modules.
2. Add `MainActivity` with edge-to-edge and splash screen.

## Handoff notes

- Shell start destination is `conversations`. The bottom navigation exposes all six required destinations: `onboarding`, `chat`, `conversations`, `providers`, `settings`, and `backup`. Every destination renders a feature-module placeholder and contains no feature behavior.
- Hilt wiring: `ChatUiApplication` is annotated with `@HiltAndroidApp`; `MainActivity` is annotated with `@AndroidEntryPoint`; `AppModule` provides the singleton `SettingsDataStore`. `HiltWiringTest` asserts the generated Hilt application component and base class exist.
- Theme and density: `MainActivity` collects `SettingsDataStore.settings` and passes `AndroidSettings` to `ChatUiApp`, which applies `ChatUiTheme(themeMode, density)`. `ShellThemeTest` renders the shell with `Theme.DARK` and `Density.COMPACT` and asserts the appearance tag and start placeholder.
- Edge-to-edge and splash: `MainActivity` calls `installSplashScreen()` before `super.onCreate()` and `enableEdgeToEdge()` after. `Theme.ChatUI.Starting` uses the AndroidX SplashScreen parent with a vector icon and a light/dark splash background.
- Predictive back: the manifest sets `android:enableOnBackInvokedCallback="true"`; Navigation Compose owns the back stack for the placeholder destinations. `ShellManifestTest` guards the manifest flag.
- Feature build files now declare the Compose dependencies needed by their placeholder composables. This keeps placeholder UI inside each feature module rather than adding feature UI to `core:designsystem` or the convention plugins.
- Removed `android/app/src/test/java/dev/chatui/PlaceholderTest.kt`, which was superseded by the shell, navigation, theme, manifest, and Hilt tests.
- No emulator or device was available for a manual launch. The assemble, unit-test, and lint gates are the recorded evidence for this task.
- Placeholder destinations intentionally left for later milestones: onboarding (M1), chat (M1), conversations (M1), providers (M1), settings (M1), and backup (M5).
