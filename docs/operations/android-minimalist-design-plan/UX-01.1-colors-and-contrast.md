# UX-01.1 - Semantic colors and contrast

- Phase: UX-01 - Calm foundations
- Status: Complete
- Order: 4
- Depends on: UX-00.3
- Output folder: `docs\operations\android-minimalist-design-plan`
- Parallel-safe: Yes with UX-01.2; coordinate shared design-system tests.

## Goal

Correct accent contrast and establish restrained semantic surfaces without
replacing the existing neutral palette or token API.

## Read first

Read the [execution contract](README.md), source-plan section 3 and
section 8, `DS\Color.kt`, `DS\Theme.kt`, and `DSTests\DesignSystemTest.kt`.

## Owns

- `DS\Color.kt` and directly required Material-role mappings in `DS\Theme.kt`.
- Color/contrast cases in `DSTests\DesignSystemTest.kt`.
- This task's contrast table and reviewed component captures.

## Deliverables

Compatible semantic colors with corrected accent/on-accent pairs, targeted
regressions, and evidence for actual text/control combinations.

## Implementation steps

1. Identify current semantic roles and exhaustive test constructions. Keep
   existing names; default any essential additional field.
2. Apply the proposed light accent `#2563EB`/on-accent `#FFFFFF` and dark
   accent `#8AB4F8`/on-accent `#0B1020`, unless an approved decision record
   supplies an equally accessible alternative.
3. Keep canvas/input/grouped/separator distinctions subtle. Do not add
   gradients, glass, new shadows, or a broad neutral-palette rewrite.
4. Check rendered normal/selected/pressed/warning/error/code combinations,
   including alpha-composited colors. Do not treat the plan's four opaque
   contrast calculations as certification of every component.
5. Keep matching dynamic on-color roles intact; UX-01.4 owns activating the
   existing persisted dynamic-color preference.
6. Update meaningful affected token assertions and add focused contrast
   regressions for the changed text/action pairs, not a large constants-only
   test suite.

## Acceptance criteria

- [x] Changed normal-text pairs meet 4.5:1; large text/essential controls meet
      3:1 where applicable.
- [x] Both palettes retain existing semantic names and readable on-colors.
- [x] No screen-specific hard-coded palette or new visual dependency appears.
- [x] Component evidence distinguishes measured contrast from visual judgment.

### Changes and compatibility

`DS\Color.kt` changes the two accent values and maps Material selected
containers to `accentSoft` / `onAccentSoft`, rather than retaining the
unrelated default Material container palette. New defaulted `fgOnDanger`
and `fgOnWarning` fields preserve existing constructors and keep the fixed
status roles readable when a dynamic scheme changes `fgOnAccent`.
Dynamic primary/container roles still use their matching supplied on-colors.
`Theme.kt` and the persisted dynamic-color preference are unchanged.

`DSTests\DesignSystemTest.kt` updates the affected token expectations and
adds three regressions: filled/pressed-state contrast, accent text on local
surfaces, and dynamic-primary on-colors not leaking into fixed status roles.
The existing Material mapping case also covers selected containers.
`Screenshots\ScreenshotTest.kt` adds two opt-in standalone component
reviews using the existing Roborazzi dependencies. The parity ledger notes
the presentation-only change; feature commitments and behavior are unchanged.

### Contrast results

WCAG sRGB relative luminance, with source-over alpha compositing before
calculating contrast. Ratios are rounded here; `contrast-report.json`
retains the calculations and source hash.

| Pair/state | Light | Dark |
| --- | --- | --- |
| Filled accent label | 6.70:1 | 8.98:1 |
| Label over modeled 12% content-colored state layer | 5.25:1 | 7.16:1 |
| Label over modeled 16% content-colored state layer | 4.82:1 | 6.62:1 |
| Accent text on input | 6.01:1 | 8.07:1 |
| Accent text on raised surface | 6.70:1 | 6.61:1 |
| Accent text on selected container | 5.82:1 | 5.57:1 |
| Selected-container matching on-color | 7.48:1 | 6.93:1 |
| Filled warning label | 5.20:1 | 13.41:1 |
| Filled error label | 5.38:1 | 5.56:1 |
| Code base text / controls | 15.25 / 9.80:1 | 17.01 / 11.18:1 |

Across the captured 12%-tinted info/warning/error banners on canvas, the
lowest title/body ratios are 13.68/8.80:1 in light and 15.64/10.28:1 in
dark. Their essential icons remain above 3:1. State-layer regressions cover
0%, 8%, 10%, 12%, and 16%, not just the opaque accent.

### Reviewed component evidence and limits

`semantic_colors_dark.png`: primary/outlined/disabled actions, selected
drawer row, filled warning/error roles, translucent banners, a code block,

API-34 component captures at 411 x 891 dp, not device screenshots or

Robolectric did not draw a native ripple when the pointer was held;
identical trial images were discarded. The final images instead explicitly
label a **modeled** 12% state-layer button. They are not native pressed-ripple
proof. Calculated state-layer contrast and visual judgment are separate.

do not certify every disabled, highlighted-code, OEM, or dynamic wallpaper
