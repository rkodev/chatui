# M3.5-00.2 - Scope, decisions, and release enablement

- Milestone: M3.5
- Status: Not started
- Order: 2
- Depends on: M3.5-00.1
- Parallel-safe: none; blocks implementation choices
- Owns: `docs/operations/M3.5/M3.5-decisions.md`, `docs/operations/M3.5/M3.5-verification.md` (decision section)
- Read first: [M3.5 plan](../M3.5-rust-desktop-implementation-plan.md) sections 5, 6.4, and 10; spec sections 10.1-10.12, 12.6, 14.5, 15.1, 18, 19

## Goal

Record the decisions that would otherwise be made implicitly during implementation, especially whether Rust is enabled for the current release, before code or packaging choices harden.

## Preconditions

- M3.5-00.1 is complete.
- Do not implement code or packaging.
- Do not modify `web/`, `android/`, `contracts/`, or `.github/`.
- Do not record secret values. Record credential availability only.

## Deliverables

- `docs/operations/M3.5/M3.5-decisions.md` with a decision table covering:
  - proceed/defer/decline for the current release;
  - platform and architecture matrix;
  - SQLite backend and FTS5 provisioning;
  - contract loading and unknown-field policy;
  - SSE parser approach;
  - secret fallback UX and keyring policy;
  - update hosting, signing, and channels;
  - math rendering strategy;
  - multi-window scope;
  - parity and M4 enablement policy;
  - `rememberKeysOnWeb` and `browserCors` treatment on desktop.
- Each decision must name a recommendation, an owner, and the task it unblocks.
- Update the decision section in `M3.5-verification.md`.

## Implementation steps

1. Read the plan's section 5 decision table and the milestone's risks and decisions.
2. Decide the enablement question first: `proceed`, `defer`, or `decline`.
   - If `proceed`, record that the full exit gate applies and M4 must include Rust if it ships.
   - If `defer` or `decline`, record that M3.5 is not complete and parity stays honest.
3. Record the platform matrix:
   - Windows x86_64 required?
   - macOS Apple Silicon required?
   - macOS Intel required, manual, or future?
   - Linux x86_64 required?
   - Linux aarch64 required, manual, or future?
4. Record the SQLite decision. Prefer `sqlx` with bundled SQLite if it preserves FTS5 and offline builds; otherwise choose `rusqlite` with bundled FTS5. Record how FTS5 will be proven.
5. Record the contract-loading decision. Prefer compile-in `providers.json` via `include_str!` plus runtime fixture loading. Record strict export validation and tolerant catalog fields.
6. Record the SSE parser decision. Prefer a hand-written bounded parser that matches the shared fixtures, not an opaque dependency.
7. Record the secrets decision. OS credential store first; explicit passphrase-based encrypted-file fallback; session-only mode; no silent plaintext.
8. Record the updater decision: manifest hosting, pinned public keys, stable/beta channels, and no update during an active stream without asking.
9. Record the math decision. Prefer a sanitized raw-source fallback for the first release unless a Rust typesetter is proven safe and renderable.
10. Record multi-window, deep-link single-instance behavior, and desktop backup-exclusion expectations.
11. Record the parity policy: Rust stays `Optional` until enabled; if enabled, required rows must meet the web/Android bar.
12. Update this task's handoff notes with the decisions and any decision still blocked by missing information.
