## Goal

Freeze the M4 release scope, confirm the open decisions, and record a measured baseline so later tasks optimize and verify against known numbers instead of guesses. This task creates no product behavior.

## Preconditions

- The milestone entry criteria in [README.md](README.md) have been checked against the current repository and CI state.
- Do not start `M4-01.1` or later until this task is `Complete`.
- Do not change application source in this task.

## Deliverables

- `M4-decisions.md` with confirmed answers for:
  - Rust desktop release status: `shipping` or `not shipping`.
  - Which clients are "enabled" for this release (web required, Android required, Rust conditional).
  - Release version/tag format and the app semver for this release.
  - Target hardware for web Lighthouse, Android cold start, and Rust cold start.
  - Whether Capacitor is included internally (default: no) and whether it may persist keys (default: no).
  - Approved release exceptions with owner and date, or `none`.
- `M4-baseline.md` with pre-change measurements:
  - web initial JS size (raw and gzip) from `web/dist`;
  - web Lighthouse mobile performance/accessibility score and the exact command;
  - Android debug APK size, release APK/AAB size if buildable, and cold-start observation;
  - Rust binary/installer size and cold start, only if shipping;
  - current Playwright, axe, Compose UI, and Rust UI suite status.
- An entry-criteria checklist with pass/fail and owner for each failure.
- Updated `README.md` status if a hard blocker prevents all M4 work.

## Implementation steps

1. Run the current contract, web, Android, and (if shipping) Rust gates to confirm the baseline:
   ```bash
   make contracts-check
   make web-lint && make web-typecheck && make web-test && make web-build
   cd web && pnpm exec playwright test
   make android-lint && make android-test && make android-assemble
   make rust-check && make rust-lint && make rust-test && make rust-build
   ```
   If a tool/device is unavailable, record the blocker rather than skipping silently.
2. Record the web bundle size:
   ```bash
   du -sh web/dist
   find web/dist -name '*.js' -printf '%s %p\n' | sort -nr | head -20
   gzip -c web/dist/assets/*.js | wc -c
   ```
   Prefer a repeatable script or documented command over ad-hoc numbers.
3. Record the current Lighthouse mobile result for the main routes using the project's documented method (local Chrome/Lighthouse or CI). Save the report under `docs/operations/M4/evidence/` if one is created.
4. Record axe status on main routes from the existing Playwright/axe setup, or note that `M4-01.1` will add it.
5. Measure Android artifact sizes from `android/app/build/outputs/` and record the build variant used.
6. If Rust is shipping, measure `rust/dist` artifacts and run the desktop smoke; otherwise record `Rust desktop: not shipping`.
7. Confirm the release version rules from spec 16.5: app semver, contract integer, backup format integer, per-platform DB versions. Write the concrete values for this release in `M4-decisions.md`.
8. List every parity row that lacks evidence today, with an owner, in `M4-decisions.md`; `M4-06.1` will verify them but must not discover the list from scratch.
9. Write both records and update the `README.md` status if required.
