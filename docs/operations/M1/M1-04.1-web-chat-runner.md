## Goal

Implement the non-React service that owns an OpenRouter stream: event reduction, buffered UI updates, persistence cadence, send lock, cancellation, regenerate, and normalized errors.

## Preconditions

- OpenRouter adapter is complete.
- Conversation service can append and update messages.

## Deliverables

- `ChatRunner` that accepts a conversation, context, request, and abort signal.
- Streaming state reducer for start, text, reasoning, usage, finish, and error.
- Zustand store for the active stream keyed by conversation ID.
- UI flush every 33-50 ms using `requestAnimationFrame` or a bounded timer.
- Persistence about every 1 s and on `visibilitychange`, `pagehide`, completion, cancellation, and error.
- One active stream per conversation and a send lock.
- Cancel that aborts the adapter, persists partial text, and marks `cancelled`.
- Regenerate that replaces the last assistant response only after confirmation of the target message.
- First-token and latency timing.
- Tests with a fake adapter covering event order, flush isolation, cancel, error, and no duplicate send.

## Implementation steps

1. Read spec 8.4 and 21.2.
2. Define `StreamingState` and reducer functions as pure functions.
3. Implement the store with selectors so only the streaming message subscribes to token changes.
4. Implement the runner lifecycle: create placeholder message, mark streaming, call adapter, reduce events, flush, persist.
5. Implement a debounced persistence helper that cannot overlap or reorder writes.
6. Implement send lock acquisition and release in a `finally` path.
7. Implement cancel and regenerate.
8. Add tests using fake timers and a controllable adapter.
9. Ensure errors preserve partial text and never auto-retry after output.

## Handoff notes

- Store shape: `useStreamingStore` holds `streams: Record<conversationId, StreamingState>`. `StreamingState` carries `conversationId`, `messageId`, `responseId`, `started`, `text`, `reasoning`, `usage`, `finishReason`, `error`, `status`, `done`, `startedAt`, `firstTokenAt`, `completedAt`, and `updatedAt`. Use `selectStream(conversationId)` or `useStreamingStream(conversationId)` so only the streaming message subscribes.
- Flush timing: UI snapshots flush every 40 ms (`DEFAULT_FLUSH_INTERVAL_MS`) through a bounded timer. The final snapshot is flushed immediately when the adapter resolves.
- Persistence timing: partial messages persist every 1000 ms (`DEFAULT_PERSIST_INTERVAL_MS`), on `visibilitychange`, on `pagehide`, and on completion, cancellation, and error. `SerialMessagePersister` coalesces pending snapshots and never overlaps or reorders writes.
- Cancellation semantics: `cancel(conversationId)` sets the cancelled flag, aborts the runner controller, writes the current partial text as `cancelled`, waits for the adapter to settle, and returns the final message. Events received after cancellation are ignored. An external `signal` is linked to the same controller and follows the same path.
- Send lock: the active-stream map is the lock. It is acquired synchronously before the first await and released in `finally`, so a duplicate send returns `{ ok: false, reason: 'busy' }`.
- Regenerate: the caller must pass the confirmed assistant `target`. The runner validates role and conversation, then reuses the target id and sequence. It does not create a new message or branch.
- Errors: adapter error events and thrown adapter failures are normalized into `ChatError`. Partial text is preserved, the message status becomes `error`, and the runner never retries after output (retry policy remains in the adapter).
