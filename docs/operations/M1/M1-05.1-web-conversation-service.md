## Goal

Provide the plain TypeScript conversation service used by chat and history UI: create, list, rename, delete, title defaulting, message append, and last-active tracking.

## Preconditions

- Typed settings and provider/model services are available.
- Existing repositories are the only persistence path.

## Deliverables

- `createConversation()` using the default provider/model and system prompt.
- `ensureConversationForSend()` or equivalent safe new-chat behavior.
- `deriveTitle(firstUserMessage)` with trim, whitespace collapse, and first 60 Unicode code points.
- `renameConversation`, `deleteConversation`, `getConversation`, and paginated `listConversations`.
- `appendMessage(message)` that updates conversation metadata in the same transaction.
- `setLastActiveConversation` and `getLastActiveConversation` through typed settings.
- Tests for title defaulting, create/delete, message append metadata, and pagination.

## Implementation steps

1. Read `ConversationRepository`, `MessageRepository`, and the domain types.
2. Implement the title helper in one exported function and test blank, long, multi-line, and non-Latin input.
3. Implement create using the current default provider/model. If no provider exists, return a typed "not configured" result rather than throwing an unhandled error.
4. Implement delete with the existing repository transaction; do not remove attachments.
5. Implement append through `MessageRepository.appendMessage` and keep provider/model snapshots on assistant messages.
6. Add a small repository method only if the service cannot list needed data efficiently.
7. Wire last-active tracking through the typed settings service.
8. Add service tests with fake IndexedDB.

## Acceptance criteria

- [ ] First user message becomes the title, capped at 60 code points.
- [ ] New chat uses defaults and is safe when no provider is configured.
- [ ] Rename and delete work and persist.
- [ ] Appending an assistant message stores provider/model/provider-label snapshots.
- [ ] Last-active conversation persists across simulated reload.
- [ ] No UI is added.
- [ ] Web gate passes.
