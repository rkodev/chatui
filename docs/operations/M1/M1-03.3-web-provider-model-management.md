## Goal

Deliver OpenRouter provider management and the model picker/manage-models surfaces, including per-conversation and global model selection plus curated routing controls.

## Preconditions

- Onboarding can create an OpenRouter provider.
- Services can validate keys, refresh models, and persist selections.

## Deliverables

- Provider list/details for OpenRouter: key label, usage, limit, free-tier, rate-limit note, CORS status, enabled toggle, key rotation/removal.
- Provider-docs link from preset `docsUrl`.
- Model picker with search, provider groups, pinned first, capability chips, context window, modalities, price per million, free badge, unavailable warning, manual add, and model details.
- Manage models: pin/hide, manual add, and refresh.
- Global default provider/model settings.
- Per-conversation override that persists immediately and applies to the next send.
- Assistant-message snapshots shown in message metadata.
- Minimal curated routing controls: `allow_fallbacks`, `sort` (`price`, `throughput`, `latency`), `data_collection: "deny"`, with a warning that denying data collection can reduce availability.
- Routing summary text.
- Tests for model pricing/free badge, model switching, defaults, and routing serialization state.

## Implementation steps

1. Read the existing settings placeholder routes and provider service API.
2. Replace provider placeholders with a real list and detail view.
3. Render `/key` metadata without exposing the key.
4. Build the model picker as an accessible dialog. Use existing primitives.
5. Implement search and grouping in a pure selector with tests.
6. Implement pin/hide/manual add through the model service and repository.
7. Implement global defaults and per-conversation override. On override, update the conversation record immediately.
8. Add the routing control component and store the values in `conversation.params.extra.openrouter.provider`.
9. Show a routing summary only when a preference is active.
10. Ensure an unavailable default model shows a warning and does not silently substitute on send.

## Handoff notes

- Routing state lives in `conversation.params.extra.openrouter.provider`. `withRoutingPreferences` writes only the curated `provider` object and preserves other advanced OpenRouter fields (`models`, `route`, `reasoning`). The request builder already serializes that object unchanged.
- Model switching is a single conversation-record update through `ProviderManagementService.setConversationModel`: it resolves the model and provider, rejects disabled providers, then writes `providerId`, `modelId`, and `modelLabel` immediately. Past messages are untouched; `ConversationService.appendMessage` continues to snapshot provider/model on assistant messages.
- Global defaults are validated by `ProviderManagementService.setDefaults`; a model must exist and belong to the selected provider. Changing provider without a model clears a mismatched model instead of silently keeping it.
- Unavailable defaults and conversation models return warnings from `getDefaultModelWarning` and `resolveConversationModel`. The latter never substitutes another model, so the future send path can block instead of silently changing models.
- Pricing is stored as USD per token and displayed per million tokens. Display rounding is limited to 2 decimals at or above $1, 4 decimals at or above $0.01, and 6 decimals below that; persisted values are never rewritten. Zero effective price and the `:free` suffix both render as "Free".
- Provider/model route placeholders now render real screens. `ProviderManagementProvider` lazily builds the production service from IndexedDB; tests inject a fake through the same context.
