## Goal

Complete the Android OpenRouter adapter with streaming, normalized events, reasoning, usage, errors, retry, cancellation, routing, and protected-field enforcement.

## Preconditions

- SSE transport and key/catalog methods are complete.
- Expected and request vectors exist.

## Deliverables

- `streamChat(context, request): Flow<StreamEvent>` or the existing interface shape.
- Request body construction matching web: model, system message, messages, stream flags, supported parameters, reasoning, curated provider options.
- Attribution headers.
- Text, reasoning, finish, usage, and error mapping.
- Reasoning deduplication matching the shared expected vectors.
- Usage/cost normalization.
- Error mapping for 401, 402, 403, 404, 429, 400 context, 503, network before/after first token, timeout, and cancellation.
- Retry policy: max 3 attempts, jittered exponential backoff base 800 ms, cap 8 s, honor `Retry-After`, retry only before first token.
- 120 s inactivity watchdog.
- Protected-field rejection for advanced JSON.
- MockWebServer tests for all fixtures and error/retry/cancel cases.

## Implementation steps

1. Implement a single request-body builder and test exact JSON.
2. Configure OkHttp timeouts: connect 30 s, read 0 during stream, call 0, plus the inactivity watchdog.
3. Call the SSE transport and map raw data into events.
4. Defensively concatenate content arrays.
5. Apply reasoning precedence and deduplication.
6. Track first token and never retry after it.
7. Parse `Retry-After` and implement jittered backoff.
8. Map errors to `ChatError` without keys or raw headers.
9. Reject protected advanced fields before sending.
10. Add tests for every fixture and error path.
11. Run the Android gate.

### Flow and error API

```kotlin
override fun streamChat(
    context: ProviderContext,
    request: NormalizedChatRequest,
): Flow<StreamEvent>

fun streamChat(
    context: ProviderContext,
    request: NormalizedChatRequest,
    supportedParameters: List<String>,
): Flow<StreamEvent>
```

The flow is cold. Terminal failures are emitted as one `StreamEvent.ErrorEvent`
and the flow completes; it does not throw for provider, network, or timeout
failures. Coroutine cancellation cancels the underlying OkHttp call and does
not emit an event because the collector is gone. The builder throws
`OpenRouterRequestException` for protected-field overrides, and `streamChat`
converts that into an `invalid_request` error event before any request.

### Retry timing

The first retry starts at 800 ms plus symmetric jitter, doubles per attempt,
and caps at 8 s. A provider `Retry-After` value (header or
`error.metadata.retry_after_seconds`) overrides the local backoff. Retries stop
after any text or reasoning delta, and the attempt count is capped at 3.

### Watchdog

Streaming uses a dedicated OkHttp client with connect 30 s, read 0, and call 0.
`OpenRouterStreamer` resets a 120 s inactivity watchdog on every SSE event.
When it fires, the producer is cancelled (which cancels the OkHttp call) and a
retryable `timeout` error is emitted. The timeout is injectable for tests.

### Error mapping

- HTTP errors use `{ error: { code, message, metadata } }`; a top-level
  `message` is also accepted. `metadata.provider_name` becomes
  `details.providerName`, `metadata.raw` becomes `details.raw`, and
  `metadata.retry_after_seconds` becomes both `retryAfterSeconds` and
  `details.retryAfterSeconds`.
- In-stream errors use the same envelope inside an HTTP 200 stream. They are
  always non-retryable, preserve already-emitted text, and use the chunk `id`
  as `requestId`.
- `start` is emitted once per `streamChat` call. A retry does not emit a second
  `start`; the first attempt's `responseId` is retained.
- The adapter emits `usage` only when the provider reports it, matching the
  shared expected vectors.
- `403` maps to `content_filter` for moderation/policy/content messages and to
  `permission` otherwise. `400` maps to `context_length` for context-length
  messages and to `invalid_request` otherwise. `413` maps to
  `context_length`.
