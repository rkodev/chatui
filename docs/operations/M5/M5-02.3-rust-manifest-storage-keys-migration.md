# M5-02.3 - Rust manifest, storage keys, and SQLite migration

- Milestone: M5
- Status: Complete
- Order: 8
- Depends on: M5-01.4
- Parallel-safe: yes, with `M5-02.1` and `M5-02.2`
- Owns: `rust/crates/chatui-storage/`, `rust/crates/chatui-domain/`, `rust/crates/chatui-backup/`
- Read first: [M5 plan](../M5-backup-and-sync-implementation-plan.md) sections 3.3 and 5.3; spec sections 6.1, 6.4, and 13.3; `contracts/schema/backup-manifest-body.schema.json`

## Goal

Add the durable data needed for sync on Rust: a random conversation `storageKey`,
a monotonic `revision`, tombstones with `deviceId`, a manifest writer/reader, and
a self-contained conversation payload. Migrate existing SQLite data without loss.

## Preconditions

- `M5-01.4` is `Complete` and the envelope codec exists.
- Rust is conditional. If Rust is not shipping, mark this task `Cancelled`.
- `M5-01.1` schemas are the source of truth for manifest and conversation shapes.

## Deliverables

- New migration `rust/crates/chatui-storage/migrations/0002_backup_sync.sql`:
  - `ALTER TABLE conversations ADD COLUMN storage_key TEXT NOT NULL DEFAULT ''`.
  - `ALTER TABLE conversations ADD COLUMN revision INTEGER NOT NULL DEFAULT 1`.
  - `CREATE TABLE tombstones (...)` with `id`, `conversation_id`, `message_id`,
    `deleted_at`, `device_id`.
  - Indexes on `tombstones(conversation_id)` and `tombstones(deleted_at)`.
- Domain updates in `rust/crates/chatui-domain/`:
  - `Conversation` gains `storage_key` and `revision`.
  - New `Tombstone` struct.
- Mapper and repository updates in `rust/crates/chatui-storage/`:
  - `ConversationRepository` sets `storage_key` and `revision`.
  - New `TombstoneRepository`.
- New manifest and payload code in `rust/crates/chatui-backup/`:
  - `manifest.rs` build/parse.
  - `conversation_payload.rs` build/parse.
- Tests:
  - Migration 0001 -> 0002 with existing data.
  - `storage_key` is 32 hex chars and unique.
  - Manifest and payload round trips.
  - Tombstone repository CRUD.

## Implementation steps

1. Read `0001_initial.sql`, `mappers.rs`, `repositories/conversations.rs`, and
   the domain `Conversation`.
2. Add `0002_backup_sync.sql`. Never edit `0001_initial.sql`.
3. Backfill `storage_key` for existing rows. SQLite cannot generate random hex
   directly; use a Rust migration step after `sqlx::migrate!` or a deterministic
   placeholder that the repository replaces on first read. Document the choice.
4. Update the domain `Conversation` and `Tombstone` structs with serde field
   names matching the shared JSON.
5. Update mappers and `ConversationRepository` create/update to set
   `storage_key` and increment `revision`.
6. Add `TombstoneRepository` with insert, list, and delete.
7. Implement `manifest.rs` and `conversation_payload.rs` in `chatui-backup`.
   Use the schema field names exactly.
8. Add migration and round-trip tests.
9. Run the Rust gates.

## Handoff notes

- Added `Conversation.storage_key` (32 lowercase hex chars) and
  `Conversation.revision` (starts at 1). `new_conversation_storage_key()`
  generates 128 random bits with `rand::rngs::OsRng`.
- `ConversationRepository` assigns both on create, preserves the storage key on
  update/upsert, and increments the revision. Rename, pin, archive, and message
  append also increment it.
- Migration `0002_backup_sync.sql` adds the columns, the `tombstones` table, and
  the tombstone indexes. SQLite cannot generate portable random defaults, so
  `run_migrations` backfills empty keys from Rust immediately after the runner
  finishes. A partial unique index keeps real keys unique while allowing the
  temporary empty value.
- Added `Tombstone`, `TombstoneRow`, and `TombstoneRepository` with insert,
  list-for-conversation, list-all, and delete.
- Added `manifest.rs` and `conversation_payload.rs` with schema validation
  against the shared backup schemas, opaque object keys, and no secret fields.
- Export keeps its existing contract: `storage_key` and `revision` are omitted
  when empty/zero and the export service strips them before validation. Import
  backfills them in `remap_conversation`.
- Verification: `cd rust && cargo fmt --all --check` passed;
  `cd rust && cargo clippy -p chatui-storage -p chatui-backup --all-targets -- -D warnings`
  passed; `cd rust && cargo test -p chatui-storage -p chatui-backup` passed
  (31 backup tests, 76 storage tests).
- Scope note: adding required fields to `chatui-domain::Conversation` means
  other workspace crates that construct `Conversation` literals will need the
  two new fields when they are next compiled. The task-owned crates and their
  verification targets compile and pass.
