## Goal

Implement the native Anthropic Messages adapter with thinking/text separation, base64 images, system prompts, usage, and error mapping.

## Preconditions

- The OpenAI-compatible preset adapter and shared transport exist.
- Do not send the web-only `anthropic-dangerous-direct-browser-access` header unless the contract explicitly requires it on desktop.
- Do not add Anthropic-specific logic outside the adapter.
- Do not modify `web/`, `android/`, or `contracts/`.

## Deliverables

- Anthropic request serialization:
  - top-level `system`;
  - text and base64 image blocks;
  - `max_tokens` always emitted, default 1024 when unset;
  - `stop_sequences`;
  - `anthropic-version`.
- Anthropic SSE normalization:
  - `message_start` -> `start` and initial usage;
  - `content_block_start` text/thinking;
  - `content_block_delta` text/thinking deltas;
  - `message_delta` output usage and stop reason;
  - `message_stop` -> finish;
  - `error` -> normalized error.
- Reasoning and answer text kept separate.
- Anthropic model discovery mapping.
- Tests against Anthropic request, stream, thinking, error, and catalog vectors.

## Implementation steps

1. Read `web/src/providers/anthropic.ts` and the Anthropic fixtures.
2. Implement headers:
   - `x-api-key`;
   - `anthropic-version: 2023-06-01`;
   - `content-type: application/json`;
   - `Accept: text/event-stream`.
3. Serialize normalized messages into Anthropic `messages` with text and image blocks. Put the system prompt in the top-level `system` field.
4. Always emit `max_tokens`, using 1024 when unset.
5. Map `stop` to `stop_sequences`.
6. Implement SSE event handling. Map thinking deltas to `reasoning-delta` and text deltas to `text-delta`. Never concatenate them.
7. Merge initial and final usage correctly.
8. Map stop reasons and errors to the shared types.
9. Implement Anthropic `/models` mapping.
10. Add tests for text, thinking/text separation, usage ordering, auth errors, 429, 404, context errors, and attachments.
11. Run the shared conformance suite.

## Handoff notes

- Request mapping: `build_body` puts the system prompt in the top-level
  `system` field, serializes text parts as `text` blocks, images as
  `{"type":"image","source":{"type":"base64","media_type":...,"data":...}}`,
  and text files as `\n\n[File: <name>]\n<utf-8 content>` text blocks.
  `max_tokens` is always emitted and defaults to 1024. `stop` maps to
  `stop_sequences`. `temperature` and `top_p` are emitted only when the model
  advertises them. Advanced JSON under `params.extra.anthropic` is merged at the
  top level after protected fields (`model`, `messages`, `stream`,
  `stream_options`) are rejected with sorted `details.protectedFields`.
- Header decision: the desktop adapter sends `x-api-key`,
  `anthropic-version: 2023-06-01`, `content-type: application/json`, and
  `Accept: text/event-stream`. It deliberately strips
  `anthropic-dangerous-direct-browser-access` even though the shared contract
  lists it in `defaultHeaders`, because that header is web-only per spec 7.6 and
  the M2 Android adapter made the same decision. The key is added as a
  `SecretHeader` and never enters `PreparedChatRequest.headers`, a URL, or an
  error message.
- Stream mapping: `message_start` emits `start` and captures initial usage;
  `content_block_start`/`content_block_delta` map `text`/`text_delta` to
  `text-delta` and `thinking`/`thinking_delta` to `reasoning-delta` without
  concatenation; `message_delta` merges output usage and records the stop
  reason; `message_stop` emits `finish`; `error` maps to a non-retryable
  `ChatError`. `end_turn`/`stop_sequence` -> `stop`, `max_tokens` -> `length`,
  `tool_use` -> `tool_calls`, `refusal` -> `content_filter`.
- Error mapping: HTTP errors use the shared `map_http_error_for` with the
  Anthropic `{type:"error",error:{...}}` envelope. In-stream errors use
  `map_stream_error`, which maps `overloaded_error` to status 529 and keeps
  in-stream errors non-retryable. The shared vectors for 401, 403, 404, 429,
  400-context, 529, and the in-stream overloaded error all pass.
- Discovery: `GET /models` maps `{data:[...]}` through the shared OpenAI catalog
  mapper with `anthropic_catalog_defaults`, producing text+image input,
  text output, text/vision/streaming capabilities, and the shared supported
  parameter list. `validate_key` uses the same endpoint and returns empty key
  metadata because Anthropic exposes no OpenRouter-style key introspection.
- Test names: `registry_enables_anthropic`,
  `every_anthropic_request_vector_matches_through_the_adapter`,
  `anthropic_defaults_max_tokens_to_1024`, `anthropic_headers_are_desktop_safe`,
  `every_anthropic_stream_vector_matches_through_the_adapter`,
  `anthropic_thinking_and_text_stay_separate`,
  `every_anthropic_http_error_vector_matches_through_the_adapter`,
  `anthropic_in_stream_error_matches_the_shared_vector`,
  `anthropic_catalog_maps_the_shared_vector`,
  `anthropic_validate_key_uses_models_endpoint`,
  `anthropic_credentials_stay_in_headers_and_never_in_urls`,
  `anthropic_cancellation_before_first_token_returns_cancelled`,
  `anthropic_cancellation_after_first_token_preserves_partial_text`,
  `anthropic_retry_allowed_before_partial_output`, and
  `anthropic_retry_not_allowed_after_partial_output`.
- Files touched beyond the owned adapter and conformance test:
  `adapter.rs`, `lib.rs`, and `registry.rs` to wire the new variant and enable
  the preset; `openai_compatible.rs` and `openrouter_adapter.rs` conformance
