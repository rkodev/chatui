## Goal

Add per-conversation system prompt, generation parameters, provider extras, and a conversation settings surface.

## Preconditions

- M2-00.2 request vectors and extra namespace rule exist.
- M2-01.3 models expose supported parameters.

## Deliverables

- Conversation settings route/sheet with model, system prompt, temperature, top P, max output tokens, stop sequences, reasoning effort, streaming toggle, routing summary, export, and delete entry points.
- Provider extras editor with JSON validation and protected-field rejection.
- Unsupported-parameter note when a selected model ignores a value.
- Immediate persistence of settings and model changes.
- Parameters preserved when switching models.
- Tests for persistence, protected fields, unsupported params, and route state.

## Implementation steps

1. Review the existing ChatParams, conversation settings, routing, and request builder.
2. Add the conversation settings route/sheet.
3. Wire prompt and parameter fields to conversation persistence.
4. Add provider extras with shared namespace and validation.
5. Show an inline note when a parameter is unsupported by the selected model.
6. Preserve values across model switches where valid and clear invalid extras.
7. Add tests for persistence, validation, and request behavior.
8. Run web gates.

## Handoff notes

- Route path: `/chat/$conversationId/settings`, linked from the chat header as “Conversation settings”.
- Extra JSON namespace: `params.extra[provider.presetId]` via `extraNamespaceForPreset`; OpenRouter is `openrouter`, Gemini is `google`, Anthropic is `anthropic`, Ollama is `ollama`.
- Unsupported-parameter behavior: values stay stored on the conversation, the settings screen shows an inline note listing ignored fields, and provider request builders omit unsupported core parameters. No values are cleared on a same-provider model switch. Switching providers preserves core parameters but prunes extras belonging to the previous provider namespace.
- Protected fields: `model`, `messages`, `stream`, and `stream_options` are rejected by the extras editor before persistence; adapters also reject them defensively.
- Persistence: `ProviderManagementService.setConversationSettings` writes system prompt and parameters immediately. `deleteConversation` removes the conversation through the repository and clears a matching last-active pointer.
- Export: the conversation settings surface exposes a disabled per-conversation export entry point; implementation remains owned by M2-04.
