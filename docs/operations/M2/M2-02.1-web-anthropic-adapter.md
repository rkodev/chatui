- Status: Complete
- Parent task: M2-02
- Order: 6
- Depends on: M2-01.3
- Parallel-safe: yes, with M2-02.2, M2-02.3, and M2-06.1

- Read first: [M2 plan](../M2-providers-and-content-implementation-plan.md) sections 3.2 and 4.4; spec sections 7.5, 7.6, 7.9

## Goal

Implement the web Anthropic adapter with native headers, system handling, thinking separation, attachments, and error mapping.

## Preconditions

- M2-00.1 Anthropic expected vectors exist.
- M2-01.1 generic transport is available.

## Deliverables

- Anthropic model discovery from the shared catalog fixture.
- Anthropic key validation where supported.
- Chat streaming with `x-api-key`, `anthropic-version`, and web-only `anthropic-dangerous-direct-browser-access`.
- Top-level system prompt handling.
- Text and thinking content block mapping with separation.
- Base64 image block request serialization.
- Finish reason and usage mapping.
- Anthropic error mapping, retry, and cancellation.
- Fixture tests and adapter registration.

## Implementation steps

1. Read the Anthropic fixture and expected vector.
2. Implement headers exactly from the preset and spec; do not send the browser-access header outside web.
3. Map `message_start`, `content_block_start/delta/stop`, `message_delta`, `message_stop`, and error events.
4. Keep thinking blocks separate from answer text and do not replay reasoning.
5. Serialize system prompts at the top level and image parts as base64 blocks.
6. Add tests for text, thinking, usage, finish, errors, retry, cancellation, and protected fields.
7. Register the adapter without changing OpenAI-compatible behavior.
8. Run web gates.

## Acceptance criteria

- [x] Anthropic text and thinking fixtures pass.
- [x] Headers match the preset and spec.
- [x] System prompt is top-level, not a user message.
- [x] Image parts serialize as base64 blocks.
- [x] Usage, finish reason, retry, cancellation, and errors map correctly.
- [x] No secret appears in URLs or logs.

## Handoff notes

- Adapter registry entry: `web/src/providers/anthropic.ts` exports `anthropicAdapter`; `openrouter.ts` and `openrouterStream.ts` dispatch to it when the resolved preset kind is `anthropic`, so existing feature services keep working without OpenRouter regressions.
- Supported error envelopes: Anthropic HTTP `{ "type": "error", "error": { "type", "message" } }` and in-stream `error` events; `overloaded_error` maps to HTTP-equivalent 529 / `provider`.
- Deferred Anthropic features: prompt caching, tool use replay, PDF/document blocks, and live browser CORS verification (M2-02.4).
