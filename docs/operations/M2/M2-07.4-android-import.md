## Handoff notes

- Import limits: `MAX_IMPORT_BYTES` is 50 MiB and is checked against the SAF
  document bytes and the UTF-8 text length before parsing.
  `MAX_IMPORT_ATTACHMENT_BYTES` is 20 MiB per decoded attachment. Attachment
  names are limited to 255 characters and reject path separators,
  Windows-reserved characters, control characters, leading/trailing whitespace,
  `.`, and `..`. IDs are limited to 256 characters and reject control
  characters. SHA-256 values must be 64 hex characters; base64 bytes must match
  both the declared size and SHA-256.
- Merge/replace semantics: merge is the default and upserts by id without
  deleting local records. Re-importing the same archive is idempotent. Providers
  keep the local `enabled`, `secretId`, and `createdAt` values. Models keep the
  local `hidden`, `pinned`, manual source, and `createdAt` values. Models merge
  by `(providerId, remoteId)`; if a local model already has that identity under
  a different id, imported conversation/message/settings references are remapped
  to the local id. Merge leaves local settings untouched. Replace clears
  conversations, messages, FTS rows, attachments, providers, and models inside
  one Room transaction, writes the archive settings, restores the previous
  settings if the transaction fails, and removes orphaned attachment bytes.
  Secrets, backup configuration, and the sync queue are not touched.
- Entry points: `ImportService` in
  `android/feature/conversations/.../importer/ImportService.kt`; `ImportWriter`
  and `ImportDao` in `android/core/database`; `ImportModule`/`ImportEntryPoint`
  expose the service to the shell. `ImportDocumentReader` and
  `rememberImportDocumentLauncher` provide the SAF open-document flow, and
  `ImportReplaceConfirmationDialog`/`IMPORT_REPLACE_CONFIRMATION` provide the
  explicit replace confirmation. M2-07.5 owns the settings/data UI wiring.
- Validation: `validateImportArchive` rejects duplicate IDs, duplicate model
  identities, duplicate message sequences, dangling conversation/message/
  provider/model/attachment references, unsafe attachment names, and malformed
  SHA-256 values. `decodeAttachmentBytes` rejects invalid base64, size
  mismatches, SHA-256 mismatches, and oversized attachments. `validateChatExport`
  enforces the shared schema and `formatVersion` 1 before any write.
- Tests: `ImportWriterTest` covers merge, replace, local flag preservation, and
  transaction rollback with byte cleanup. `ImportServiceTest` covers the export
  round trip, merge idempotence, replace, invalid JSON/schema/size/duplicate
  IDs/unsafe names/dangling references/attachment bytes, model-id remapping,
  settings behavior, and ID/order/snapshot/attachment preservation.
  `ImportDocumentReaderTest` covers SAF reads, the size limit, missing streams,
  and the replace confirmation copy.
