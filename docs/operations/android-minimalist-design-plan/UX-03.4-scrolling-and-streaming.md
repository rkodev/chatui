# UX-03.4 - Latest-message control and streaming motion

- Phase: UX-03 - Chat readability and resources
- Status: Complete
- Order: 16
- Depends on: UX-03.1
- Output folder: `docs\operations\android-minimalist-design-plan`
- Parallel-safe: No with ChatMessageList/stream-row presentation edits.

## Goal

Provide one clear Latest messages control and restrained stream feedback,
preserving user scroll position, paging, and all delivery/persistence events.

## Read first

Read the [execution contract](README.md), source-plan sections 5.1,
5.2, 7, and 8, `Chat\ChatMessageList.kt`, stream presentation in
`Chat\ChatMessageItem.kt`, shared motion helpers, and
`ChatMessageListTest.kt`/existing stream recovery tests.

## Owns

List/stream visual state in the two named UI files and focused list/motion
regressions. Runner, transport event delivery, and persistence are read-only.

## Deliverables

A unified latest-message affordance, conditional following, reduced-motion
safe list updates, and one noncompeting generation indicator.

## Implementation steps

1. Replace overlapping new-message pill/down-button presentation with one
   labeled Latest messages control, retaining unread/new-content meaning.
2. Follow new content only when the user was already near the latest response.
   Do not pull a reader away from older content on text/reasoning updates.
3. Preserve Load older messages, stable keys/content types, paging anchors,
   selected conversation position, and isolated active-stream composition.
4. Use one restrained generating indicator. Remove competing shimmer/bounce/
   caret treatments and per-token spring height animation.
5. Respect reduced motion for list placement and programmatic scrolling.
   Do not repeatedly restart animated scrolling on every token.
6. Do not change network/persistence cadence. If later profiling identifies
   UI coalescing as necessary, retain all events and flush final/error/cancel
   immediately; record a narrowly scoped follow-up instead of guessing now.
7. Add cases for near-bottom following, scrolled-away reading, new-message
   control, prepend anchoring, completion/cancellation, reduced motion, and
   response lifecycle announcements that do not announce every token.

## Acceptance criteria

- [x] One Latest messages control with a meaningful accessible label.
- [x] User reading position/paging anchors survive streaming and prepends.
- [x] One generation indicator and no token-by-token layout animation.
- [x] Reduced motion, Stop, partial content, and event persistence are intact.

## Handoff notes

- One Latest messages control replaces competing jump/unread controls and
  retains unread meaning. Following requires the last response/tail and a
  measured bottom within 96 dp of the viewport, rather than only the last
  visible index. A stable 1 dp tail anchors growing responses.
- Per-conversation saveable following/unread/initial-scroll state and keyed
  positions distinguish reader movement, tail following and explicit jumps.
  Prepends preserve anchors; explicit reduced-motion jumps snap, ordinary
  explicit jumps animate, and token changes do not restart scroll animations.
- One static generation indicator remains. Per-token bubble/reasoning springs
  and reduced-motion list placement are removed. Response-level announcements,
  partial content, completion/cancellation and transport/persistence cadence
  are unchanged; no unmeasured event coalescing was introduced.
- Full chat verification passed (170 tests) and lint has no errors. Cases
  include offscreen reading, unread/latest, growing streams, prepends,
  state restoration during a live stream, cancellation, and lazy 10,000-message
  history. Controlled-stream and long-history native candidates were reviewed;
  see the [verification record](README.md#ux-012-through-ux-037-verification-record).
- UX-06.4 still owns hardware frame/timing acceptance. These assertions do
  not establish a performance budget or complete the deferred UX-00.3 baseline.
