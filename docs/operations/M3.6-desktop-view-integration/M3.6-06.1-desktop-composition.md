## Goal

Compose the real services, controllers, and feature views into
`chatui-desktop`: onboarding gate, lazy controller creation, destination
navigation, menus, shortcuts, deep links, window state, settings application,
and the Models overlay.

## Preconditions

- Every dependency task is complete and its handoff notes list the constructors
  and public methods to call.
- Do not duplicate business logic already owned by controllers.
- Do not add a second runtime, pool, or secret backend.
- Do not modify `web/`, `android/`, or `contracts/`.

## Deliverables

- Desktop startup:
  - open the database through `ServiceRuntime`;
  - read `Settings::onboarding_completed`;
  - show onboarding when incomplete and the shell when complete;
  - persist completion and switch to the shell after a successful connect or
    skip.
- Shell composition:
  - build the settings, providers, models, data, history, chat, and onboarding
    controllers;
  - install their window handles into the shell factory properties;
  - lazily create a controller on first navigation and sync it on every visit.
- Navigation and actions:
  - sidebar navigation syncs the active controller;
  - New Chat, Search, Attach File, Export, Import, Copy Last Response, Stop,
    Previous/Next Conversation, Documentation, and About call real controllers;
  - settings changes apply to the shell, composer, and message list;
  - the Models overlay opens from Settings and closes back to the previous
    destination;
  - deep links open the target conversation when onboarding is complete and
    show the safe not-found state otherwise.
- Error handling:
  - database or secret-backend failures show a user-safe startup error instead
    of panicking;
  - no placeholder copy remains in the normal navigation flow.
- A manual smoke that visits every destination.

## Implementation steps

1. Read every dependency handoff note and list the constructors to call.
2. Replace the `--onboarding-incomplete` flag path with the persisted setting.
3. Build `ServiceRuntime` and the adapters, then the controllers.
4. Install factory properties on `ShellWindow` using the embedding pattern from
   `M3.6-01.1` and the property names from `M3.6-03.1`.
5. Add a lazy `ensure_controller(destination)` helper and call `sync()` on
   navigation.
6. Route menu and shortcut commands to the controllers; remove notice-only
   placeholders for implemented actions.
7. Apply settings to shell/composer/message-list after each settings change.
8. Wire onboarding completion, skip, and failure paths.
9. Wire deep links and the Models overlay.
10. Keep window-state, single-instance, theme polling, and clipboard behavior.
11. Run the smoke on Linux and record results and blockers.

## Acceptance criteria

- [ ] Startup shows onboarding only when completion is false.
- [ ] All five destinations render real controllers and views.
- [ ] Navigating back and forth reuses controllers and syncs state.
- [ ] New chat, search, export, import, attach, copy, and stop perform real
      actions.
- [ ] Settings changes apply to the live shell, composer, and message list.
- [ ] Models opens as an overlay and closes correctly.
- [ ] Deep links route to a real conversation or a safe not-found state.
- [ ] Database and secret failures produce a user-safe message.
- [ ] No placeholder copy is reachable through normal navigation.
- [ ] The smoke run and blockers are recorded.
