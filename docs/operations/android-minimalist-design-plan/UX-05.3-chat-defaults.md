# UX-05.3 - Grouped chat-default controls

- Phase: UX-05 - Settings, data, and backup
- Status: Blocked
- Order: 31
- Depends on: UX-05.2
- Output folder: `docs\operations\android-minimalist-design-plan`
- Parallel-safe: No with SettingsScreens/SettingsRoute chat-default edits.

## Goal

Make Chat defaults understandable through essentials and labeled groups while
retaining every generation, composer, and privacy control.

## Read first

Read the [execution contract](README.md), source-plan sections 5.4,
5.7, and 6, `SettingsUI\SettingsScreens.kt`, `SettingsUI\SettingsRoute.kt`,
`SettingsUI\SettingsViewModel.kt`, stored settings definitions, and existing
`SettingsScreensTest.kt`/`SettingsViewModelTest.kt`.

## Owns

Chat-default presentation and its callback plumbing/tests. Settings storage,
provider service semantics, and feedback coalescing remain separate.

## Deliverables

Provider/model and system prompt first, Generation/Composer/Privacy groups,
and discoverable summaries of active defaults.

## Implementation steps

1. Retain UX-05.2's default provider/model entry at the top with system prompt
   and a clear "new conversations" scope explanation.
2. Group temperature, Top P, max output, stop sequences, reasoning effort,
   and streaming under Generation. Preserve exact inputs, supported ranges,
   unset/default versus explicit values, validation, and reset semantics.
3. Place send-key choice/multiline explanation in Composer. Keep all existing
   modes and keyboard alternatives; do not introduce a new default.
4. Place token-usage display and remote-image control in Privacy with clear
   labels. Keep their current persisted values/defaults; UX-05.5 corrects
   contradictory explanatory copy.
5. Summarize active values when a group is collapsed. Save only lightweight
   nonsecret disclosure state as appropriate; do not reset user values when
   a section is hidden or the model changes.
6. Preserve immediate writes/errors. Do not convert blank/invalid numeric
   input to zero, silently clamp it, or add a Save button.
7. Add cases for every moved control, nullable/default distinctions, collapsed
   state retention, unavailable-model warning, immediate persistence, and
   320 dp/200% fonts/IME with long values.

## Acceptance criteria

- [x] All prior chat-default controls remain reachable and correctly scoped.
- [x] Numeric/default distinctions and validation are unchanged.
- [x] Collapsing/reopening groups does not reset or stage values.
- [ ] Small-screen text/actions reflow with 48 dp targets.

## Out of scope

## Handoff notes

Implemented on 2026-11-17. **Blocked by UX-05.2 and actual small-window/
large-font IME acceptance; owner: Android maintainer.**

- Changed `SettingsUI\SettingsScreens.kt`, `SettingsRoute.kt`,
  `SettingsViewModel.kt` and their existing tests. Provider/model and default
  system prompt precede lightweight saved Generation/Composer/Privacy
  disclosures with active summaries. Hiding a group never clears its values.
- Generation retains temperature, Top P, nullable max output, stop sequences,
  reasoning effort and streaming, including numeric inputs, sliders and
  explicit reset. Blank nullable input means default; invalid, nonfinite or
  out-of-range input produces a field error without writing zero or clamping.
  Atomic parameter patches read the latest stored settings so rapid edits do
  not overwrite a newer field.
- Composer retains Enter and modifier+Enter modes and multiline explanation.
  Privacy retains usage display and remote-image preference, with their
  original persisted defaults. Scope copy distinguishes new-chat generation
  defaults from app-wide composer/privacy settings.
- `SettingsScreensTest` exercises the moved controls, disclosure retention,
  warning, narrow wrapping and targets; `SettingsViewModelTest` exercises
  nullable/reset/invalid values and immediate atomic writes. The full
  settings suite passed **40 tests**, with lint passing. Commands and
  integrated results are in the
  [verification record](README.md#ux-0506-verification-record).
- Actual-shell `integrated_chat_defaults_411_font150_*` and the selectively
  updated standalone chat-default phone/tablet goldens show intentional
  grouping, not a new Save workflow. Actual 320 dp/200% keyboard-visible
  editing remains UX-06.2/06.5 evidence, so the final criterion stays open.
