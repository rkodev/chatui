# M4-04.1 - Web deployment artifacts, container, headers, and recipes

- Milestone: M4
- Status: Not started
- Order: 5
- Depends on: M4-02.1
- Parallel-safe: yes, with `M4-03.1`
- Owns: `deploy/` (Dockerfile, Caddyfile or nginx config, Compose file), `docs/operations/M4/deployment.md`, `web/public/config.json` (public-only validation), deployment recipes; may adjust `web/vite.config.ts` base/output if needed
- Read first: [M4 milestone](../../milestones/M4-polish-and-release.md) workstream 4; spec sections 8.9, 14.1, 14.2, 12.2, and 8.6; existing `web/public/config.json` and `web/vite.config.ts`

## Goal

Produce a minimal static web deployment with a container, correct SPA fallback, correct cache and security headers, public-only runtime config, and documented recipes for the supported hosting targets. Run it and verify the behavior.

## Preconditions

- `M4-02.1` is `Complete` so the built app includes the PWA/manifest assets.
- Do not require environment variables for normal operation; `config.json` contains only public configuration.
- Never bake secrets into the image, config, or build.
- Do not add analytics, telemetry, hidden network destinations, or server-side prompt proxying.

## Deliverables

- A minimal static container using Caddy or nginx with:
  - SPA fallback to `index.html`;
  - `index.html` and `config.json` served no-cache;
  - hashed assets served immutable;
  - `/healthz` returning a static 200 where the server supports it;
  - security headers: CSP from spec 8.6/14.1, `X-Content-Type-Options`, `Referrer-Policy`, minimal `Permissions-Policy`, and `Cross-Origin-Opener-Policy`.
- A `config.json` that is public-only, validated at startup, and contains no secrets.
- Deployment recipes/documentation for Docker Compose, Cloudflare Pages, Netlify, Vercel, GitHub Pages, and the roksky hosting entry point.
- A container/smoke verification record under `docs/operations/M4/evidence/deployment/`.
- A `docs/operations/M4/deployment.md` that another operator can follow without reading source.

## Implementation steps

1. Inspect `web/vite.config.ts`, `web/public/config.json`, and the web build output (`web/dist`) to confirm paths and hashing.
2. Create the `deploy/` directory with:
   - a multi-stage `Dockerfile` that builds the web app and copies only `dist` into a minimal Caddy/nginx image;
   - a Caddyfile or nginx config implementing SPA fallback, cache rules, headers, and `/healthz`;
   - a `docker-compose.yml` for local/one-click use.
3. Header rules:
   - `index.html` and `config.json`: `Cache-Control: no-cache` (or `no-store` for config if the app refetches).
   - Hashed assets: `Cache-Control: public, max-age=31536000, immutable`.
   - Add CSP from spec 8.6/14.1, `X-Content-Type-Options: nosniff`, `Referrer-Policy`, minimal `Permissions-Policy`, and `Cross-Origin-Opener-Policy`.
   - Ensure the CSP allows the provider origins and web workers required by the app; do not weaken it to `unsafe-inline` unless a documented, minimal need exists.
4. Verify `/healthz` returns 200 from the container.
5. Add `config.json` startup validation if not already present; ensure it only accepts public fields and fails closed on malformed input.
6. Build and run the container locally:
   ```bash
   docker build -f deploy/Dockerfile -t chatui-web:local .
   docker run --rm -p 8080:80 chatui-web:local
   ```
   Adjust the port/server command to the chosen base image.
7. Smoke test:
   - load a deep route and confirm SPA fallback;
   - confirm `index.html`/`config.json` no-cache and asset immutable headers;
   - confirm security headers;
   - confirm `/healthz`;
   - confirm no secrets appear in the image/config.
8. Write recipes for Docker Compose, Cloudflare Pages, Netlify, Vercel, GitHub Pages, and roksky. Keep each recipe minimal and link to the shared header/cache requirements.
9. Record evidence: `docker run` output, `curl -I` headers for each asset class, deep-link response, `/healthz`, and an image size listing.

## Acceptance criteria

- [ ] Container builds and serves the SPA with deep-link fallback.
- [ ] `index.html` and `config.json` are no-cache; hashed assets are immutable.
- [ ] Security headers are present and CSP matches spec 8.6/14.1 without an unjustified weakening.
- [ ] `/healthz` returns 200 where supported.
- [ ] No environment variables are required for normal operation.
- [ ] `config.json` is public-only and validated at startup.
- [ ] Container/image contains no secrets.
- [ ] Recipes exist for Docker Compose, Cloudflare Pages, Netlify, Vercel, GitHub Pages, and roksky.
- [ ] Deployment smoke evidence is recorded.

## Verification

```bash
make web-build
docker build -f deploy/Dockerfile -t chatui-web:local .
docker run --rm -d --name chatui-web-smoke -p 8080:80 chatui-web:local
curl -sSI http://localhost:8080/
curl -sSI http://localhost:8080/config.json
curl -sSI http://localhost:8080/healthz
curl -sS http://localhost:8080/some/deep/route | head
docker stop chatui-web-smoke
```

Adjust ports and commands to match the chosen server. Include the actual header output in the evidence file.

- Android/iOS store distribution.
- Adding runtime configuration that is not public.
