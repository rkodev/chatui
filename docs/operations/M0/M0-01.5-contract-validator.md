## Goal

Provide a deterministic, dependency-isolated validator that fails with file-and-field-specific errors when contracts drift.

## Preconditions

- Provider presets, all five schemas, all fixtures, and the parity table exist.
- Do not add a root Node workspace or root `package.json`.

## Deliverables

- `scripts/package.json` with a pinned validator dependency set. `ajv` and `ajv-formats` are acceptable. Use ESM where practical.
- `scripts/package-lock.json`.
- `scripts/validate-contracts.mjs` that:
  - parses every JSON file under `contracts/`, including schemas, presets, model catalogs, and error fixtures
  - validates `providers.json` against `provider-preset.schema.json`
  - validates model catalog fixtures against `model-info.schema.json`, applying the raw-versus-normalized mapping decided in M0-01.2
  - validates settings, export, and backup schema files are valid JSON Schema and can be compiled
  - checks every fixture is non-empty and valid UTF-8
  - enforces unique preset IDs and required preset fields
  - enforces exactly one default/reference/required preset and that it is OpenRouter
  - checks `contracts/parity.md` has the required columns and all required rows
  - exits `0` on success and non-zero on any failure
  - prints errors in the form `path: field: message`
  - does not make network calls
- Keep validator dependencies isolated under `scripts/`; do not create a root workspace.

## Implementation steps

1. Create `scripts/package.json` and install `ajv` plus `ajv-formats` with a lockfile.
2. Write small helper functions for reading JSON, reporting errors, and gathering files.
3. Compile schemas once and reuse validators.
4. Implement every validation rule as a separate function so failures are easy to locate.
5. Make the script exit non-zero after collecting all errors, not on the first one, unless a fatal parse error prevents further work.
6. Run it against the real contracts.
7. Deliberately break a temporary copy of a preset or parity file and confirm the failure message names the file and field. Revert the temporary change.

## Acceptance criteria

- [ ] `make contracts-install` succeeds.
- [ ] `make contracts-check` exits `0` against the real contract tree.
- [ ] A broken preset, schema, fixture, or parity table produces a non-zero exit with a useful message.
- [ ] The validator does not require a root workspace.
- [ ] No secret or live API data is used.
- [ ] `git status --short` shows only intended files.

## Verification

```bash
make contracts-install
make contracts-check
node scripts/validate-contracts.mjs
git status --short
```

## Out of scope

- Client-side contract loading or runtime validation.
- Expected normalized event snapshots.
