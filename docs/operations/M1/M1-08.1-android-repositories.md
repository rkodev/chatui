## Goal

Add the domain repository layer above Room so features never touch entities directly. Include transactional message append, entity/domain mapping, and a streaming-status query.

## Preconditions

- Room schema and DAOs exist and migration tests pass.
- Do not add UI in this task.

## Deliverables

- Conversation, message, provider, model, and settings repositories with entity/domain mapping.
- Transactional `appendMessage` that inserts/updates the message and updates conversation `lastMessageAt`, `messageCount`, and `updatedAt`.
- FTS text synchronization on message insert/update.
- Provider/model upsert that preserves user flags.
- A query for messages by status `streaming` and a recovery update method.
- Tests for mapping, append metadata, pagination, FTS sync, and recovery query.

## Implementation steps

1. Read every entity and DAO.
2. Create mapper functions to/from `core:model` types, reusing `ChatUiJson`.
3. Implement repositories with `Flow` reads and `suspend` writes.
4. Add a DAO transaction for message + conversation update if the existing DAO methods cannot compose atomically.
5. Add the streaming-status query without changing the schema version unless a new index is truly required.
6. Extract searchable text from message parts for FTS.
7. Add tests with in-memory Room.
8. Run the Android gate.

### Repository APIs

`android/core/database/src/main/kotlin/dev/chatui/core/database/repository/`:

- `ConversationRepository`: `observeAll`, `observeActive`, `get`, `create`,
  `upsert`, `update`, `rename`, `setPinned`, `setArchived`, `delete`.
- `MessageRepository`: `get`, `latest`, `older`, `observeConversation`,
  `count`, `appendMessage`, `updateMessage`, `deleteMessage`, `search`,
  `streamingMessages`, `markStreamingCancelled`, `markCancelled`.
  `appendMessage` returns `AppendMessageResult(message, conversation)`.
- `ProviderRepository`: `observeAll`, `get`, `upsert`,
  `upsertPreservingFlags`, `setEnabled`, `delete`.
- `ModelRepository`: `observeForProvider`, `forProvider`, `get`,
  `findByRemoteId`, `insert`, `upsert`, `upsertPreservingFlags`, `update`,
  `delete`, `deleteForProvider`.

All reads return `core:model` domain types. Writes accept domain types. Page
reads return ascending sequence order; the DAO still returns newest-first.

### Mapping decisions

- `Mappers.kt` uses `ChatUiJson` and explicit serializers, so `core:database`
  does not need the Kotlin serialization compiler plugin.
- Enum columns store contract serial names (`openai-compatible`, `streaming`,
  `tool_calls`, and so on), matching the existing DAO test data.
- `ConversationEntity.syncState` stores only `SyncState`; the v1 schema has no
  columns for `lastSyncedAt` or `remoteRevision`. M5 owns the full sync shape.
- FTS text includes text and reasoning parts plus tool-call names/arguments,
  tool results, image alt text, and file names.
- `ProviderRepository.upsertPreservingFlags` keeps the stored `enabled` and
  `secretId` (an incoming secret is used only when none is stored) and keeps
  `createdAt`.
- `ModelRepository.upsertPreservingFlags` matches by `(providerId, remoteId)`
  first, keeps the stored id/`createdAt`/`hidden`/`pinned`, and keeps
  `source = MANUAL` when the stored model was manual.

### DAO transaction added

`MessageDao.appendWithConversation(message, searchText, updatedAt)` inserts or
updates the message, replaces its FTS row, and updates the conversation's
`lastMessageAt`, `messageCount`, and `updatedAt` in one `@Transaction`. It
returns the updated `ConversationEntity` or `null` when the conversation is
missing. `MessageDao` also gained `streaming()`, `cancelStreaming(updatedAt)`,
`updateStatus`, `getConversation`, and `updateConversationMessageMetadata`.

### Settings decision

No Room settings entity exists, and `core:datastore` already owns typed
settings through `SettingsDataStore`/`AndroidSettings`. Adding a settings
repository to `core:database` would either duplicate that facade or create a
module cycle, so settings remain in `core:datastore` for M1-07.1 to wire.
