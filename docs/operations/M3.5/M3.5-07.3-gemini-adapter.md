## Goal

Implement the native Google Gemini adapter with `alt=sse`, system instructions, inline images, generation config, usage metadata, and finish-reason mapping.

## Preconditions

- The OpenAI-compatible preset adapter and shared transport exist.
- Do not put the API key in the query string.
- Do not add Gemini-specific logic outside the adapter.
- Do not modify `web/`, `android/`, or `contracts/`.

## Deliverables

- Gemini request serialization:
  - `systemInstruction`;
  - `contents` with `model` role for assistant turns;
  - `inlineData` for images;
  - `generationConfig` with sampling controls;
  - `stopSequences`.
- Streaming endpoint selection with `alt=sse` and `x-goog-api-key`.
- Streaming normalization:
  - `candidates[0].content.parts[].text` -> `text-delta`;
  - `usageMetadata` -> usage;
  - finish reasons: `STOP` -> `stop`, `MAX_TOKENS` -> `length`, `SAFETY`/`RECITATION` -> `content_filter`, others -> `unknown`.
- Gemini `/models` mapping.
- Tests against Gemini request, stream, finish-reason, error, and catalog vectors.

## Implementation steps

1. Read `web/src/providers/gemini.ts` and the Gemini fixtures.
2. Implement headers with `x-goog-api-key`. Never put the key in the URL.
3. Serialize the system prompt as `systemInstruction`.
4. Convert normalized messages to `contents`; assistant messages use `role: "model"`.
5. Convert images to `inlineData` with `mimeType` and base64 data.
6. Put sampling controls under `generationConfig` and map `stop` to `stopSequences`.
7. Build the streaming URL with `:streamGenerateContent?alt=sse`.
8. Normalize text deltas, usage metadata, and finish reasons.
9. Implement Gemini `/models` mapping.
10. Add tests for text, finish reasons, usage, auth/context/permission errors, 429, and attachments.
11. Run the shared conformance suite.

## Handoff notes

- Request mapping: `build_body` puts the system prompt in
  `systemInstruction.parts[0].text`, serializes messages as `contents` with
  `role: "model"` for assistant turns and `"user"` for every other role, text
  parts as `{ "text": ... }`, images as
  `{ "inlineData": { "mimeType": ..., "data": ... } }`, and text files as
  `\n\n[File: <name>]\n<utf-8 content>` text parts. `maxOutputTokens` is emitted
  whenever set; `temperature`, `topP`, and `stopSequences` are emitted only when
  the model advertises the matching supported parameter. Advanced JSON under
  `params.extra.google` is merged at the top level after protected fields
  (`model`, `messages`, `stream`, `stream_options`) are rejected with sorted
  `details.protectedFields`.
- URL and header decision: the streaming URL is
  `POST {base}/models/{model}:streamGenerateContent?alt=sse` with a leading
  `models/` stripped from the model ID. The key is added as a `SecretHeader`
  named `x-goog-api-key` and never enters `PreparedChatRequest.headers`, a URL,
  or an error message. `content-type: application/json` and
  `Accept: text/event-stream` are set for streaming requests.
- Stream mapping: each `data:` payload emits `start` once, then
  `candidates[].content.parts[].text` as `text-delta` (parts with
  `thought: true` become `reasoning-delta`). `usageMetadata.promptTokenCount`,
  `candidatesTokenCount`, and `totalTokenCount` map to the shared `Usage`.
  A candidate `finishReason` emits `finish` and then `usage`, matching the
  shared vector order. A stream that starts without a finish reason emits
  `finish` with `unknown`; an empty stream is a parse error.
- Finish-reason table: `STOP` -> `stop`, `MAX_TOKENS` -> `length`,
  `SAFETY`/`RECITATION` -> `content_filter`, everything else -> `unknown`.
- Error mapping: HTTP errors use the shared `map_http_error_for` with the
  Gemini `{ "error": { "code", "message", "status" } }` envelope, then apply
  Gemini-specific code rules: 400 with an API-key/credential message -> `auth`,
  400 with a context/token-count message -> `context_length`, 403 with a
  content-filter message -> `content_filter`, otherwise the shared status
  mapping. In-stream errors use `map_stream_error_for` and stay non-retryable.
  `x-goog-request-id` is preserved as the request ID.
- Discovery: `GET /models` maps `{ "models": [...] }` with
  `google_catalog_defaults`, using `baseModelId` (or `name` without the
  `models/` prefix) as the remote ID, `displayName` as the label,
  `inputTokenLimit` as the context window, and `outputTokenLimit` as the max
  output. `validate_key` uses the same endpoint and returns empty key metadata
  because Gemini exposes no OpenRouter-style key introspection.
- Test names: `registry_enables_gemini`,
  `every_gemini_request_vector_matches_through_the_adapter`,
  `gemini_headers_use_x_goog_api_key`,
  `every_gemini_stream_vector_matches_through_the_adapter`,
  `gemini_finish_reasons_match_the_shared_vector`,
  `every_gemini_http_error_vector_matches_through_the_adapter`,
  `gemini_in_stream_error_matches_the_shared_vector`,
  `gemini_catalog_maps_the_shared_vector`,
  `gemini_validate_key_uses_models_endpoint`,
  `gemini_credentials_stay_in_headers_and_never_in_urls`,
  `gemini_cancellation_before_first_token_returns_cancelled`,
  `gemini_cancellation_after_first_token_preserves_partial_text`,
  `gemini_retry_allowed_before_partial_output`, and
  `gemini_retry_not_allowed_after_partial_output`.
- Files touched beyond the owned adapter and conformance test:
