# M0-04.2 - Core model, common utilities, network interfaces

- Status: Complete
- Parent task: M0-04
- Order: 15
- Depends on: M0-04.1
- Parallel-safe: yes, with M0-02.2
- Owns: `android/core/model/**`, `android/core/common/**`, `android/core/network/**`, module build files for those modules, corresponding tests
- Read first: [M0 plan](../M0-foundations-implementation-plan.md) sections 3.3 and 4.5; spec sections 6, 7.1, 7.2, 9.2, 12.3

## Goal

Implement the pure Kotlin domain model, shared error/redaction/retry utilities, and network interfaces. No HTTP client or provider implementation is allowed.

## Preconditions

- The Gradle module graph exists and builds.
- Keep `core:model` free of Android framework dependencies.

## Deliverables

- `core:model`:
  - serializable data classes and enums mirroring spec section 6:
    `Provider`, `Model`, `Conversation`, `ChatParams`, `Message`, `ContentPart`, `Attachment`, `Usage`, `ChatError`, `Settings`, `BackupConfig`
  - `StreamEvent` and `FinishReason` exactly as spec section 7.2
  - `MessageRole` and `MessageStatus`
  - UUIDv7 IDs
  - ISO 8601 `Instant` serialization
  - a documented provisional `syncState`/`SyncMeta` placeholder, not a sync implementation
  - no Android imports
- `core:common`:
  - result/error types that do not conflict with later provider errors
  - redaction helpers for `Authorization`, `x-api-key`, and `x-goog-api-key`
  - retry policy primitives: max 3 attempts, jittered exponential backoff starting at 800 ms with an 8 s cap, and `Retry-After` support hook
  - test utilities shared by later modules
- `core:network`:
  - interfaces only: `ProviderAdapter`, `ProviderContext`, `ProviderKeyInfo`, `NormalizedChatRequest`
  - streaming signature returning a coroutine `Flow<StreamEvent>` or equivalent
  - no OkHttp calls, endpoints, SSE parser, or provider classes
- Tests:
  - serialization round trips for every domain type, including `StreamEvent` and `ChatError`
  - UUIDv7 shape/uniqueness
  - Instant ISO 8601 round trip
  - redaction removes values
  - retry/backoff boundaries

## Implementation steps

1. Create the model files and serializers.
2. Implement a tested UUIDv7 generator or add a vetted dependency. Do not assume a platform UUIDv7 API.
3. Add provisional sync fields and document them.
4. Implement redaction and retry utilities in `core:common`.
5. Add network interfaces only.
6. Write tests and run the module tests plus the app build.

## Handoff notes

Completion record (2026-11-02):

- `core:model` is a pure Kotlin JVM module with no Android imports. It contains `Provider`, `Model`, `Conversation`, `ChatParams`, `Message`, `ContentPart`, `Attachment`, `Usage`, `ChatError`, `Settings`, `BackupConfig`, `StreamEvent`, `FinishReason`, `MessageRole`, `MessageStatus`, and the supporting enums. All are `@Serializable` with contract serial names.
- UUIDv7: `UuidV7Generator` implements RFC 9562 locally (48-bit millisecond timestamp, version `7`, variant `10`, 74 random bits) with injectable `Random` and clock. `newId()` uses a process-wide `SecureRandom`-backed generator; `isUuidV7()` validates the canonical shape. No platform UUIDv7 API is assumed.
- `Instant` serialization: `InstantIso8601Serializer` encodes `java.time.Instant.toString()` and decodes with `Instant.parse`. Model files opt in with `@file:UseSerializers(InstantIso8601Serializer::class)`. `ChatUiJson` ignores unknown keys, omits defaults, and keeps explicit nulls for required nullable fields.
- Provisional sync shape: `Conversation.sync: SyncMeta?` with `SyncMeta(state: SyncState, lastSyncedAt: Instant?, remoteRevision: String?)` and `SyncState { local, pending, synced, conflict }`. This is a documented placeholder only; M5 owns the final sync semantics.
- `core:common` provides `Outcome`/`AppError` (deliberately separate from domain `ChatError`), `Redaction` for `Authorization`, `x-api-key`, and `x-goog-api-key` (case-insensitive headers and diagnostic text), `RetryPolicy`, `RetryAfter`, and shared test utilities `FakeClock` and `FixedRandom`.
- Retry constants: `maxAttempts = 3`, `baseDelayMillis = 800`, `maxDelayMillis = 8_000`, `jitterFraction = 0.2`. `canRetry(attemptsMade)` allows attempts 1 and 2 after the first failure. `backoffMillis` yields 800, 1600, 3200, 6400, 8000, ...; `nextDelayMillis` applies symmetric jitter and honors `Retry-After` when larger.
- `core:network` contains interfaces/types only: `ProviderAdapter`, `ProviderContext`, `ProviderKeyInfo`, `NormalizedChatRequest`, `NormalizedMessage`, `NormalizedRole`, and `ModelInfo`. `streamChat` returns a cold `Flow<StreamEvent>`. OkHttp/SSE dependencies were removed from the module; no endpoints, parsers, or provider classes exist.
- Verification: `cd android && ./gradlew :core:model:testDebugUnitTest` passed; `cd android && ./gradlew :core:common:testDebugUnitTest` passed; `cd android && ./gradlew :app:assembleDebug` passed. `./gradlew :core:network:test` also passed. A `--rerun-tasks` run of all three module test suites passed.
- Decision: the task's verification commands use Android-style `testDebugUnitTest`, but `core:model` and `core:common` are pure Kotlin JVM modules that expose `test`. A `testDebugUnitTest` alias task was registered in those two module build files so the specified commands work without changing the module type.
- Decision: `ModelInfo` was added to `core:network` because `ProviderAdapter.listModels` needs a provider-neutral return type; it is a plain data class, not a provider implementation.
