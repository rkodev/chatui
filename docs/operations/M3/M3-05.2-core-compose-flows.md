# M3-05.2 - Core Compose UI flows

- Milestone: M3
- Status: Not started
- Order: 24
- Depends on: M3-04.6, M3-03.4
- Parallel-safe: yes, with M3-06.2 and M3-06.3
- Owns: Compose UI tests in `android/app/src/test/` and feature test sources, small testability seams needed by those tests
- Read first: [M3 plan](../M3-android-depth-implementation-plan.md) sections 3.4 and 4.6; spec section 15.1

## Goal

Close the gaps in Compose UI coverage for the required M3 surfaces and add a route-level send/stream flow.

## Preconditions

- All M3 feature tasks that change screens are complete.
- Use fake providers and fake data only; do not contact live providers.
- Do not change production behavior just to satisfy a test unless a real bug is exposed.

## Deliverables

- Passing Compose/Robolectric coverage for:
  - onboarding welcome, provider picker, key entry, validation error, and success;
  - chat empty, send, streaming, stop, complete, and error states;
  - model picker search, grouping, selection, and unavailable state;
  - provider list, custom provider form, provider detail, key rotation, and error states;
  - settings root, appearance, chat defaults, data, backup placeholder, and about;
  - the new adaptive shell, drawer/sidebar, share flow, deep-link not-found state, and shortcut help.
- At least one route-level test that drives send -> stream -> complete through the ViewModel and screen with a fake adapter.
- A short coverage map in the task handoff listing test files and screens.

## Implementation steps

1. Inventory existing tests:
   ```bash
   rg -n "createComposeRule|createAndroidComposeRule" android/app/src/test android/feature android/core
   ```
2. Read the existing tests for onboarding, chat, model picker, providers, settings, and conversations. Reuse their fakes and test tags.
3. Add the missing route-level chat test using `ChatViewModel` and a controlled `FakeProviderAdapter`:
   - send a user message;
   - assert the user row appears;
   - emit streamed deltas and assert they render in one streaming row;
   - emit finish and assert the action row/complete state;
   - cancel and assert the stop/partial state.
4. Add or extend screen tests for the M3 shell, share, deep-link not-found, shortcuts, and provider management. Keep them in the module that owns the screen.
5. Ensure every test uses unique stable IDs and does not depend on real time; use fixed clocks and zones.
6. Run the full Android unit-test suite and fix only test seams or real defects.
7. Record the coverage map in the handoff notes.

## Acceptance criteria

- [ ] Every required screen in the list above has a passing Compose test.
- [ ] A route-level send/stream/complete test exists.
- [ ] Tests use fake providers only.
- [ ] No production behavior changes without a linked defect.
- [ ] The full `make android-test` suite passes.
- [ ] The coverage map is recorded in the handoff.
