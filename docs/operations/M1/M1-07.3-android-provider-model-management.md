## Goal

Deliver Android provider management and the model picker/manage-models surfaces, including defaults and curated routing controls.

## Preconditions

- Onboarding can create an OpenRouter provider.
- Services can validate, refresh, and persist models.

## Deliverables

- Provider list/detail with key label, usage, limit, free tier, rate-limit note, CORS status, enabled toggle, key rotation/removal.
- Provider-docs link from preset `docsUrl`.
- Model picker bottom sheet with search, provider groups, pinned first, capability chips, context, modalities, price per million, free badge, unavailable warning, manual add, and details.
- Manage models: pin/hide, manual add, refresh.
- Global default provider/model and per-conversation override with immediate persistence.
- Assistant-message snapshots in metadata.
- Minimal curated routing controls (`allow_fallbacks`, `sort`, `data_collection: "deny"`) and routing summary.
- Tests for model pricing/free badge, switching, defaults, and routing state.

## Implementation steps

1. Read the provider placeholder and service APIs.
2. Build provider list/detail ViewModels and composables.
3. Render `/key` metadata without exposing the secret.
4. Build the model picker bottom sheet and search/grouping selectors.
5. Implement pin/hide/manual add through the model repository.
6. Implement global defaults and per-conversation override.
7. Add routing controls and store values in `conversation.params.extra.openrouter.provider`.
8. Show a routing summary only when active.
9. Add tests and run the Android gate.

## Handoff notes

- Routing state lives in `conversation.params.extra.openrouter.provider`. `withRoutingPreferences` writes only the curated `provider` object and preserves other advanced OpenRouter fields (`models`, `route`, `reasoning`). The request builder already serializes that object unchanged.
- Model switching is a single conversation-record update through `ProviderManagementService.setConversationModel`: it resolves the model and provider, rejects disabled providers, then writes `providerId`, `modelId`, and `modelLabel` immediately. Past messages are untouched; the future chat runner must continue to snapshot provider/model on assistant messages.
- Global defaults are validated by `ProviderManagementService.setDefaults`; a model must exist and belong to the selected provider. Changing provider without a model clears a mismatched model instead of silently keeping it.
- Unavailable defaults and conversation models return warnings from `getDefaultModelWarning` and `resolveConversationModel`. The latter never substitutes another model, so the future send path can block instead of silently changing models.
- Pricing is stored as USD per token and displayed per million tokens. Display rounding is limited to 2 decimals at or above $1, 4 decimals at or above $0.01, and 6 decimals below that; persisted values are never rewritten. Zero effective price and the `:free` suffix both render as "Free".
- The provider list/detail, model picker, defaults, manage-models, conversation model control, and routing controls are ready for M1-08.2 to wire into the shell. `ProvidersPlaceholder` remains in place until that navigation task.
