# M3-01.4 - Network security config and local cleartext policy

- Milestone: M3
- Status: Complete
- Order: 8
- Depends on: M3-00.2
- Parallel-safe: yes, with M3-01.1, M3-01.2, M3-01.3
- Owns: `android/app/src/main/AndroidManifest.xml`, `android/app/src/main/res/xml/network_security_config.xml`, local-host validation code and tests
- Read first: [M3 plan](../M3-android-depth-implementation-plan.md) sections 3.1, 3.7, and 4.2; spec sections 9.6 and 12.3; M3-00.2 cleartext decision

## Goal

Enable local providers without allowing cleartext to public hosts, using the policy recorded in `M3-decisions.md`.

## Preconditions

- M3-00.2 records the cleartext policy.
- Do not add a global trust-all manager or disable certificate validation.
- Do not add an in-app WebView.

## Deliverables

- `android:networkSecurityConfig` declared in the app manifest.
- `res/xml/network_security_config.xml` with the approved local-host policy.
- A single helper that decides whether a host is allowed to use cleartext.
- Tests for allowed local hosts and refused public hosts.
- Local provider device evidence for the M2 Ollama/LM Studio/llama.cpp deferral.

## Implementation steps

1. Read the decision in `M3-decisions.md`, `contracts/providers.json`, `ProviderCreation.kt`, and the network adapters.
2. Add `android:networkSecurityConfig="@xml/network_security_config"` to the `<application>` element.
3. Create `network_security_config.xml`:
   - keep `base-config` cleartext disabled unless the decision explicitly says otherwise;
   - add `domain-config` entries for the approved loopback/emulator/`.local` hosts;
   - if the decision requires arbitrary RFC1918 IPs, implement the approved app-layer allowlist and document why the XML cannot express CIDR ranges.
4. Add a pure `isAllowedCleartextHost(host: String): Boolean` helper in the provider/network layer. Handle IPv4 private ranges only if the decision requires them; include loopback, IPv6 loopback, and the emulator host.
5. Reject cleartext for public hosts before the request is sent. Keep HTTPS behavior unchanged.
6. Add unit tests for:
   - `localhost`, `127.0.0.1`, `::1`, `10.0.2.2` as allowed where the decision says so;
   - a public `http://` host refused;
   - `https://` public hosts unaffected;
   - non-http schemes refused.
7. On a device/emulator with a local server, verify the local preset can reach it. If no local server is available, record the blocker.
8. Add a note to `M3-verification.md` describing the policy and device result.

## Handoff notes

- M3-01.5 owns the user-facing cleartext warning and the certificate-validation guard. The interceptor currently refuses public cleartext with a `CleartextNotAllowedException`; adapters map it to their generic network error until M3-01.5 adds the specific warning copy.
- LM Studio and llama.cpp were not running during the device check, so only Ollama was exercised on device. Their loopback and RFC1918 addresses are covered by the same unit tests.
- `.local` mDNS resolution was not exercised on the emulator. The policy resolves `.local` names and refuses a public result; RFC1918 literals remain the supported fallback.
- The policy resolves a hostname before the request and OkHttp resolves it again when connecting. A DNS-rebinding window remains; pinning the resolved address would require a custom OkHttp `Dns` and is not part of this task.
