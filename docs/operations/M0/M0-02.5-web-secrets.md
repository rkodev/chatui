## Goal

Implement the three web secret-storage modes and central redaction helpers. Keys must never be written to `localStorage`, URLs, logs, or the Cache API.

## Preconditions

- The `secrets` IndexedDB store and `SecretRepository` exist.
- `crypto.subtle` is available in the runtime; tests may need a WebCrypto polyfill or Node's global `crypto`.

## Deliverables

- `web/src/storage/SecretStore.ts` with a clear API:
  - `setSecret(id, value, mode)`
  - `getSecret(id)`
  - `deleteSecret(id)`
  - `forgetAll()`
  - an explicit unlock path for passphrase mode
- Three modes:
  - `session`: keep secrets in memory only; a new store instance loses them.
  - `remember`: generate one non-extractable AES-GCM 256-bit `CryptoKey` per browser profile, store the key in IndexedDB, and persist only IV plus ciphertext in the `secrets` store.
  - `passphrase`: derive AES-GCM with PBKDF2-HMAC-SHA256, 600,000 iterations, and a random salt; never store the passphrase or derived key on disk; require unlock after reload.
- `web/src/platform/crypto.ts`:
  - AES-GCM encryption/decryption primitives
  - random IV generation
  - key generation and passphrase key derivation
  - a constructor/options path that lets tests lower PBKDF2 iterations while production always uses 600,000
- `web/src/platform/redaction.ts`:
  - central helpers for redacting `Authorization`, `x-api-key`, `x-goog-api-key`, and other configurable secret headers
  - text redaction for diagnostic messages
  - case-insensitive matching
  - no secret values in output
- Tests:
  - remember mode encrypts and decrypts
  - ciphertext in IndexedDB does not contain plaintext
  - session mode loses secrets when a new store instance is created
  - passphrase mode fails before unlock and succeeds after the correct passphrase
  - wrong passphrase fails cleanly
  - redaction removes all supported header values

## Handoff notes

- Persisted record shape:
  - Remember payload: `{ id: 'remember:<secretId>', iv: <base64 IV>, ciphertext: <base64 AES-GCM ciphertext>, createdAt, updatedAt }`.
  - Passphrase payload: `{ id: 'passphrase:<secretId>', iv, ciphertext, createdAt, updatedAt }`.
  - Device key: `{ id: '__chatui_device_key__', iv: null, ciphertext: null, key: CryptoKey, createdAt, updatedAt }`. The key is generated with `extractable: false`.
  - Passphrase salt: `{ id: '__chatui_passphrase_salt__', iv: <base64 salt>, ciphertext: null, createdAt, updatedAt }`.
  - Passphrase verification: `{ id: '__chatui_passphrase_check__', iv, ciphertext, createdAt, updatedAt }`, encrypting a fixed non-secret marker so a wrong passphrase fails before any secret is read.
- The mode is encoded in the record id prefix (`remember:` / `passphrase:`), so no plaintext mode field is added to `SecretRecord`.
- PBKDF2 override: `createCrypto({ pbkdf2Iterations })` and `SecretStore({ pbkdf2Iterations })` exist for tests only. Production defaults to `PBKDF2_ITERATIONS = 600_000`; tests use 1,000.
- Vitest/WebCrypto: the jsdom environment already exposes `crypto.subtle` and `structuredClone`, so no polyfill was needed. `fake-indexeddb` round-trips the non-extractable `CryptoKey` correctly.
- `forgetAll()` deletes every record in the `secrets` store, including the device key and passphrase salt/verification records, and clears in-memory session and passphrase state.
