## Goal

Prove the desktop UI is keyboard reachable, has visible focus, provides accessible names, respects reduced motion, and passes at least one screen-reader smoke test per tier-1 OS.

## Preconditions

- All UI feature tasks are complete enough to navigate.
- Do not claim screen-reader coverage that was not run.
- Do not record personal data or real conversations in evidence.
- Do not modify `web/`, `android/`, or `contracts/`.

## Deliverables

- `docs/operations/M3.5/accessibility.md` with:
  - keyboard navigation results;
  - focus-visible results;
  - accessible names for icon-only controls;
  - live-region behavior for response start/complete/errors;
  - reduced-motion behavior;
  - contrast notes;
  - one screen-reader smoke test per tier-1 OS, or a precise blocker.
- Automated checks in the UI test harness where the framework supports them.
- Accessibility evidence in `M3.5-verification.md`.

## Implementation steps

1. Read spec section 11.11 and the framework decision's accessibility notes.
2. Audit every interactive element for keyboard reachability and visible focus.
3. Audit icon-only buttons for accessible names.
4. Audit streaming announcements: announce start, completion, and errors, not every token.
5. Verify reduced-motion behavior for transitions and streaming indicators.
6. Check contrast for body text, large text, and UI boundaries against section 11.11 thresholds.
7. Run a screen-reader smoke test on each available OS:
   - Windows: Narrator;
   - macOS: VoiceOver;
   - Linux: Orca or the available screen reader.
   Record the OS, screen reader, build, steps, and result.
8. If an OS or screen reader is unavailable, record a blocker instead of a pass.
9. Add automated semantics/focus tests where possible.
10. Record the evidence in `M3.5-verification.md`.

## Acceptance criteria

- [ ] Keyboard navigation reaches all interactive surfaces.
- [ ] Focus rings are visible.
- [ ] Icon-only controls have accessible names.
- [ ] Streaming announcements are bounded and useful.
- [ ] Reduced motion is respected.
- [ ] Contrast meets the spec thresholds or deviations are recorded.
- [ ] One screen-reader smoke test per available tier-1 OS is recorded.
- [ ] Unavailable OS/screen-reader checks are precise blockers.
- [ ] No personal data or real conversations appear in evidence.
