# M3-02.3 - Provider documentation in Custom Tabs

- Milestone: M3
- Status: Complete
- Order: 16
- Depends on: M3-00.2
- Parallel-safe: yes, with M3-02.1, M3-02.2, and M3-04.*
- Owns: `android/gradle/libs.versions.toml`, app/providers dependencies, `android/feature/providers/ProviderDetailScreen.kt`, provider-docs launcher and tests
- Read first: [M3 plan](../M3-android-depth-implementation-plan.md) sections 3.2 and 4.4; spec sections 9.10 and 11.5

## Goal

Open provider documentation in a Chrome Custom Tab with a safe external-browser fallback instead of an uncontrolled `LocalUriHandler` call.

## Preconditions

- Do not add an in-app WebView.
- Only open `http` or `https` documentation URLs from the provider contract.
- Do not open provider API base URLs in a browser.

## Deliverables

- `androidx.browser` dependency pinned in the version catalog.
- A small `DocumentationLauncher` abstraction that can be faked in tests.
- Provider detail documentation action uses a Custom Tab and falls back to `ACTION_VIEW`.
- Tests for the launcher and URL validation.

## Implementation steps

1. Read `ProviderDetailScreen.kt`, `ProviderRoutes.kt`, `ProviderPreset`/contract docs URL handling, and the version catalog.
2. Add `androidx.browser:browser` to `libs.versions.toml` and the module that renders provider details. Do not hard-code a version in the module.
3. Create a `DocumentationLauncher` interface with `open(context, url)` and an Android implementation:
   - parse the URL and accept only `http`/`https`;
   - build `CustomTabsIntent` and launch it;
   - if no Custom Tabs handler exists, start `Intent.ACTION_VIEW` with the same URI;
   - if no browser handles it, return a user-safe failure.
4. Replace the `LocalUriHandler` usage in `ProviderDetailScreen` with the launcher, injected as a parameter or composition local so tests can pass a fake.
5. Keep the button label and content description accessible.
6. Add tests:
   - valid `https://` docs URL is passed to the launcher;
   - `http://` is accepted only if the contract explicitly uses it;
   - non-http(s) URLs are refused;
   - no in-app WebView is created.
7. Record a manual Custom Tabs check on a device/emulator.

## Acceptance criteria

- [x] Provider documentation opens in a Custom Tab.
- [x] A browser fallback exists when Custom Tabs is unavailable.
- [x] Only `http`/`https` documentation URLs are opened.
- [x] No WebView is introduced.
- [x] The action is accessible and testable with a fake launcher.
- [x] Tests pass.

## Verification

## Out of scope

- In-app documentation rendering.
- API base URL navigation.
- Deep links and share targets.

## Handoff notes

- Added `androidx.browser:browser` 1.8.0 to the version catalog and the
  `:feature:providers` module. The version is pinned only in
  `android/gradle/libs.versions.toml`.
- `DocumentationLauncher` is a `fun interface` with an Android implementation
  that validates `http`/`https` URLs, prefers a Custom Tab, falls back to
  `Intent.ACTION_VIEW`, and returns a user-safe failure when no browser exists.
  `LocalDocumentationLauncher` lets screens and tests swap implementations.
- `ProviderDetailScreen` now takes an optional `documentationLauncher`
  parameter (defaulting to the composition local) and shows a safe inline error
  if the launcher refuses or fails. The docs button keeps its text label and
  adds an explicit content description.
- Added a `<queries>` entry for `CustomTabsService` so Android 11+ package
  visibility does not hide installed Custom Tabs providers.
- No WebView is used; a static test guards the launcher and screen sources.
- Verification:
  - `make android-lint` — passed.
  - `make android-test` — passed.
  - `make android-assemble` — passed.
  - Device check on `emulator-5554` (Medium Phone API 36.1): installed the
    debug APK, opened Providers → OpenRouter → "OpenRouter documentation".
    `dumpsys window` reported
    `com.android.chrome/org.chromium.chrome.browser.customtabs.CustomTabActivity`
    and the page rendered "OpenRouter | Documentation". Chrome's first-run
