## Goal

Expose the full provider management flow from the Android app shell and update the UI for all enabled presets and Custom providers.

## Preconditions

- M2-05.3 provider services are complete.
- Existing provider screens and ViewModels are available.

## Deliverables

- Provider route in `ShellNavHost` replacing `ProvidersPlaceholder`.
- Provider list/detail support for enabled presets and Custom providers.
- Navigation from chat model chip and settings to provider management.
- Provider tests and navigation tests.

## Implementation steps

1. Read `ShellNavHost`, `ProvidersPlaceholder`, and provider routes.
2. Replace the placeholder with the real provider list/detail routes.
3. Update provider list/detail for multiple presets and Custom.
4. Wire chat and settings entry points.
5. Add navigation tests.
6. Run Android gates.

## Acceptance criteria

- [x] Provider management is reachable from the shell.
- [x] Chat and settings entry points open provider management.
- [x] Enabled presets and Custom providers are visible.
- [x] OpenRouter provider flow still works.
- [x] Placeholder is no longer routed.
- [x] Android gates pass.

## Handoff notes

- Route wiring:
  - `ShellNavHost` now resolves `ProviderManagementService` through
    `ProviderManagementEntryPoint` and routes `providers` to
    `ProviderListRoute`. Provider details use the nested
    `providers/{providerId}` route from `ProviderDestination`.
  - `ShellDestination.Providers.matches` also matches `providers/...`, so the
    bottom navigation and top-bar title stay on Providers while a detail screen
    is open.
  - The chat model chip and availability banner already called
    `onOpenProviders`; they now land on the real provider list. The shell
    settings destination wraps `SettingsPlaceholder` with a "Manage providers"
    action that navigates to the provider list. Settings screens themselves
    remain M2-06.5 work.
  - `ProvidersPlaceholder` was deleted; no route references it.
- Provider UI:
  - `ProviderListScreen` now has a preset creation form for every enabled
    OpenAI-compatible preset (OpenRouter, OpenAI, Groq, Mistral, DeepSeek, xAI,
    Together, Fireworks, LM Studio, llama.cpp) plus the existing Custom form.
    Presets that use `none` auth hide the key field.
  - `ProviderAvailability` gained `requiresKey`, derived from the contract auth
    type, so the UI does not hard-code which presets need a key.
  - `ProviderDetailScreen` shows preset id, base URL, and auth style for every
    provider. The OpenRouter routing note and docs label are now
    provider-specific instead of OpenRouter-only.
- Navigation test coverage:
  - `ShellNavigationTest` asserts the provider detail route is registered,
    accepts a provider id, and keeps the Providers destination selected.
  - `SettingsRouteTest` asserts the settings entry point invokes provider
    navigation.
  - `ProviderRoutesTest` renders the stateful list and detail routes with the
    fake management service.
  - `ProviderListViewModelTest` covers preset creation, missing preset/key
    validation, and the existing Custom flow. `ProviderListScreenTest` covers
    enabled preset chips, the preset form, and Custom visibility.
    `ProviderDetailScreenTest` covers Custom provider metadata.
