# M6-01.4 - Tenant configuration validator and docs

- Milestone: M6
- Status: Not started
- Order: 4
- Depends on: M6-01.2, M6-01.3
- Parallel-safe: no; blocks hosting tasks
- Owns: `scripts/validate-tenant-config.mjs`, `docs/hosting/tenant-configuration.md`, `docs/hosting/branding.md`
- Read first: [M6 plan](../M6-managed-hosting-implementation-plan.md) sections 3.1 (T-02 through T-12), 4, and 9; `web/src/app/config.ts`; `web/public/config.json`; `deploy/roksky.md`; `docs/operations/M4/deployment.md`

## Goal

Add a repeatable tenant config check and write the operator-facing tenant and
branding documentation so a smaller model or operator can validate and publish a
tenant without including secrets or inventing fields.

## Preconditions

- `M6-01.2` is `Complete` and the tenant manifest schema is valid.
- `M6-01.3` is `Complete` and the public config templates are valid.
- The validator may use Node built-ins and existing repository dependencies. Do
  not add a new package unless the repository already uses it.

## Deliverables

- `scripts/validate-tenant-config.mjs`:
  - CLI: `node scripts/validate-tenant-config.mjs <config.json> [more.json] [--origin https://tenant.example.com]`.
  - Validate JSON parse and required field types.
  - Reject unknown top-level fields.
  - Validate `defaultTheme` values and non-empty `appName`.
  - Validate `defaultProviderPreset` is one of `enabledPresets`.
  - Validate `enabledPresets` has no duplicates and includes `custom` only when
    `allowCustomProviders` is true.
  - Require `telemetry === false` for a hosted tenant config.
  - Validate `openRouter.attributionOrigin` and `docsUrl` as absolute URLs.
  - If `--origin` is supplied, require `openRouter.attributionOrigin` to match
    it exactly, including a custom domain.
  - Recursively reject forbidden key names such as `apiKey`, `secret`,
    `secretKey`, `accessKey`, `accessKeyId`, `accountKey`, `password`,
    `passphrase`, `token`, `credential`, `credentials`, `privateKey`, and
    `serviceAccount`.
  - Scan values for common secret patterns, including `sk-...`, Google API key,
    Slack token, and private-key headers. Reuse the patterns from the M4 image
    scan evidence where practical.
  - Print `tenant config ok: <path>` on success. Print every issue with path and
    message on failure. Exit nonzero on any failure.
  - Support multiple files and `--help`.
- `docs/hosting/tenant-configuration.md`:
  - Explain the split: private operator tenant manifest versus public app
    `config.json`.
  - Document every public field, its type, and its purpose.
  - Document subdomain/region constraints and the region meaning/data residency
    statement from `DEC-M6-07`.
  - Document the full and minimal templates, the exact origin replacement, the
    no-secret rule, and the validation command.
  - Document the review and approval step before publish.
  - State the same `config.json` must self-host the exported build.
- `docs/hosting/branding.md`:
  - Document app name, default theme, enabled presets, custom-provider allowance,
    OpenRouter attribution origin/title, docs link, telemetry, and feature-flag
    decision.
  - State the PWA install-name/icon limitation or the branded-build decision.
  - Include a branding review checklist.

## Implementation steps

1. Read the config schema and tests to mirror validation rules without importing
   TypeScript.
2. Write the validator with clear error paths and no dependency on a browser.
3. Run it against both templates from `M6-01.3`.
4. Create temporary invalid copies under `/tmp` and verify the validator rejects
   unknown fields, `telemetry: true`, a mismatched origin, and a forbidden key
   name. Do not commit the temporary files.
5. Write the tenant configuration and branding docs.
6. Link the M6 plan, M4 deployment contract, config templates, and validator.
7. Run the validator, web config tests, and a docs link check.

## Acceptance criteria

- [ ] The validator exists, is executable with Node, and prints actionable
      errors.
- [ ] Both valid templates pass.
- [ ] Unknown fields, secrets, `telemetry: true`, and origin mismatch fail.
- [ ] The validator never prints a secret value in full. Redact values in errors.
- [ ] `docs/hosting/tenant-configuration.md` and
      `docs/hosting/branding.md` exist and reference the real files.
- [ ] The docs state that config is public, no-cache, and secret-free.
- [ ] The docs state that the same public config supports self-hosting.
- [ ] No secret, real key, passphrase, or private endpoint is committed.

## Verification

```bash
node scripts/validate-tenant-config.mjs deploy/roksky/templates/config.full.json
node scripts/validate-tenant-config.mjs deploy/roksky/templates/config.minimal.json
cd web && pnpm exec vitest run src/app/config.test.ts
```

Negative checks:

```bash
tmp="$(mktemp)"
node -e 'const fs=require("fs");const p=process.env.TMP_CONFIG;const c=JSON.parse(fs.readFileSync("deploy/roksky/templates/config.minimal.json","utf8"));c.apiKey="redacted";fs.writeFileSync(p,JSON.stringify(c))' TMP_CONFIG="$tmp"
node scripts/validate-tenant-config.mjs "$tmp"
rm -f "$tmp"
```

The last command must exit nonzero.
