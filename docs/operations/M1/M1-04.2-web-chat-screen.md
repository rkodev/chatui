## Goal

Render the chat screen on top of `ChatRunner`: virtualized history, isolated streaming message, scroll behavior, message layout, metadata, and chat states.

## Preconditions

- ChatRunner and conversation service are complete.
- Do not implement Markdown, code, composer, or actions in this task; leave focused extension points.

## Deliverables

- Chat route that loads the conversation and its newest message page.
- Virtualized/windowed message list using `@tanstack/react-virtual` or an equivalent already-approved dependency.
- Stable keys and content types; pagination of older messages on scroll.
- Scroll anchoring and auto-scroll only when near the bottom.
- Isolated streaming message selector.
- Message item with role layout, metadata (model/provider/time/usage when enabled), cancelled/interrupted state, and inline error card.
- Chat states: no provider, empty conversation, sending, streaming, complete, error, model unavailable.
- Live-region announcements for response start, complete, and error only.
- Component tests for rendering order, states, pagination, and streaming isolation.

## Implementation steps

1. Read the chat placeholder route and root layout.
2. Build a `useConversationMessages` hook using the repository/service with paging.
3. Implement the virtualized list and load-older behavior.
4. Implement near-bottom detection and scroll anchoring.
5. Build a memoized `MessageItem` keyed by ID and content revision.
6. Subscribe only the streaming item to the active stream store.
7. Render error cards with normalized message, retry affordance hook, and details disclosure.
8. Render a model-unavailable state that disables sending.
9. Add live regions with start/complete/error text only.
10. Add tests and run the gate.

## Acceptance criteria

- [ ] Chat history renders in sequence order with stable keys.
- [ ] Older messages paginate without duplicating or reordering.
- [ ] Auto-scroll only occurs when near the bottom.
- [ ] Streaming token updates do not re-render unrelated history items.
- [ ] Empty, no-provider, streaming, complete, error, cancelled, and model-unavailable states exist.
- [ ] Live region announces start/complete/error, not tokens.
- [ ] Web gate passes.
