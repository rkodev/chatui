# M3.5-12.1 - Full conformance and critical-case evidence

- Milestone: M3.5
- Status: Not started
- Order: 46
- Depends on: all prior tasks
- Parallel-safe: none; full gate
- Owns: `rust/tests/conformance/` (final suite), `docs/operations/M3.5/conformance.md`, `docs/operations/M3.5/M3.5-verification.md` (conformance and critical-case sections)
- Read first: [M3.5 plan](../M3.5-rust-desktop-implementation-plan.md) sections 3.8 and 6; spec sections 7.4, 10.12, 15.1, 15.2

## Goal

Run the full shared conformance suite and every applicable critical case, and produce evidence that the Rust desktop client meets the same behavioral bar as web and Android.

## Preconditions

- All core, provider, storage, secret, UI, packaging, and CI tasks are complete.
- Do not modify shared fixtures to make tests pass.
- Do not claim a case that was not run.
- Do not record real keys, prompts, or personal data.
- Do not modify `web/`, `android/`, or `contracts/` except the parity file in M3.5-12.2.

## Deliverables

- A full conformance run covering:
  - every stream, model, error, request, catalog, fallback, capability, math, and export vector;
  - the OpenRouter section 7.4 checklist;
  - all provider adapters in the enabled set.
- Critical-case evidence for section 15.2 cases that apply to desktop, including:
  - first run and onboarding;
  - invalid/valid key;
  - catalog mapping;
  - OpenRouter streaming and keep-alives;
  - reasoning and usage;
  - in-stream and HTTP errors;
  - provider streaming;
  - cancellation and partial persistence;
  - network retry before/after first token;
  - model switch;
  - routing and protected fields;
  - reload during streaming;
  - Markdown safety;
  - large conversation;
  - export/import;
  - clear data;
  - 429 `Retry-After`.
- Process-death and restart evidence:
  - kill the process during a stream;
  - relaunch;
  - verify the message is cancelled and partial content survives.
- `docs/operations/M3.5/conformance.md` with pass/fail, test names, and evidence.
- Verification-report sections with commands and results.

## Implementation steps

1. Read spec sections 7.4, 10.12, 15.1, and 15.2.
2. Run the full Rust suite:
   ```bash
   make contracts-check
   make rust-fmt
   make rust-lint
   make rust-nextest
   make rust-conformance
   make rust-build
   make rust-deny
   make rust-audit
   ```
3. Run the provider conformance suites for every enabled adapter.
4. Execute the OpenRouter checklist and record each item with a test name or manual evidence.
5. Walk the section 15.2 list and mark each case `pass`, `N/A`, or `blocked`. Include the test name or procedure.
6. Run the process-death procedure on the available OS. Use the release or debug build consistently and record which.
7. Verify partial content survives cancellation and failure.
8. Verify export/import round-trip and clear-data behavior.
9. Verify no secrets appear in logs, exports, or crash output.
10. Record results in `conformance.md` and `M3.5-verification.md`.

## Acceptance criteria

- [ ] Every shared fixture vector passes.
- [ ] The OpenRouter checklist is fully recorded.
- [ ] Every applicable section 15.2 case has evidence or an explicit N/A.
- [ ] Process death preserves partial content and marks the message cancelled.
- [ ] Cancellation preserves partial content.
- [ ] Export/import and clear data are verified.
- [ ] No secrets appear in evidence or logs.
- [ ] The conformance report contains test names and commands.
- [ ] No shared fixture was modified to force a pass.
- [ ] Blockers are explicit, not hidden.
