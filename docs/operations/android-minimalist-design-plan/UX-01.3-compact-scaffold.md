## Goal

Add a stable compact title-bar option to the existing scaffold so chat no
longer needs an unwired 96 dp expanded header.

## Read first

Read the [execution contract](README.md), source-plan sections 3, 5.1,
and 9, `DS\ChatUiScaffold.kt`, `DSTests\ComponentsTest.kt`, and
`Shell\ChatUiApp.kt` as a read-only consumer reference.

## Owns

- `DS\ChatUiScaffold.kt` and its `DSTests\ComponentsTest.kt` coverage.
- Minimal shared layout-token additions only if not already provided.
- No production shell adoption; UX-02.2 and UX-02.3 own it.

## Deliverables

An explicit compact scaffold variant retaining the scaffold's existing slots,
snackbar ownership, accessibility hooks, and inset behavior.

## Implementation steps

1. Read the current expanded/collapsed height logic and existing call sites.
   Add an explicit compact mode/style rather than pretending an unrelated
   `rememberScrollState()` represents a destination's `LazyColumn`.
2. In compact mode, target a 64-72 dp minimum with subtitle and about 56 dp
   without, excluding system insets. Permit bounded growth for font scaling:
   one title line ordinarily and two at larger fonts, with complete accessible
   text. The owner approved a single-line model label and 48 dp minimum in
   very short keyboard layouts to preserve input space.
3. Preserve title/subtitle click hooks, navigation/action slots, test tags,
   snackbar host, and content padding contracts.
4. Keep the model/title hit area at least 48 dp and reachable independently
   of transcript scrolling. Avoid large-title collapse or separator animation
   work in the compact path.
5. Retain a compatible default/legacy path for consumers not adopted yet.
   Do not add a second nested scaffold or consume IME/system padding twice.
6. Add cases for subtitle/no-subtitle, long title, 200% font, compact height,
   and unchanged content/snackbar inset placement.

## Acceptance criteria

- [x] Compact mode has no 96 dp expanded-title floor or dummy-scroll coupling.
- [x] Text reflows within approved bounds; full text and model interaction remain accessible.
- [x] Existing consumers still compile and their default behavior is preserved.
- [x] Insets/snackbar/action slots remain owned once.

## Handoff notes

- Added `TitleBarStyle.Compact`; the compatible default remains `Large`.
  Compact title/model callbacks, descriptions, modifiers, navigation/actions,
  snackbar ownership, and scaffold content padding are preserved. Ordinary
  minima are 56 dp without a subtitle and 72 dp with one.
- **Owner-approved refinement:** the initial 320 dp/200% capture let a long
  title consume most of the viewport. Titles now use one ordinary/two scaled
  lines with ellipsis, retaining full text in semantics. Below 240 dp of
  inset-adjusted height the model becomes the single visible label; the full
  conversation title remains its accessible state. Below 160 dp, redundant
  padding is removed while targets remain at least 48 dp.
- Insets are read to choose presentation, not consumed again. Compact mode
  ignores dummy scroll state. Existing large-title consumers are unchanged.
- Executed full design-system tests (51 passed), design-system lint (no
  errors), and `:app:compileDebugKotlin` (passed). Native cases check actual
  two-line ellipsis, full semantic text, short-keyboard body/action bounds,
  subtitle/no-subtitle minima, and snackbar/content placement.
- Reviewed foundation and simulated-IME candidates listed in the
  [verification record](README.md#ux-012-through-ux-037-verification-record).
  Production adoption is implemented by UX-02.2/UX-02.3; real keyboard/focus
  acceptance remains explicitly blocked in UX-02.3, not claimed here.
