## Goal

Implement the web sync engine: read the remote manifest, merge by revision,
upload dirty encrypted objects, rewrite the manifest with preconditions, and
resolve conflicts deterministically. Restore must be non-destructive by default.

## Preconditions

- `M5-03.1` is `Complete` and the S3 adapter works.
- `M5-02.1` provides the manifest, payload, storage keys, revisions, and
  tombstones.
- Do not implement UI in this task.

## Deliverables

- `web/src/features/backup/sync.ts`:
  - `SyncEngine` with `sync()`, `backupNow()`, `restore()`, and `deleteRemote()`.
  - Device ID and backup salt creation on first setup.
  - Read `manifest.enc`; create an empty manifest if absent.
  - Merge local and remote manifests by conversation revision.
  - Upload dirty conversations and attachments.
  - Rewrite the manifest with new revisions and `If-Match`.
  - Retry with bounded backoff and re-read on conflict.
  - Drain the existing `syncQueue`.
- `web/src/features/backup/merge.ts`:
  - Message set merge by UUID, ordered by `sequence`, then `createdAt`, then
    `id`.
  - Deletion tombstones with `deletedAt` and `deviceId`; deletion wins over an
    older update.
  - Conversation metadata LWW by `updatedAt`, tiebreak `deviceId`.
  - Concurrent additions kept and sequences renumbered deterministically.
  - Never drop local messages.
- `web/src/features/backup/sync.test.ts`:
  - Empty remote creates a manifest.
  - Local-only, remote-only, and both-sides changes.
  - Concurrent additions keep both and renumber deterministically.
  - Concurrent metadata edits resolve by LWW and device ID.
  - Deletion tombstone wins over an older update.
  - Manifest conflict retries and re-reads.
  - Interrupted upload leaves local data unchanged.
  - Restore merges by default and never wipes local data.
  - Wrong passphrase fails before any local mutation.

## Implementation steps

1. Read the manifest, payload, tombstone, and S3 adapter code.
2. Implement device ID and backup salt creation. Store them in `backupConfig`.
3. Implement `readRemoteManifest`:
   - `getObject('manifest.enc')`.
   - If `not_found`, return an empty manifest.
   - Decrypt and parse; reject unknown `formatVersion`.
4. Implement `mergeManifests`:
   - Compare conversation revisions.
   - Keep the higher revision; on equal revision use `updatedAt` then `deviceId`.
   - Merge tombstones as a set.
5. Implement `mergeConversation`:
   - Merge messages by UUID as a set.
   - Apply tombstones; deletion wins over an older update.
   - Order by `sequence`, `createdAt`, `id`.
   - Renumber sequences deterministically when concurrent additions collide.
   - Assert the local message set is a subset of the merged set.
6. Implement `uploadDirty`:
   - Build and encrypt conversation payloads.
   - Upload attachments by `sha256` if absent.
   - Track uploaded keys.
7. Implement `writeManifest`:
   - Encrypt the manifest.
   - `putObject` with `If-Match` from the last read ETag.
   - On `conflict`, re-read and retry with backoff.
8. Implement `restore`:
   - Merge by default.
   - Only replace when the caller passes an explicit `replace: true`.
9. Implement `deleteRemote` with a typed confirmation token supplied by the
   caller; do not delete local data.
10. Drain `syncQueue` after a successful sync.
11. Add tests and run the web gates.

## Handoff notes

- `SyncEngine` takes an injected `StorageAdapter`, passphrase, and optional
  `attachmentStore`/`settings` sources. UI wiring (`M5-05.1`) should construct
  it from the saved backup config and secret store.
- `iterations` is a test-only PBKDF2 override; production callers must omit it.
- Message-level tombstones are applied locally during merge but are not carried
  in the manifest because the frozen manifest schema has no `messageId` field.
  Conversation-level tombstones are carried in the manifest.
- `restore({ replace: true })` clears local conversations and messages but keeps
  attachment metadata and bytes; orphan cleanup remains a separate concern.
- Scheduling (`M5-06.2`) and UI (`M5-05.1`) remain out of scope.
