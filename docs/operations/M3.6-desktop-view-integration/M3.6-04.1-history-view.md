## Goal

Add the Slint History view and a controller that binds `ConversationHistory` and
`ConversationSearchService` to a real, interactive sidebar: groups, new chat,
archive, load-more, rename, delete with undo, drafts, and search.

## Preconditions

- `M3.6-02.1` provides the shared runtime and repositories.
- `M3.6-03.1` provides the shell host container and factory property.
- Do not change the history view model contract unless a test requires it.
- Do not load the entire conversation table in one query.
- Do not modify `web/`, `android/`, or `contracts/`.

## Deliverables

- `conversations/view.rs` with:
  - a `HistoryWindow` Slint component: grouped list, active row, draft badge,
    archived toggle, load-more, new chat, rename field, delete with undo,
    search field and bounded results;
  - `sync_window` that maps `HistoryState` and search state to Slint models;
  - `HistoryController` that owns the async history and search services and a
    runtime handle, exposes the window, and wires callbacks.
- Async behavior:
  - load, refresh, load-more, search, new chat, rename, archive, delete/undo on
    the runtime;
  - results marshalled to the Slint event loop;
  - no blocking storage calls on the Slint thread.
- Exports from `conversations/mod.rs` and `lib.rs`.
- Component and controller tests with a temporary database.

## Implementation steps

1. Define the Slint component and its properties/callbacks.
2. Write `sync_window` for groups, rows, drafts, pending delete, status, and
   search.
3. Build `HistoryController` over `ConversationHistory`,
   `ConversationSearchService`, and a runtime handle.
4. Wire new chat, selection, rename, archive toggle, load-more, search, delete,
   and undo.
5. Keep delete undo timing consistent with `DEFAULT_UNDO_WINDOW`.
6. Marshal async results through `slint::Weak::upgrade_in_event_loop` or a
   short poll timer.
7. Ensure empty, loading, and error states render.
8. Add tests for grouping, search, rename, archive, delete/undo, drafts, and
   navigation.
9. Export the controller and window from the crate root.

## Completion record

- Status: Complete
- Commands and results:
  - `cd rust && cargo fmt --all --check` — clean.
  - `cd rust && cargo clippy -p chatui-ui --all-targets -- -D warnings` — clean.
  - `cd rust && cargo nextest run -p chatui-ui` — 383 passed, 0 failed.
- Decisions:
  - Added `conversations/view.rs` with `HistoryWindow`, `sync_window`,
    `HistoryViewState`, `HistoryRuntime`, and `HistoryController`.
  - The Slint model is a flat `[HistoryRow]` with explicit group-header rows.
    This preserves `group_conversations` order and avoids nested Slint struct
    arrays while still rendering a grouped sidebar.
  - Async results are marshalled through a `std::sync::mpsc` channel and applied
    by `HistoryController::poll` on the Slint thread. The desktop calls `poll`
    from a short timer; tests call it directly. This avoids relying on
    `upgrade_in_event_loop`, which does not run under the testing backend's
    `init_no_event_loop`.
  - `HistoryRuntime` is a small `spawn` trait rather than a concrete
    `tokio::runtime::Handle`, so `chatui-ui` does not need the `tokio` `rt`
    feature and the desktop can adapt its existing `ServiceRuntime`.
  - Delete undo uses the configured `HistoryConfig::undo_window` (default
    `DEFAULT_UNDO_WINDOW`, 5 seconds). The commit task sleeps for the window
    plus 10 ms before calling `commit_delete`, so a slightly early wake-up
    cannot leave a delete uncommitted.
  - Search is triggered explicitly by the Search button or Enter, not on every
    keystroke, to keep the bounded FTS query off the typing path.

## Handoff notes

- `HistoryController` constructor:
  `HistoryController::new(history: ConversationHistory, search: ConversationSearchService, runtime: Arc<dyn HistoryRuntime>) -> Result<Self, slint::PlatformError>`.
  It creates the window, wires callbacks, and starts the first active-page load.
- Public methods the desktop binary calls:
  - `window() -> &HistoryWindow` for the shell `history-factory`.
  - `state() -> Ref<HistoryViewState>` for read-only inspection.
  - `sync()` to push the current state into the window.
  - `poll()` to drain async results; call it from a short Slint timer
    (50-100 ms is sufficient).
  - `load(archived: bool)` and `refresh()` to reload.
  - `set_on_open_conversation(handler: impl Fn(&str) + 'static)` to navigate to
    the chat route after selection or new chat.
- Runtime assumptions for `M3.6-06.1`:
  - Implement `HistoryRuntime` over the shared `ServiceRuntime` runtime. The
    trait method is
    `fn spawn(&self, future: Pin<Box<dyn Future<Output = ()> + Send + 'static>>)`.
    A thin wrapper around `tokio::runtime::Handle::spawn` is enough; do not
    create a second runtime.
  - The runtime must have the `time` driver enabled because delete commit uses
    `tokio::time::sleep`.
  - The controller never blocks on storage. `poll` only drains the channel and
    updates Slint properties, so it is safe on the Slint thread.
  - The shell factory must return the controller's own handle, for example
    `slint::ComponentFactory::new(move |_| Some(controller.window().clone_strong()))`.
    Keep the controller alive for the lifetime of the shell.
- The view exposes `HistoryRow` and `SearchRow` Slint structs. Group headers are
  rows with `is-header: true`; conversation rows carry `id`, `active`, `draft`,
  `pinned`, and `archived`.
- Tests live in `conversations/view.rs` and use a temporary file-backed SQLite
  database (`tempfile::tempdir()` + `open_database`) or `open_in_memory` for the
  error paths. They cover grouping, new chat, rename, archive, delete/undo,
  delete commit, search ready/empty/error, drafts, load-more, navigation,
  loading/empty/error states, and direct `sync_window` mapping.
