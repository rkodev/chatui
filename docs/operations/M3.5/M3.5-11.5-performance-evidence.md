# M3.5-11.5 - Performance, cold start, and installer-size evidence

- Milestone: M3.5
- Status: Not started
- Order: 45
- Depends on: M3.5-11.2, M3.5-11.4
- Parallel-safe: none; follows CI evidence
- Owns: `docs/operations/M3.5/performance.md`, `docs/operations/M3.5/M3.5-verification.md` (performance section), measurement scripts if needed
- Read first: [M3.5 plan](../M3.5-rust-desktop-implementation-plan.md) sections 3.7 and 6; spec sections 10.9, 11.9

## Goal

Measure and record cold start, installer size, and build time with a reproducible method, and document any miss against the milestone budgets.

## Preconditions

- Packaging and CI artifacts exist.
- Do not claim a measurement that was not run.
- Do not use a debug build to claim release performance.
- Do not modify `web/`, `android/`, or `contracts/`.

## Deliverables

- `docs/operations/M3.5/performance.md` with:
  - machine and OS specification;
  - build type and artifact version;
  - cold-start method and run count;
  - cold-start median and range;
  - installer size per OS;
  - build time per OS if available;
  - comparison against the under-1.5-second cold-start target and under-40-MB installer target;
  - documented misses and causes.
- Measurement scripts or commands where practical.
- Performance evidence in `M3.5-verification.md`.

## Implementation steps

1. Read spec sections 10.9 and 11.9.
2. Define a cold-start method. For example: launch the packaged app with a clean process state, measure time to the shell being interactive, and run at least five iterations.
3. Record the machine, OS version, CPU, RAM, and disk type.
4. Measure the release artifact, not the debug build.
5. Record the median and range. Do not report only the best run.
6. Measure installer size for each available OS artifact. Record the compressed and installed sizes if they differ.
7. Record build time if available.
8. Compare against the budgets and document any miss with the likely cause.
9. Add a measurement script or exact commands to the performance document.
10. Record the evidence in `M3.5-verification.md`.

## Acceptance criteria

- [ ] The measurement method is reproducible.
- [ ] Machine and OS details are recorded.
- [ ] Cold-start median and range are recorded from at least five runs.
- [ ] Installer size per available OS is recorded.
- [ ] Build time is recorded where available.
- [ ] Results are compared against the budgets.
- [ ] Misses are documented with a cause.
- [ ] Only release artifacts are used for claims.
- [ ] Performance evidence is in the verification report.

## Verification

```bash
make rust-build
make rust-package
ls -lh rust/dist/
```

Plus the documented cold-start procedure and results.

## Out of scope

- Optimizing the app beyond the profile and feature-gating work.
- Web/Android performance.
- Updater correctness (M3.5-11.3).
