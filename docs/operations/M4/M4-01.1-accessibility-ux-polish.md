# M4-01.1 - Accessibility and UX polish across enabled clients

- Milestone: M4
- Status: Complete
- Order: 2
- Depends on: M4-00.1
- Parallel-safe: yes, with `M4-02.1` (coordinate on `web/src/app` files)
- Owns: web accessibility/UX tests and small fixes under `web/src/styles`, `web/src/ui`, `web/src/features`, `web/e2e`; Android semantics/touch-target fixes under `android/feature` and `android/app`; Rust UI accessibility fixes under `rust/crates/chatui-ui` only if shipping; `docs/operations/M4/evidence/accessibility/`
- Read first: [M4 milestone](../../milestones/M4-polish-and-release.md) workstream 1; spec sections 3.7-3.8, 11.8, 11.9, 11.10, 11.11, and 11.12

## Goal

Verify and polish accessibility and UX on every enabled client using WCAG 2.2 AA expectations, responsive breakpoints, standard states, and keyboard shortcuts. Fix only small, test-covered defects. Do not redesign screens or add features.

## Preconditions

- `M4-00.1` is `Complete` and states which clients are enabled.
- Existing M3 Android accessibility work (semantics, 48 dp targets, TalkBack, reduced motion) is the baseline, not repeated implementation.
- Do not add localization or translations.
- Do not introduce new feature behavior to satisfy polish.

## Deliverables

- Web:
  - axe run on main routes (`/`, chat, conversations, providers, settings, data) with no serious or critical issues.
  - Keyboard-only navigation pass across all primary flows, including dialogs/sheets and focus return.
  - Visible focus styles, 4.5:1 body-text contrast, accessible names for icon-only buttons, and semantic live regions for stream start/complete/error only.
  - Reduced-motion and scalable-text verification; table and code-block overflow behavior.
  - Responsive checks at the section 11.9 breakpoints: mobile drawer, compact desktop, persistent sidebar, optional params panel; message column max 48 rem.
  - Empty, loading, error, and offline states use section 11.8 copy and behavior; no raw JSON is the primary error.
  - Keyboard shortcuts from section 11.10 on web.
- Android:
  - Material 3 semantics, content descriptions, 48 dp targets, TalkBack pass, predictive back ordering, reduced motion, and optional dynamic color recorded as optional/not implemented.
- Rust (only if `shipping`):
  - Keyboard-first navigation, focus rings, high-DPI/scaling, and screen-reader bridge smoke tests on tier-1 desktop OSes.
- Evidence files under `docs/operations/M4/evidence/accessibility/` with command output, axe JSON/HTML, and manual check notes.
- Small fixes with tests for each concrete issue found.

## Implementation steps

1. Read the web styles/theme, route screens, dialogs, and existing Playwright/axe setup; read the Android semantics/test tags; read `rust/crates/chatui-ui` accessibility tests only if shipping.
2. Web axe:
   - Add or extend a Playwright test that visits each main route and runs `@axe-core/playwright`.
   - Fail on `serious` and `critical` impact. Record `moderate`/`minor` findings separately.
   - Save the axe JSON/HTML output for each route.
3. Web keyboard and focus:
   - Tab through onboarding, chat send/stop, model picker, conversations, providers, settings, and data controls.
   - Verify dialogs/sheets trap focus, close on Escape where expected, and return focus to the trigger.
   - Fix missing visible focus or focus order defects in shared primitives, not per screen.
4. Web semantics and contrast:
   - Confirm icon-only buttons have accessible names.
   - Confirm streaming live regions announce start/complete/error only, not every token.
   - Check body-text contrast with the theme tokens; adjust tokens only if a test proves a violation.
5. Web responsive and states:
   - Check the breakpoints from section 11.9 at representative widths.
   - Confirm the message column max is 48 rem.
   - Walk empty, loading, error, and offline states; confirm the copy/behavior and that errors are human-readable, not raw JSON.
   - Verify tables and code blocks scroll/overflow without breaking layout.
6. Web shortcuts:
   - Implement/verify every shortcut in spec section 11.10, and confirm shortcuts do not fire while typing in inputs unless specified.
7. Android:
   - Re-run the M3 accessibility checks and fix only regressions or concrete gaps. Confirm 48 dp targets, TalkBack flow, predictive back, and reduced motion.
   - Record dynamic color as optional/not implemented unless the release decision says otherwise.
8. Rust (only if shipping):
   - Run keyboard navigation, focus ring, DPI/scaling, and screen-reader bridge smoke checks. Fix small issues with tests; record OS limitations honestly.
9. Record all evidence and handoff notes.
