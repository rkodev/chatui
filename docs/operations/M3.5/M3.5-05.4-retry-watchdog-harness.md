## Goal

Implement the shared retry, inactivity-watchdog, and cancellation behavior and create the network mock harness later provider tasks will reuse.

## Preconditions

- The HTTP client and SSE parser exist.
- Do not retry after partial output.
- Do not add provider-specific logic here.
- Do not modify `web/`, `android/`, or `contracts/`.

## Deliverables

- Retry policy:
  - at most 3 attempts including the first;
  - exponential backoff with jitter;
  - base 800 ms, cap 8 seconds;
  - `Retry-After` honored when present;
  - no retry after text or reasoning has been emitted.
- Cancellation via `tokio_util::sync::CancellationToken` or equivalent.
- A 120-second inactivity watchdog that cancels a stalled stream with a retryable `timeout` error.
- A reusable `wiremock` or `httpmock` harness for:
  - SSE chunking;
  - keep-alives;
  - mid-stream errors;
  - cancellation;
  - `Retry-After`;
  - connection and timeout failures.
- Tests for retry counts, jitter bounds, abort-aware sleep, watchdog firing, and no-retry-after-partial.

## Implementation steps

1. Read `web/src/providers/retry.ts` and spec section 7.9.
2. Implement `compute_retry_delay(attempt, policy)` with a deterministic jitter injection point for tests.
3. Implement `retry_delay_for(retry_after, attempt, policy)` where provider `Retry-After` wins.
4. Implement an abort-aware sleep using `tokio::select!` and the cancellation token.
5. Implement a retry loop helper that accepts a closure or adapter call, tracks whether text/reasoning was emitted, and stops retrying when partial output exists.
6. Implement the inactivity watchdog around the response stream. Reset it on every received chunk. On 120 seconds of inactivity, cancel the request and return a retryable `timeout`.
7. Build the network mock harness under `tests/network/`. Keep it reusable by later adapter tests.
8. Add tests:
   - 3 attempts max;
   - jitter within the documented range;
   - `Retry-After` overrides local backoff;
   - cancellation interrupts sleep and stream reads;
   - no retry after partial output;
   - watchdog fires with a retryable timeout.
9. Document the harness API in `docs/operations/M3.5/conformance.md` or a small provider test note.

## Handoff notes

- Retry API: `RetryPolicy` defaults to 3 attempts, 800 ms base, 8 s cap, and
  25% positive jitter. `compute_retry_delay` uses a time-seeded jitter source;
  `compute_retry_delay_with_jitter` is the deterministic test injection point.
  `retry_delay_for` lets a provider `Retry-After` value win, and
  `retry_after_from_header` parses whole-second header values.
- Retry loop: `retry_with(policy, cancel, attempt)` calls the closure with the
  1-based attempt number. The closure returns `AttemptOutcome<T>`; a failure
  carries `AttemptFailure` with the normalized error, `PartialOutput`, and an
  optional `Retry-After`. The loop stops on partial output, a non-retryable
  error, the attempt limit, or cancellation. `sleep` races the cancellation
  token so a stop does not wait for the backoff.
- Cancellation: `cancel::Cancellation` wraps `CancellationToken` and exposes
  `token`, `cancel`, `is_cancelled`, `cancelled`, and `child`. The token is
  re-exported as `chatui_providers::CancellationToken`.
- Watchdog: `InactivityWatchdog::with_default_timeout` uses 120 seconds. Call
  `reset()` on every received chunk and race `expired()` against the next
  stream read. On expiry it cancels the shared token and sets `timed_out()`;
  the caller returns `NetworkError::timeout()`, which is retryable. Tests use
  short timeouts (20-50 ms) to avoid a 120-second wait.
- Harness: `tests/network/harness.rs` provides `NetworkHarness` (wiremock) and
  `ChunkedSseServer` (raw TCP chunked SSE). `wiremock` buffers response bodies,
  so the raw server is used for real chunk boundaries, abrupt mid-stream
  failures, and cancellation while a stream is open. Provider tests can include
  it with `#[path = "network/harness.rs"] mod harness;`. The API is documented
  in `docs/operations/M3.5/conformance.md`.
- Test names: retry unit tests cover `retry_stops_after_three_attempts`,
  `jitter_stays_within_documented_bounds`, `retry_after_overrides_local_backoff`,
  `cancellation_interrupts_sleep`, `no_retry_after_partial_output`, and
  `watchdog_fires_with_retryable_timeout`. The `network` target covers
  `harness_serves_chunked_sse`, `harness_serves_keepalives`,
  `harness_reports_mid_stream_error`, `harness_honors_retry_after`,
  `harness_simulates_connection_failure`, `harness_simulates_timeout`,
  `cancellation_interrupts_stream_reads`, `watchdog_cancels_stalled_stream`,
  `retry_attempts_three_times_before_giving_up`,
  `retry_does_not_repeat_after_partial_output`, and
  `retry_loop_uses_retry_after_from_failure`.
- Timing flakiness mitigation: tests use millisecond-scale timeouts and
  `tokio::time::timeout` guards around every wait. The only elapsed-time
  assertion uses a 50 ms `Retry-After` with a 40 ms lower bound.
- Verification: `cargo fmt --all --check` passed;
  `cargo clippy -p chatui-providers --all-targets -- -D warnings` passed;
  `cargo nextest run -p chatui-providers` passed 113/113 tests.
- No provider-specific adapter logic was added. `Cargo.toml` gained the
