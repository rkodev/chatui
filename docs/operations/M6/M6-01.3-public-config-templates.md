# M6-01.3 - Public config templates and feature-flag handling

- Milestone: M6
- Status: Not started
- Order: 3
- Depends on: M6-01.1
- Parallel-safe: yes, with `M6-01.2`
- Owns: `deploy/roksky/templates/config.full.json`, `deploy/roksky/templates/config.minimal.json`, `deploy/roksky/templates/README.md`, `web/src/app/config.ts`, `web/src/app/config.test.ts`, `web/public/config.json`
- Read first: [M6 plan](../M6-managed-hosting-implementation-plan.md) sections 2.1, 3.1 (T-02, T-03, T-04, T-08, T-11), and 4; `web/src/app/config.ts`; `web/src/app/config.test.ts`; `web/public/config.json`; spec section 8.9

## Goal

Provide validated public tenant config templates that contain only fields the app
actually consumes, and resolve the optional feature-flag requirement without
weakening the strict config schema.

## Preconditions

- `M6-01.1` is `Complete` and `DEC-M6-06`, `DEC-M6-08`, and `DEC-M6-13` are
  recorded.
- Do not add secrets, private endpoints, storage credentials, provider keys, or
  server-only values.
- Do not invent config fields the web app does not read.

## Deliverables

- `deploy/roksky/templates/config.full.json`:
  - A complete valid config using all currently supported public fields.
  - Example app name, theme, enabled preset list, custom-provider allowance,
    OpenRouter attribution, docs URL, and `telemetry: false`.
  - Example origin `https://chat.example.com`, documented as replaceable.
- `deploy/roksky/templates/config.minimal.json`:
  - A valid config with the required fields and the smallest supported preset
    set. OpenRouter must remain the default and included.
- `deploy/roksky/templates/README.md`:
  - Explain what operators replace: app name, default theme, presets, custom
    provider allowance, attribution origin/title, docs URL, and telemetry.
  - State that the file is public, served no-cache, and must contain no secrets.
  - Explain that the same file must work for a self-hosted deployment.
- Feature flags, following `DEC-M6-06`:
  - If no flags are exposed in M6: do not add a flag field. Document that the
    schema stays strict and no feature flags are available.
  - If flags are exposed: add an optional, typed allowlist object to
    `web/src/app/config.ts`, update the config and runtime consumers, update
    `web/public/config.json` only if a default is required, and add tests for
    accepted and rejected flag keys.
- Tests:
  - Parse both templates with `configSchema` and run `validateConfigPresets`.
  - Assert each template has `telemetry: false`.
  - Assert each template has a valid `openRouter.attributionOrigin`.
  - Assert unknown fields still fail.
  - Add flag tests only if flags are implemented.

## Implementation steps

1. Read the config schema, default config, and config tests.
2. Create the full template from the current known-good public fields.
3. Create the minimal template with OpenRouter and only the required fields.
4. Add template README guidance, including replacing the example origin with the
   real tenant origin, including a custom domain.
5. Apply the feature-flag decision. Keep the schema strict if flags are not
   exposed.
6. Add tests that read the templates from the repository. When tests run from
   `web/`, resolve templates as `../deploy/roksky/templates/<name>`.
7. Run the web config tests and full web gates if config code changed.

## Acceptance criteria

- [ ] Full and minimal config templates exist.
- [ ] Both templates parse with the strict schema and pass preset validation.
- [ ] Both templates contain only public fields and no secret-shaped values.
- [ ] Both templates use `telemetry: false`.
- [ ] The OpenRouter attribution origin is documented as the exact tenant
      origin.
- [ ] The feature-flag decision is implemented or explicitly documented as
      "none".
- [ ] PWA install-name/icon branding limitation is documented.
- [ ] Tests cover both templates.
- [ ] No secret, real key, passphrase, or private endpoint is committed.

## Verification

```bash
make web-typecheck
cd web && pnpm exec vitest run src/app/config.test.ts
make web-lint && make web-test
```

If feature flags are added, also run the full web gate.

## Out of scope

- Tenant manifest schema (`M6-01.2`).
- The tenant config validator CLI and tenant configuration docs (`M6-01.4`).
- Branded PWA icon generation or a separate tenant build pipeline.
