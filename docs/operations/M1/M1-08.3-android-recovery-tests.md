## Goal

Make interrupted Android streams recover safely after process death and prove conversation persistence.

## Preconditions

- Conversation list and navigation work.
- Repositories expose the streaming-status query and update methods.

## Deliverables

- Startup recovery that finds messages with status `streaming`, marks them `cancelled`, preserves partial parts, and records an interruption explanation.
- Recovery invoked once per app start before chat interaction.
- UI explanation for interrupted messages.
- Tests for process death/reload, partial text preservation, and no duplicate messages.
- Repository/DAO persistence tests for conversations and messages.

## Implementation steps

1. Read the repository recovery API and application startup path.
2. Implement a recovery service with an injectable clock and sender.
3. Invoke recovery from the application-scoped startup path or a dedicated initializer.
4. Ensure recovery is idempotent when run twice.
5. Show an interrupted state in the chat message item when it lands.
6. Add tests using a fake/in-memory database.
7. Add a test that simulates a streaming row at startup and asserts partial content.
8. Run the Android gate.

## Acceptance criteria

- [ ] Streaming messages become cancelled on startup.
- [ ] Partial content is preserved.
- [ ] Recovery is idempotent.
- [ ] The user sees an interruption explanation.
- [ ] Conversation persistence survives reload.
- [ ] No duplicate messages are created.
- [ ] Android gate passes.

## Verification

```bash
make android-lint && make android-test && make android-assemble
```

## Out of scope

- Chat runner.
- Full Compose screenshot suite.
- Background services or foreground streaming.
