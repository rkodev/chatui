## Goal

Make `contracts/` the only source of provider presets, schemas, and export shapes, with strict Rust types and no duplicated provider metadata.

## Preconditions

- M3.5-02.1 is complete.
- Do not edit `contracts/` or copy its provider presets into Rust source.
- Do not add network or UI dependencies to `chatui-contracts`.
- Do not modify `web/` or `android/`.

## Deliverables

- `chatui-contracts` loads `contracts/providers.json` through `include_str!` or generated constants.
- Serde types for provider presets, auth, key validation, model discovery, attribution, and browser CORS.
- Schema loading for all five `contracts/schema/*.json` files.
- `ChatExport`, `ExportAttachment`, and export settings types matching the export schema.
- A runtime `AppConfig` for app name and public origin used by attribution headers.
- Tests proving the preset count, required presets, schema validity, unknown-field behavior, and export round-trip.
- A documented contract evolution policy for strict export fields and tolerant catalog fields.

## Implementation steps

1. Read `contracts/providers.json`, all `contracts/schema/*.json`, `contracts/fixtures/expected/chatui-export.json`, and `web/src/providers/registry.ts`.
2. Add `serde`, `serde_json`, `jsonschema`, and any small URL helper needed. Keep the dependency set minimal.
3. Define `ProviderPreset` and nested types for `auth`, `keyValidation`, `modelDiscovery`, `defaultHeaders`, `attributionHeaders`, `browserCors`, `docsUrl`, `defaultModelId`, `default`, `reference`, and `required`.
4. Load presets with `include_str!("../../../contracts/providers.json")` or a build script. Parse into `Vec<ProviderPreset>`. Do not hardcode a second list.
5. Validate:
   - the array is non-empty;
   - preset IDs are unique;
   - exactly one preset has `default = true` and `reference = true` (OpenRouter);
   - required presets are present;
   - `custom` is present as the user-defined provider preset.
6. Load every schema file. Provide a helper that compiles schemas once and validates a `serde_json::Value`.
7. Define `ChatExport` and `ExportAttachment` exactly as the export schema requires. Keep `format = "chatui.export"`, integer `formatVersion`, RFC 3339 timestamps, and the semantic app version string.
8. Add `AppConfig { name: String, origin: String }` or equivalent. Keep attribution values free of personal data. Do not load `.env` files or secrets.
9. Test deserialization of every provider preset and every schema file.
10. Test that `contracts/fixtures/expected/chatui-export.json` deserializes into `ChatExport` and round-trips without changing field names.
11. Add a test proving unknown provider or model catalog fields are ignored where the spec allows tolerance, while unknown export fields are rejected.
12. Document the contract evolution policy in the crate docs or `docs/operations/M3.5/tooling.md`.

### Result (2026-11-07)

Implemented `chatui-contracts` with four modules:

- `providers`: `ProviderPreset`, `ProviderAuth`, `KeyValidation`,
  `ModelDiscovery`, `ProviderCatalog`, and `ProviderCatalogError`. The catalog
  is embedded with `include_str!("../../../../contracts/providers.json")` and
  validated for non-empty content, unique IDs, exactly one default and
  reference preset (OpenRouter), required presets, and the `custom` preset.
  `provider_catalog()` and `provider_presets()` load it once through
  `OnceLock`.
- `schema`: `SchemaName` for all five `contracts/schema/*.json` files,
  `SchemaSet` that parses and compiles every schema once, and
  `validate_schema`/`schemas` helpers. Format validation is enabled.
- `export`: `ChatExport`, `ExportAttachment`, and `ExportSettings` (an alias of
  the shared domain `Settings`). `ChatExport::new` sets
  `format = "chatui.export"` and `formatVersion = 1`; `ChatExport::validate`
  applies the full export schema.
- `config`: `AppConfig { name, origin }` with HTTP(S) origin validation and
  attribution resolution for the `app.name` and `app.origin` placeholders.

Unknown-field policy: provider presets and model catalog records ignore unknown
fields (tolerant catalogs), while `ChatExport` and `ExportAttachment` use
`deny_unknown_fields` and the export schema rejects unknown nested fields
(strict export). The policy is documented in the crate-level docs in
`rust/crates/chatui-contracts/src/lib.rs`.

Contract ambiguity: `providers.json` has no version field, so additive preset
fields are treated as safe and removals/renames require a schema change and a
`contractVersion` bump. `ExportSettings` reuses `chatui_domain::Settings`
rather than defining a second shape.
