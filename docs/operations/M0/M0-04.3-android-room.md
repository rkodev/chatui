# M0-04.3 - Room schema, DAOs, FTS, migrations

- Status: Complete
- Parent task: M0-04
- Order: 16
- Depends on: M0-04.2
- Parallel-safe: yes, with M0-02.3
- Owns: `android/core/database/**`, its module build file, `android/core/database/schemas/**`, corresponding tests
- Read first: [M0 plan](../M0-foundations-implementation-plan.md) sections 3.3 and 4.5; spec sections 6, 9.5, 15.1

## Goal

Implement the Room database, entities, DAOs, full-text search, schema export, and migration tests. No UI may access Room directly.

## Preconditions

- Domain models exist.
- Room, KSP (or kapt), Robolectric, and AndroidX test dependencies are configured.

## Deliverables

- Room entities matching spec 9.5:
  - `ConversationEntity`
  - `MessageEntity`
  - `AttachmentEntity`
  - `ProviderEntity`
  - `ModelEntity`
  - `SecretEntity`
  - `BackupConfigEntity`
  - `SyncQueueEntity`
- Indexes:
  - `messages(conversationId, sequence)`
  - unique `models(providerId, remoteId)`
  - `attachments(sha256)`
- DAOs for every entity with focused queries:
  - conversation list/update/delete
  - last 50 messages plus older-page pagination
  - attachment metadata
  - provider and model CRUD
  - ciphertext-only secret CRUD
  - backup config and sync queue placeholders
- `messages_fts` FTS table over message text using FTS4 unless FTS5 is proven reliable at minSdk 26. Keep it synchronized through Room triggers or repository writes, and prove search finds inserted text.
- `ChatUiDatabase` version 1 with `exportSchema = true` and a committed schema JSON.
- Migrations:
  - every change gets a Room migration
  - `MigrationTestHelper` test for the current migration path
  - destructive migration is not enabled in release builds
  - export/import uses a separate format version, not the Room version
- Tests that run under `testDebugUnitTest`, using Robolectric where needed:
  - in-memory DAO tests
  - migration test using `MigrationTestHelper`
  - FTS search test
  - unique model constraint test
  - pagination test

## Implementation steps

1. Add Room KSP configuration and the database module dependencies.
2. Create entities and DAOs.
3. Add the FTS table and synchronization mechanism.
4. Add database version 1 and schema export.
5. Add migration test infrastructure even if version 1 is the only version, so future migrations are trivial to add.
6. Write DAO, FTS, uniqueness, and pagination tests.
7. Run the database module tests and the app build.

## Handoff notes

Completion record (2026-11-02):

- Schema version: `CHATUI_DATABASE_VERSION = 1` in `DatabaseVersion.kt`. Export/import uses the independent `CHATUI_EXPORT_FORMAT_VERSION = 1`; the two constants are deliberately separate.
- Entities: `ConversationEntity`, `MessageEntity`, `AttachmentEntity`, `ProviderEntity`, `ModelEntity`, `SecretEntity`, `BackupConfigEntity`, `SyncQueueEntity`, and the FTS entity `MessageFtsEntity`. Fields follow spec 9.5; structured values are JSON strings and timestamps are ISO 8601 UTC strings.
- Indexes: `messages(conversationId, sequence)`, unique `models(providerId, remoteId)`, and `attachments(sha256)` are present in the exported schema. Additional conversation/provider/sync indexes support list and cleanup queries.
- FTS: FTS4 (`@Fts4(notIndexed = ["messageId"])`) on `messages_fts(messageId, text)`. FTS4 was chosen for minSdk 26 compatibility; FTS5 was not used. Synchronization is performed by `MessageDao.insert/update/delete`, which write the message row and FTS row in one `@Transaction`. `ConversationDao.deleteWithChildren` also removes FTS rows. No SQLite JSON1 dependency or trigger is required.
- Pagination: `MessageDao.DEFAULT_PAGE_SIZE = 50`. `latest()` returns the newest 50; `older(conversationId, beforeSequence)` returns the next older page using the oldest sequence as an exclusive cursor.
- Migrations: `MIGRATIONS` is an empty array for version 1. `MigrationTest` uses `MigrationTestHelper` with the committed schema export and validates version 1 under Robolectric. Future migrations should add a `Migration` to `MIGRATIONS` and a create-old/insert/run/assert test.
- Destructive migration: `ChatUiDatabase.builder()` never calls `fallbackToDestructiveMigration()`. `DestructiveMigrationGuardTest` bumps `user_version` to 2 and asserts opening the database throws `IllegalStateException` instead of recreating it.
- Schema export: `android/core/database/schemas/dev.chatui.core.database.ChatUiDatabase/1.json` is committed. The module adds `schemas` as a test assets source dir so `MigrationTestHelper` can read it.
- Tests: 44 tests across DAO, FTS, uniqueness, pagination, migration, and destructive-migration guard suites. All run under `testDebugUnitTest` with Robolectric SDK 34.
- Verification: `cd android && ./gradlew :core:database:testDebugUnitTest` passed (44 tests, 0 failures); `cd android && ./gradlew :app:assembleDebug` passed; `find android/core/database/schemas -type f` printed `android/core/database/schemas/dev.chatui.core.database.ChatUiDatabase/1.json`.
- Environment note: Maven Central returned HTTP 429 while resolving `org.robolectric:nativeruntime-dist-compat:1.0.19`. The artifact was fetched from the Google Maven Central mirror into a local file repository and exposed through a local Gradle init script; no repository or build configuration in the project was changed for this workaround.
- Decision: `BackupConfigEntity` and `SyncQueueEntity` are schema placeholders only. Their fields mirror spec 6.2 and the web IndexedDB placeholder shape; no backup or sync behavior is implemented.
- Decision: `SecretEntity` stores only `ciphertext`; there is no plaintext column. Encryption/decryption remains in `core:datastore` (M0-04.4).
