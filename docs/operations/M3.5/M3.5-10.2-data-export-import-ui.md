## Handoff notes

### Data UI states

- `DataSection` covers usage, export, import, clear, stored keys, and backup.
  `DataNavigation` starts on usage and is independent of the settings route.
- `DataViewModel` owns usage, conversation options, export format, attachment
  opt-in, import mode, replace confirmation, archive text, clear phrase,
  stored-key summaries, pending key removal, busy operation, error copy, status,
  and the last export/import/clear summaries.
- `DataController` loads usage, conversations, and keys on construction and
  after import, clear, and key removal. `reload` clears the previous error
  before refreshing.
- The Slint `DataWindow` renders every section, the plaintext warning, the
  include/exclude lists, progress text, result summaries, and the backup link.

### Export options

- Full export is always `chatui.export` JSON. Per-conversation export supports
  JSON and Markdown.
- Attachment bytes default to excluded. The checkbox opts in for JSON exports
  only; Markdown never includes bytes.
- The plaintext warning is always visible on the export section.
- `EXPORT_INCLUDES` lists conversations, messages, providers, models, and
  settings. `EXPORT_EXCLUDES` lists secrets, attachment bytes unless opted in,
  and backup credentials.
- `MemoryDataService::export_all` builds a real `ChatExport`, validates it, and
  serializes it with `chatui_storage::encode_export`. Tests parse the artifact
  and assert every entity kind is present and the secret value is absent.

### Import and replace behavior

- `ImportMode` defaults to `Merge`. Replace requires the explicit
  `replace_confirmed` checkbox; `DataViewModel::import_request` rejects replace
  without it.
- `MemoryDataService::import_text` validates with
  `chatui_storage::validate_import_archive` before touching in-memory data, so
  invalid JSON or schema violations leave local data unchanged.
- Merge upserts archive records by ID and keeps local records that are not in
  the archive. Replace clears conversations, messages, attachments, providers,
  models, and settings first, then writes the archive. Secrets are untouched.
- The UI accepts pasted archive JSON because native file dialogs are M3.5-10.3.

### Clear and per-key deletion

- Clear-all requires the exact phrase `DELETE ALL DATA`. The button is disabled
  until the phrase matches, and `clear_request` rejects anything else.
- Clear-all removes conversations, messages, attachments, providers, models,
  and stored keys, and keeps appearance/chat settings.
- Per-key removal uses a two-step click: the first click sets
  `pending_key_removal`, the second calls the service. The service removes the
  secret and the cached `metadata.key` label while keeping the provider record
  and its models.

### Tests

- `data::route::tests::*` cover section labels, IDs, indices, and navigation.
- `data::state::tests::*` cover usage rows/total, export defaults, Markdown
  opt-out, import merge/replace confirmation, clear phrase, per-key removal,
  conversation selection, backup copy, export documentation, byte formatting,
  and non-secret key metadata.
- `data::service::tests::*` cover usage counts, export entity coverage and
  secret exclusion, attachment-byte opt-in, JSON/Markdown conversation export,
  merge/replace import, invalid import without data loss, clear-all, per-key
  deletion, and missing-conversation export.
- `data::view::tests::*` cover the Slint window, export/import/clear/key
  callbacks, section navigation, and the backup handler.
- `data::tests::*` cover the controller end to end: usage refresh, export
  options, JSON/Markdown export, merge/replace import, invalid import, typed
  clear confirmation, per-key deletion, and the backup placeholder.

- `rust/crates/chatui-ui/src/lib.rs` declares `pub mod data` and re-exports the
  public data types. No `web/`, `android/`, or `contracts/` files were changed.
