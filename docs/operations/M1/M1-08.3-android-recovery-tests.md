## Handoff notes

### Recovery trigger

`AppStartup` is an application-scoped singleton invoked from `MainActivity`
before `ChatUiApp` is composed. It runs `StreamingRecoveryService` once per
process and waits for both recovery and persisted settings before rendering the
shell, so chat interaction cannot start against a stale `streaming` row. A
recovery failure is logged (`ChatUiStartup`) and does not block the shell; the
next process start retries because the in-memory guard is per process.

### Explanation copy

`INTERRUPTION_NOTE` is
"The app closed before this response finished. Partial content is preserved."
Recovery sets `status = cancelled`, `finishReason = cancelled`, and a
`ChatError(code = cancelled, message = INTERRUPTION_NOTE)` while preserving the
message id, sequence, parts, usage, and timestamps. `InterruptedMessageNotice`
in `feature:chat` renders that note for recovered messages; M1-09 mounts it
under the assistant message item. It renders nothing for user cancellations or
other cancelled errors.

### Idempotency mechanism

Recovery scans only rows whose status is `streaming` and updates each row to
`cancelled`. A second pass finds no streaming rows, so it is a no-op. The
startup guard adds a `@Volatile` fast path plus a `Mutex`-protected critical
section so concurrent callers run recovery once. Re-appending an existing
message id updates the row instead of inserting a duplicate, which the
file-backed persistence test asserts across a database reopen.

### Scope

No chat runner, composer, background service, foreground streaming, or Compose
screenshot suite was added. The chat message item itself remains M1-09; this
task supplies the recovery contract and the notice composable it will mount.
