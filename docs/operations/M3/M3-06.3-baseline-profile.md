## Goal

Generate and install a baseline profile, then measure cold start with a documented method.

## Preconditions

- M3-06.1 minified release build works.
- M3-03.4 and M3-04.5 are complete so the profiled app includes the final shell and startup cleanup.
- Do not fabricate a `baseline-prof.txt` or claim a start time without a run.

## Deliverables

- Baseline-profile plugin/module configured for the app.
- A generation task that produces a real profile.
- `profileinstaller` or the equivalent dependency in the app.
- A startup benchmark or documented `am start -W` procedure.
- Cold-start measurements with device, API, build type, run count, and median.
- Golden profile source committed if the project convention stores it.

## Implementation steps

1. Read `android/app/build.gradle.kts`, `settings.gradle.kts`, the version catalog, and the app startup path.
2. Add `androidx.profileinstaller` to the app.
3. Add the baseline-profile plugin and a `:baselineprofile` module using the current compatible plugin version from the version catalog:
   - target the `:app` release-like variant;
   - use `BaselineProfileRule` to exercise app startup and key screens;
   - generate the profile on the selected device/emulator.
4. Verify the generated profile is non-empty and contains app package entries.
5. Measure startup:
   - install the release APK with the profile installed;
   - run at least five cold starts with `adb shell am start -W -n dev.chatui/.MainActivity`;
   - record each total time and the median;
   - note the device, API level, build type, and whether the profile was installed.
6. If the plugin or device is unavailable, record a precise blocker. Do not mark the task complete.
7. Record the profile path, generation command, and measurement table in the handoff and in `M3-verification.md`.

## Acceptance criteria

- [x] A real baseline profile is generated and non-empty.
- [x] The app includes the profile installer.
- [x] Startup is measured at least five times on a recorded device/API.
- [x] The median is recorded.
- [x] The startup budget is met or the miss is documented with a cause.
- [x] No profile or timing is fabricated.

### Startup measurement

Build type: `release` (R8 minified, resource shrunk), signed with a temporary
local measurement keystore outside the repository. The keystore and passwords
were not committed; release signing policy remains M3-06.2.

Procedure:

1. Install the release APK.
2. Trigger profile installation with
   `adb shell am broadcast -a androidx.profileinstaller.action.INSTALL_PROFILE -n dev.chatui/androidx.profileinstaller.ProfileInstallReceiver`
   (result=1).
3. Apply the profile with `adb shell cmd package compile -m speed-profile dev.chatui`
   (`Success`; `dumpsys package` then reports `[status=speed-profile]`).
4. For each run: `adb shell am force-stop dev.chatui`, then
   `adb shell am start -W -n dev.chatui/.MainActivity`.

| Run | TotalTime (ms) | LaunchState |
| --- | --- | --- |
| 1 | 713 | COLD |
| 2 | 743 | COLD |
| 3 | 730 | COLD |
| 4 | 888 | COLD |
| 5 | 831 | COLD |

Median: **743 ms**. Budget: 1,500 ms. Result: met on the recorded emulator.
The first launch after install, before the profile was applied, was 794 ms and
is not part of the five-run set.
