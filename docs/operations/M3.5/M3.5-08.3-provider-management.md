- Milestone: M3.5
- Status: Not started
- Order: 30
- Depends on: M3.5-08.2, M3.5-04.2, M3.5-06.4
- Parallel-safe: yes, with M3.5-08.4
- Owns: `rust/crates/chatui-ui/src/providers/`, provider management tests
- Read first: [M3.5 plan](../M3.5-rust-desktop-implementation-plan.md) sections 3.6 and 4.10; spec sections 3.3, 3.4, 7.4, 11.5

## Goal

Implement provider list and detail management, custom providers, key rotation/removal, forget-key actions, and OpenRouter metadata display without exposing secrets.

## Preconditions

- Onboarding works and the secret lifecycle exists.
- Do not store keys in provider records or logs.
- Do not add model picker behavior in this task.
- Do not modify `web/`, `android/`, or `contracts/`.

## Deliverables

- Provider list with:
  - enabled/disabled state;
  - OpenRouter recommended badge;
  - key-present indicator without showing the key;
  - add-provider entry point.
- Provider detail with:
  - key label, usage, limit, free-tier, and rate-limit metadata for OpenRouter;
  - docs link from the contract;
  - browser-CORS metadata displayed where relevant;
  - non-secret custom headers.
- Custom provider form:
  - label, base URL, auth style, non-secret headers;
  - HTTPS validation;
  - local cleartext warning;
  - key entry and test connection;
  - save/edit.
- Key lifecycle:
  - rotate key;
  - forget key;
  - forget all keys with confirmation;
  - clear key state when a provider is deleted.
- Tests with fakes and fake keys only.

## Implementation steps

1. Read spec sections 3.3, 3.4, 7.4, and 11.5, plus `web/src/features/providers/*`.
2. Build the provider list view model over the provider repository and secret-store presence checks.
3. Build provider detail. Use `/key` metadata already stored on the provider record. Never fetch or display the key.
4. Implement custom provider creation and editing. Validate URL scheme and show the cleartext warning for local/private hosts.
5. Implement key rotation through `SecretStore`, with test connection before replacing the old key. Preserve the old key if validation fails.
6. Implement forget-key and forget-all with explicit confirmation. Do not leave stale key-present indicators.
7. Implement provider deletion: remove models and secret entries, clear conversations' active selection safely, and keep historical model labels.
8. Add tests for list/detail, add/edit custom, invalid URL, failed rotation preserving the old key, forget flows, and deletion cascade.
9. Document the key lifecycle and error states.

## Acceptance criteria

- [ ] Provider list and detail render without exposing keys.
- [ ] OpenRouter metadata is displayed.
- [ ] Docs links come from the contract.
- [ ] Custom providers can be added and edited safely.
- [ ] HTTP localhost is allowed with a warning; public cleartext is rejected.
- [ ] Key rotation validates before replacing.
- [ ] Failed rotation preserves the old key.
- [ ] Forget key/all keys work with confirmation.
- [ ] Provider deletion removes models and secrets and preserves historical labels.
- [ ] Tests use fake keys only.
- [ ] No model picker behavior is added.
