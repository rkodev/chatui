# M5-05.2 - Android backup/restore UI and settings

- Milestone: M5
- Status: Not started
- Order: 16
- Depends on: M5-04.2
- Parallel-safe: yes, with `M5-05.1` and `M5-05.3`
- Owns: `android/feature/backup/`, `android/feature/settings/`, `android/app/`
- Read first: [M5 plan](../M5-backup-and-sync-implementation-plan.md) sections 3.6 and 5.3; spec sections 13.7 and 21.5; `android/feature/backup/src/main/kotlin/dev/chatui/feature/backup/BackupPlaceholder.kt`

## Goal

Replace the Android backup placeholder with a working settings and restore flow:
configure a backend, test connectivity, enable backup, show status, back up now,
restore, and delete the remote backup with typed confirmation.

## Preconditions

- `M5-04.2` is `Complete` and the sync engine works.
- `M5-03.2` provides the S3 adapter and connectivity test.
- Do not add a new design system or redesign settings.

## Deliverables

- `android/feature/backup/`:
  - `BackupViewModel.kt` with UI state and actions.
  - `BackupSettingsScreen.kt` replacing `BackupPlaceholder`.
  - `BackupStatus.kt` model.
- Settings fields:
  - Backend selector (`s3` first; other backends disabled until `M5-07.2`).
  - Endpoint, region, bucket, prefix, access key, secret key, passphrase.
  - "Test connection", "Enable backup".
  - Status: last backup, pending changes, last error, storage usage.
  - "Back up now", "Restore from backup", "Delete remote backup".
  - Typed confirmation for delete and replace-on-restore.
  - Client-side statement and passphrase-loss warning.
- Credential storage through the existing `SecretStore`; never persist the
  passphrase.
- Navigation wiring in `ShellNavHost.kt` and the settings entry.
- Tests:
  - ViewModel state transitions and validation.
  - Connectivity test success and failure.
  - Enable/disable.
  - Back up now calls the sync engine.
  - Restore defaults to merge; replace requires typed confirmation.
  - Delete remote requires typed confirmation and keeps local data.
  - Credentials are stored as secrets; passphrase is not persisted.
  - Compose UI test for the main controls and status.

## Implementation steps

1. Read the placeholder, `ShellNavHost`, settings screens, `SecretStore`, and the
   sync engine API.
2. Add `BackupViewModel` with a sealed UI state and actions.
3. Build `BackupSettingsScreen` with existing Compose primitives and design
   tokens. Keep the existing navigation entry.
4. Wire "Test connection" to the S3 adapter.
5. Wire "Enable backup" to save the config and start the sync engine.
6. Wire "Back up now", "Restore from backup", and "Delete remote backup".
7. Add typed confirmation dialogs for delete and replace.
8. Add the client-side statement and passphrase-loss warning.
9. Add ViewModel and Compose tests.
10. Run the Android gates.

## Acceptance criteria

- [ ] The placeholder is replaced with a working settings screen.
- [ ] Backend, endpoint, region, bucket, prefix, credentials, passphrase, test,
      and enable controls exist.
- [ ] Connectivity test shows success and typed errors.
- [ ] Status shows last backup, pending changes, errors, and storage usage.
- [ ] Back up now, restore, and delete remote work.
- [ ] Restore merges by default; replace requires typed confirmation.
- [ ] Delete remote requires typed confirmation and keeps local data.
- [ ] Credentials are stored as secrets; the passphrase is never persisted.
- [ ] The client-side statement and passphrase-loss warning are visible.
- [ ] Existing settings tests still pass.
