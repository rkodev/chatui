## Goal

Define shared catalog mappings, request serialization, math/export fixtures, capability inference, fallback model rules, and the CORS evidence plan.

## Preconditions

- M2-00.1 is complete.
- Raw model and stream fixtures already exist in `contracts/fixtures/`.

## Deliverables

- Expected catalog mappings for OpenAI, Anthropic, Gemini, and Ollama tags.
- Request vectors for OpenAI-compatible, Anthropic, Gemini, and Ollama requests.
- Request vectors for system prompts, image/file content parts, provider extras, and protected-field rejection.
- Capability inference rules from preset metadata.
- Fallback model rules or fallback model lists for blocked discovery.
- Math fixtures covering inline, block, invalid, and streaming-incomplete input.
- A shared `chatui.export` fixture with IDs, ordering, snapshots, and optional attachment data.
- A CORS matrix template and verification plan for every preset.
- Validator support for all new fixtures.

## Implementation steps

1. Add expected model catalogs derived from the existing raw model fixtures.
2. Add request vectors in the same format as the M1 OpenRouter request vectors.
3. Define and document how provider-specific extras are namespaced.
4. Define protected fields: `model`, `messages`, `stream`, and `stream_options`.
5. Document capability inference defaults for missing modalities, capabilities, context, and supported parameters.
6. Define the fallback model rule and represent it in a schema-compatible way.
7. Add math and export fixture inputs.
8. Add a CORS matrix template with provider, endpoint, preflight, status, conclusion, and evidence columns.
9. Extend the validator and add failure cases.
10. Run the contract gate.

## Acceptance criteria

- [ ] Every non-OpenRouter provider has expected catalog and request vectors.
- [ ] Request vectors cover system prompts, attachments, extras, and protected fields.
- [ ] Capability inference and fallback model behavior are documented and testable.
- [ ] Math and export fixtures are committed.
- [ ] CORS matrix template exists with no secrets.
- [ ] `make contracts-check` passes.
- [ ] Broken fixtures or vectors fail precisely.
- [ ] No client source changes are introduced.
