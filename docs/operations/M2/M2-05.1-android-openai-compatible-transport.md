## Goal

Extract a preset-driven OpenAI-compatible transport from the Android OpenRouter adapter while preserving OpenRouter behavior.

## Preconditions

- M2-00.2 expected and request vectors are complete.
- Do not add Custom provider UI in this task.

## Deliverables

- Generic OpenAI-compatible transport for validation, discovery, and streaming.
- Preset-driven base URL, auth, default headers, attribution, and discovery format.
- Request serialization from shared vectors.
- Existing retry, SSE, cancellation, usage, and error behavior preserved.
- Tests for OpenAI fixtures and OpenRouter regression.
- No key in URLs, logs, or provider records.

## Implementation steps

1. Read `OpenRouterAdapter`, `OpenRouterStream`, `SseTransport`, and `ProviderRegistry`.
2. Introduce a generic OpenAI-compatible adapter using preset configuration.
3. Keep OpenRouter-specific routing and in-stream behavior behind configuration.
4. Build requests from shared vectors and supported parameters.
5. Add OpenAI fixture tests and rerun M1 OpenRouter tests.
6. Run Android gates.

## Handoff notes

- Adapter entry points:
  - `OpenAICompatibleAdapter` in `OpenAICompatibleTransport.kt` is the generic
    preset-driven adapter (`validateKey`, `listModels`, `loadCatalog`,
    `refreshCatalog`, `streamChat`).
  - `OpenAICompatiblePreset.fromPreset(ProviderPreset)` builds a transport
    preset from `contracts/providers.json`.
  - `OpenRouterAdapter` is now a thin OpenRouter preset over the generic
    adapter; its constructor and public methods are unchanged.
  - `buildOpenAICompatibleChatRequestBody` is the pure request builder;
    `buildChatRequestBody` remains the OpenRouter wrapper used by M1 tests.
- Preset fields consumed:
  - `baseUrl` (fallback; the provider record's `baseUrl` wins at request time),
    `auth` (bearer, x-api-key, none; query-key is rejected so keys never enter
    URLs), `defaultHeaders`, `attributionHeaders` (`app.origin`/`app.name`),
    `modelDiscovery` (path, format, public, cache TTL), and `keyValidation`.
  - Transport-only fields: `extraNamespace`, `extraMode` (curated/all),
    `extraPassthroughFields`, `reasoningStyle` (OpenRouter object vs OpenAI
    `reasoning_effort`), `messages`, `multimodal`, `contentFilterOn400`, and
    `startBeforeStreamError`.
- OpenRouter regression notes:
  - The OpenRouter preset keeps curated `openrouter` extras, the M1 message
    strings, attribution headers, 24-hour catalog TTL, and start-before-error
    ordering. The full M1 `OpenRouterAdapterTest`, `OpenRouterStreamingTest`,
    and `OpenRouterCatalogTest` suites pass unchanged.
  - `ModelInfo` gained a defaulted `hidden` flag for embedding models, and
    `NormalizedChatRequest` gained a defaulted `attachments` map for OpenAI
    data-URL/file serialization. Both are backward compatible.
