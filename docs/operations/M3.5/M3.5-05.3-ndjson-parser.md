## Goal

Implement a bounded NDJSON line reader for Ollama's native streaming endpoint without parsing provider payloads in the transport.

## Preconditions

- Domain and conformance scaffold exist.
- Do not parse Ollama JSON in this module. The Ollama adapter owns JSON.
- Do not use an unbounded line buffer.
- Do not modify `web/`, `android/`, or `contracts/`.

## Deliverables

- An async NDJSON line reader over an async byte stream.
- A configurable maximum incomplete-line buffer.
- Handling of final lines without a trailing newline.
- Blank-line tolerance.
- Abort/cancellation support.
- Tests against `contracts/fixtures/streams/ollama-ndjson.txt` and chunk-boundary/property tests.

## Implementation steps

1. Read `web/src/providers/ollama.ts` and the Ollama stream fixture.
2. Define an async API such as `read_ndjson(stream, on_line, cancel, max_line_bytes)`.
3. Read bytes, split on `\n`, and strip a trailing `\r` if present.
4. Ignore empty lines. Do not emit blank lines as records.
5. Enforce a maximum incomplete-line buffer. Return a typed overflow error.
6. Flush the final line when the stream ends without a newline.
7. Support cancellation promptly.
8. Add tests with chunk boundaries, CRLF, split multi-byte UTF-8, blank lines, oversized lines, and the final line.
9. Do not parse JSON in the parser; adapters parse lines.
10. Document the buffer limit and error type.

## Acceptance criteria

- [ ] NDJSON lines are emitted in order.
- [ ] CRLF and LF are handled.
- [ ] Blank lines are ignored.
- [ ] The final line flushes without a trailing newline.
- [ ] The line buffer is bounded and overflow is a typed error.
- [ ] Cancellation stops reading promptly.
- [ ] No JSON parsing exists in the NDJSON module.
- [ ] Fixture and property tests pass.
