## Goal

Render conversations with a windowed message list that stays responsive for large histories, preserves scroll position, and isolates the streaming message from completed history.

## Preconditions

- The chat runner and message repositories exist.
- Do not render all messages in a large conversation.
- Do not re-render completed history on every token.
- Do not modify `web/`, `android/`, or `contracts/`.

## Deliverables

- Message list with:
  - stable keys by message ID;
  - windowing or virtualization;
  - newest-page load and older-page pagination;
  - scroll anchoring when older pages load;
  - auto-scroll only when the user is near the bottom;
  - isolated streaming message row;
  - role layout, Markdown slot, actions, metadata, status, and error states.
- Loading skeleton, empty state, and error banner.
- Tests with a 10,000-message conversation proving bounded rendering and correct ordering.
- Tests for scroll anchoring and near-bottom auto-scroll.

## Implementation steps

1. Read spec sections 9.11, 10.9, 11.2, 11.3, and 11.7, plus `web/src/features/chat/MessageList.tsx`, `useWindowedList.ts`, and Android `ChatMessageList.kt`.
2. Build the list over the message repository's newest/older page APIs.
3. Use stable keys by message ID. Do not use indexes.
4. Window or virtualize the list. Keep only a bounded set of message rows composed.
5. Isolate the streaming row. Token updates must not re-render completed rows.
6. Implement scroll anchoring when older messages are prepended.
7. Implement near-bottom detection and auto-scroll. Do not force scroll when the user has scrolled up.
8. Add message actions and metadata slots for copy, regenerate, retry, and usage/latency.
9. Add a 10,000-message test that asserts bounded composition and ordering.
10. Add scroll-anchoring and auto-scroll tests where the framework supports them.

## Handoff notes

- List API: `MessageListState` owns the loaded history, measured heights, visible window, pagination cursors, and scroll policy. `MessageListLoader::{load_newest, load_older}` wraps `MessageRepository::{newest_page, older_page}` with a bounded page size. `MessageListController` binds the state to the Slint `MessageListWindow`; `apply_newest_page`, `apply_older_page`, `set_streaming`, `set_error`, `set_loading_newest`, `set_show_token_usage`, and `scroll_to_bottom` push state into the window. Handlers are injected with `set_on_load_older`, `set_on_retry`, `set_on_retry_message`, `set_on_regenerate`, and `set_on_copy`.
- Row API: `MessageRow::from_message` and `MessageRow::from_streaming` build the role layout, Markdown slot, actions, metadata, status, and error copy. `MessageRowOptions` carries `show_token_usage`, `can_regenerate`, `can_retry`, and `is_active_stream`. The Markdown slot is plain text until M3.5-09.4 replaces the renderer.
- Windowing: `MessageListState::visible_range` computes offsets from measured heights (estimated at `DEFAULT_ESTIMATE_HEIGHT` until measured) and composes only the viewport plus `DEFAULT_OVERSCAN` rows. `MAX_WINDOW_ROWS` (64) is a hard cap even when the viewport height is unknown. `top_padding` and `bottom_padding` preserve the scroll extent for the uncomposed rows.
- Pagination: `apply_newest_page` replaces history and starts at the bottom. `begin_load_older` returns the oldest sequence and records the distance from the bottom; `apply_older_page` merges by message ID, sorts by sequence, and restores the scroll offset so the visible message does not move.
- Scroll behavior: `handle_scroll` updates the near-bottom flag and reports when an older page should load. `set_streaming` follows the bottom only when the user is near it; otherwise the scroll offset is preserved. `content_height` includes an estimated streaming-row height so auto-scroll reaches the live row.
- Streaming isolation: the live snapshot is stored separately from persisted history. `visible_rows` excludes the streaming message ID, and `MessageListController::set_streaming` updates only the streaming row and scroll offset, leaving the completed-history model untouched.
- States: the Slint window renders a loading skeleton, an empty message, and an error banner with retry. `MessageListError` carries the banner copy.
- Tests: `ten_thousand_messages_render_a_bounded_window_in_order`, `scroll_anchoring_preserves_the_visible_message_when_older_pages_load`, `auto_scroll_only_when_near_the_bottom`, `streaming_row_is_isolated_from_completed_history`, `persisted_streaming_message_is_not_rendered_twice`, `pagination_uses_newest_and_older_pages`, `loading_empty_and_error_states`, `message_row_renders_role_metadata_status_and_error`, `error_and_cancelled_rows_show_actionable_copy`, `slint_window_renders_windowed_rows_and_streaming_row`, `slint_window_shows_loading_empty_and_error_states`, `slint_window_invokes_load_older_and_copy_handlers`.
- Framework limitation: Slint's `for` loop has no key API. Stable message IDs are carried in every `MessageListRow` and used for actions, deduplication, and scroll anchoring; the window is rebuilt from IDs rather than indexes. The 10,000-message test proves the composed row count stays bounded.
