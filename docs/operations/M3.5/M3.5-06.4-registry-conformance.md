## Goal

Expose a stable adapter surface, load presets from the contract registry, and make the OpenRouter conformance checklist a real gate before any other adapter starts.

## Preconditions

- OpenRouter key/catalog, request, and streaming behavior exist.
- Do not add other provider adapters in this task.
- Do not duplicate presets or special-case the UI.
- Do not modify `web/`, `android/`, or `contracts/`.

## Deliverables

- `ProviderAdapter` trait or enum dispatch with:
  - `validate_key`;
  - `list_models`;
  - `stream_chat`;
  - cancellation and event delivery.
- `ProviderRegistry` built from `contracts/providers.json`.
- Adapter construction that consumes only preset/config context.
- A fixture-driven OpenRouter conformance suite covering:
  - `/key`;
  - `/models` and catalog mapping;
  - request bodies and headers;
  - text, keep-alive, reasoning, and usage streams;
  - HTTP and in-stream errors;
  - routing and protected fields;
  - cancellation and retry rules.
- A pass/fail checklist record in `docs/operations/M3.5/conformance.md`.

## Implementation steps

1. Read spec sections 7.1 and 7.4, plus `web/src/providers/registry.ts` and `presets.ts`.
2. Define the adapter trait. Prefer object-safe methods with a cancellation token and an `mpsc` sender or `futures::Stream` return. A small enum dispatch is acceptable if object safety becomes awkward.
3. Define `ProviderContext` with preset, base URL, auth, non-secret headers, and resolved API key. Do not include settings or storage handles.
4. Build the registry from the contract presets. Reject duplicate IDs and unknown required fields.
5. Wire `create_adapter(preset_id)` for OpenRouter. Leave other presets unimplemented with a clear `unsupported` error until M3.5-07.*.
6. Move the OpenRouter key/catalog/request/stream pieces behind the adapter without changing their behavior.
7. Add conformance tests under `rust/tests/conformance/` that call the adapter against fixtures and mocks.
8. Check every item in the section 7.4 OpenRouter checklist and record pass/fail with test names.
9. Gate additional provider work on this task being complete.
10. Record the adapter API and registry behavior for later tasks.

## Handoff notes

- Adapter API: `chatui_providers::adapter::ProviderAdapter` is a small enum
  dispatch (`OpenRouter` or `Unsupported`) with `kind`, `preset_id`,
  `is_supported`, `validate_key`, `list_models`, `prepare_request`, and
  `stream_chat`. `validate_key` and `list_models` race the request future with
  the `CancellationToken`; `stream_chat` delivers normalized `StreamEvent`
  values through a callback and returns `StreamSummary` with partial-output and
  retry state. `ProviderContext` carries only the preset, base URL, auth scheme,
  non-secret headers, and resolved key.
- Registry behavior: `ProviderRegistry::load()` reads
  `contracts/providers.json` through `chatui-contracts`, loads all 14 presets in
  contract order, rejects duplicate IDs and missing required fields, and maps
  `openrouter` to `OpenRouterAdapter` and every other preset to
  `UnsupportedAdapter`. `create_adapter(preset_id)` returns
  `RegistryError::UnknownPreset` for an unknown ID. Unsupported adapters return
  a clear `unknown` error: `Provider preset <id> is not supported yet.`
- Conformance suite: `rust/tests/conformance/tests/openrouter_adapter.rs` drives
  the adapter against the shared fixtures and mocks. It covers `/key`, `/models`
  and catalog mapping, request bodies and headers, text/keep-alive/reasoning/
  usage streams, HTTP and in-stream errors, routing and protected fields,
  cancellation before/after the first token, and retry rules. It reuses the
  provider network harness for chunked-stream cancellation and abrupt-stream
  retry cases.
- Section 7.4 checklist: recorded in `docs/operations/M3.5/conformance.md` with
  pass/fail and test names. Every adapter-level item passes. Pricing display,
  reasoning display, and usage persistence are explicitly deferred to
  M3.5-08.4/M3.5-09.1/M3.5-09.4/M3.5-09.5. Browser-direct CORS is N/A for the
  native desktop client; web evidence is owned by M1.
- No other provider adapter is implemented. No UI or storage code was added. No
  provider metadata is duplicated; the registry reads the contract only.
- Verification: `make contracts-check` passed; `cargo fmt --all --check` passed;
  `cargo clippy -p chatui-providers --all-targets -- -D warnings` passed;
  `cargo nextest run -p chatui-providers` passed (216 tests);
  `cargo nextest run -p chatui-conformance` passed (35 tests).
