# UX-03.6 - Background attachment ingestion

- Phase: UX-03 - Chat readability and resources
- Status: Not started
- Order: 18
- Depends on: UX-03.3
- Output folder: `docs\operations\android-minimalist-design-plan`
- Parallel-safe: No with ChatScreen/ChatRoute/composer ingestion edits.

## Goal

Move URI reads off the main thread and show processing feedback without losing
drafts, permissions, attachment validation, or conversation ownership.

## Read first

Read the [execution contract](README.md), source-plan sections 5.2, 6,
and 7, `Chat\ChatScreen.kt`, `Chat\ChatRoute.kt`, `Chat\ChatComposer.kt`,
the existing attachment service/read helpers and limits, and draft/attachment
tests. Read UX-03.3's processing/warning contract.

## Owns

Photo/file/paste/drop ingestion paths in the named chat files, their existing
state holder or a small lifecycle-owned read helper, and focused tests.
Change attachment service dispatching only where required by these callers;
do not change validation/storage policy.

## Deliverables

Lifecycle-safe background reads, one adding/processing state, controlled
cleanup, and focused failure/cancellation/ownership regressions.

## Implementation steps

1. Enumerate every URI-based input path, including activity-result callbacks,
   clipboard image paste, and drag/drop. Existing byte limits already cap
   reads; retain them and do not describe all current ingestion as unbounded.
2. Launch reads from a lifecycle/state owner on an appropriate background
   dispatcher. Capture the originating conversation/draft identity rather than
   attaching a late result to whichever chat is currently visible.
3. Use bounded reading and the existing type/size/capability validation.
   Avoid unnecessary byte-array copies; close streams on success/error/cancel.
4. Drive UX-03.3's processing state during ingestion. Keep text editing,
   navigation, and Stop responsive; prevent duplicate read activation where
   necessary without discarding other supported attachments.
5. Preserve URI grant handling. On denied/revoked access, oversized/invalid
   files, cancellation, or navigation, retain typed text and existing
   attachments and clean up only newly abandoned temporary work.
6. Surface a single actionable read error in the composer; never report picker
   cancellation as failure or promise an attachment was added before it exists.
7. Add deterministic tests for dispatcher/nonblocking behavior, all input
   entry paths, bounded failure, draft retention, late-result conversation
   isolation, duplicate activation, cancellation, and resource cleanup.

## Acceptance criteria

- [ ] No content-resolver URI read remains on the UI callback thread.
- [ ] Existing limits, sources, consent, and URI access semantics are preserved.
- [ ] Failed/cancelled reads retain the draft and cannot contaminate another chat.
- [ ] One processing/error presentation and no leaked stream/temp attachment.

## Out of scope

Raising/lowering file limits, draft schema changes, new attachment types,
upload/provider behavior, or background uploads.
