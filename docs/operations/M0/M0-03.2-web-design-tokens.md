## Goal

Implement the shared design tokens and theme modes with accessible contrast, density, chat font size, and reduced-motion support. Do not build feature UI.

## Preconditions

- The app shell can render a route.
- Use plain CSS custom properties and CSS modules or scoped feature CSS. Do not add Tailwind.

## Deliverables

- `tokens.css` with every semantic token from spec 11.12:
  - background, surface, raised surface, user bubble, code background
  - foreground primary, secondary, muted, on-accent
  - accent, accent-hover, subtle and strong borders
  - danger, warning, success
  - spacing 1-7, radii, body and code font tokens, heading tokens
- `themes.css` with light, dark, and system theme overrides.
- Theme application:
  - use stable data attributes or classes such as `data-theme`, `data-density`, and `data-chat-font-size`
  - system theme follows `prefers-color-scheme`
  - light and dark can be selected explicitly
- Density and font-size modes:
  - `comfortable` and `compact` density
  - `sm`, `md`, and `lg` chat font size
- Accessibility:
  - visible `:focus-visible` styles
  - text contrast at least 4.5:1 for normal text in both themes
  - reduced-motion handling via `prefers-reduced-motion`
  - no layout that depends on animation
- `layout.css` and `typography.css` for the shell only.
- A small theme provider/hook that applies the current theme and mode attributes. Persistence is optional; if added, use the existing settings repository and do not add new storage.
- Tests for token presence, theme attribute switching, density/font-size application, and reduced-motion CSS presence where practical.

## Implementation steps

1. Translate spec 11.12 into semantic CSS custom properties.
2. Add light and dark overrides and a system-theme rule.
3. Add density and chat font size selectors.
4. Add focus-visible and reduced-motion rules.
5. Wire the theme provider into the shell.
6. Add tests and run all web gates.

## Handoff notes

- Token mapping: dotted spec names map to kebab-case custom properties: `color.bg.canvas` -> `--color-bg-canvas`, `space.1` -> `--space-1`, `radius.sm` -> `--radius-sm`, `font.body.size` -> `--font-body-size`. Heading tokens are `--font-heading-family`, `--font-heading-size`, `--font-heading-size-1` through `--font-heading-size-3`, `--font-heading-line-height`, and `--font-heading-weight`. Chat text uses `--font-chat-size` and `--font-chat-line-height`.
- Theme attribute contract: `ThemeProvider` writes `data-theme` (`light|dark|system`), `data-density` (`comfortable|compact`), and `data-chat-font-size` (`sm|md|lg`) to `document.documentElement`. `system` resolves through `prefers-color-scheme` in `themes.css`. Persistence is intentionally omitted in M0; a later settings screen can pass stored values as initial props.
- Contrast: light and dark palettes are tested at 4.5:1 or better for primary, secondary, and muted text on every background token, on-accent on accent and accent-hover, and status colors on canvas. Dark `--color-fg-muted` on `--color-bg-user-bubble` is the tightest pair at about 4.53:1; review in M4 if the bubble color changes.
- M4 review: full axe/visual audit, responsive feature layouts, and component-specific focus or contrast tuning remain out of scope.
