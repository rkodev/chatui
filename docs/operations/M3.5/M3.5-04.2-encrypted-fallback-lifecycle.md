# M3.5-04.2 - Encrypted fallback, session mode, and key lifecycle

- Milestone: M3.5
- Status: Not started
- Order: 14
- Depends on: M3.5-04.1
- Parallel-safe: yes, with M3.5-03.* and M3.5-05.*
- Owns: `rust/crates/chatui-secrets/src/encrypted_file.rs`, `rust/crates/chatui-secrets/src/session.rs`, `rust/crates/chatui-secrets/src/lifecycle.rs`
- Read first: [M3.5 plan](../M3.5-rust-desktop-implementation-plan.md) sections 3.4 and 4.6; spec sections 10.6, 12.1, 12.6

## Goal

Provide an explicitly chosen encrypted-file fallback when the OS credential store is unavailable, a session-only mode, and complete key lifecycle operations.

## Preconditions

- `SecretStore` and `KeyringStore` exist.
- Do not make the encrypted file fallback automatic or silent.
- Never store plaintext keys.
- Do not log passphrases, keys, derived keys, salts, or ciphertext internals.
- Do not modify `web/`, `android/`, or `contracts/`.

## Deliverables

- Encrypted-file backend using AES-256-GCM or XChaCha20-Poly1305.
- Argon2id key derivation with a random salt and documented parameters.
- Explicit fallback selection and a user-facing explanation string.
- Safe file permissions where the platform supports them.
- Session-only mode that holds keys in memory and clears them on exit.
- Key lifecycle operations: rotate provider key, forget key, forget all keys.
- Tests for encrypt/decrypt, wrong passphrase, tamper detection, session clearing, and no plaintext on disk.

## Implementation steps

1. Read the decision in `M3.5-decisions.md` for the fallback UX and algorithms.
2. Add `argon2`, `aes-gcm` or `chacha20poly1305`, `rand`, and `zeroize` dependencies.
3. Define an encrypted-file format with:
   - a format version;
   - a random salt;
   - a nonce;
   - ciphertext;
   - KDF parameters.
   Do not include the passphrase or derived key.
4. Derive the key with Argon2id. Use a random 16-byte or stronger salt. Record the parameters in the file header or a versioned config.
5. Encrypt/decrypt with authenticated encryption. On authentication failure, return a clear error and do not fall back to plaintext.
6. Store the encrypted file under the app-data directory with restrictive permissions on Unix. Do not put secrets in filenames.
7. Implement explicit fallback selection:
   - OS store available: use it by default;
   - OS store unavailable: require the user to choose the encrypted fallback;
   - never silently write a plaintext file.
8. Implement session-only mode. Clear keys on exit and on explicit lock. Use `zeroize` for buffers.
9. Implement provider-key rotation, forget key, and forget all keys through the `SecretStore` trait.
10. Add tests using a temporary directory:
    - round-trip;
    - wrong passphrase fails;
    - tampered ciphertext fails;
    - no plaintext sentinel appears in the file;
    - session mode clears keys;
    - rotation and forget flows work.
11. Document the fallback and session behavior for the UI task.

## Acceptance criteria

- [ ] Encrypted fallback uses Argon2id and an AEAD.
- [ ] Salt and nonce are random and stored safely.
- [ ] Wrong passphrase and tampering fail closed.
- [ ] No plaintext key appears on disk.
- [ ] Fallback is explicit, never silent.
- [ ] Session-only mode clears keys on exit.
- [ ] Rotate, forget key, and forget all keys work.
- [ ] Tests use temporary directories and no real keys.
- [ ] No UI or provider code is added.
