## Goal

Create the chat runner and streaming state that sends messages, persists partial content, handles cancellation, and supports stop, regenerate, and retry without duplicating the provider event model.

## Preconditions

- Provider adapters, repositories, and chat/provider/model UI exist.
- Do not create a second `StreamEvent` model.
- Do not persist every token; bounded persistence is required.
- Do not retry after partial output.
- Do not modify `web/`, `android/`, or `contracts/`.

## Deliverables

- Chat runner that:
  - appends the user message immediately;
  - creates a streaming assistant placeholder;
  - calls the selected provider adapter;
  - appends text and reasoning deltas;
  - records usage, finish reason, error, latency, and first-token time;
  - persists streaming text at most once per second and on pause/completion/cancellation/error.
- Stop action that cancels the request and persists partial content as `cancelled`.
- Regenerate and retry actions that follow the shared rules.
- Model/provider snapshot on the assistant message.
- Streaming state isolated from history rendering.
- Error handling with the shared `ChatError` copy.
- Tests with a fake adapter covering send, stream, stop, regenerate, retry, error, and partial persistence.

## Implementation steps

1. Read spec sections 7.1-7.3, 7.9, 10.7, 11.3, 11.4, and 11.7, plus `web/src/features/chat/ChatRunner.ts` and `useChatSession.ts`.
2. Define the runner state machine: idle, sending, streaming, cancelling, complete, error.
3. On send:
   - persist the user message with sequence;
   - build the normalized request from conversation history and params;
   - create the assistant message with provider/model snapshots;
   - call the adapter with a cancellation token.
4. Reduce normalized events into the assistant message. Keep reasoning separate from answer text.
5. Persist at most once per second and on terminal events. Use the repository from `chatui-storage`.
6. Implement stop: cancel the token, persist partial content, set `cancelled`, and keep the UI stable.
7. Implement regenerate for the last assistant response only. Implement retry only when the shared policy allows it.
8. Track first-token time and total latency.
9. Surface errors without losing typed text or partial output.
10. Add tests with a fake adapter and an in-memory or temporary repository. Assert persistence cadence, cancellation, and no-retry-after-partial.
11. Document the runner API and state transitions.

## Acceptance criteria

- [ ] The user message appears immediately and is persisted.
- [ ] Assistant streaming appends text and reasoning separately.
- [ ] Partial content persists at most once per second and on terminal events.
- [ ] Stop cancels and marks the message `cancelled`.
- [ ] Regenerate works only for the last assistant response.
- [ ] Retry follows the shared policy and never retries after partial output.
- [ ] Usage, finish reason, latency, and first-token time are recorded.
- [ ] Provider/model snapshots are stored.
- [ ] Streaming state is isolated from history rendering.
- [ ] No second stream event model exists.
- [ ] Tests pass.
