## Goal

Implement a provider-agnostic Android SSE transport with OkHttp that matches the web transport behavior and supports cancellation.

## Preconditions

- OkHttp and `okhttp-sse` are available.
- Do not map OpenRouter JSON in this task.

## Deliverables

- SSE line/event parser that handles CRLF/LF, multi-line `data:`, comments, unknown fields, and final flush.
- Bounded buffering with a typed transport error.
- Cancellation from coroutine cancellation to the OkHttp call.
- An API that emits raw data strings or events to the adapter.
- MockWebServer tests for chunked responses, keep-alives, split chunks, final buffer, malformed data, and cancellation.

## Implementation steps

1. Read spec 9.6 and the web SSE task expectations.
2. Choose `okhttp-sse` if it exposes enough control; otherwise implement a bounded line reader over the response body.
3. Normalize line endings and collect `data:` lines per event.
4. Ignore comment and unknown fields.
5. Enforce a maximum event/buffer size.
6. Process the final partial event when the body ends.
7. Ensure cancellation closes the response and cancels the call.
8. Add MockWebServer tests with `MockResponse.setBody`/chunked bodies.
9. Run the Android gate.

## Handoff notes

### Transport API

```kotlin
class SseTransport(
    client: OkHttpClient,
    maxBufferChars: Int = DEFAULT_MAX_SSE_BUFFER_CHARS,
) {
    fun stream(request: Request): Flow<String>
}
```

`stream` is cold: each collection executes a new OkHttp call. It emits the raw
concatenated `data:` value for each SSE event. `data: [DONE]` is passed through
as a normal data event; adapters must stop on it. Empty data values are not
emitted, so keep-alive comments never produce blank messages.

### Error types

- `SseTransportException` - base class for normalized transport failures.
- `SseBufferOverflowException` - an incomplete event or line exceeded the
  buffer limit; exposes `maxBufferChars`.
- `SseHttpException` - non-success HTTP status; exposes `code`, `headers`, and a
  bounded raw `body`.
- `SseReadException` - the call could not be opened or the body could not be
  read; wraps the original `IOException`.

### Buffer limit

`DEFAULT_MAX_SSE_BUFFER_CHARS = 1024 * 1024` characters (UTF-16 code units).
The limit applies to data retained for an incomplete event and to a single
line. Complete events are drained as soon as their terminating blank line
arrives, so a stream of many small events does not accumulate. Tests can
override the limit with `maxBufferChars`. Error bodies are separately bounded
to 64 KiB.

### Cancellation

The flow uses `callbackFlow` and registers `awaitClose` before executing the
call. Cancelling the collecting coroutine invokes `Call.cancel()` and cancels
the reader job, which closes the response body and unblocks a pending read. A
normal completion does not cancel the call. The cancellation test asserts both
that the flow stops promptly and that OkHttp's `EventListener.canceled` fires.

### Decisions

- Implemented a bounded line reader over the OkHttp response body instead of
  `okhttp-sse`. `okhttp-sse` does not expose a buffer limit, and the task
  requires bounded buffering with a typed error. The `okhttp-sse` dependency
  remains available for later use.
- The transport does not check the response content type; any successful body
  is parsed as SSE.
- The transport does not parse provider JSON or interpret `[DONE]`; those
  remain adapter responsibilities.
