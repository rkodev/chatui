5. Capture failure artifacts without secrets.
6. Add a package script and update CI when appropriate.
7. Run the full suite and fix flakes.

## Handoff notes

- Mock provider design: `web/e2e/fixtures/mockProvider.ts` intercepts the OpenRouter base URL with Playwright routing. It serves a deterministic catalog, `/key` metadata, and SSE chat completions, including success, provider-error, HTTP-error, and delayed scenarios. CORS preflight is handled explicitly. No live provider is contacted and no real key is used.
- Test runtime: 15 tests run in about 30 seconds locally with four workers. The config builds the app and serves the production bundle with `vite preview`; CI retries once and uses two workers.
- Known flaky areas: the sidebar title is refreshed on navigation, so tests that need the derived conversation title reload or navigate before using it. The provider-switch test creates a second provider through the UI and then updates the conversation record through IndexedDB because the conversation settings surface has no provider selector; this is documented in `web/e2e/README.md`.
- Coverage: first-run onboarding (including invalid key), send/stream with usage, model switch mid-conversation, provider switch persistence and next-send routing, reload persistence, export/import round trip with ID/order/model-snapshot checks, delete/undo, clear data, offline read, error/retry, cancel, and axe smoke checks on onboarding and chat.
