## Goal

Measure and record cold start, installer size, and build time with a reproducible method, and document any miss against the milestone budgets.

## Preconditions

- Packaging and CI artifacts exist.
- Do not claim a measurement that was not run.
- Do not use a debug build to claim release performance.
- Do not modify `web/`, `android/`, or `contracts/`.

## Deliverables

- `docs/operations/M3.5/performance.md` with:
  - machine and OS specification;
  - build type and artifact version;
  - cold-start method and run count;
  - cold-start median and range;
  - installer size per OS;
  - build time per OS if available;
  - comparison against the under-1.5-second cold-start target and under-40-MB installer target;
  - documented misses and causes.
- Measurement scripts or commands where practical.
- Performance evidence in `M3.5-verification.md`.

## Implementation steps

1. Read spec sections 10.9 and 11.9.
2. Define a cold-start method. For example: launch the packaged app with a clean process state, measure time to the shell being interactive, and run at least five iterations.
3. Record the machine, OS version, CPU, RAM, and disk type.
4. Measure the release artifact, not the debug build.
5. Record the median and range. Do not report only the best run.
6. Measure installer size for each available OS artifact. Record the compressed and installed sizes if they differ.
7. Record build time if available.
8. Compare against the budgets and document any miss with the likely cause.
9. Add a measurement script or exact commands to the performance document.
10. Record the evidence in `M3.5-verification.md`.

## Handoff notes

### Result (2026-11-08)

Measured on the Linux x86_64 host described in
[M3.5-verification.md](M3.5-verification.md) section 1: Ubuntu 26.04.1 LTS,
Linux 7.0.0-42-generic, Intel Core i9-10980HK (8 cores / 16 threads), 30 GiB
RAM, NVMe SSD, GNOME on Wayland, rustc/cargo 1.98.1. Release profile only
(`lto = "thin"`, `codegen-units = 1`, `strip = "symbols"`, `panic = "abort"`),
app version 0.1.0, source revision `6e29be9`.

Method: [`scripts/measure-cold-start.py`](../../../scripts/measure-cold-start.py)
launches the packaged release binary with `--smoke --no-single-instance` and
fresh `XDG_CONFIG_HOME`/`XDG_DATA_HOME`/`XDG_CACHE_HOME` directories. It uses
`WAYLAND_DEBUG=1` to find the main window surface and records the first
`wl_surface.attach(wl_buffer)` plus `commit()` as the first frame. One
unmeasured warmup run loads the binary into the page cache; the measured runs
are cold process starts with a warm file cache. The `--smoke` timer exits after
1500 ms, so total wall time is only a cross-check.

Results:

| Item | Result |
| --- | --- |
| Packaged `.deb` cold start, 10 runs | median 417.1 ms, range 321.8-1051.1 ms |
| Build-tree release binary cold start, 10 runs | median 426.6 ms, range 312.7-491.7 ms |
| Cold-file-cache single observation | 1090.5 ms |
| `.deb` installer size | 6,826,114 bytes (6.51 MiB / 6.83 MB) |
| `.tar.gz` installer size | 9,003,566 bytes (8.59 MiB / 9.00 MB) |
| Installed size (both Linux artifacts) | 18.52 MiB / 19.42 MB |
| `make rust-build` incremental | 1.50 s |
| `make rust-package` incremental | 12.11 s |
| Clean-ish release build (M3.5-11.1) | 5m 47s (347.5 s) |

Budget comparison: cold start is under the 1.5 s target (median 417.1 ms,
worst run 1051.1 ms); installer size is under the 40 MB target (largest
artifact 8.59 MiB). No Linux miss was observed. macOS and Windows cold start
and installer sizes are unmeasured because no macOS or Windows runner or
machine is available (B-01 and B-02); they are not claimed as passes.

Verification commands and results:

| Command | Result |
| --- | --- |
| `make rust-build` | Pass (exit 0); release workspace build finished |
| `make rust-package` | Pass (exit 0); `.deb` and `.tar.gz` written with checksums |
| `ls -lh rust/dist/` | `.deb` 6.6 MiB, `.tar.gz` 8.6 MiB, `SHA256SUMS` 188 bytes |
| `python3 scripts/measure-cold-start.py --binary <packaged .deb binary> --runs 10` | Pass; median 417.1 ms, range 321.8-1051.1 ms |
| `python3 scripts/measure-cold-start.py --binary rust/target/release/chatui-desktop --runs 10` | Pass; median 426.6 ms, range 312.7-491.7 ms |

Decisions:

- The primary claim uses the packaged `.deb` binary, not the build-tree binary.
- The file cache is warmed before the measured runs so the result is
  reproducible without root access to drop the page cache. The cold-file-cache
  case was observed once at 1090.5 ms and also stayed under the target.
- `WAYLAND_DEBUG` logging adds overhead, so the first-frame values are upper
  bounds.
- The method is Linux/Wayland specific; macOS and Windows need their own
  runners and methods.
