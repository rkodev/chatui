- Read first: [M4 milestone](../../milestones/M4-polish-and-release.md) workstreams 5-6 and "Exit gate"; spec sections 5.4, 8.6, 10.12, 12, 14.1, 14.4, 14.5, 15.2, 16.5, and 21.7; `M4-decisions.md`, `M4-performance.md`, `deployment.md`, and `release.md`

## Goal

Audit every parity row, every critical test case, and every security/privacy and deployment requirement, then decide honestly whether the phase 1 release gate passes. This task is verification-heavy and must not implement features to make checks pass. Any substantive fix becomes a separate follow-up task.

## Preconditions

- Every earlier M4 task is `Complete` or explicitly cancelled with an approved deferral.
- `M4-decisions.md` states whether Rust is shipping.
- Do not quietly mark an incomplete row complete. Do not declare success with an open blocker.
- Do not record secrets, prompts, conversation content, personal data, or signing material in evidence.

## Deliverables

- `contracts/parity.md` updated with:
  - Web and Android status per row, each backed by a test, manual check, or linked artifact;
  - Rust as `Optional`, `Complete`, or `Blocked`, honestly;
  - approved exceptions with owner and date.
- `M4-verification.md` with:
  - the commit/host/date under test;
  - a parity audit table linking each row to evidence;
  - evidence for critical test cases 1-28 from spec 15.2 on every enabled client;
  - OpenRouter conformance results for `/key`, `/models`, streaming, reasoning, usage/cost, routing, errors, and browser CORS on web;
  - security/privacy verification (see below);
  - deployment verification (container SPA fallback, headers, public-only config);
  - the definition-of-done review against spec 21.7;
  - release notes, migration notes, known issues, and a blocker list with owners.
- Security/privacy evidence:
  - no keys in logs, URLs, Cache API, exports, or backup metadata;
  - web CSP and security headers present;
  - Android and (if shipping) Rust secret storage and backup exclusion verified;
  - no analytics, telemetry, hidden network destinations, or server-side prompt proxying;
  - export warnings for plaintext data are present.
- Deployment evidence: static build and container run with SPA fallback, correct headers, and public-only config; Android signing policy and Rust update-manifest signing documented if applicable.
- A final gate decision: `Pass`, `Pass with approved exceptions`, or `Blocked`, with the blocker list.

## Implementation steps

1. Read `contracts/parity.md`, `M4-decisions.md`, and the evidence from tasks `M4-01.1` through `M4-05.1`.
2. Walk every parity row:
   - for Web and Android, verify with a named test, manual check, or artifact;
   - for Rust, mark `Optional`/`Complete`/`Blocked` per the shipping decision;
   - do not accept self-reported completion without evidence.
3. Critical cases 1-28 from spec 15.2:
   - map each case to an existing test or run a manual check;
   - record the artifact path or command for each enabled client;
   - record any gap as a blocker or an approved exception with owner/date.
4. OpenRouter conformance:
   - run the contract and conformance suites and record results for `/key`, `/models`, streaming, reasoning, usage/cost, routing, errors, and browser CORS on web.
5. Security/privacy audit:
   - search logs, URLs, Cache API, exports, and backup metadata for key material and fail if found;
   - verify web CSP and security headers against the running container;
   - verify Android secret storage and backup exclusion; verify Rust if shipping;
   - verify there is no analytics, telemetry, hidden network destination, or server-side prompt proxying;
   - verify plaintext-export warnings.
6. Deployment verification:
   - build the static bundle and run the container from `M4-04.1`;
   - confirm SPA fallback, cache headers, security headers, `/healthz`, and public-only `config.json`;
   - document Android signing policy and Rust update-manifest signing if applicable.
7. Definition of done: walk spec 21.7 item by item and record met/exempted with a reason.
8. Write `M4-verification.md`, update `contracts/parity.md`, and update `release-notes.md` known issues and blockers.
9. Make the final gate decision. If blocked, keep the task `In progress` or `Blocked` and list owners; do not mark `Complete`.

## Acceptance criteria

- [ ] Every parity row has Web/Android evidence and honest Rust status.
- [ ] Every critical test case 1-28 has evidence on every enabled client, or an approved exception with owner/date.
- [ ] OpenRouter conformance passes for the listed surfaces; browser CORS is verified on web.
- [ ] No key appears in logs, URLs, Cache API, exports, or backup metadata.
- [ ] Web CSP/security headers, Android secret storage/backup exclusion, and Rust (if shipping) are verified.
- [ ] No analytics, telemetry, hidden network destination, or server-side prompt proxying exists.
- [ ] Plaintext-export warnings are present.
- [ ] Deployment verification passes with SPA fallback, headers, and public-only config.
- [ ] Spec 21.7 definition of done is met or explicitly exempted.
- [ ] Release notes, migration notes, known issues, and blocker list exist.
- [ ] Final gate decision is recorded and no release blocker remains.

## Verification

```bash
make contracts-check
make web-lint && make web-typecheck && make web-test && make web-build
cd web && pnpm exec playwright test
make android-lint && make android-test && make android-assemble
cd android && ./gradlew :app:lintRelease :app:testDebugUnitTest :app:assembleRelease :app:bundleRelease
make rust-check && make rust-lint && make rust-test && make rust-build
cd rust && cargo deny check && cargo audit
```

Plus Lighthouse/axe reports, container smoke tests, artifact checksums, and the parity audit record.

## Out of scope

- Implementing product fixes discovered during the audit; create follow-up tasks instead.
- M5 backup/sync, M6 managed hosting, store listings, privacy-policy copy, and localization.
- Re-running performance optimization (owned by `M4-03.1`).
