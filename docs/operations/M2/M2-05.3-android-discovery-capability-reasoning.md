## Goal

Make discovery, fallback models, capability inference, and reasoning usable for every enabled OpenAI-compatible preset on Android.

## Preconditions

- M2-05.2 preset enablement is complete.
- Expected catalog vectors exist.

## Deliverables

- Per-preset discovery using the preset's path and format.
- Per-preset cache keys, TTL, forced refresh, and last-known-good.
- Fallback model selection when discovery is blocked.
- Capability inference for missing modalities, capabilities, context, and supported params.
- Reasoning normalization for OpenAI-compatible streams.
- Tests for catalog mapping, discovery failure, fallback, capabilities, and reasoning.

## Implementation steps

1. Read `ModelService`, `ProviderGateway`, and the OpenRouter catalog mapper.
2. Generalize discovery by preset format while preserving OpenRouter cache behavior.
3. Add fallback model selection.
4. Add capability inference at the catalog-to-model boundary.
5. Normalize `reasoning_content` and other supported reasoning fields.
6. Add tests for discovery failure and missing metadata.
7. Run Android gates.

## Acceptance criteria

- [x] Discovery works for every enabled OpenAI-compatible preset in tests.
- [x] Blocked discovery yields fallback models and a warning.
- [x] Missing modalities/capabilities are inferred.
- [x] Reasoning appears separately and is not replayed.
- [x] OpenRouter catalog/free badge behavior is unchanged.
- [x] Android gates pass.

## Handoff notes

- Discovery/fallback behavior:
  - `OpenAICompatibleAdapter.loadCatalog` already used each preset's
    `modelDiscovery.path`, format, `cacheTtlSeconds`, and the provider record id
    in the cache key. `DiscoveryTest` now iterates every
    `M2_ENABLED_PRESET_IDS` entry and covers independent cache keys, TTL
    expiry, forced refresh, last-known-good, and the no-snapshot failure.
  - Added `FallbackModels.kt` in `core:network` with the shared fallback lists
    (`openai`, `anthropic`, `google`, `ollama`), the contract `defaultModelId`
    for every other non-OpenRouter preset, and the shared
    `selectFallbackModel` rule. OpenRouter intentionally keeps no fallback list
    so its M1 empty-catalog onboarding failure and catalog behavior are
    unchanged.
  - `ModelService.refreshModels` now returns cached models with
    `degraded: true` and a non-blocking notice when discovery fails, or
    persists fallback rows (marked `metadata.fallback`) when no cache exists.
    `selectDefaultModel` creates fallback rows when needed and applies the
    shared notices. `RefreshModelsResult` gained defaulted `degraded`,
    `notice`, and `refreshError` fields.
- Capability inference defaults:
  - `inferOpenAIModelMetadata` in `OpenAICompatibleTransport.kt` follows
    `contracts/fixtures/expected/capability-inference.json`. Raw
    `inputModalities`/`input_modalities`, output modalities, capabilities,
    supported parameters, and context/output limits win; missing modalities and
    supported parameters use preset defaults; missing limits are `null`; missing
    capabilities are derived in the order `text`, `vision`, `files`, `tools`,
    `reasoning`, `streaming`. `OpenAICatalogTest` asserts every fixture case.
- Reasoning fields:
  - `delta.reasoning_content` (DeepSeek and other OpenAI-compatible providers),
    `delta.reasoning`, and `delta.reasoning_details` are normalized into
    `ReasoningDelta` separately from `TextDelta`. Repeated identical chunks are
    preserved for generic OpenAI-compatible presets; the OpenRouter reference
    keeps its M1 de-duplication. `buildOpenAICompatibleChatRequestBody` ignores
    `ContentPart.Reasoning`, so reasoning is never replayed.
- Scope note: `ProviderGateway`/DI still route through `OpenRouterGateway`.
  Runtime per-preset adapter selection is left for M2-05.4/M2-06; this task
  proves per-preset discovery at the adapter boundary and keeps the service
  contract preset-aware.
