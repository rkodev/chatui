## Goal

Prove that every primary destination renders and operates real UI, that the
normal flow contains no placeholder copy, and that accessibility, secret
handling, and the desktop smoke pass. Record the evidence.

## Preconditions

- `M3.6-06.1` is complete and its smoke has run at least once.
- Do not fix product behavior in this task. Record defects as blockers and
  create follow-up tasks.
- Do not modify `web/`, `android/`, or `contracts/`.

## Deliverables

- `verification.md` with:
  - the commit under test, host, backend, and date;
  - a per-destination table: view shown, real data source, actions exercised,
    result;
  - format, lint, test, and smoke command output summaries;
  - accessibility checks for navigation, feature controls, composer, message
    list, and overlays;
  - a placeholder-copy search result proving no placeholder string is reachable;
  - a secret-handling check: no key in logs, exports, or UI metadata;
  - a blocker list with owners and next actions.
- An integration test under `rust/apps/desktop/tests/` (or a UI test in
  `chatui-ui`) that builds the shell with test factories and asserts each
  destination shows its real component, not placeholder text.
- Extended accessibility assertions if a control is missing a name.

## Implementation steps

1. Run the full formatting, lint, unit, component, and desktop test suites.
2. Build the integration test that navigates all five destinations and asserts
   a real control exists in each.
3. Run the desktop smoke with `--smoke --no-single-instance` and record the
   environment.
4. Manually exercise new chat, send, stop, search, provider edit, settings
   change, data export, and import against a temporary profile.
5. Run the accessibility tree checks for navigation and feature controls.
6. Search the rendered copy and source for the placeholder strings and record
   the result.
7. Verify exports exclude secrets and attachment bytes by default.
8. Record performance observations for startup and destination switching.
9. Write `verification.md` and mark blockers honestly.

## Acceptance criteria

- [ ] Every primary destination renders a real view.
- [ ] An integration test proves no placeholder body is shown.
- [ ] Core actions work in each destination.
- [ ] Navigation and feature controls have accessible names.
- [ ] Composer, message list, and overlays pass the accessibility checks.
- [ ] No secret value appears in logs, exports, or UI metadata.
- [ ] Format, lint, and test commands pass.
- [ ] The desktop smoke passes or has a recorded environment blocker.
- [ ] `verification.md` records commands, results, and blockers.

## Verification

```bash
cd rust && cargo fmt --all --check
cd rust && cargo clippy --workspace --all-targets -- -D warnings
cd rust && cargo nextest run --workspace
cd rust && cargo run -p chatui-desktop -- --smoke --no-single-instance
```

If the smoke needs a display server, run it under the project's documented
headless setup and record the exact command.

- Packaging, signing, and release changes.
- Performance optimization beyond recording observations.
