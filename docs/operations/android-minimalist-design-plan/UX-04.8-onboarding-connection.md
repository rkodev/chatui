# UX-04.8 - Focused onboarding connection

- Phase: UX-04 - Setup, providers, and models
- Status: Not started
- Order: 27
- Depends on: UX-02.4
- Output folder: `docs\operations\android-minimalist-design-plan`
- Parallel-safe: Yes with other feature screens; no with onboarding edits.

## Goal

Make welcome and connection the shortest understandable setup path while
retaining provider choice, validation, catalog browsing, and error recovery.

## Read first

Read the [execution contract](README.md), source-plan section 5.6,
`Onboarding\OnboardingScreen.kt`, `Onboarding\OnboardingRoute.kt`,
the existing onboarding ViewModel/service, and `OnboardingScreenTest.kt`
and related onboarding state tests.

## Owns

Welcome/connection/catalog presentation in the existing onboarding screen/
route, necessary presentation state, and focused onboarding tests. The
optional-backup transition remains compatible for UX-04.9.

## Deliverables

Compact welcome/theme choice, focused credential entry, one connection
progress treatment, and a disclosed virtualized public catalog.

## Implementation steps

1. Keep a small mark and short BYOK/local-storage explanation, provider choice
   with OpenRouter initially selected, and one Get started action. Make theme
   choice an optional compact row rather than the dominant panel.
2. Lead connection with required key/connection fields and Connect. Preserve
   show/hide, Paste, help/documentation, optional label, and provider-specific
   validation. Do not add a login, cloud account, or marketing carousel.
3. Use one pending connection treatment rather than both button progress and
   a duplicate testing row. Keep errors near relevant input and retain entered
   values after recoverable failure.
4. Put public model discovery/browsing behind View available models. Preserve
   catalog loading/error/retry and cached data; virtualize rows and avoid
   fetching on every recomposition/disclosure animation.
5. Keep credential protection/current memory lifetime and scrollable action
   access with the IME/large text. Never save keys into generic saved state
   or validate by generating a paid answer.
6. Add focused cases for initial provider/theme options, provider choice,
   paste/show/hide, validation failure retention, single progress state,
   disclosed catalog/retry, and 320 dp/200% fonts with keyboard visible.

## Acceptance criteria

- [ ] Welcome/connection have one clear primary action and less decoration.
- [ ] Every existing provider/key/help/catalog option remains available.
- [ ] Errors retain input; pending state is truthful and nonduplicated.
- [ ] No paid validation call, new prerequisite, or sensitive saved-state leak.
