- Read first: [M3.5 plan](../M3.5-rust-desktop-implementation-plan.md) sections 3.8 and 6; spec sections 5.4, 10.12, 15.2, 17 (M3.5), 19

## Goal

Update parity honestly, satisfy or explicitly block the section 10.12 release gate, and produce the M3.5 verification report that lets M4 include or exclude Rust correctly.

## Preconditions

- M3.5-12.1 is complete and its evidence exists.
- Do not claim required parity rows that were not delivered.
- Do not mark M3.5 complete if it is deferred or declined.
- Do not edit web or Android code.
- Do not record secrets, signing material, or personal data.

## Deliverables

- Updated `contracts/parity.md`:
  - honest Rust implementation status;
  - `Optional` until enablement, then required rows marked with evidence;
  - no unapproved exception.
- Complete `docs/operations/M3.5/M3.5-verification.md` with:
  - environment and toolchain;
  - conformance and critical-case evidence;
  - persistence/process-death evidence;
  - secret-storage evidence;
  - export/import evidence;
  - packaging, signing, and update evidence;
  - performance and installer-size actuals;
  - OS smoke matrix;
  - web/Android non-regression results;
  - blockers and approved deferrals.
- Updated `docs/operations/M3.5/README.md` task statuses.
- Updated `docs/milestones/README.md` M3.5 status only if the enablement decision and gate justify it.
- A release-gate checklist for section 10.12.

## Implementation steps

1. Read the enablement decision in `M3.5-decisions.md` and the evidence from M3.5-12.1.
2. Walk the section 10.12 release gate item by item:
   - contracts validate and are consumed without duplicated metadata;
   - OpenRouter onboarding, `/key`, catalog, streaming, reasoning, usage/cost, routing, and errors pass;
   - conversations persist across restarts and process death;
   - partial content survives cancellation/failure;
   - keys use a secure backend or explicit fallback, never plaintext;
   - parity has no unresolved required Rust entries;
   - artifacts and update manifests are signed.
3. Update `contracts/parity.md` with the honest status. If Rust is not enabled, keep it `Optional` and do not claim implementation.
4. Complete `M3.5-verification.md` using the plan's evidence matrix. Include exact commands and results.
5. Run the web and Android non-regression gates:
   ```bash
   make web-lint
   make web-typecheck
   make web-test
   make web-build
   make android-lint
   make android-test
   make android-assemble
   ```
   Record results. Do not modify their code.
6. Confirm no M3.5 task modified `web/` or `android/` except documentation/parity.
7. Update the task index statuses.
8. Update the milestone status table only if the gate is genuinely complete. If deferred, record that instead.
9. Record the M4 implication: include Rust if enabled; otherwise state explicitly that it is post-preview/parallel.
