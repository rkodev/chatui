- Milestone: M6
- Status: Not started
- Order: 15
- Depends on: M6-01.4, M6-02.1
- Parallel-safe: yes, with `M6-03.1` and `M6-04.1`
- Owns: `scripts/verify-hosted-deployment.mjs`
- Read first: [M6 plan](../M6-managed-hosting-implementation-plan.md) sections 3.5 (D-04, D-07), 3.6 (V-01, V-02, V-06), 7, and 9; `deploy/Caddyfile`; `deploy/roksky/edge/Caddyfile`; `docs/operations/M4/deployment.md`; `docs/operations/M4/evidence/deployment/README.md`

## Goal

Add a repeatable hosted-deployment check that fails with a nonzero exit code when
a tenant or local static deployment violates the SPA fallback, cache, security
header, CSP, `/healthz`, or public config contract.

## Preconditions

- `M6-02.1` is `Complete` and the edge template is stable.
- `M6-01.4` is `Complete` so the public config validation rules are known.
- Use Node built-ins. Do not add a package unless the repository already uses it.
- The script must work against a local container and a remote tenant.

## Deliverables

- `scripts/verify-hosted-deployment.mjs`:
  - CLI:
    `node scripts/verify-hosted-deployment.mjs <base-url> [--origin <expected-origin>] [--asset <path>] [--timeout <ms>]`.
  - Support `--help`.
  - Normalize the base URL and reject non-HTTP(S) URLs.
  - Check `/`:
    - Status `200`, HTML content type, body contains an app-shell marker such as
      `<!doctype html>`.
    - `Cache-Control: no-cache`.
    - Exact security headers: `X-Content-Type-Options: nosniff`,
      `Referrer-Policy: no-referrer`, the minimal `Permissions-Policy`,
      `Cross-Origin-Opener-Policy: same-origin`, and the section 14.1 CSP.
  - Discover one hashed `/assets/...` URL from the shell HTML, or use `--asset`.
    - Check status `200` and `Cache-Control: public, max-age=31536000, immutable`.
  - Check `/config.json`:
    - Status `200`, JSON content type, `Cache-Control: no-cache`.
    - Parse JSON and check the public config shape, `telemetry: false`, no secret
      key names, no secret-shaped values, and `openRouter.attributionOrigin`.
    - If `--origin` is supplied, require the attribution origin to match it.
  - Check `/healthz`:
    - Status `200`, empty body, and the security headers.
  - Check a deep route such as `/m6/deep/route`:
    - Status `200`, HTML app shell, `Cache-Control: no-cache`.
  - Check every response for the security headers and report the actual value on
    mismatch.
  - Print a compact pass/fail table and a final `PASS` or `FAIL` line.
  - Exit `1` on any failure or network error; exit `0` only when all checks pass.
  - Never print secret values. Redact config values in errors.
- Optionally add `docs/operations/M6/evidence/verification-script.md` explaining
  usage and the expected local and staging runs. If added, keep it short.

## Implementation steps

1. Read the Caddyfile and M4 header evidence to copy the exact expected values.
2. Read the public config schema/validator to mirror the no-secret checks.
3. Implement URL normalization, fetch with timeout, and response checks.
4. Parse the shell HTML to find one `/assets/` URL. Handle no-asset failure with
   a clear message and support `--asset`.
5. Validate the config and origin.
6. Check `/healthz` and a deep route.
7. Print a table with check, expected, actual, and result.
8. Run against the local container. Then run a negative test against a wrong URL
   or a server missing `/healthz`, and confirm exit `1`.
9. Document usage in the script `--help`.

## Acceptance criteria

- [ ] The script exists and runs with Node without new dependencies.
- [ ] It checks shell, asset, config, `/healthz`, and deep-route behavior.
- [ ] It checks all security headers and the exact CSP.
- [ ] It checks config no-secret, `telemetry: false`, and exact origin behavior.
- [ ] It fails nonzero on any mismatch or network error.
- [ ] It never prints a secret value in full.
- [ ] It passes against the local M4 container.
- [ ] It fails against a deliberately bad URL or missing endpoint.
- [ ] Usage is documented in `--help` and, optionally, an evidence note.

## Verification

```bash
make web-build
docker build -f deploy/Dockerfile -t chatui-web:m6-verify .
docker run --rm -d --name chatui-m6-verify -p 8082:80 chatui-web:m6-verify
node scripts/verify-hosted-deployment.mjs http://localhost:8082
docker stop chatui-m6-verify

node scripts/verify-hosted-deployment.mjs http://127.0.0.1:1; test "$?" -ne 0
```

The first run must pass; the second must fail. The real staging run is
`M6-05.2`.

## Out of scope

- Browser chat, provider configuration, storage connectivity, and export/restore
  smoke (`M6-05.2`).
- DNS or TLS validation beyond what an HTTP client sees.
- Changing the deployment contract or headers.

differs by edge provider here.
