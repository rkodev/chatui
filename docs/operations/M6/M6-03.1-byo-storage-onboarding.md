## Goal

Write the tenant-facing onboarding guide for connecting user-owned, S3-compatible
object storage to the hosted web app for encrypted backups. The guide must make
clear that storage credentials and the backup passphrase remain client-side and
are never sent to ChatUI.

## Preconditions

- `M6-01.4` is `Complete`; the public config and tenant docs exist.
- M5 is complete and the backup settings/adapters already exist. Do not rebuild
  the backup feature in this task.
- `DEC-M6-08` confirms BYO storage only and no ChatUI-managed storage.
- Do not include real credentials, bucket names tied to a real user, or
  passphrases.

## Deliverables

- `docs/hosting/byo-storage.md` covering:
  - What BYO storage is and why it is optional.
  - S3-compatible onboarding first; note that M5 also supports Azure Blob, GCS,
    Google Drive, and WebDAV but keep the walkthrough focused on S3-compatible.
  - Prerequisites: a dedicated bucket or prefix, least-privilege access key,
    region/endpoint, and the tenant origin for CORS.
  - Step-by-step setup: create bucket/prefix, create credentials, configure CORS
    using `docs/operations/M5/web-s3-cors.md`, open `/settings/backup`, choose
    S3-compatible, enter endpoint/region/bucket/prefix, enter the access key and
    secret, enter a strong backup passphrase, run "Test connection", enable
    backup, and run "Back up now".
  - Link to M5 CORS and bucket-policy guidance instead of duplicating every
    provider-specific detail. Add only tenant-specific notes.
  - Exact-origin rule: the CORS allowed origin must be the tenant origin,
    including a custom domain. Changing domains requires updating CORS.
  - Client-side statement: credentials are held in browser secret storage, the
    passphrase is held only in memory, and neither is sent to ChatUI.
  - Passphrase-loss warning: losing the passphrase means losing access; ChatUI
    support cannot recover it.
  - No managed storage statement: ChatUI does not sell or operate storage in M6.
  - Links to M5 backup/restore evidence and the M5 README. Forward links to the
    hosted backup/restore, privacy, and provider-terms docs are allowed because
    later M6 tasks own them; M6-04.3 rechecks every forward link.
  - A checklist the user can complete before leaving the page.
