# UX-05.5 - Quiet autosave and truthful privacy copy

- Phase: UX-05 - Settings, data, and backup
- Status: Blocked
- Order: 33
- Depends on: UX-05.3, UX-05.4
- Output folder: `docs\operations\android-minimalist-design-plan`
- Parallel-safe: No with settings/data feedback or About copy edits.

## Goal

Stop routine settings emissions from queuing saved snackbars and reconcile
misleading privacy/backup wording without changing any persisted behavior.

## Read first

Read the [execution contract](README.md), source-plan sections 2 and
5.7, `SettingsUI\SettingsScreens.kt`, `SettingsUI\SettingsRoute.kt`,
`SettingsUI\SettingsViewModel.kt`, `SettingsUI\DataSettingsScreen.kt`,
`SettingsStore\AndroidSettings.kt`, and settings/data feedback tests.

## Owns

Settings autosave-feedback presentation/completion signals, narrowly related
data/About/privacy copy, and focused screen/ViewModel regressions. Settings
storage/defaults remain read-only.

## Deliverables

Quiet coalesced saved feedback, persistent actionable save errors, and copy
that accurately describes the existing remote-image/backup/privacy behavior.

## Implementation steps

1. Trace the existing "saved" effects and settings emissions. Initial load,
   collection restart, or unrelated settings emission must not announce a save.
2. Use real mutation completion/error signals for feedback. Coalesce only UI
   confirmation during rapid edits; keep the existing immediate persistence.
   Do not add a Save button or debounce writes as a cosmetic fix.
3. Keep an unobtrusive readable saved state where useful, with at most one
   appropriate announcement. A failed write must remain visible/actionable
   and must not be overwritten by a misleading success.
4. Remove any remaining duplicate data-operation result presentation while
   retaining UX-05.4's pending/cancel semantics.
5. Correct obsolete "backup unavailable" wording and privacy claims.
   `loadRemoteImages` currently defaults to true: explain actual controls/
   contacts accurately without changing defaults/resetting users. Record the
   spec/default discrepancy as separate product work.
6. Keep local-storage/BYOK copy honest about configured provider requests,
   enabled remote images, and optional backup destinations. Preserve plaintext
   export and passphrase-loss warnings; do not promise absolute offline behavior.
7. Add regressions for initial load, rapid mutations, recreation/recollection,
   failed write then retry, one operation result, truthful image/backup copy,
   and unchanged stored values.

## Acceptance criteria

- [x] No saved-snackbar queue on initialization or settings emissions.
- [x] Feedback tracks actual writes without staging/delaying persistence.
- [x] Errors are persistent and not masked by success.
- [x] Privacy/backup copy is accurate; defaults/preferences remain unchanged.

## Handoff notes

Implemented on 2026-11-17; **blocked on UX-05.3/UX-05.4 acceptance and
actual TalkBack announcement review (UX-06.2), owned by the Android maintainer.**

- Changed settings ViewModel/route/screens, related Data result ownership,
  backup encryption copy, and existing settings/data tests. Mutation
  completions, not the collected settings stream, increment save feedback.
  A mutex serializes immediate writes; only the unobtrusive UI confirmation
  waits 450 ms to coalesce rapid edits. There is no delayed persistence,
  staged value or new Save button.
- Initial load, recollection and unrelated emissions do not announce saves.
  Pending writes suppress a premature Saved message. Failed mutations are
  retained by mutation key for Retry; another successful field or catalog
  refresh cannot mask the error. A successful retry clears its own failure.
  Data operations have one result/error path (UX-05.4).
- About/privacy explains unencrypted local conversations, device-bound keys,
  direct provider requests, permitted image-host contacts, optional storage
  backup and readable plaintext exports. Backup copy distinguishes the
  memory-only passphrase from credentials used to authenticate to storage;
  it no longer claims storage credentials never leave the device.
- **Separate product decision, not implemented:** `loadRemoteImages` defaults
  to **true**, whereas the product specification describes blocked-by-default.
  This change corrects copy only. Neither default nor existing true/false
  values were changed or migrated. Passphrase-loss/plaintext warnings remain.
- Full **40-case settings** and **51-case backup** suites pass, including
  initialization/rapid writes/invalid values/failure/retry/single-result/copy
  cases; seven actual-shell settings-route cases pass. Lint passes.
  See the [verification record](README.md#ux-0506-verification-record) and
  UX-06.1's affected About/settings/data/backup goldens. JVM live-region
  assertions and images are not an actual screen-reader announcement review.
