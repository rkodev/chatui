# M2-01.2 - Web preset enablement and Custom providers

- Status: Complete
- Parent task: M2-01
- Order: 4
- Depends on: M2-01.1
- Parallel-safe: yes, with M2-05.2
- Owns: `web/src/providers/registry.ts`, `web/src/app/config.ts`, `web/public/config.json`, `web/src/features/providers/providerService.ts`, provider tests
- Read first: [M2 plan](../M2-providers-and-content-implementation-plan.md) sections 3.2, 3.8, and 4.3; spec sections 3.4, 5.3, 7.5, 8.3, 8.5

## Goal

Enable the launch OpenAI-compatible presets and Custom provider creation on web without exposing unsupported providers or bypassing contract validation.

## Preconditions

- M2-01.1 generic transport works.
- Contracts already contain every preset.

## Deliverables

- M2 preset enablement replacing the M1 OpenRouter-only gate.
- Runtime config that lists enabled presets and allows Custom provider creation.
- Registry availability labels for enabled, disabled, and coming-later presets.
- Custom provider form and service: base URL, auth type, optional non-secret headers, label.
- Validation for http(s) URLs, auth fields, duplicate labels, and forbidden secret headers.
- Secret storage remains separate from provider records.
- Tests for config validation, preset selection, Custom creation, and rollback on failure.

## Implementation steps

1. Read the current M1 gating in `registry.ts` and `config.ts`.
2. Replace `M1_ENABLED_PRESET_IDS` with an M2 enablement contract.
3. Update `web/public/config.json` to enable the launch presets.
4. Add a validated Custom provider path that does not mutate `contracts/providers.json`.
5. Add UI copy for disabled/coming-later presets if any remain.
6. Ensure Custom headers cannot contain secrets or overwrite auth headers.
7. Add tests for valid and invalid Custom providers.
8. Run web gates.

## Acceptance criteria

- [x] All launch OpenAI-compatible presets can be enabled without source edits.
- [x] Custom providers require base URL and auth style.
- [x] Non-secret custom headers are stored separately from keys.
- [x] Empty or invalid Custom input is rejected with actionable copy.
- [x] Provider record writes roll back when secret writes or persistence fail.
- [x] OpenRouter remains the default and required preset.
- [x] No native adapters or attachment work is added.
- [x] Web gates pass.

## Verification

```bash
make web-lint && make web-typecheck && make web-test && make web-build
```

## Out of scope

- Anthropic, Gemini, and Ollama adapters.
- Custom provider import from a file.
- Attachment and conversation data work.

## Completion record

- Replaced the M1 OpenRouter-only gate with `M2_ENABLED_PRESET_IDS` in
  `web/src/providers/registry.ts`. The M2 list covers OpenRouter, OpenAI, Groq,
  Mistral, DeepSeek, xAI, Together, Fireworks, LM Studio, llama.cpp, and Custom.
  Anthropic, Gemini, and Ollama remain in contracts but are labelled
  `coming-later`.
- Added `available`, `disabled`, and `coming-later` availability states.
  `getPresetAvailability` and `getEnabledPresets` now accept the deployment's
  runtime allow-list.
- Updated `web/src/app/config.ts` to validate the M2 allow-list, require
  OpenRouter as the contract default and required preset, reject duplicate or
  unknown presets, reject native-adapter presets, and require `custom` in
  `enabledPresets` exactly when `allowCustomProviders` is true.
- Updated `web/public/config.json` to enable every launch OpenAI-compatible
  preset and allow Custom providers.
- Added `ProviderService.createPresetProvider` for enabled OpenAI-compatible
  presets and `ProviderService.createCustomProvider` for Custom providers.
  Custom creation validates http(s) base URLs, auth style, key presence,
  duplicate labels, and forbidden authentication headers. Non-secret headers
  live on the provider record; keys live only in the secret store.
- Added rollback: a failed secret write leaves no provider record, and a failed
  provider write deletes the newly written secret.
- Added `CustomProviderForm` and wired it into the provider list when
  `allowCustomProviders` is true. Updated provider-list and onboarding copy for
  available, disabled, and coming-later presets.
- Added tests for config validation, M2 preset selection, Custom creation,
  invalid input, duplicate labels, forbidden headers, and both rollback paths.
- Verification: `make web-lint && make web-typecheck && make web-test && make web-build`
  passed. `web-test` ran 70 files / 578 tests.

## Handoff notes

- M2 enabled preset list: `openrouter`, `openai`, `groq`, `mistral`, `deepseek`,
  `xai`, `together`, `fireworks`, `lmstudio`, `llamacpp`, `custom`.
- Custom provider contract fields: `label`, `baseUrl`, `authType` (`bearer`,
  `x-api-key`, or `none`), optional `apiKey`, optional non-secret `headers`, and
  `rememberKeys`. The provider record stores `presetId: "custom"`, the base URL,
  auth type, headers, and `secretId`; it never stores the key.
- Config schema changes: no new fields. `enabledPresets` now accepts the M2
  OpenAI-compatible presets, and `allowCustomProviders` is allowed when
  `custom` is also listed in `enabledPresets`.
- Provider UI beyond the Custom creation form and availability copy remains for
  M2-01.3, which owns the full provider list/detail UI for enabled presets.
