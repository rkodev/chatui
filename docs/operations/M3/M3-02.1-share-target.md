## Goal

Accept `ACTION_SEND` `text/plain` shares from other apps, including warm starts, and prefill a composer without losing any existing draft.

## Preconditions

- M3-03.4 is complete so the shell navigation is stable.
- M3-00.2 records the share-target draft behavior.
- Do not log or persist shared text beyond the local draft store.
- Do not add file/image sharing.

## Deliverables

- Manifest share `intent-filter` for `ACTION_SEND` with `text/plain`.
- `singleTop` launch behavior so warm-start shares reach `onNewIntent`.
- A pure share-intent parser with tests.
- An application-scoped external-intent channel that survives activity recreation long enough to be consumed once.
- Shell handling that creates a new conversation, stores the shared text as its draft, and navigates to it.
- Proof that existing drafts are unchanged.

## Implementation steps

1. Read `MainActivity.kt`, `ChatUiApp.kt`, `ShellScaffold`, `ShellNavHost`, `ChatDestination`, `ConversationService.createConversation`, and `ChatDependencies.drafts`.
2. Add to the `MainActivity` element:
   - `android:launchMode="singleTop"`;
   - an `<intent-filter>` with `ACTION_SEND`, `CATEGORY_DEFAULT`, and `MIME type="text/plain"`.
3. Create `ShareTextParser` with a pure function:
   - return `null` unless action is `ACTION_SEND`;
   - accept `text/plain` only;
   - read `Intent.EXTRA_TEXT` as a string;
   - trim; reject empty/blank text;
   - cap the accepted length at a documented limit.
4. Create an application-scoped `ExternalIntentRouter` with a `StateFlow` of a pending sealed action. Keep it out of Compose state.
5. In `MainActivity.onCreate`, parse the launch intent and submit it. Override `onNewIntent`, call `setIntent(intent)`, parse, and submit.
6. In `ShellScaffold` or `ChatUiApp`, collect the pending action after the NavController exists:
   - resolve `ConversationService` through the existing `ConversationEntryPoint`;
   - call `createConversation()`;
   - if the result is configured, set the draft through the shared `ChatDrafts` instance resolved from `ChatEntryPoint`;
   - navigate to `ChatDestination.createRoute(conversationId)`;
   - consume the pending action exactly once.
7. If conversation creation returns `NotConfigured`, navigate to onboarding/providers and show the existing actionable state; do not drop the text silently.
8. Ensure repeated delivery of the same intent does not create duplicate conversations. Use a stable intent key or a consumed flag.
9. Add tests for parser valid/invalid cases, one-time consumption, navigation callback, and draft preservation.
10. Record a manual device share check in the handoff.

## Handoff notes

### Implementation

- `MainActivity` is `singleTop` and registers an `ACTION_SEND` / `text/plain` filter.
- `ShareTextParser` is a pure parser that trims text, rejects blank/non-text/non-send intents, and caps accepted text at 20,000 characters.
- `ExternalIntentRouter` is a Hilt singleton with a `StateFlow<ExternalIntentAction?>`. It ignores a repeated action while pending and after it was consumed, so a redelivered intent cannot create a second conversation.
- `ExternalIntentHandler` creates a new conversation, writes the shared text to that conversation's draft through the shared `ChatDrafts` instance, and returns the chat route. Existing drafts are never touched.
- `ChatUiApp` collects the pending action after `rememberNavController()` exists. A `NotConfigured` result navigates to onboarding or providers and leaves the action pending so the text is not silently dropped.

### Decisions

- A share always opens a new conversation, matching the M3-00.2 decision. This is what keeps the active composer and every other draft unchanged.
- The parser truncates over-limit text rather than rejecting it, so a large share still reaches the composer.
- The router deduplicates by a stable text-derived key. Two consecutive shares of identical text are treated as the same intent; a different share is accepted immediately.
- No shared text, intent key, or draft content is logged.

### Manual device share check

- Cold start: `adb shell am start -a android.intent.action.SEND -t text/plain -p dev.chatui --es android.intent.extra.TEXT shared_text_cold` launched `dev.chatui/.MainActivity`.
- Warm start: the same command while the activity was running reported `intent has been delivered to currently running top-most instance` and the activity stayed resumed, confirming `singleTop` / `onNewIntent` delivery.
- No fatal exception appeared in logcat. The emulator's System UI was unresponsive during `uiautomator dump`, so the composer text itself was verified by the handler/draft tests rather than a visual dump.
