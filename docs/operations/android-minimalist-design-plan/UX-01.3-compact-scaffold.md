# UX-01.3 - Compact scaffold title bar

- Phase: UX-01 - Calm foundations
- Status: Not started
- Order: 6
- Depends on: UX-01.1, UX-01.2
- Output folder: `docs\operations\android-minimalist-design-plan`
- Parallel-safe: Yes with UX-01.4 if changes stay out of shared theme/app files.

## Goal

Add a stable compact title-bar option to the existing scaffold so chat no
longer needs an unwired 96 dp expanded header.

## Read first

Read the [execution contract](README.md), source-plan sections 3, 5.1,
and 9, `DS\ChatUiScaffold.kt`, `DSTests\ComponentsTest.kt`, and
`Shell\ChatUiApp.kt` as a read-only consumer reference.

## Owns

- `DS\ChatUiScaffold.kt` and its `DSTests\ComponentsTest.kt` coverage.
- Minimal shared layout-token additions only if not already provided.
- No production shell adoption; UX-02.2 and UX-02.3 own it.

## Deliverables

An explicit compact scaffold variant retaining the scaffold's existing slots,
snackbar ownership, accessibility hooks, and inset behavior.

## Implementation steps

1. Read the current expanded/collapsed height logic and existing call sites.
   Add an explicit compact mode/style rather than pretending an unrelated
   `rememberScrollState()` represents a destination's `LazyColumn`.
2. In compact mode, target a 64-72 dp minimum with subtitle and about 56 dp
   without, excluding system insets. Permit growth for font scaling/long text.
3. Preserve title/subtitle click hooks, navigation/action slots, test tags,
   snackbar host, and content padding contracts.
4. Keep the model/title hit area at least 48 dp and reachable independently
   of transcript scrolling. Avoid large-title collapse or separator animation
   work in the compact path.
5. Retain a compatible default/legacy path for consumers not adopted yet.
   Do not add a second nested scaffold or consume IME/system padding twice.
6. Add cases for subtitle/no-subtitle, long title, 200% font, compact height,
   and unchanged content/snackbar inset placement.

## Acceptance criteria

- [ ] Compact mode has no 96 dp expanded-title floor or dummy-scroll coupling.
- [ ] Text grows rather than clips; model interaction remains reachable.
- [ ] Existing consumers still compile and their default behavior is preserved.
- [ ] Insets/snackbar/action slots remain owned once.
