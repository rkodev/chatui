## Handoff notes

- Import limits: `MAX_IMPORT_BYTES` is 50 MiB and is checked against the file size and the UTF-8 text length before `JSON.parse`. `MAX_IMPORT_ATTACHMENT_BYTES` is 20 MiB per decoded attachment. Attachment names are limited to 255 characters and reject path separators, Windows-reserved characters, control characters, leading/trailing whitespace, `.`, and `..`. SHA-256 values must be 64 hex characters; base64 bytes must match both the declared size and SHA-256.
- Merge/replace semantics: merge is the default and upserts by id without deleting local records. Re-importing the same archive is idempotent. Models merge by `(providerId, remoteId)`; if a local model already has that identity under a different id, imported conversation/message/settings references are remapped to the local id. Settings merge only writes keys that are absent locally, so local preferences win. Replace clears conversations, messages, attachments, providers, models, and settings inside the same transaction that writes the archive, then removes orphaned attachment bytes. Secrets, backup config, and the sync queue are not touched.
- Invalid-import evidence: `importService.test.ts` covers valid round trip, shared contract fixture schema acceptance, invalid JSON/schema, oversized input, duplicate IDs/model identities, unsafe attachment names, dangling references, byte/size/SHA mismatches, merge idempotence, model-id remapping, settings merge, and replace cleanup. Every invalid case asserts the local record counts are unchanged. `DataImportPanel.test.tsx` covers merge default, replace confirmation/cancel, replace success, and error display.
- Entry points: `ImportService` in `web/src/features/settings/importService.ts`; `createImportService()` in `importServiceFactory.ts`; `DataImportPanel` on `/settings/data`; `DataSettingsScreen` now creates export and import services from one IndexedDB connection.
