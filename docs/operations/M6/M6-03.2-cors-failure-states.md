## Goal

Document the tenant-specific CORS requirements and a user-facing failure-state
matrix for BYO storage, including custom domains, without duplicating all
canonical provider detail from M5.

## Preconditions

- `M6-03.1` is `Complete` and the onboarding guide exists.
- Use the M5 CORS doc as the canonical source; add only tenant/custom-domain
  specifics.
- Do not imply CORS is authorization. The bucket policy still controls access.

## Deliverables

- `docs/hosting/cors-and-failures.md`:
  - Link to `docs/operations/M5/web-s3-cors.md` as the canonical CORS and bucket
    policy source.
  - Exact-origin rule: use the tenant origin, for example a subdomain or custom
    domain. Avoid `*` for production.
  - Required methods, request headers, exposed headers (`ETag`), and max age,
    stated once and linked to M5 for the provider examples.
  - Preflight explanation: the browser sends `OPTIONS`; the bucket answers it;
    the app does not send it directly.
  - Custom-domain change checklist: update CORS allowed origins, public config
    `openRouter.attributionOrigin`, and any provider-side origin restrictions.
    Keep the old origin only during a migration window, then remove it.
  - Failure-state matrix with columns: symptom, likely cause, user action,
    operator action, and evidence/test reference. Cover at minimum:
    - Invalid or expired access key -> `auth`.
    - Key exists but lacks bucket permissions -> `permission`.
    - Missing `ListBucket` on connectivity test -> `permission`.
    - Bucket or prefix does not exist -> `not_found`.
    - CORS/preflight blocked before the request is sent.
    - Wrong endpoint, DNS, TLS, or offline -> `network`.
    - Provider outage, throttling, or 5xx -> `server`.
    - Concurrent manifest write or precondition failure -> `conflict`.
    - `ETag` missing after `PUT`.
    - Eventual consistency or stale reads.
    - Wrong region for a SigV4 endpoint.
  - Provider notes for AWS S3, Cloudflare R2, MinIO, and Backblaze B2, linking
    M5 for full details.
  - Security notes: credentials stay client-side, use a dedicated bucket or
    prefix, CORS is not authorization, and no plaintext is uploaded.
  - A short "how to reproduce safely" section using MinIO and synthetic data.

## Implementation steps

1. Read the M5 CORS doc and the storage error types.
2. Read the S3 adapter and tests to confirm the error mapping.
3. Write the tenant-specific CORS rules and custom-domain checklist.
4. Build the failure-state matrix from the actual typed error codes.
5. Add provider notes that link rather than copy the canonical M5 details.
6. Add the safe reproduction procedure with MinIO and synthetic data.
7. Check every claim against the adapter code and tests.
