- Status: Complete

- Depends on: M2-00.2
- Parallel-safe: yes, with M2-05.1

- Read first: [M2 plan](../M2-providers-and-content-implementation-plan.md) sections 3.2 and 4.3; spec sections 7.1, 7.3, 7.5, 7.6, 7.9

## Goal

Extract a preset-driven OpenAI-compatible transport from the OpenRouter implementation while preserving OpenRouter behavior exactly.

## Preconditions

- M2-00.2 expected vectors and request vectors are complete.
- Do not add Custom provider UI in this task.

## Deliverables

- One adapter surface for key validation, model discovery, and chat streaming parameterized by a provider preset.
- Preset-driven base URL, auth headers, attribution headers, default headers, and model-discovery format.
- Request builder that uses the shared request vectors.
- Error, retry, cancellation, and SSE behavior that preserves M1 OpenRouter semantics.
- Preset runtime context that carries only the provider id, base URL, auth type, headers, and API key.
- Tests for OpenAI-compatible text, usage, errors, retry, cancellation, and protected fields.
- OpenRouter regression suite remains green.

## Implementation steps

1. Read the existing `openrouter.ts`, `openrouterStream.ts`, `sse.ts`, and `retry.ts`.
2. Introduce a generic OpenAI-compatible transport without changing normalized event shapes.
3. Move OpenRouter-specific behavior behind a preset/adaptor configuration object.
4. Keep attribution header behavior only where the preset declares attribution headers.
5. Build request bodies from the shared request vectors and the model's supported parameters.
6. Preserve OpenRouter in-stream error handling, reasoning deduplication, and usage mapping.
7. Add adapter tests against OpenAI fixtures and rerun OpenRouter tests.
8. Run web gates.

## Acceptance criteria

- [x] The OpenAI-compatible transport is preset-driven, not OpenRouter-named.
- [x] OpenRouter behavior and tests are unchanged.
- [x] OpenAI text, usage, retry, cancellation, and error fixtures pass.

- [x] `make web-lint && make web-typecheck && make web-test && make web-build` passes.

  for key validation, model discovery, and chat streaming. It owns request
  serialization, auth/default/attribution headers, SSE mapping, error mapping,
  retry, cancellation, and usage normalization.
- Added `web/src/providers/openaiCatalog.ts` for the OpenAI `/models` format and
  `web/src/providers/presets.ts` to convert contract presets into transport
  presets. `web/src/providers/openrouterPreset.ts` binds the OpenRouter preset.
- Reduced `web/src/providers/openrouter.ts` and
  `web/src/providers/openrouterStream.ts` to preset-bound wrappers so every M1
  import and behavior stays stable.
- Updated `web/src/features/providers/runtime.ts` to build a context containing
  only the provider id, base URL, auth style, non-secret headers, and API key.
- Added `web/src/providers/openaiCompatible.test.ts` covering OpenAI request
  vectors, text/reasoning/usage streams, HTTP and in-stream errors, retry,
  cancellation, protected fields, auth headers, key validation, discovery, and
  the adapter surface. Added `web/src/features/providers/runtime.test.ts` for
  the preset runtime context.
- Verification: `make web-lint && make web-typecheck && make web-test && make web-build`
  passed. `web-test` ran 69 files / 552 tests, including the unchanged
  OpenRouter regression suite.
- No native adapters, attachment UI, preset enablement, or Custom provider UI
  were added.

## Handoff notes

- Generic adapter entry points: `createOpenAICompatibleAdapter(preset)` and the
  unbound `validateKey`, `listModels`, `loadCatalog`, `refreshCatalog`, and
  `streamChat` exports from `web/src/providers/openaiCompatible.ts`.
- Preset fields consumed: `id`, `displayName`, `baseUrl`, `auth`,
  `defaultHeaders`, `attributionHeaders`, `modelDiscovery`, `keyValidation`,
  `extraNamespace`, `extraMode`, `extraPassthroughFields`, `reasoningStyle`, and
  `messages`.
- Derived OpenRouter compatibility notes: OpenRouter is a preset with
  `extraMode: 'curated'`, `extraPassthroughFields` of `provider`, `models`,
  `route`, and `reasoning`, `reasoningStyle: 'openrouter'`, and the original M1
  error copy. The transport also accepts `delta.reasoning_content` and maps
  OpenAI stream error `type` values to HTTP-like statuses; both are additive and
  leave the OpenRouter fixtures unchanged.
- M2-01.2 can replace the M1 enablement gate and use
  `createOpenAICompatibleAdapter` for each enabled preset. M2-01.3 can extend
  discovery defaults, fallback selection, and reasoning UI without changing the
  transport surface.
