## Handoff notes

- Search service API: `ConversationService.searchConversations(query, limit)` returns
  `List<ConversationSearchResult>`. `DefaultConversationService` combines
  `ConversationRepository.searchByTitle` (escaped `LIKE` over active titles) with
  `MessageRepository.searchWithConversations` (FTS4 `MATCH` joined to
  `conversations` in SQLite). Archived conversations are excluded.
- Result grouping: one `ConversationSearchResult` per conversation with
  `titleMatched` plus newest-first `messageMatches` (message id, sequence, role,
  snippet, createdAt). Results are ordered pinned-first, then by
  `lastMessageAt`, and capped at `limit`.
- Debounce/cancellation: `ConversationListViewModel` debounces 300 ms, cancels
  the previous job on every keystroke, and checks a generation counter before
  applying a result.
- UI: the sidebar search field renders loading, empty, error/retry, and grouped
  result states. Each result shows the title, a title-match marker, and up to
  three message snippets. Selecting a result opens the conversation.
- FTS safety: user input is reduced to letters/digits/underscores and emitted as
  prefix terms, so quotes, parentheses, `NEAR`, and `-` cannot break the query.
  FTS4 uses implicit AND between adjacent prefix terms.
- Verification: `make android-lint && make android-test && make android-assemble`
