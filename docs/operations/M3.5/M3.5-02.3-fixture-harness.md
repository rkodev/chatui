## Goal

Create a reusable fixture harness over `contracts/fixtures/**` so every later adapter, parser, catalog, and export task tests against the same shared oracle.

## Preconditions

- Domain and contract types exist.
- Do not implement provider adapters in this task.
- Do not copy fixture content into Rust source or rewrite expected vectors.
- Do not modify `contracts/`, `web/`, or `android/`.

## Deliverables

- A `chatui-conformance` test package that loads fixtures from `contracts/` at test time using repository-relative paths.
- Typed loaders for:
  - stream fixtures under `contracts/fixtures/streams/`;
  - model fixtures under `contracts/fixtures/models/`;
  - error fixtures under `contracts/fixtures/errors/`;
  - request vectors under `contracts/fixtures/requests/`;
  - expected vectors under `contracts/fixtures/expected/`.
- Assertions for fixture inventory counts and expected-vector shape.
- A documented conformance API that later tasks can call.
- `docs/operations/M3.5/conformance.md` describing how to add a conformance case.

## Implementation steps

1. Read `contracts/fixtures/expected/README.md` and `contracts/fixtures/requests/README.md`.
2. Add a helper that resolves the repository root from `CARGO_MANIFEST_DIR` and loads files from `contracts/`.
3. Implement typed loaders. For stream expectations, model the shared shape:
   ```json
   {
     "source": "openrouter-text.sse",
     "events": [],
     "text": "",
     "reasoning": "",
     "retryAllowed": false
   }
   ```
4. Implement request-vector loaders for the four kinds: `chat-request`, `protected-fields`, `attribution`, and `default-model`.
5. Implement catalog, fallback, capability, math, and export loaders as needed by later tasks.
6. Add inventory tests that fail if a fixture or expected file is missing. Expected counts are: 14 presets, 5 schemas, 11 streams, 6 model fixtures, 28 error fixtures, 22 request vectors, and 21 expected vectors.
7. Add a test that every expected stream vector references an existing raw stream fixture.
8. Add a test that every request vector has a known kind and provider ID.
9. Add a test that `chatui-export.json` deserializes through `chatui-contracts`.
10. Document how later tasks add adapter-specific cases without editing the shared vectors.

## Acceptance criteria

- [ ] The conformance package is a workspace member and builds.
- [ ] All fixture families have typed loaders.
- [ ] Inventory counts are asserted.
- [ ] Every expected stream vector resolves to a real raw fixture.
- [ ] Request-vector kinds and provider IDs are validated.
- [ ] `chatui-export.json` loads through the contract types.
- [ ] `docs/operations/M3.5/conformance.md` explains how to add a case.
- [ ] No fixture or contract file is modified.

## Verification

```bash
cd rust && cargo fmt --all --check
cd rust && cargo nextest run -p chatui-conformance
```

## Out of scope

- Adapter-specific normalized-event assertions (added by provider tasks).
- Running a real provider.
- Editing shared vectors or the contract validator.
