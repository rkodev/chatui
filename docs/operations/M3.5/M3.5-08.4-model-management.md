# M3.5-08.4 - Model management, discovery UI, and model picker

- Milestone: M3.5
- Status: Not started
- Order: 31
- Depends on: M3.5-08.2, M3.5-06.1, M3.5-07.4
- Parallel-safe: yes, with M3.5-08.3
- Owns: `rust/crates/chatui-ui/src/models/`, model management and picker tests
- Read first: [M3.5 plan](../M3.5-rust-desktop-implementation-plan.md) sections 3.6 and 4.10; spec sections 3.3, 7.4, 7.8, 11.5

## Goal

Implement model discovery refresh, model list management, search, pinned/hidden state, capability and pricing display, manual model add, and the model picker.

## Preconditions

- Onboarding, catalog loading, and fallback/capability inference exist.
- Do not expose secrets or provider keys in model metadata.
- Do not rewrite provider model IDs.
- Do not modify `web/`, `android/`, or `contracts/`.

## Deliverables

- Model management screen:
  - provider grouping;
  - refresh discovery;
  - cached/fallback models on discovery failure;
  - pinned/hidden toggles;
  - manual add with `remoteId`, label, context, capabilities;
  - capability chips, context, modalities, per-million input/output price, free badge, source.
- Model picker:
  - search;
  - pinned models first;
  - provider groups;
  - default model indication;
  - unavailable model warning;
  - docs link from provider metadata.
- Empty/loading/error states with retry.
- Tests with fixture catalogs and fake adapters.

## Implementation steps

1. Read spec sections 3.3, 7.4, 7.8, and 11.5, plus `web/src/features/providers/ModelPickerDialog.tsx`, `modelService.ts`, and `features/settings/ModelsSettingsScreen.tsx`.
2. Build the model list view model over the model repository and discovery service.
3. Implement refresh. On failure, keep cached models and show a non-blocking notice with retry.
4. Implement search across label and `remoteId`. Keep pinned models first, then provider groups.
5. Implement pinned/hidden toggles and persistence.
6. Implement manual model add and edit where the spec requires it.
7. Display capabilities, context, modalities, price per million, free badge, and source.
8. Implement the picker's default model and unavailable-model states.
9. Add tests for search, grouping, pinned/hidden, discovery failure, manual add, free badge, price formatting, and unavailable selection.
10. Document the model management API and fallback behavior.

## Acceptance criteria

- [ ] Model discovery refresh works and preserves cached models on failure.
- [ ] Search, pinned-first ordering, and provider grouping work.
- [ ] Pinned/hidden state persists.
- [ ] Capability chips, context, modalities, price, and free badge render correctly.
- [ ] Manual model add works with validation.
- [ ] The picker shows the default model and unavailable states.
- [ ] Provider model IDs are not rewritten.
- [ ] Tests use fixture catalogs and fake adapters.
- [ ] No chat or conversation behavior is added.
