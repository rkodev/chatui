## Owns

## Deliverables

A reachable-action ledger covering all nine capability families and a short
decision record separating fixed design decisions, integration gaps, and
separately scoped product questions.

## Implementation steps

1. Record the revision and any existing local modifications. Do not revert
   them or use an old operations pack's completion status as current proof.
2. For each capability in section 6, record its present entry path, source
   owner, important consent/confirmation, proposed entry path, implementation
   task ID from the index, and required regression/evidence.
3. Distinguish reachable behavior from unused components and disabled
   placeholders. Explicitly record the Conversations placeholder, the model
   callback that opens Providers, unwired Manage models/curated routing, and
   duplicated attachment warnings.
4. Record the fixed placement rules: no bottom bar, full-screen compact Chats,
   840 dp permanent-sidebar breakpoint, one New chat per history host, model
   picker in the header, and secondary actions in More.
5. Record settings/theme propagation gaps and the `loadRemoteImages` true
   default versus contradictory copy/spec. Assign truthful copy to UX-05.5;
   leave any default change outside this program.
6. List platform precedence and confirmation invariants: onboarding/pending
   share or deep link/last-active restore, one-layer Back, import/restore modes,
   key removal, and clear-all/remote-delete exact confirmations.
7. Link every ledger row to an implementation owner and a UX-06 evidence
   owner. Do not declare an unused component or unperformed manual check done.
