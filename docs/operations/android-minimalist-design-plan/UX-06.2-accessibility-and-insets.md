## Goal

Verify that reduced chrome has not reduced discoverability, touch access,
readability, screen-reader support, or keyboard/Back usability.

## Read first

Read the [execution contract](README.md), source-plan section 8 and
section 10, UX-06.1's matrix, `AppTests\AccessibilityFocusTest.kt`,
`ShellInsetsTest.kt`, `ShellBackNavigationTest.kt`, `BackPolicyTest.kt`,
`KeyboardShortcutsTest.kt`, and `MotionHapticsThemeTest.kt`.

## Owns

Integrated accessibility/focus/inset regression cases in existing app/feature
tests and this task's manual evidence matrix. Return production defects to
their owning implementation tasks instead of accumulating an unbounded UI patch.

## Deliverables

Reviewed touch/contrast/font/focus/back/inset evidence, focused regressions
for integration gaps, and actual TalkBack/hardware-keyboard results.

## Implementation steps

1. Exercise 320 dp/200% fonts, 150% fonts, large display scaling, short
   landscape, both densities/themes, and dynamic-color/fallback combinations.
   Confirm wrapping, scrollable forms, minimum 48 dp targets, and measured
   4.5:1 normal-text/3:1 applicable large-text/control contrast.
2. With TalkBack, verify meaningful icon names and selected/expanded/disabled
   states, role identity, reading order, visible alternatives to gestures,
   and no duplicated decorative stops.
3. Verify response start/end/cancel/error announcements without per-token
   chatter or duplicate warnings. Test saved/error feedback after rapid edits.
4. With hardware keyboard, verify visible focus and shortcut/help access.
   Dismiss picker/dialog/editor and restore focus to its initiator without
   unexpectedly opening the IME.
5. Test layered Back with actual combinations: dialog over sheet, sheet over
   drawer, drawer with keyboard, then navigation. One action closes one layer;
   hierarchical Up returns correctly after canonical settings/provider entries.
6. Check gesture and three-button navigation, keyboard-visible composer/
   credential forms, snackbar Undo, rotation, and crossing 840 dp. Ensure
   system/IME insets are consumed once and actions never sit behind system UI.
7. Add only missing focused regressions and record manual results by actual
   device/API/configuration. Missing TalkBack/hardware/manual evidence keeps
   the required part blocked; semantics tests alone are not completion.

## Acceptance criteria

- [ ] Small/large-font layouts retain every action with accessible targets.
- [ ] Actual TalkBack and keyboard flows are understandable and operable.
- [ ] Focus, layered Back, reduced motion, and insets have reviewed evidence.
- [ ] No unresolved contrast/clipping/discoverability regression is waived silently.

Run affected feature tests only for newly added cases, and attach manual
TalkBack/keyboard/contrast results separately from automated output.

## Out of scope

Replacing accessibility services, removing actions to pass layout checks,
requiring gestures, or treating a device-unavailable result as a pass.
