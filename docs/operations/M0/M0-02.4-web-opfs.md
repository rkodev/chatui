## Goal

Implement content-addressed attachment byte storage with OPFS first and an IndexedDB Blob fallback. Do not build attachment UI.

## Preconditions

- The IndexedDB schema, `AttachmentRepository`, and `attachmentBlobs` store exist.
- Tests run under jsdom, where OPFS is not available by default.

## Deliverables

- `web/src/platform/capabilities.ts`:
  - detect OPFS availability without throwing
  - expose a stable capability result for tests and callers
- `web/src/platform/files.ts`:
  - a small filesystem abstraction so tests can inject a fake OPFS directory handle
  - functions for write, read, delete, list, and existence under an `attachments` directory
- `web/src/storage/AttachmentStore.ts`:
  - `put(bytes, sha256)` returns a `storageKey` of `attachments/<sha256>`
  - `get(storageKey)` returns bytes
  - `delete(storageKey)`
  - deduplication by SHA-256
  - OPFS as the primary backend
  - IndexedDB `attachmentBlobs` as fallback when OPFS is unavailable or fails
  - `cleanupOrphans(referencedSha256: Set<string>)` removing unreferenced OPFS files and fallback blobs
  - no provider uploads and no network calls
- Tests:
  - OPFS path with an injected fake directory handle
  - fallback path with a forced capability failure and fake-indexeddb
  - deduplication returns the same storage key
  - orphan cleanup removes only unreferenced bytes
  - read/delete behavior for missing keys is explicit and does not crash silently

## Implementation steps

1. Implement capability detection and the filesystem abstraction.
2. Implement the OPFS backend and test it with a fake handle.
3. Implement the IndexedDB fallback using the `attachmentBlobs` store keyed by SHA-256.
4. Implement orphan cleanup from a caller-provided referenced set.
5. Test both paths and the cleanup helper.
6. Run all web gates.

## Handoff notes

- The fallback store is the existing `attachmentBlobs` IndexedDB store keyed by the raw SHA-256 string. Records are `{ sha256, blob, size, createdAt }`; `AttachmentStore` writes and reads them only when OPFS is unavailable or an OPFS operation fails.
- Capability detection can be overridden per store with `new AttachmentStore({ db, capabilities: { opfs: false } })`. Tests also inject a fake OPFS implementation through `fileSystem`; passing `fileSystem: null` disables OPFS even when the capability result says it is available.
- `AttachmentStore` is intentionally not re-exported from `web/src/storage/index.ts` because that file is outside this task's scope. Import it from `web/src/storage/AttachmentStore.ts` until a later task updates the barrel.
- `cleanupOrphans(referencedSha256)` expects raw SHA-256 values, not storage keys, and returns the removed `attachments/<sha256>` keys. OPFS cleanup is best-effort; fallback blobs are always cleaned.
- Missing reads and deletes throw `AttachmentNotFoundError`; malformed keys throw `InvalidStorageKeyError`. No empty-byte or silent-success result is returned.
- Remaining for M2: attachment pickers, image downscaling, thumbnails, EXIF stripping, message rendering, and wiring `cleanupOrphans` to app startup.
