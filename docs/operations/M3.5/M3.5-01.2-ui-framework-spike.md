# M3.5-01.2 - UI framework spike and decision

- Milestone: M3.5
- Status: Not started
- Order: 4
- Depends on: M3.5-00.2, M3.5-01.1
- Parallel-safe: yes, with M3.5-02.1
- Owns: `docs/operations/M3.5/framework-decision.md`, `rust/spikes/ui-framework/` (temporary), `docs/operations/M3.5/M3.5-verification.md` (framework section)
- Read first: [M3.5 plan](../M3.5-rust-desktop-implementation-plan.md) sections 3.1 and 4.3; spec sections 10.2, 10.8, 10.9, 11.9, 11.11

## Goal

Lock the desktop UI framework before any feature UI, using a time-boxed comparison of Dioxus, Slint, Iced, and Tauri against the milestone's desktop, accessibility, performance, packaging, and testability needs.

## Preconditions

- The workspace exists and compiles.
- Do not build production UI or modify `chatui-ui` feature code in this task.
- Tauri is a comparison only. The milestone forbids a WebView-based production client.
- Do not modify `web/` or `android/`.

## Deliverables

- A temporary prototype under `rust/spikes/ui-framework/` that is not a member of the main workspace (use an empty `[workspace]` table or a detached manifest).
- `docs/operations/M3.5/framework-decision.md` with:
  - criteria and weights;
  - Dioxus, Slint, Iced, and Tauri comparison;
  - prototype results on the available OS;
  - accessibility, high-DPI, native menu, file dialog, clipboard, drag-and-drop, window-state, deep-link, and test-harness notes;
  - binary-size and build-time observations;
  - chosen framework, fallback, and reasons;
  - explicit note that Tauri cannot be selected without a spec change.
- A framework section in `M3.5-verification.md`.

## Implementation steps

1. Read spec sections 10.2, 10.8, 10.9, 11.9, and 11.11.
2. Create a detached spike package under `rust/spikes/ui-framework/`. Do not add it to the main workspace members. Keep the prototype minimal: one window, one text field, one button, one list, one native menu, and one file-picker call where the framework supports it.
3. Build and run the prototype on the available OS. Record the exact command and result.
4. Compare the frameworks against these criteria:
   - native desktop behavior on Windows, macOS, and Linux;
   - accessibility bridge and keyboard focus;
   - high-DPI and font scaling;
   - packaging support (MSI/DMG/AppImage/deb/rpm);
   - binary size and build time;
   - test harness and snapshot support;
   - native menus, dialogs, clipboard, drag-and-drop, window state, tray, multi-window, and deep-link hooks;
   - async integration with `tokio`;
   - dependency and unsafe surface.
5. Record Tauri's WebView architecture and why it is disqualified from production under the current milestone.
6. Choose a framework. The spec recommends Dioxus. If the spike shows a blocking issue, record the evidence and choose a fallback.
7. Record the decision in `framework-decision.md` and update `M3.5-verification.md`.
8. Keep the prototype if it is useful evidence; otherwise delete it after recording the decision. Do not leave it as a main workspace member.

## Acceptance criteria
