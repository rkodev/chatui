## Goal

Create the shared desktop UI foundation: tokens, themes, density, font size, reduced motion, focus-visible states, and the responsive shell with a persistent sidebar and narrow-window drawer.

## Preconditions

- The framework decision is recorded.
- Domain types exist.
- Do not build onboarding, provider, model, chat, or settings feature screens in this task.
- Do not add hidden network destinations.
- Do not modify `web/`, `android/`, or `contracts/`.

## Deliverables

- Rust token constants matching every semantic name in section 11.12.
- Light, dark, and system theme support.
- Density (`comfortable`, `compact`), chat font size (`sm`, `md`, `lg`), and reduced-motion handling.
- Focus-visible ring behavior and keyboard navigation primitives.
- Responsive shell:
  - persistent sidebar at desktop widths;
  - drawer or navigation stack at narrow widths;
  - placeholders for chat, history, providers, settings, and data areas.
- Minimal desktop app entry point that renders the shell.
- Tests or snapshots for tokens, theme switching, breakpoints, focus, and reduced motion.

## Implementation steps

1. Read the framework decision and spec sections 11.9, 11.11, and 11.12.
2. Implement `tokens.rs` with the shared semantic names. Keep names identical to the web/Android tokens where possible.
3. Implement theme selection for system/light/dark. Follow the OS theme when `system` is selected.
4. Implement density, chat font size, and reduced-motion settings as inputs to the shell.
5. Implement focus-visible rings and keyboard traversal. Every interactive element must be reachable.
6. Implement the responsive shell. Use a width breakpoint from section 11.9. Keep every destination reachable in both layouts.
7. Wire the shell into `apps/desktop`. Use fake or empty view models; do not add feature behavior.
8. Add tests or snapshots for token values, theme resolution, breakpoint behavior, focus, and reduced motion.
9. Document the shell API and any framework-specific constraints.

## Handoff notes

### Token API

- `tokens::Rgba` is an sRGB color with `rgb`, `from_rgba`, `from_hex`,
  `to_hex`, `to_slint`, `relative_luminance`, and `contrast_ratio`.
- `tokens::Tokens` carries every resolved value. `Tokens::light()` and
  `Tokens::dark()` mirror `web/src/styles/tokens.css` and `themes.css`.
- `tokens::TOKEN_NAMES` lists every semantic name from spec section 11.12,
  including the expanded `font.heading.*` names. `every_spec_token_name_exists`
  and `token_names_are_unique` guard the list.
- `tokens::DensityScale` mirrors the web comfortable/compact density contract.
- `tokens::ChatTypography` exposes `sm`, `md`, and `lg` chat text sizes.
- `tokens::Motion` exposes standard and reduced durations.

### Theme behavior

- `theme::ThemeSettings` wraps the domain `Theme`, `Density`, and
  `ChatFontSize` preferences plus `ReducedMotion`.
- `ThemeSettings::resolve_theme(system_is_dark)` follows the OS for
  `Theme::System` and ignores it for explicit light/dark.
- `ThemeSettings::tokens`, `density_scale`, `chat_typography`, `motion`, and
  `reduced_motion` resolve the rest of the appearance contract.
- `ReducedMotion::System` follows the OS; `Reduce` and `NoPreference` override
  it.
- The Slint `NavItem` background animation uses the `reduced-motion` property:
  0 ms when reduced, 120 ms otherwise.

### Breakpoints and shell API

- Breakpoints: `< 600 px` drawer, `600-839 px` collapsible sidebar,
  `840-1279 px` persistent sidebar, `>= 1280 px` persistent sidebar plus params
  panel. Constants are `NARROW_BREAKPOINT`, `COMPACT_BREAKPOINT`, and
  `WIDE_BREAKPOINT`.
- `shell::ShellState` is framework-independent state. `sidebar_visible`,
  `drawer_visible`, `toggle_sidebar`, `navigate`, `set_width`, `focus_order`,
  and `handle_key` implement the layout policy.
- `shell::Destination` lists Chat, History, Providers, Settings, and Data with
  labels, accessible labels, stable focus ids, and placeholder copy.
- `shell::ShellController` owns the state and the Slint `ShellWindow`, wires
  `navigate`, `toggle-sidebar`, `close-drawer`, and `width-changed`, and keeps
  the window in sync through `sync_window`.
- `shell::theme_tokens`, `density_tokens`, and `chat_tokens` convert Rust
  values to the Slint structs.

### Accessibility

- `accessibility::FocusRing` comes from the active tokens.
- `accessibility::FocusOrder` provides first/last/next/previous/focus-by-id,
  pointer-focus suppression, and Tab/Shift+Tab/arrow/Home/End/Enter/Space/Escape
  handling.
- `accessibility::Focusable` requires an accessible label, so icon-only
  controls cannot be added without a name.
- The Slint `NavItem` uses `FocusScope`, `focus-changed-event` with
  `FocusReason.tab-navigation` for the focus-visible ring, and
  `accessible-role: button` plus `accessible-label`. The narrow top bar menu
  button is labelled "Toggle navigation".

### Framework constraints

- Slint 1.18.1 is used per the M3.5-01.2 decision. The shell markup lives in an
  inline `slint::slint!` block in `shell.rs` so the task stays inside its owned
  source paths; there is no separate `.slint` file or build script.
- `i-slint-backend-testing` is used with `init_no_event_loop()` for headless
  window creation. Element introspection (`ElementHandle`) requires
  `SLINT_EMIT_DEBUG_INFO=1` at build time, so the tests use generated property
  getters and callbacks instead of element queries. This keeps the fixed
  verification command working without a global debug-info build setting.
- `cargo run --manifest-path rust/apps/desktop/Cargo.toml` opens a real window
  and blocks by design. Use `-- --smoke` for an unattended run that exits after
  1.5 s.
- No feature screens, network calls, or hidden destinations were added. The
  destinations render placeholder copy only.
