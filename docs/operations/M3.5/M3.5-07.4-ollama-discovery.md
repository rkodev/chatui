## Goal

Implement Ollama's native NDJSON chat and `/api/tags` discovery, plus shared fallback-model selection and capability inference for presets whose discovery is missing or degraded.

## Preconditions

- OpenAI-compatible preset behavior exists.
- Do not fork provider logic per OS.
- Do not use the OpenAI-compatible path as the only Ollama implementation; native NDJSON is primary.
- Do not modify `web/`, `android/`, or `contracts/`.

## Deliverables

- Ollama native adapter:
  - `POST /api/chat` with NDJSON;
  - system prompt as the first message;
  - text/file concatenation;
  - image base64 arrays;
  - `options` for sampling controls;
  - `num_predict` for max output tokens;
  - final usage from `prompt_eval_count` and `eval_count`.
- Ollama discovery at `/api/tags` mapped into the shared `Model` shape.
- A documented OpenAI-compatible fallback for custom local servers.
- Shared discovery fallback selection:
  - use the preset default model when present in the catalog;
  - otherwise select the first non-hidden text model by `remoteId`;
  - when the catalog is empty, use the first fallback preset model;
  - emit the exact shared unavailable/fallback notices.
- Capability inference from preset defaults when the provider omits modalities, capabilities, context, or supported parameters.
- Tests against Ollama request, stream, error, tags, fallback, and capability vectors.

## Implementation steps

1. Read `web/src/providers/ollama.ts`, `fallbackModels.ts`, `openaiCatalog.ts`, and the shared fallback/capability vectors.
2. Implement Ollama native base URL handling: strip the trailing `/v1` from the contract base URL when using `/api/*`.
3. Implement `POST /api/chat` with NDJSON. Parse each line as JSON in the adapter, not the transport.
4. Map `message.content` to text deltas, `done` and `done_reason` to finish, and `prompt_eval_count`/`eval_count` to usage.
5. Map images to the message `images` array as base64. Concatenate file parts with the shared file header.
6. Map sampling controls under `options`; `maxOutputTokens` maps to `num_predict`; `stop` maps to `stop`.
7. Implement `/api/tags` discovery and map names to models with preset defaults.
8. Implement fallback selection and notices exactly as the request-vector README specifies.
9. Implement capability inference in the shared order `text`, `vision`, `files`, `tools`, `reasoning`, `streaming`.
10. Add tests for NDJSON completion, usage, errors, tags, fallback present/missing/no-text cases, and capability inference.
11. Run the shared conformance suite.

## Handoff notes

- Native protocol mapping: `POST /api/chat` with `stream: true`. The system
  prompt is the first message. Text and text-file parts concatenate into
  `message.content` with the shared `\n\n[File: name]\n` header. Images become
  the `message.images` base64 array. Sampling controls live under `options`;
  `maxOutputTokens` maps to `num_predict`, `stop` maps to `stop`, and
  `temperature`/`top_p` are emitted only when supported. Advanced JSON under
  `params.extra.ollama` is forwarded except for the protected fields `model`,
  `messages`, `stream`, and `stream_options` and the transport selectors
  `transport`/`mode`.
- Base URL handling: `ollama_native_base_url` strips a trailing `/v1` (and
  trailing slashes) so native calls use `/api/chat` and `/api/tags` at the
  server root. Discovery derives its URL from the resolved base URL rather than
  the contract's absolute discovery path, so a user-configured remote Ollama
  server works.
- Stream mapping: each NDJSON line is parsed in the adapter. `message.content`
  becomes `text-delta`, `message.thinking` becomes `reasoning-delta`, `done`
  and `done_reason` become `finish`, and `prompt_eval_count`/`eval_count`
  become `usage`. `done_reason` maps `stop` -> `stop`, `length` -> `length`,
  `content_filter` -> `content_filter`, `tool_calls` -> `tool_calls`, and
  anything else -> `unknown`. A stream that starts but never reports `done`
  finishes with `unknown`; an empty 200 response is a parse error.
- Errors: Ollama's `{ "error": "message" }` and
  `{ "error": { "message": ... } }` envelopes both normalize. HTTP 404 maps to
  `model_not_found`, 5xx to `provider` (retryable), and in-stream errors are
  never retryable. No key is sent because the preset auth type is `none`.
- Discovery: `GET /api/tags` maps `model` (or `name`) to `remoteId`, uses the
  Ollama text-only preset defaults, and hides IDs containing `embed`.
- Fallback selection: `fallback_model_ids_for` returns the shared explicit
  lists for `openai`, `anthropic`, `google`, and `ollama`, an empty list for
  `openrouter`, and the contract default for every other preset.
  `select_fallback_model` implements the shared order and emits the exact
  notices: `Discovery unavailable; using fallback model <id>.`,
  `Discovery unavailable; no fallback model is available.`,
  `Default model <id> is unavailable; using <id>.`, and
  `Default model <id> is unavailable; no text model is available.`
- Capability inference: raw values win; missing modalities and supported
  parameters use preset defaults; missing limits stay `None`; missing
  capabilities are derived in the order `text`, `vision`, `files`, `tools`,
  `reasoning`, `streaming`.
- OpenAI-compatible fallback: a custom local server uses the shared
  OpenAI-compatible adapter through its own preset. The Ollama preset can also
  opt in per request with `params.extra.ollama.transport` (or `mode`) set to
  `openai-compatible`; the selector is stripped before the request is sent.
- Test names: `registry_enables_ollama`,
  `every_ollama_request_vector_matches_through_the_adapter`,
  `ollama_native_urls_strip_the_v1_suffix`,
  `every_ollama_stream_vector_matches_through_the_adapter`,
  `every_ollama_http_error_vector_matches_through_the_adapter`,
  `ollama_in_stream_error_matches_the_shared_vector`,
  `ollama_catalog_maps_the_shared_vector`,
  `ollama_capability_inference_matches_the_shared_vector`,
  `fallback_model_ids_match_the_shared_vector`,
  `fallback_selection_matches_the_shared_vector`,
  `ollama_validate_key_is_a_no_op`,
  `ollama_openai_compatible_fallback_uses_the_shared_transport`,
  `ollama_cancellation_before_first_token_returns_cancelled`,
  `ollama_cancellation_after_first_token_preserves_partial_text`,
  `ollama_retry_allowed_before_partial_output`,
  `ollama_retry_not_allowed_after_partial_output`.
- Deviation: the contract's Ollama `modelDiscovery.path` is an absolute
  `http://localhost:11434/api/tags` URL. The adapter ignores that absolute path
  and derives `/api/tags` from the resolved base URL so custom hosts work. The
  contract file is unchanged.
