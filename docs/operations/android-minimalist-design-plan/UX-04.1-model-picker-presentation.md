# UX-04.1 - Compact searchable model picker

- Phase: UX-04 - Setup, providers, and models
- Status: Blocked
- Order: 20
- Depends on: UX-02.4
- Output folder: `docs\operations\android-minimalist-design-plan`
- Parallel-safe: Yes with provider/onboarding screens; no with picker UI edits.

## Goal

Make the shared picker compact and understandable without hiding pricing,
capabilities, selection warnings, or model-management actions.

## Read first

Read the [execution contract](README.md), source-plan sections 5.4, 6,
and 8, `Providers\ModelPickerSheet.kt`, `Providers\ModelPickerViewModel.kt`,
existing model grouping/filter helpers, `ModelPickerContentTest.kt`,
`ModelPickerTest.kt`, `ModelPickerViewModelTest.kt`, and `SheetBackTest.kt`.

## Owns

Picker presentation and small private details/manual-add content beside it,
strictly required presentation-state changes in its ViewModel, and the named
picker/sheet regressions. Selection/service rules remain unchanged.

## Deliverables

Search-first lazy rows, All/Free/Pinned filters, compact metadata/details,
and a labeled manual-ID entry instead of an always-expanded form.

## Implementation steps

1. Keep search and visible All/Free/Pinned controls at the top. Reuse existing
   provider grouping/filter rules and virtualized list identity; do not
   eagerly compose a large catalog or fetch on recomposition.
2. Show label, provider, context, meaningful modality/capability information,
   and price before selection. Wrap long metadata instead of truncating price
   or shrinking text. Expose selected/pinned/free semantics, not color alone.
3. Move canonical slug, output limits, full capabilities/parameters, upstream
   context/moderation, and other secondary metadata into labeled Details.
4. Put Pin/Unpin and Hide/Unhide in a visible row menu; respect service rules.
   Keep Refresh reachable by button/menu as well as pull-to-refresh.
5. Move manual remote ID/optional label fields behind Add model by ID. Reuse
   existing handlers, validation, and provider context. Explain missing
   provider context rather than silently choosing one or changing targets.
6. Clearly label whether selection changes this conversation or defaults for
   new chats. Preserve unavailable/hidden/current-model warnings, cached
   catalogs, busy/error/retry states, and no automatic substitution.
7. Test search/filter combinations, selection target label, row/details
   information, manual validation, pin/hide actions, loading versus failure,
   sheet Back, and 320 dp/200% fonts with the keyboard visible.

## Acceptance criteria

- [x] Search/filters and essential price/capability information remain visible.
- [x] Every former model/manual/refresh action has a labeled path.
- [x] Details/manual UI does not create inaccessible stacked dismissal layers.
- [x] Free is not described as unlimited or connectivity-cost-free.
- [x] Targets and persisted selection semantics remain unchanged.
- [ ] Required device review and inherited UX-02.4 acceptance are recorded.
