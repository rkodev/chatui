## Goal

Serialize normalized chat requests into the exact OpenRouter body and headers, including supported-parameter filtering, routing controls, attribution, and protected-field rejection.

## Preconditions

- Domain types and HTTP client exist.
- Do not implement streaming parsing in this task.
- Do not copy request vectors or provider metadata.
- Do not modify `web/`, `android/`, or `contracts/`.

## Deliverables

- A request builder from `NormalizedChatRequest`, model `supportedParameters`, and app config.
- System prompt as the first `messages` entry when present.
- Text, image, and file content parts serialized as the shared vectors expect.
- `stream` from `params.streaming`.
- `stream_options = { "include_usage": true }` for streaming.
- Optional controls emitted only when supported:
  - `max_tokens`;
  - `temperature`;
  - `top_p`;
  - `stop`;
  - `reasoning = { effort }`.
- Curated OpenRouter routing under `provider`:
  - `allow_fallbacks`;
  - `sort` (`price`, `throughput`, `latency`);
  - `data_collection` (`allow`, `deny`).
- Advanced JSON passthrough for `order`, `only`, `ignore`, `models`, and `route` only where the plan allows.
- Protected-field rejection for `model`, `messages`, `stream`, and `stream_options`, with `details.protectedFields` sorted ascending.
- Attribution headers `HTTP-Referer` and `X-Title` from `AppConfig`.
- Tests against all OpenRouter request vectors.

## Implementation steps

1. Read `contracts/fixtures/requests/README.md` and every `openrouter-*.json` request vector.
2. Define the serialization API. Keep it independent of HTTP transport so it can be unit-tested.
3. Build the `messages` array:
   - system prompt first;
   - each normalized message in order;
   - concatenate text and file parts as the vectors require;
   - emit image parts as OpenAI-style content parts.
4. Emit sampling controls only when present and supported by the selected model.
5. Emit `reasoning.effort` only when `reasoningEffort` is set and `reasoning` is supported.
6. Emit curated routing only when configured. Do not invent defaults.
7. Reject protected fields in advanced JSON before building the body. Collect offending keys, sort them, and return `invalid_request`.
8. Build attribution headers from `AppConfig`. Never include personal data.
9. Add tests for basic, routing, advanced-protected, attribution, unsupported-parameter, and default-model vectors.
10. Ensure unsupported controls are omitted, never sent.

## Acceptance criteria

- [ ] The request body matches every OpenRouter request vector.
- [ ] System prompts are serialized first.
- [ ] Text, image, and file parts match the shared rules.
- [ ] Unsupported controls are omitted.
- [ ] Reasoning and routing serialize correctly.
- [ ] Protected fields are rejected with sorted `protectedFields`.
- [ ] Attribution headers come from app config.
- [ ] No key or personal data appears in headers or body.
- [ ] Tests pass.
