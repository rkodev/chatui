## Goal

Review the composed production experience, including chrome, navigation, and
small-window states that standalone screenshot fixtures cannot establish.

## Read first

Read the [execution contract](README.md), source-plan sections 3-5 and
10, UX-00.2's fixtures/captures, all screen-lane endpoint handoffs,
`Screenshots\ScreenshotTest.kt`, `Shell\ChatUiApp.kt`,
`Shell\AdaptiveShell.kt`, and `Shell\ShellNavHost.kt`.

## Owns

Existing screenshot harness/test-only fixtures and narrowly required captures
under `android\app\src\test\screenshots`, plus reviewed comparison evidence.
Production fixes return to the owning implementation task.

## Deliverables

Deterministic actual-shell goldens, a representative coverage matrix, and
reviewed before/after differences mapped to intentional design changes.

## Implementation steps

1. Reuse UX-00.2's injected fake services and real shell/navigation. Keep useful
   standalone goldens but label them; do not use `ScreenshotSidebar` or a
   fallback chat header as proof of the production composition.
2. Cover real Chats root, chat/header/composer, drawer/permanent sidebar,
   missing setup/error, model picker/manual/details, provider create/detail/
   management, conversation advanced settings, onboarding/optional backup,
   settings/data, and backup overview/config/recovery.
3. Use representative pairwise combinations: 320 x 568, 360 x 640, 411 x 891,
   640 x 360 dp, 840 dp breakpoint and wider; both themes/densities and 100%/
   150%/200% fonts. Specifically capture narrow chat/picker/credential forms
   with large text and keyboard/inset conditions supported by the harness.
4. Include long names/prices/errors, attachments, code/reasoning/tables, and
   relevant loading/empty/pending/error states. Freeze clocks, fake streams,
   data, and motion; use invented content/credentials only.
5. Inspect current diffs before selectively recording intentional new goldens.
   Record a reason for changed title/action/width placement; do not approve
   clipping, missing controls, wrong themes, or duplicate warnings as expected.
6. Link reviewed comparisons and uncovered manual-only states to UX-06.2/
   UX-06.5. Reopen an owning task for defects rather than hiding them by
   blanket golden regeneration.

## Acceptance criteria

- [x] Production compact/expanded composition is actually captured.
- [x] Matrix includes large-font/short-window and sensitive-form edge cases.
- [ ] Each changed golden has reviewed intent; no unexplained regression.
- [x] No real content/secrets and no claims that screenshots prove device speed.


Use the existing Roborazzi recording workflow only for reviewed intentional

## Out of scope

New screenshot frameworks, screenshot-only alternate layouts, unreviewed
mass recording, or functional/performance acceptance by image similarity alone.

Review covered all theme/density variants using contact sheets and full-size
edge cases. Intentional changes are one title/action owner, real compact Chats,
calmer transcript chrome, wrapping controls, new settings groups, ordinary data
actions first, focused secure forms and status-first backup. Twenty-two
existing standalone PNGs were selectively updated: root/Appearance/chat-default/
About/data phone+tablet, plus real onboarding backup setup. The remaining
standalone foundation/picker cases are labeled as such, not counted as shell
proof. Theme/density overrides in static captures are not proof of preference
application; `SettingsRouteTest` separately checks live application.

Review corrections include enum-accurate swatches, waiting for catalog labels
rather than raw IDs, scrolling to the actual Extras editor, real resource font
scale for separate modal windows, and clearing draft focus before static stream
captures so cursor blink is not a golden difference. Image fixtures serialize
result publication on Main while fetching/decoding remains IO; every image
variant waits for all four real swatches and uses a fixed list anchor. Pending
attachment captures wait for decoded thumbnail pixels rather than a blank
placeholder. This changes neither production loaders nor image tolerances.

Recording and separate verification scopes/results are in the
[verification record](README.md#ux-0506-verification-record). New functional
or visual failures are not excused by recording; older unrelated chat/history/
shell expectations remain unchanged and keep the full gate red. Generated
comparison/report files are ignored under `android\app\build`; only intended
goldens are source artifacts.

Screenshots do not render a real IME or establish TalkBack, hardware keyboard,
gesture/three-button navigation, lifecycle, contrast measurements, speed or
usability. Those remain UX-06.2/06.4/06.5, and the final visual acceptance
criterion stays open while the upstream/full-gate issues remain.
