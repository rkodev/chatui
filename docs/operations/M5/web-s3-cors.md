# Web S3-compatible bucket CORS

The web client talks directly to the user's bucket. There is no server proxy, so
the bucket must allow browser cross-origin requests from the ChatUI origin. CORS
is not authorization: the access key still needs the bucket permissions listed
below, and every object the client writes is already encrypted.

## Required CORS configuration

| Setting | Value |
| --- | --- |
| Allowed origins | The exact ChatUI origin, for example `https://chatui.example.com`. Avoid `*` for a production bucket. |
| Allowed methods | `GET`, `PUT`, `HEAD`, `DELETE` |
| Allowed request headers | `authorization`, `x-amz-date`, `x-amz-content-sha256`, `x-amz-security-token`, `content-type`, `if-match`, `if-none-match` |
| Exposed response headers | `ETag`, `Last-Modified`, `x-amz-request-id`, `x-amz-version-id` |
| Max age | `3600` seconds or less |

`OPTIONS` preflight requests are generated by the browser and must be answered
by the bucket's CORS layer. The adapter does not send `OPTIONS` itself.

`ETag` must be exposed. The adapter captures it from `PUT` and `HEAD` responses
and sends it back as `If-Match` on manifest rewrites. Without the exposed
header, the browser hides the value and conditional writes cannot be used.

## AWS S3 example

CORS configuration:

```json
[
  {
    "AllowedOrigins": ["https://chatui.example.com"],
    "AllowedMethods": ["GET", "PUT", "HEAD", "DELETE"],
    "AllowedHeaders": [
      "authorization",
      "x-amz-date",
      "x-amz-content-sha256",
      "x-amz-security-token",
      "content-type",
      "if-match",
      "if-none-match"
    ],
    "ExposeHeaders": ["ETag", "Last-Modified", "x-amz-request-id", "x-amz-version-id"],
    "MaxAgeSeconds": 3600
  }
]
```

Least-privilege bucket policy for a dedicated backup bucket. Replace the
account, user, bucket, and prefix with your own values:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "ChatUIBackupObjects",
      "Effect": "Allow",
      "Principal": {
        "AWS": "arn:aws:iam::123456789012:user/chatui-backup"
      },
      "Action": ["s3:GetObject", "s3:PutObject", "s3:DeleteObject"],
      "Resource": "arn:aws:s3:::chatui-backup/chatui/*"
    },
    {
      "Sid": "ChatUIBackupListBucket",
      "Effect": "Allow",
      "Principal": {
        "AWS": "arn:aws:iam::123456789012:user/chatui-backup"
      },
      "Action": ["s3:ListBucket"],
      "Resource": "arn:aws:s3:::chatui-backup",
      "Condition": {
        "StringLike": {
          "s3:prefix": ["chatui/*"]
        }
      }
    }
  ]
}
```

The connectivity test performs `HEAD` on the bucket. If the policy omits
`s3:ListBucket`, the test can return `permission` even when object reads and
writes would work. Grant `s3:ListBucket` scoped to the backup prefix, or expect
the connectivity test to report a permission error.

## Provider notes

### AWS S3

- Use the regional endpoint, for example `https://s3.us-east-1.amazonaws.com`.
  The adapter defaults to virtual-hosted-style URLs for AWS endpoints.
- Set the bucket region in the adapter configuration. A wrong region produces
  `auth` or `server` errors from SigV4.
- Conditional writes with `If-Match` and `If-None-Match` are supported. A
  failed precondition returns `409` or `412`, which the adapter maps to
  `conflict`.
- Apply the CORS configuration above in the bucket's Permissions tab or with
  `put-bucket-cors`.

### Cloudflare R2

- Use the S3 endpoint `https://<account-id>.r2.cloudflarestorage.com` and the
  `auto` region unless your account documents a different value.
- The adapter defaults to path-style URLs for R2.
- Configure CORS in the R2 bucket settings. R2 supports the same method and
  header names as S3.
- Verify conditional write support in your account. The adapter sends
  `If-Match`/`If-None-Match` and maps `409`/`412` to `conflict`; if a provider
  ignores the precondition, the sync engine must still re-read before rewriting
  the manifest.

### Contabo Object Storage

- Use the region-specific S3 endpoint shown in the Contabo console, for example
  `https://eu2.contabostorage.com`.
- The adapter defaults to path-style URLs.
- CORS support and conditional write behavior vary by region and plan. Check
  the provider documentation and run the connectivity test before saving the
  configuration.
- If the provider does not expose `ETag`, the adapter re-reads with `HEAD` after
  a write. If the provider also ignores conditional headers, treat conflicts as
  best-effort and rely on the sync engine's re-read and retry.

### MinIO

- Use the MinIO server URL, for example `https://minio.example.com`, and the
  bucket name. The adapter defaults to path-style URLs.
- Configure CORS with `mc cors set` or the MinIO console. A minimal policy:

  ```json
  {
    "CORSRules": [
      {
        "AllowedOrigins": ["https://chatui.example.com"],
        "AllowedMethods": ["GET", "PUT", "HEAD", "DELETE"],
        "AllowedHeaders": [
          "authorization",
          "x-amz-date",
          "x-amz-content-sha256",
          "x-amz-security-token",
          "content-type",
          "if-match",
          "if-none-match"
        ],
        "ExposeHeaders": ["ETag", "Last-Modified"],
        "MaxAgeSeconds": 3600
      }
    ]
  }
  ```

- MinIO supports conditional writes. A local MinIO instance is the recommended
  smoke test for the web adapter.

### Backblaze B2 (S3-compatible API)

- Use the S3 endpoint `https://s3.<region>.backblazeb2.com`, for example
  `https://s3.us-west-004.backblazeb2.com`.
- The adapter defaults to path-style URLs.
- Create an application key restricted to the backup bucket. B2 application
  keys are not the same as the account master key.
- Configure CORS rules on the bucket with the B2 CLI or the web console. B2's
  S3-compatible API supports the standard method and header names, but verify
  `ETag` exposure and conditional write behavior for your account.
- If `ETag` is not returned, the adapter performs a `HEAD` re-read after the
  write.

## Troubleshooting

| Symptom | Likely cause |
| --- | --- |
| Browser blocks the request before it is sent | The origin is missing from the bucket CORS rules, or `OPTIONS` is not allowed. |
| `auth` on every request | Wrong access key, secret, region, or endpoint. |
| `permission` on `testConnection` | The key lacks `s3:ListBucket` on the bucket, or the bucket policy is too narrow. |
| `conflict` on manifest rewrite | Another device wrote the manifest first. Re-read and retry. |
| `ETag` is `undefined` after `PUT` | The bucket does not expose `ETag` in CORS, or the provider omits it. The adapter falls back to `HEAD`. |
| `network` error | DNS, TLS, offline, or the bucket endpoint is unreachable. |

## Security notes

- Credentials and the backup passphrase stay in the browser. Do not put them in
  a proxy, a server log, or a task file.
- The adapter only accepts `Uint8Array` bodies. Callers must encrypt with the
  backup envelope codec before writing; no plaintext upload path exists.
- CORS controls which browser origins may call the bucket. It does not replace
  IAM or bucket-policy authorization.
- Use a dedicated bucket or prefix for ChatUI backups so a leaked key has a
  narrow blast radius.
