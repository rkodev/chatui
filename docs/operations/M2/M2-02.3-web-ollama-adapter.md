## Goal

Implement native Ollama NDJSON chat and `/api/tags` discovery, with the OpenAI-compatible path as a fallback for custom local servers.

## Preconditions

- M2-00.1 Ollama expected vectors exist.
- M2-01.1 generic transport is available.

## Deliverables

- Native `/api/chat` NDJSON streaming.
- Native `/api/tags` discovery and model mapping.
- OpenAI-compatible fallback for custom local servers.
- Ollama error, retry, cancellation, and usage mapping.
- `OLLAMA_ORIGINS` documentation for browser access.
- Fixture tests and adapter registration.

## Implementation steps

1. Read the Ollama NDJSON and tags fixtures.
2. Implement a bounded NDJSON reader that handles partial lines and final flush.
3. Map `done`, `done_reason`, prompt/eval counts, and durations to normalized events and usage.
4. Implement `/api/tags` discovery and model naming.
5. Select the OpenAI-compatible fallback when the preset or user configuration requires it.
6. Document `OLLAMA_ORIGINS` and local cleartext expectations.
7. Add tests for NDJSON completion, errors, cancellation, discovery, and fallback.
8. Register the adapter without regressing other providers.
9. Run web gates.

## Acceptance criteria

- [ ] Ollama NDJSON completes and records usage.
- [ ] `/api/tags` discovery maps models correctly.
- [ ] The fallback path is selected deterministically.
- [ ] Errors, retry, and cancellation follow the shared contract.
- [ ] `OLLAMA_ORIGINS` is documented.
- [ ] Web gates pass.
