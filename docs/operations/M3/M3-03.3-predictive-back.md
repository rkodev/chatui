# M3-03.3 - Predictive back ordering

- Milestone: M3
- Status: Complete
- Order: 12
- Depends on: M3-03.1, M3-03.2
- Parallel-safe: no; shares shell and chat files
- Owns: `android/app/src/main/java/dev/chatui/shell/`, `android/feature/chat/ChatScreen.kt`, dialog/sheet call sites, back-navigation tests
- Read first: [M3 plan](../M3-android-depth-implementation-plan.md) sections 3.2 and 4.3; spec sections 9.3, 9.10, and 3.8

## Goal

Make back always close the topmost layer before leaving the screen, with predictable ordering and no double navigation.

## Preconditions

- M3-03.1 and M3-03.2 are complete.
- Android predictive-back callback is already enabled in the manifest; keep it enabled.
- Do not change the destination graph or introduce new screens.

## Deliverables

- A single ordered back policy: dialog or sheet -> drawer -> keyboard -> navigation.
- Explicit handlers for every overlay and for the drawer.
- Tests proving each layer closes before the next.
- No double pop or accidental app exit when a dialog/sheet is open.

## Implementation steps

1. Read `AndroidManifest.xml` (`enableOnBackInvokedCallback`), `ShellNavHost`, `ShellScaffold`, `ConversationListScreen`, `ChatScreen`, `ConversationSettingsSheet`, `ModelPickerSheet`, and chat dialogs.
2. Define the priority order explicitly in the shell/chat:
   - confirmation/dialog;
   - modal bottom sheet;
   - conversation drawer;
   - keyboard (let the system IME consume it where applicable);
   - navigate back.
3. Use `BackHandler` (and `PredictiveBackHandler` only if the Compose version supports it without an experimental opt-in that breaks the build) with `enabled` conditions tied to state.
4. Ensure a sheet/dialog `onDismissRequest` and the back handler share the same close function so they cannot both pop navigation.
5. Add tests that open each layer, invoke back, and assert only that layer closes. Cover:
   - delete/rename dialog;
   - conversation settings sheet;
   - model picker sheet;
   - conversation drawer;
   - plain navigation back.
6. Run on a device/emulator with gesture back if available and record the result.

## Acceptance criteria

- [x] Back closes a dialog before a sheet, drawer, or navigation.
- [x] Back closes a sheet before a drawer or navigation.
- [x] Back closes the drawer before navigating.
- [x] Keyboard back is not intercepted by the app.
- [x] No double pop or app exit occurs with an overlay open.
- [x] Predictive-back callback remains enabled.

## Out of scope

- Hardware keyboard shortcuts (M3-03.4).
- Changing drawer/sidebar layout (M3-03.1).
- Changing dialog content or business logic.

## Handoff notes

- Added `BackPolicy.kt` in the shell with the fixed order `Dialog -> Sheet -> Drawer -> Keyboard -> Navigation`. `appHandlesBack` returns false for the IME and navigation so the app never intercepts keyboard back.
- Dialogs and modal sheets are separate windows and already consume back through their `onDismissRequest` callbacks. Added fallback `BackHandler`s at each call site that share the same close function, so a fallback can never both close the overlay and pop navigation.
- The shell drawer keeps Material3's predictive-back callback. The shell's own drawer `BackHandler` is registered before `AdaptiveShell` as a fallback, so the predictive animation is not replaced.
- Added `androidx.activity.compose` to the providers module for the sheet fallback handlers.
- Tests added: `BackPolicyTest`, `ShellBackNavigationTest` (drawer, sheet-before-drawer, plain navigation, root back), `ConversationListBackTest` (rename/delete dialogs), `SheetBackTest` (conversation settings, nested delete confirmation, model picker), and `ChatScreenBackTest` (send confirmation).
- Verification:
  - `make android-lint` - passed.
  - `make android-test` - passed.
  - `make android-assemble` - passed.
  - `cd android && ./gradlew :app:connectedDebugAndroidTest` - passed on `Medium_Phone_API_36.1(AVD) - 16`.
- Manual gesture-back check was not performed separately; the instrumentation suite ran on the API 36.1 emulator. The manifest still has `android:enableOnBackInvokedCallback="true"` and `ShellManifestTest` covers it.
