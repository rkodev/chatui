## Goal

Implement model discovery refresh, model list management, search, pinned/hidden state, capability and pricing display, manual model add, and the model picker.

## Preconditions

- Onboarding, catalog loading, and fallback/capability inference exist.
- Do not expose secrets or provider keys in model metadata.
- Do not rewrite provider model IDs.
- Do not modify `web/`, `android/`, or `contracts/`.

## Deliverables

- Model management screen:
  - provider grouping;
  - refresh discovery;
  - cached/fallback models on discovery failure;
  - pinned/hidden toggles;
  - manual add with `remoteId`, label, context, capabilities;
  - capability chips, context, modalities, per-million input/output price, free badge, source.
- Model picker:
  - search;
  - pinned models first;
  - provider groups;
  - default model indication;
  - unavailable model warning;
  - docs link from provider metadata.
- Empty/loading/error states with retry.
- Tests with fixture catalogs and fake adapters.

## Handoff notes

- Model UI states: management mode includes hidden rows and shows pin/hide,
  manual add, refresh, counts, and source; picker mode excludes hidden rows,
  applies search, marks the default model, and shows the unavailable warning and
  provider docs link. Loading, empty, and error states are exposed; the error
  state has a retry action.
- Discovery/fallback behavior: a successful refresh upserts by
  `(provider_id, remote_id)` and preserves local ID, pinned, hidden, source, and
  manual label/metadata. A failed refresh keeps cached models and returns a
  non-blocking notice. An empty cache uses the preset fallback list marked
  `metadata.fallback = true` with `source = preset`. No fallback returns the
  discovery error.
- Search rules: case-insensitive match on label, `remote_id`, and canonical
  slug. Pinned models form the first group; remaining models are grouped by
  provider label and sorted by label then `remote_id`.
- Provider model IDs are copied from the catalog and never rewritten.
- Manual add validates a non-empty unique `remote_id`, rejects a zero context
  window, defaults an empty label to `remote_id`, and defaults empty
  capabilities/modalities to text.
- Deviation: manual model edit is not implemented because spec section 7.8 only
  requires manual add. The web reference also only implements add.
- Deviation: the picker's selection action is "Set default" because
  per-conversation routing is out of scope for this task.
- Documentation: `rust/crates/chatui-ui/src/models/README.md` records the API,
  refresh/fallback behavior, search/grouping rules, validation, display rules,
  and security boundary.
