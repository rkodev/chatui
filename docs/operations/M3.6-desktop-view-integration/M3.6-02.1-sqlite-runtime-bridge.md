# M3.6-02.1 - SQLite runtime, secrets, and sync bridge

- Milestone: M3.6
- Status: Complete
- Order: 2
- Depends on: none
- Parallel-safe: yes, with M3.6-01.1
- Owns: `rust/apps/desktop/src/services/`, `rust/apps/desktop/Cargo.toml`, `rust/apps/desktop/src/main.rs` (module declaration only)
- Read first: [M3.6 plan](PLAN.md) sections 3 and 4; `rust/crates/chatui-storage/src/db.rs`; `rust/crates/chatui-storage/src/recovery.rs`; `rust/crates/chatui-secrets/src/encrypted_file.rs` (`select_store`); `rust/crates/chatui-ui/src/settings/service.rs` (`RepositorySettingsPersistence`)

## Goal

Add the desktop service foundation: a shared `tokio` runtime, database open and
migration, startup recovery, repository construction, explicit secret-store
selection, and a reusable synchronous bridge over the async storage traits.

## Preconditions

- `chatui-storage`, `chatui-secrets`, and `chatui-providers` are workspace
  crates.
- Do not open the real user database in tests. Use `open_in_memory` or a
  temporary directory.
- Do not log, render, or persist secret values.
- Do not modify `web/`, `android/`, or `contracts/`.

## Deliverables

- `rust/apps/desktop/src/services/` module with:
  - a `ServiceRuntime` that owns a `tokio::runtime::Runtime`, a `SqlitePool`,
    and the shared repositories;
  - database bootstrap that opens the default database, runs migrations,
    verifies pragmas and FTS5, and runs startup recovery;
  - a `block_on` helper for local synchronous UI services;
  - a secret-store selection helper that uses `chatui_secrets::select_store`
    with an explicit fallback decision and returns a user-safe error when the
    choice is unresolved;
  - a synchronous `SettingsStore` adapter over `SqliteSettingsRepository` and a
    generic helper usable by later adapters.
- Tests using an in-memory or temporary database for bootstrap, migrations,
  recovery wiring, settings round-trip, and secret-store selection errors.
- A documented decision in `Completion record` for the default secret fallback.

## Implementation steps

1. Add `tokio`, `chatui-providers`, and `chatui-secrets` to the desktop
   dependencies. Keep existing dependency versions.
2. Create `src/services/mod.rs` and declare it from `main.rs`.
3. Build `ServiceRuntime::open()` that:
   - creates a multi-thread runtime;
   - opens the database with `open_default_database` on the runtime;
   - runs migrations, pragma verification, FTS5 verification, and recovery;
   - constructs `SqliteProviderRepository`, `SqliteModelRepository`,
     `SqliteConversationRepository`, `SqliteMessageRepository`,
     `SqliteSettingsRepository`, `SqliteSecretRepository`, and the attachment
     store.
4. Add `ServiceRuntime::block_on` and a `SyncSettingsStore` implementing the
   `chatui_ui::settings::SettingsStore` trait.
5. Add a secret-store selector that maps the fallback choice to `select_store`
   and returns `SecretError` without exposing values.
6. Decide and document the desktop default: OS keyring when available, else
   an explicit prompt or session-only mode. Do not silently write plaintext.
7. Add tests for database bootstrap, settings round-trip, and unavailable
   secret-store handling.
8. Do not construct feature controllers in this task.

## Completion record

- Status: Complete
- Secret fallback decision: OS keyring when available. When it is unavailable,
  `select_store` returns `SecretError::FallbackRequired`, which the desktop
  helper maps to `SecretStoreError::FallbackRequired`. Onboarding (`M3.6-06.1`)
  must prompt the user to choose the encrypted-file fallback or session-only
  mode. There is no silent plaintext fallback. `session_only_secret_store()`
  resolves the explicit session-only choice.
- Commands and results:
  - `cd rust && cargo fmt --all --check` - passed.
  - `cd rust && cargo clippy -p chatui-desktop --all-targets -- -D warnings` -
    passed.
  - `cd rust && cargo nextest run -p chatui-desktop` - 76 tests passed, 0
    skipped.
- Known limitations:
  - `ServiceRuntime` is declared from `main.rs` but not composed into the
    running app; composition is `M3.6-06.1`.
  - `SyncBridge::block_on` must not be called from inside an async task on the
    same runtime. The Slint thread is synchronous, so local SQLite work is safe.
  - `chatui-providers` is added for later adapters but is not used yet.
  - `sqlx` is a direct desktop dependency so `ServiceRuntime` can name
    `SqlitePool`; it uses the same version and features as `chatui-storage`.

## Handoff notes

- Later adapters must reuse `ServiceRuntime` and must not create a second
  runtime or pool.
- Record the exact secret fallback so `M3.6-06.1` can wire the onboarding gate.
- The recorded fallback is: OS keyring when available; otherwise
  `SecretStoreError::FallbackRequired` and an explicit user choice between the
  encrypted-file fallback and session-only mode.
- Reuse `ServiceRuntime::bridge()` for later synchronous adapters and
  `ServiceRuntime::settings_store()` for the settings adapter.
