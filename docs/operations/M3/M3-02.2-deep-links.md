- Milestone: M3

## Goal

Open `chatui://chat/<id>` links in the matching conversation or the existing safe not-found state.

## Preconditions

- M3-02.1 external-intent channel exists.
- Do not add HTTPS app-link verification in this task.
- Do not auto-create a conversation for an unknown link.

## Deliverables

- Manifest `VIEW`/`BROWSABLE` filter for scheme `chatui`, host `chat`, path prefix.
- A pure deep-link parser that validates scheme, host, and conversation ID.
- Cold-start and warm-start routing through the external-intent channel.
- Safe handling for malformed links and missing conversations.
- Deep-link tests.

## Implementation steps

1. Read `MainActivity`, the M3-02.1 intent router, `ChatDestination`, `ShellNavHost`, `ChatScreen` not-found state, and `ConversationService.getConversation`.
2. Add a manifest intent filter on `MainActivity`:
   - action `android.intent.action.VIEW`;
   - category `DEFAULT` and `BROWSABLE`;
   - scheme `chatui`;
   - host `chat`;
   - `pathPrefix="/"`.
3. Add `DeepLinkParser`:
   - accept only `chatui://chat/<id>`;
   - require exactly one non-empty path segment;
   - reject extra query-based secrets or unexpected paths;
   - validate the ID length and character set used by UUIDv7 IDs;
   - return `null` for malformed links.
4. Route a valid ID through the external-intent channel:
   - if onboarding is incomplete, finish onboarding first and keep the link pending;
   - otherwise navigate to `ChatDestination.createRoute(id)`.
5. Do not call `createConversation`; a missing conversation must render the existing not-found state.
6. Ensure repeated delivery of the same link does not navigate twice.
7. Add tests:
   - manifest filter exists;
   - valid link parses;
   - wrong scheme/host, empty ID, extra segment, and invalid characters are rejected;
   - cold-start and warm-start routing;
   - missing conversation shows not-found;
   - onboarding gating.
8. Record an `adb` deep-link check in the handoff:
   ```bash
   adb shell am start -a android.intent.action.VIEW -d "chatui://chat/<id>" dev.chatui
   ```

## Acceptance criteria

- [x] The link is not handled before onboarding when onboarding is incomplete.

## Handoff notes

### Implementation

- `MainActivity` now registers a `VIEW` / `BROWSABLE` filter for `chatui://chat/...` alongside the existing share filter. The activity remains `singleTop`, so warm links arrive through `onNewIntent`.
- `DeepLinkParser` is a pure parser. It accepts only `ACTION_VIEW` intents with scheme `chatui`, host `chat`, exactly one non-empty path segment, and a canonical UUIDv7 id. Query strings, fragments, user info, explicit ports, extra segments, wrong schemes/hosts, and non-UUIDv7 ids return `null`.
- `ExternalIntentIntake` converts an activity intent into one `ExternalIntentAction`. Share intents keep precedence; otherwise a valid deep link becomes `ExternalIntentAction.OpenChat`.
- `ExternalIntentRouter` deduplicates `OpenChat` by conversation id, so repeated delivery of the same link is ignored while pending and after consumption.
- `ExternalIntentHandler` routes `OpenChat` without calling `createConversation` or `getConversation`. A missing conversation therefore reaches the existing `ChatScreen` not-found state.
- When onboarding is incomplete, `OpenChat` returns `OpenOnboarding` and leaves the action pending. The shell's `LaunchedEffect` is keyed on `settings.onboardingCompleted`, so the link is handled after onboarding finishes.
- No conversation content, prompt, or secret is placed in the URL or logged.

### Decisions

- A trailing slash after the id is treated as the same single path segment because `Uri.pathSegments` collapses it. Extra segments are still rejected.
- Deep links are validated against the same canonical UUIDv7 pattern used for local entity ids (`isUuidV7`), so arbitrary route strings cannot be injected through the link.
- The parser rejects any query string rather than trying to allow-list parameters. This prevents a link from smuggling tokens or other data.
