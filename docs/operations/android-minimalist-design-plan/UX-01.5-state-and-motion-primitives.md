- Phase: UX-01 - Calm foundations
- Status: Complete

## Goal

Make the existing shared loading, feedback, and motion tools suitable for a
quiet, inexpensive UI before screens adopt them.

## Deliverables

Static/low-cost loading states, distinct loading/failure/cancellation
presentation contracts, and reduced-motion-safe shared feedback.

## Implementation steps

1. Reuse `EmptyState`, `ErrorState`, `InlineBanner`, skeleton, and button
   primitives. Remove unnecessary nested decoration rather than replacing the
   component kit or adding a new notification framework.
2. Allow static skeleton/loading treatment without a permanent shimmer loop.
   Preserve cached content during refresh where the consumer supplies it.
3. Keep one error presentation owner possible: short actionable copy with
   optional Details/Retry, no mandatory duplicate snackbar.
4. Keep purposeful transitions short (normally 100-180 ms) and make all shared
   animation helpers respect OS reduced motion. Do not globally disable native
   navigation/sheet accessibility behavior.
5. Ensure pending buttons reject duplicate activation while their labels,
   errors, and cancellation remain distinguishable. A pending state is not
   success and does not erase the user's input.
6. Add focused component/motion tests for static loading, reduced motion,
   pending/error transitions, long messages, and accessible action labels.
   Confirm foundation APIs from UX-01.1 through UX-01.4 compose together.

## Acceptance criteria

- [x] Screens can show one calm loading/error state without continuous effects.
- [x] Reduced motion applies to the shared helpers used by later tasks.
- [x] Pending, success, failure, and cancellation remain distinguishable.
- [x] Foundation changes preserve targets, theme flags, and scaffold contracts.

## Out of scope

Bulk migration of every feature state, changing network retry/persistence,
or implementing chat-specific scroll/stream behavior.

## Handoff notes

- Skeletons are static by default; optional animation respects
  `LocalReducedMotion`. Existing empty/error/banner APIs remain available
  without a mandatory second snackbar. Loading buttons retain their labels,
  disable duplicate activation, and expose pending state.
- Shared standard transitions are short (120/160 ms, with 180 ms transition
  primitives). Reduced-motion helpers return the supplied modifier rather
  than dropping caller semantics/layout. Native sheet/navigation behavior is
  not globally disabled by production code.
- Executed full design-system tests (51 passed) and lint (no errors).
  Component/motion cases cover pending-to-enabled behavior, long labels,
  static loading, reduced-motion specs, and preserved modifiers.
- Foundation candidates exercise the Android animator-setting read path:
  scale 1 at 100%/150% text and scale 0 at 200%, with no explicit theme
  reduced-motion override. Both themes/densities are captured and the
  resolved motion value is asserted. See the
  [verification record](README.md#ux-012-through-ux-037-verification-record).
- These are Robolectric/native-rendering results, not hardware timing or
  vibration acceptance. Requested navigation/chat tasks consume these APIs;
  physical acceptance remains with UX-06.
