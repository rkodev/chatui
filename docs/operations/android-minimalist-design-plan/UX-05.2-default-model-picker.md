# UX-05.2 - Global-default model-picker entry

- Phase: UX-05 - Settings, data, and backup
- Status: Not started
- Order: 30
- Depends on: UX-05.1, UX-04.1
- Output folder: `docs\operations\android-minimalist-design-plan`
- Parallel-safe: No with settings model callbacks or the app picker host.

## Goal

Open the shared full picker from Chat defaults with the Defaults target,
without changing any existing conversation's model.

## Read first

Read the [execution contract](README.md), source-plan sections 5.4 and
5.7, `SettingsUI\SettingsRoute.kt`, `SettingsUI\SettingsScreens.kt`,
`SettingsUI\SettingsViewModel.kt`, `Providers\DefaultsScreen.kt`,
`Providers\ModelPickerViewModel.kt`, and UX-02.4/UX-04.1 host contracts.

## Owns

Default-model entry/callbacks in the listed settings files, app-owned host/
navigation integration, and focused settings/picker/app-route regressions.
Existing default-provider/model service rules stay authoritative.

## Deliverables

A searchable global-default picker entry with correct target label, immediate
persistence, coherent provider context, and refreshed settings state.

## Implementation steps

1. Replace the unsearchable default-model dropdown with a labeled picker entry
   invoking `ModelPickerTarget.Defaults`, never a current-conversation ID.
2. Keep the existing default-provider choice and validation. The picker may
   load a provider-scoped catalog; do not remove provider selection or invent
   a new cross-provider selection rule.
3. Reuse the app host and existing picker/service. `DefaultsScreen` may be a
   useful adapter, but do not mount a competing full settings implementation
   or assume the currently unused component is already production-wired.
4. Explain that the selection affects new chats. Preserve unavailable/hidden
   default warnings, cached catalogs, busy/error recovery, and explicit choices.
5. Refresh the settings summary from persisted defaults after selection.
   Keep open-chat model/params/history snapshots unchanged, and restore
   initiating focus/Back after dismissing the picker.
6. Add integration cases for changing defaults, cancel/failure, provider context,
   reopen, a newly created chat using the chosen default, and an existing chat
   retaining its own model/parameters.

## Acceptance criteria

- [ ] Chat defaults opens the shared picker with the Defaults label/target.
- [ ] Provider/model defaults remain coherent and immediately persisted.
- [ ] New chats use the result; existing chats are not silently changed.
- [ ] Cancel/failure, warnings, state refresh, and focus/Back are correct.
