# UX-02.4 - App-owned model-picker host

- Phase: UX-02 - Navigation and entry points
- Status: Not started
- Order: 12
- Depends on: UX-02.3
- Output folder: `docs\operations\android-minimalist-design-plan`
- Parallel-safe: No with shell, ChatRoute, or ChatScreen callback edits.

## Goal

Make Change model open the real picker, distinct from provider repair, with
explicit conversation/default targets and app-owned cross-feature hosting.

## Read first

Read the [execution contract](README.md), source-plan sections 2, 4,
5.4, and 9, `Shell\ChatUiApp.kt`, `Shell\ShellNavHost.kt`,
`Chat\ChatTopBarState.kt`, `Chat\ChatRoute.kt`, `Chat\ChatScreen.kt`,
`Providers\ModelPickerViewModel.kt`, `Providers\ModelPickerSheet.kt`,
and the existing provider-management service APIs.

## Owns

App-level picker presentation and narrowly required chat callback contracts,
the existing picker route/host adapter, and app/chat/picker regression tests.
A small private host in the existing shell package is allowed; no new module.

## Deliverables

Separate model-selection/provider-management callbacks and a lifecycle-safe
shared host using existing `ModelPickerTarget.Conversation` and `.Defaults`.

## Implementation steps

1. Trace the current `onOpenModelPicker = providersCallback` path. Split model
   selection from missing-provider/key repair through ChatRoute, ChatScreen,
   top-bar state, and the shell without importing provider UI into chat.
2. Let `app` own sheet/navigation presentation and construct the existing
   picker ViewModel with an explicit target. Key conversation state by its
   actual ID; do not reuse a stale picker for the next conversation.
3. Wire chat title/model to `ModelPickerTarget.Conversation(id)`. Keep setup/
   repair actions opening Providers with their current actionable context.
4. Provide a Defaults-target request contract for UX-05.2 and a reusable
   conversation request contract for UX-04.6. Test the host's target isolation
   now without adding fake user-facing buttons just to exercise Defaults.
5. Preserve service selection rules, immediate persistence, history snapshots,
   system prompt, and generation params. Refresh the initiating header/state
   from the persisted result rather than assuming unrelated ViewModels observe
   each other's snapshots.
6. Coordinate sheet/menu dismissal and BackPolicy so one layer closes at a
   time. Restore initiating focus; handle deleted/missing conversation and
   selection failure without redirecting silently or applying to another chat.
7. Add regressions for direct header-to-picker, repair-to-Providers, conversation
   versus defaults isolation, switching conversation IDs, failed selection,
   dismissal, and persisted header refresh.

## Acceptance criteria

- [ ] Header Change model opens model selection, not the Providers screen.
- [ ] Conversation/default requests cannot update the wrong target.
- [ ] Chat has no new provider-UI dependency; app owns cross-feature presentation.
- [ ] Existing parameters/history snapshots, focus, and layered Back survive.
