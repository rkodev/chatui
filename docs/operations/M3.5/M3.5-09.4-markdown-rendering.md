## Goal

Render assistant content safely with GFM Markdown, code highlighting and copy, tables, task lists, links, math fallback, blocked raw HTML, and blocked remote images by default.

## Preconditions

- The message list exists.
- Do not execute raw HTML, scripts, or untrusted links.
- Do not bundle a browser engine.
- Do not modify `web/`, `android/`, or `contracts/`.

## Deliverables

- `pulldown-cmark` GFM renderer with:
  - headings, lists, tables, task lists, links, inline/fenced code;
  - safe link allowlist (`http`, `https`, `mailto`, in-app anchors);
  - raw HTML rendered as text, not HTML;
  - remote images blocked by default;
  - incomplete fenced code during streaming rendered as a code block.
- `syntect` or equivalent highlighting with a bounded theme and language set.
- Code block language label, copy exact text, and wrap/scroll toggle.
- Math handling:
  - render math if a safe Rust-compatible renderer is chosen;
  - otherwise show bounded raw source with a clear fallback.
- Tests for XSS payloads, raw HTML, unsafe links, remote images, incomplete fences, copy text, and math fallback.

## Implementation steps

1. Read spec sections 11.6 and 11.7, plus `web/src/features/chat/MarkdownRenderer.tsx`, `CodeBlock.tsx`, and `MathRenderer.tsx`.
2. Add `pulldown-cmark` and a bounded `syntect` setup.
3. Implement safe rendering. Never enable raw HTML. Render HTML source as text.
4. Allowlist link schemes. Open external links with an explicit action and no secret-bearing URL.
5. Block remote images unless `settings.loadRemoteImages` or a per-message action allows them.
6. Render incomplete code fences during streaming as code blocks.
7. Implement code copy using the exact source text, not highlighted markup.
8. Implement math fallback. If no safe Rust renderer is chosen, show bounded raw source and do not break the message.
9. Add tests with XSS payloads, script tags, `javascript:` links, remote images, tables, task lists, and incomplete fences.
10. Document the renderer's safety boundaries and math decision.

## Handoff notes

- Renderer API: `render_markdown(source, &RenderOptions) -> RenderedMarkdown` and `render_markdown_default(source)`. `RenderedMarkdown` exposes `blocks: Vec<Block>` and `plain_text()` for copy/tests. `RenderOptions { load_remote_images, highlight_code }` defaults to blocked remote images and enabled highlighting. `CodeBlock` exposes `language_label()`, `copy_text()`, and `is_highlighted()`; `CodeBlockView`/`CodeWrap` provide the wrap/scroll toggle state. The model is framework-independent so the Slint row can map it to native text/code widgets without changing the `MessageRow` contract.
- Safety boundaries: raw HTML becomes `Block::Html` or `Inline::Text` and is never parsed. Links are limited to `http`, `https`, `mailto`, and in-app `#anchors`; credentials, missing hosts, relative paths, protocol-relative URLs, and every other scheme are rejected. `LinkRef::action()` returns `OpenExternal`, `InAppAnchor`, or `Blocked` for the UI action layer. Images are limited to `http`/`https` and are blocked by default; `ImageRef::can_load()` supports a per-message "Load image" action. `close_incomplete_fence` closes an unterminated fence for rendering only. `CodeBlock::copy_text()` returns the exact parser source, never highlighted markup.
- Highlighting: `syntect` 5.3 with the pure-Rust `fancy-regex` engine, one fixed theme (`base16-ocean.dark`), and a 26-language allowlist: bash, c, cpp, csharp, css, diff, go, html, java, javascript, json, jsx, kotlin, markdown, php, python, ruby, rust, shellscript, sql, swift, toml, tsx, typescript, xml, yaml. Aliases (`rs`, `py`, `js`, `sh`, `.ts`, etc.) normalize to the allowlist. Unsupported languages and highlighting failures fall back to plain text.
- Math decision: no safe Rust TeX renderer is bundled in this milestone. `MathSource` keeps bounded raw source (`MAX_MATH_SOURCE_CHARS = 4096`), restores `$...$`/`$$...$$` delimiters, exposes `fallback_label()` = "Math (raw source)", and never breaks the message. Fenced `math`, `latex`, `tex`, and `katex` blocks are treated as display math.
- Tests: `gfm_renders_headings_lists_tables_and_task_lists`, `raw_html_is_inert_text`, `unsafe_link_schemes_are_rejected`, `link_allowlist_rejects_credentials_and_missing_hosts`, `remote_images_are_blocked_by_default_and_allowed_by_setting`, `image_allowlist_rejects_non_http_sources`, `incomplete_fence_renders_as_code_block`, `close_incomplete_fence_appends_only_when_needed`, `code_copy_returns_exact_source`, `fenced_code_is_highlighted_when_enabled`, `math_falls_back_to_bounded_raw_source`, `ordered_list_start_is_preserved`, `blockquote_and_thematic_break_render`, `empty_document_is_empty`, `xss_payloads_are_inert`, `supported_language_set_is_bounded`, `language_aliases_normalize`, `highlighting_returns_spans_for_supported_language`, `unsupported_language_falls_back_to_plain_text`, `code_block_copy_returns_exact_source`, `code_block_without_highlighting_keeps_source`, `language_label_defaults_to_code`, `code_block_wrap_toggle_switches_between_wrap_and_scroll`, `theme_is_fixed`, `math_fallback_preserves_source_and_delimiters`, `math_source_is_bounded`, `math_language_detection`.
- Security limitations: the renderer does not open links or load images itself; it returns safe URLs and blocked-image metadata for the UI action layer. No browser engine, script execution, raw HTML parsing, or remote image fetch is introduced. The Slint message row still displays the plain `markdown` string because `message_list.rs` is outside this task's owned paths; wiring the structured model into that row is a follow-up UI change.
