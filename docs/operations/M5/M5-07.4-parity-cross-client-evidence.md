## Goal

Prove the M5 exit gate with cross-client restore, conflict tests, safe-failure
tests, storage inspection, and updated parity rows. This task changes no product
behavior except parity documentation and evidence.

## Preconditions

- Every required web, Android, and Rust task is `Complete`.
- A real or MinIO S3 bucket is available for the cross-client test.
- Do not record secrets, passphrases, prompts, or conversation content in
  evidence. Use synthetic data only.

## Deliverables

- `contracts/parity.md`:
  - Update the `Backup/sync` row for web, Android, and Rust to the delivered
    status.
  - Add a short release-status note with evidence links.
- `docs/operations/M5/M5-verification.md`:
  - Exit-gate checklist with pass/fail and evidence links.
  - Commands and results for every gate.
  - Cross-client restore procedure and result.
  - Conflict test results: concurrent additions, concurrent metadata edits,
    deletion tombstones, deterministic renumbering.
  - Safe-failure results: wrong passphrase, tampered ciphertext, interrupted
    upload.
  - Storage inspection: opaque object names and ciphertext only.
  - No provider keys in backup metadata.
  - Scheduling evidence: Android WorkManager constraints, web and Rust

  - Malicious-provider delete/rollback risk statement; no Byzantine claim.
- `docs/operations/M5/evidence/`:
  - Cross-client restore log (synthetic data).
  - Bucket object listing showing `manifest.enc`,
    `conversations/<storageKey>.enc`, and `attachments/<sha256>.enc`.
  - Test output excerpts.
- A final `README.md` status update if the milestone is complete.

## Implementation steps

1. Confirm every required task is `Complete` and Rust is resolved.
2. Run the full gate:
   ```bash
   make contracts-check
   make web-lint && make web-typecheck && make web-test && make web-build
   cd web && pnpm exec playwright test
   make android-lint && make android-test && make android-assemble
   cd android && ./gradlew :app:connectedDebugAndroidTest
   make rust-check && make rust-lint && make rust-test && make rust-build
   ```
3. Cross-client restore:
   - Configure web and Android with the same bucket, prefix, and passphrase.
   - Create synthetic conversations and attachments on web.
   - Back up from web.
   - Restore on Android into an empty profile.
   - Verify conversations, messages, ordering, and attachments.
   - Repeat in the reverse direction.
4. Conflict tests:
   - Concurrent additions on both clients; verify both are kept and sequences
     are renumbered deterministically.
   - Concurrent metadata edits; verify LWW with `deviceId` tiebreak.
   - Deletion on one client and update on the other; verify deletion wins.
5. Safe-failure tests:
   - Wrong passphrase fails without local mutation.
   - Tampered ciphertext fails.
   - Interrupted upload leaves local data unchanged and resumes.
6. Storage inspection:
   - List bucket objects and record names and sizes.
   - Confirm no plaintext and no provider keys in metadata.
7. Scheduling evidence:
   - Android: show WorkManager constraints and a test result.
   - Web and Rust: link the scheduling docs.
8. Update `contracts/parity.md` and write `M5-verification.md`.
9. Update the M5 `README.md` status and the milestone index if complete.

## Acceptance criteria

- [ ] Cross-device restore works with encrypted data on web and Android.
- [ ] The provider cannot read content, attachments, or meaningful metadata.
- [ ] Conflict tests pass for concurrent edits, additions, and deletions.
- [ ] A failed or interrupted sync never destroys local data.
- [ ] Wrong passphrase and tampered ciphertext fail safely.
- [ ] No provider API keys appear in backup metadata.
- [ ] Android scheduling respects WorkManager constraints; web and Rust are documented.
- [ ] Backup rows in parity are updated and reviewed.
- [ ] The backup format is versioned and round-trip tested in every shipping client.
- [ ] `make contracts-check` passes.
- [ ] Evidence contains only synthetic data and no secrets.
