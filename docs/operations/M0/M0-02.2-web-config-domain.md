# M0-02.2 - Runtime config and domain model

- Status: Not started
- Parent task: M0-02
- Order: 7
- Depends on: M0-02.1
- Parallel-safe: yes, with M0-04.2
- Owns: `web/public/config.json`, `web/src/app/config.ts`, `web/src/app/bootstrap.ts` if not already complete, `web/src/domain/**`, corresponding `web/src/test` and `*.test.ts` files
- Read first: [M0 plan](../M0-foundations-implementation-plan.md) sections 3.2 and 4.3; spec sections 6, 8.6, 8.9, 21.4

## Goal

Load public runtime configuration with zod and define the shared web domain types and identifier/time helpers. This task must not persist data or implement a feature screen.

## Preconditions

- The web scaffold builds and tests run.
- `contracts/providers.json` exists, but do not copy provider metadata into web source.

## Deliverables

- `web/public/config.json` with:
  - `appName`, `defaultTheme`, `defaultProviderPreset`, `enabledPresets`, `allowCustomProviders`
  - `openRouter.attributionOrigin`, `openRouter.appTitle`
  - `docsUrl`, `telemetry`
- `web/src/app/config.ts`:
  - zod schema for the config shape
  - `loadConfig()` fetching `/config.json` with a no-cache policy
  - a typed `AppConfig` export
  - a clear `ConfigError` diagnostic that fails visibly, never silently
  - a React provider or equivalent bootstrap path so the app can render the error state
- Domain files under `web/src/domain/`:
  - `provider.ts`, `model.ts`, `conversation.ts`, `message.ts`, `settings.ts`, `errors.ts`, `ids.ts`, `time.ts`, and an `index.ts` barrel
  - all entities and unions from spec section 6, including `Provider`, `Model`, `Conversation`, `ChatParams`, `Message`, `ContentPart`, `Attachment`, `Usage`, `ChatError`, `Settings`, and `BackupConfig`
- `SyncMeta` placeholder:
  - define a documented provisional type in `conversation.ts`
  - do not implement sync behavior
  - record the unresolved final shape for M5
- UUIDv7 and timestamp helpers:
  - `newId()` using `uuid` v7
  - `nowIso()` returning a UTC ISO 8601 string
  - small predicates or parsers only where they support tests
- Tests:
  - config accepts valid JSON and rejects invalid shapes or missing required fields
  - `newId()` produces UUIDv7 values and is usable as an entity ID
  - `nowIso()` produces a valid ISO 8601 UTC string
  - domain type fixtures or compile-time checks cover the unions

## Implementation steps

1. Read spec section 6 and the runtime config example in spec 8.9.
2. Add `public/config.json` and the zod schema.
3. Implement the loader and a visible error path.
4. Add domain types. Do not add provider-specific request types.
5. Add ID and timestamp helpers.
6. Write tests for config and helpers.
7. Run all web gates.

## Acceptance criteria

- [ ] Valid config loads and is available to the app.
- [ ] Invalid config produces a visible diagnostic and does not fall back silently.
- [ ] Domain types mirror spec section 6 with no provider adapters.
- [ ] IDs are UUIDv7 and timestamps are ISO 8601 UTC.
- [ ] Tests cover config success/failure and ID/time helpers.
- [ ] Web lint, typecheck, tests, and build pass.

## Verification

```bash
cd web && pnpm lint
cd web && pnpm typecheck
cd web && pnpm test
cd web && pnpm build
```

## Out of scope

- Loading `contracts/providers.json` at runtime. That belongs to M1.
