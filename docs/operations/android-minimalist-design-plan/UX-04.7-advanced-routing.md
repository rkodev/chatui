## Goal

Expose existing curated OpenRouter routing controls alongside full advanced
extras JSON, preserving unknown fields and avoiding stale-state overwrites.

## Owns

Advanced-section integration in the named provider UI/state-holder files and

`ConversationRoutingViewModelTest`, and settings/route tests. Service merge
fixes are allowed only if required to prevent an integration data-loss bug.

## Deliverables

A reachable Advanced section containing validated extras JSON, existing
curated routing controls, warnings, and an active routing summary.

## Implementation steps

1. Keep full provider extras JSON available with current validation and
   restrictions against overriding core request fields. Do not replace it
   with a limited curated form.
2. Wire existing routing controls/ViewModel for the current conversation and
   applicable OpenRouter context. Preserve enable/fallbacks/sort/data-collection
   choices and warning/summary semantics; do not change defaults for privacy copy.
3. Route writes through existing service APIs for
   `conversation.params.extra.openrouter.provider`. Preserve unrelated/unknown
   JSON keys and existing generation/system-prompt values.
4. Coordinate raw-editor, generation, and routing snapshots after persistence.
   A later write from one ViewModel must not overwrite newer changes from
   another. Retain invalid in-progress JSON for correction rather than silently
   discarding it on a curated-control update.
5. Show active overrides/routing in the collapsed summary, keep warnings/
   validation actionable, and retain non-OpenRouter extras without displaying
   inappropriate routing controls.
6. Add interleaving regressions: edit raw unknown fields then routing, routing
   then generation, invalid JSON then retry, model/provider context change,
   unsupported core-field injection, and reopen persistence.

## Acceptance criteria

- [ ] Curated routing is reachable in production, not merely previewed.
- [ ] Full extras JSON and all existing routing choices remain available.
- [ ] Interleaved updates cannot lose unknown extras or overwrite newer state.
- [ ] Active summaries/warnings and invalid-input recovery are correct.
