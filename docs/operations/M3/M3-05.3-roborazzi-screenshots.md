# M3-05.3 - Roborazzi screenshot suite

- Milestone: M3
- Status: Not started
- Order: 25
- Depends on: M3-05.2
- Parallel-safe: yes, with M3-05.4 and M3-05.5
- Owns: `android/app/src/test/` screenshot tests and goldens, `android/app/build.gradle.kts` test/plugin configuration, `android/gradle/libs.versions.toml`
- Read first: [M3 plan](../M3-android-depth-implementation-plan.md) sections 3.4 and 4.6; spec section 15.1

## Goal

Add light/dark and phone/tablet screenshot coverage for the key M3 screens so visual regressions are visible.

## Preconditions

- M3-05.2 is complete and the screens are stable.
- Use fake keys, fake conversations, and fixture data only.
- Do not add screenshots of secret-entry screens with real-looking keys.

## Deliverables

- Roborazzi plugin and dependencies pinned in the version catalog.
- Screenshot tests in the app module so `:app:verifyRoborazziDebug` is the single gate.
- Goldens for onboarding, chat empty/streaming/error, model picker, provider list/detail, settings root, data settings, conversation list, and the expanded shell.
- Each screen captured in light/dark and phone/tablet configurations.
- A handoff note with the record and verify commands.

## Implementation steps

1. Add Roborazzi to `libs.versions.toml` and the app module:
   - plugin entry;
   - `roborazzi` and `roborazzi-compose` test dependencies;
   - any required Compose UI test dependencies already present.
2. Configure screenshot output in the app module or a shared convention. Keep goldens in a predictable path.
3. Create `android/app/src/test/java/dev/chatui/screenshots/` tests with `createComposeRule`/`captureRoboImage`.
4. Use fixed configurations:
   - phone: `@Config(qualifiers = "w411dp-h891dp")`;
   - tablet: `@Config(qualifiers = "w840dp-h1280dp")`;
   - light and dark via `ChatUiTheme(themeMode = Theme.LIGHT/DARK, reducedMotion = true)`.
5. Capture the required screens with fake data. For error and streaming states, use fixed `ChatUiState` or fake ViewModel states.
6. Record goldens with:
   ```bash
   cd android && ./gradlew :app:recordRoborazziDebug
   ```
7. Verify with:
   ```bash
   cd android && ./gradlew :app:verifyRoborazziDebug
   ```
8. Review every golden for secret leakage and expected content.
9. Record commands and file paths in the handoff notes.

## Acceptance criteria

- [ ] `:app:verifyRoborazziDebug` passes on a clean checkout.
- [ ] Every required screen has phone/tablet and light/dark goldens.
- [ ] Goldens use only fake data.
- [ ] The screenshot task is in the app module and matches the milestone command.
- [ ] No secret, key, prompt, or personal data appears in a golden.
- [ ] Record/verify commands are documented.

## Verification

```bash
cd android && ./gradlew :app:verifyRoborazziDebug
make android-test
```

## Out of scope

- Device screenshots or Play Store screenshots.
- Accessibility/TalkBack evidence (M3-07.2).
- Changing product screens for visual reasons.
