# UX-02.3 - Toolbar overflow and hierarchical navigation

- Phase: UX-02 - Navigation and entry points
- Status: Not started
- Order: 11
- Depends on: UX-02.2
- Output folder: `docs\operations\android-minimalist-design-plan`
- Parallel-safe: No with ChatUiApp/ChatTopBarState/ChatScreen edits.

## Goal

Reduce the permanent toolbar to useful title/model, history or Back, and More,
without losing share, settings, New chat, or keyboard help.

## Read first

Read the [execution contract](README.md), source-plan sections 4, 5.1,
and 8, `Shell\ChatUiApp.kt`, `Shell\AdaptiveShell.kt`,
`Shell\BackPolicy.kt`, `Chat\ChatTopBarState.kt`, `Chat\ChatScreen.kt`,
and `ShellTopBarTest`, `ShellBackNavigationTest`, `KeyboardShortcutsTest`,
and `AccessibilityFocusTest`.

## Owns

Toolbar/menu presentation in the listed shell/chat files, necessary
`ChatRoute.kt` callbacks, and focused app/chat toolbar tests. Share services,
external-intent handling, and message content are read-only.

## Deliverables

Compact production toolbar adoption, discoverable secondary-action menus,
correct Back/Up affordances, and preserved keyboard/share behavior.

## Implementation steps

1. Use the compact title/model treatment in production. Keep one header owner;
   preserve a standalone fallback only where previews/tests genuinely need it,
   never as a duplicate in the real shell.
2. In chat, retain the leading history control and model/title hit area.
   Replace permanent share/settings/help icons with one labeled More button.
3. Put Conversation settings, Share as text, Share as Markdown, New chat, and
   Keyboard shortcuts directly in the chat menu. Reuse existing callbacks;
   sharing should still take two app taps, not an extra unlabeled submenu.
4. On Chats root expose Providers, App settings, and Keyboard shortcuts in
   overflow. Use Back/Up for hierarchical provider/settings screens rather
   than a misleading drawer icon; preserve actual back-stack parent behavior.
5. Dismiss menus before invoking navigation/platform shares. Restore focus
   after dismissal without forcing the IME open. Preserve one-layer Back:
   dialog, sheet, drawer, keyboard, navigation.
6. Update moved-action tests to open More first. Retain accessible labels and
   useful tags. Verify hardware shortcuts still invoke the same actions.
   Do not claim the existing misrouted model callback fixed; UX-02.4 owns it.

## Acceptance criteria

- [ ] Toolbar is compact; title/model appears once in production.
- [ ] Every relocated action has a visible labeled menu entry and correct effect.
- [ ] Text/Markdown share, keyboard help, and New chat retain behavior.
- [ ] Back/Up, focus restoration, and layered dismissal remain correct.
