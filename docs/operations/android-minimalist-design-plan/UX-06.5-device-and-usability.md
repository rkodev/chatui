# UX-06.5 - Device flows and usability walkthrough

- Phase: UX-06 - Integrated acceptance
- Status: Blocked
- Order: 40
- Depends on: UX-06.2
- Output folder: `docs\operations\android-minimalist-design-plan`
- Parallel-safe: Yes with performance on separate hardware/accounts/fixtures.

## Goal

Prove preserved real-device flows and easier task discovery, especially on an
entry-level phone, rather than accepting attractive screenshots alone.

## Read first

Read the [execution contract](README.md), source-plan sections 6 and
10, UX-00.1's full preservation ledger, UX-06.1's capture matrix,
UX-06.2's accessibility findings, existing app instrumentation tests, and
draft/stream/import/backup recovery evidence.

## Owns

Device/manual/usability evidence and focused missing regression cases in the
existing app/feature test suites. Implementation fixes go back to their owners.
Use fake accounts/content; do not collect personal participant information.

## Deliverables

A device/state matrix, before/after preservation-ledger evidence, and an
anonymous task-based usability report with actionable findings.

## Implementation steps

1. Cover API 26 compatibility, API 31+ dynamic color/fallback, a current target
   platform, actual entry-level and mid-tier phones, and expanded resizing.
   Use representative pairwise states rather than every Cartesian combination;
   record which checks are physical, emulator, or automated.
2. Exercise history/create/search/archive/pin/rename/delete/undo; stream/nonstream/
   Stop/retry/regenerate/edit-truncation; drafts, partial/interrupted content,
   process recreation, rotation, and scrolling to older messages.
3. Exercise real photo/files/SAF cancellation/grants, image paste/drop/removal,
   capability warnings/send-anyway, all send-key modes, text/Markdown share,
   cold/warm incoming text, valid/stale chat links, and hardware shortcuts.
4. Exercise picker conversation/default isolation, manual/hidden-model recovery,
   provider auth/header/key flows, generation/default distinctions, advanced
   extras/routing, and offline/missing-key/model/slow-provider recovery.
5. Exercise data export warning/secret exclusion, merge/replace imports,
   key removal/clear-all, optional-backup skip, five backend forms, test/enable/
   manual backup, merge/replace restore, and typed remote-delete safeguards
   using existing fake/local test facilities. Never perform destructive tests
   against real user data/storage.
6. Ask a small group of nontechnical users to start/find a chat, change model,
   add/remove an attachment, stop generation, find an advanced setting, and
   skip optional backup without teaching hidden gestures. Record anonymous
   completion counts, wrong turns, unreadable labels, and accidental actions.
7. Treat a core task needing explanation of an unlabeled icon/gesture as a
   design defect. Reopen the owning task, retest the affected flow, and attach
   updated evidence. Do not replace missing users/devices with fabricated success.
8. Reconcile every ledger row with evidence or an explicit blocker. Distinguish
   separately excluded future features from required integration work.

## Acceptance criteria

- [ ] Every preservation family has actual before/after flow evidence.
- [ ] Device-only input/lifecycle/intent/data safeguards are exercised safely.
- [ ] Nontechnical-user walkthrough results are recorded anonymously.
- [ ] No unresolved core-task discoverability or functionality regression.

## Verification

```powershell
Set-Location .\android
.\gradlew.bat :app:connectedDebugAndroidTest
```

Record manual case IDs, device/API/build, actual outcomes, and artifact links.
Run focused JVM cases for any new regressions; an automated pass does not
replace manual usability or permission/lifecycle evidence.

## Out of scope

Telemetry/user research infrastructure, personal participant records, real
paid-provider calls, destructive tests on live data, or marking unavailable
hardware/usability evidence complete.
