## Goal

Provide application-scoped Android services for settings, provider creation, secret storage, key validation, catalog refresh, and default model selection, and wire them into Hilt.

## Preconditions

- Adapter and repositories are complete.
- Do not build screens in this task.

## Deliverables

- Hilt providers for `ChatUiDatabase`, `SecretStore`/`TinkSecretCipher`, shared `OkHttpClient`, clock, repositories, provider registry, and provider/model services.
- Typed settings access through `SettingsDataStore`.
- `createOpenRouterProvider`, `validateProviderKey`, `refreshModels`, `selectDefaultModel`, `rotateKey`, `removeKey`, and `setProviderEnabled`.
- No secret stored in Room provider rows.
- Hilt wiring tests and service unit tests.

## Implementation steps

1. Read `AppModule`, `ChatUiDatabase`, `SecretStore`, and `SettingsDataStore`.
2. Add Hilt providers with correct scopes. Use `@ApplicationContext` and `@Singleton`.
3. Build a shared OkHttp client with the timeouts and no logging of secrets.
4. Implement provider creation using the secret store and provider repository.
5. Implement validation and model refresh using the adapter and model repository.
6. Implement default model selection using the M1-01.2 rule.
7. Add tests for provider creation, validation, refresh, and delete behavior.
8. Run the Android gate.

## Acceptance criteria

- [ ] Hilt provides the database, secret store, HTTP client, repositories, registry, and services.
- [ ] Provider creation stores the key only in the secret store.
- [ ] Validation persists non-secret key metadata.
- [ ] Catalog refresh preserves user flags.
- [ ] Default model selection follows the shared rule.
- [ ] No UI is added.
- [ ] Android gate passes.

## Verification

```bash
make android-lint && make android-test && make android-assemble
```

## Out of scope

- Onboarding, provider management, and model picker screens.
- Chat runner.
- Additional providers.
