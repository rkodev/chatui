## Goal

Create shared normalized expectations for every non-OpenRouter stream and error fixture so web and Android adapters have the same target.

## Preconditions

- M1 is complete and its expected OpenRouter vectors still pass.
- Do not modify client source in this task.

## Deliverables

- Expected normalized event sequences for `openai-text.sse`.
- Expected normalized event sequences for `openai-reasoning.sse`, including reasoning and text separation.
- Expected normalized event sequences for `anthropic-text.sse`, including thinking/text separation where the fixture supports it.
- Expected normalized event sequences for `gemini-text.sse`, including `STOP`, `MAX_TOKENS`, `SAFETY`, and `RECITATION` mapping cases.
- Expected normalized event sequences for `ollama-ndjson.txt`, including final usage.
- Expected normalized keep-alive, in-stream error, and 429 behavior.
- Normalized `ChatError` expectations for auth, permission, rate limit, quota, model not found, context length, content filter, network, timeout, and provider failures.
- Validator support and a deliberate-broken-vector test.

## Implementation steps

1. Read the existing OpenRouter expected vectors and keep their shape as the canonical format.
2. Add one expected JSON file per non-OpenRouter stream fixture under `contracts/fixtures/expected/`.
3. Add provider-specific error fixtures under `contracts/fixtures/errors/` for HTTP and in-stream failures.
4. Define expected normalized errors with stable codes, retryability, status, and request ID behavior.
5. Extend `scripts/validate-contracts.mjs` to validate the new expected files and fail on drift.
6. Add a broken-vector validation case so the validator reports a precise file and field.
7. Run the contract gate.

## Handoff notes

- Expected-vector naming convention: stream expectations use the raw fixture
  basename (`openai-text.json`, `ollama-ndjson.json`, `error-429.json`).
  Synthetic stream cases use `<provider>-<topic>.json`
  (`anthropic-thinking.json`, `gemini-finish-reasons.json`). Error expectation
  files use `<scope>-errors.json` (`openrouter-errors.json`,
  `provider-errors.json`).
- Error fixture naming convention: HTTP fixtures use
  `<provider>-<status>-<case>.json` and carry `{ status, headers, body }`.
  In-stream fixtures use `<provider>-stream-<case>.sse` or `.txt` and are raw
  provider payloads. Existing OpenRouter fixtures remain bare bodies and are
  unchanged.
- Validator extension points: `EXPECTED_STREAM_SOURCES` maps expected files to
  raw stream fixtures; `EXPECTED_FILES` lists every required expected vector.
  New expected shapes dispatch from `validateExpectedVectors` to
  `validateProviderErrorsExpected`, `validateAnthropicThinkingExpected`, and
  `validateGeminiFinishReasonsExpected`. `validateFixtureEncoding` now scans
  every fixture for obvious secret patterns. `runBrokenVectorSelfTest` runs on
  every invocation and fails the gate if a deliberately broken stream vector or
  `ChatError` code is not reported with its file and field.
- Known deviations or deferred provider cases: `anthropic-text.sse` contains
  text blocks only, so thinking/text separation is covered by the synthetic
  `anthropic-thinking.json` case rather than a raw fixture. Gemini
  `MAX_TOKENS`, `SAFETY`, and `RECITATION` are covered by
  `gemini-finish-reasons.json` because the raw `gemini-text.sse` fixture only
  exercises `STOP`. Network and timeout errors are synthetic because they have
  no HTTP envelope. In-stream error cases set `retryable: false` to reflect the
  no-auto-retry-after-partial-output rule; `error-429.json` keeps
  `retryAllowed: true` because no text was emitted.
- Verification: `make contracts-install` (up to date, 0 vulnerabilities),
  `make contracts-check` (Contract validation passed), and `git status --short`
  (only the expected/error fixtures, validator, README, and this task file).

  `contracts/fixtures/expected/openai-text.json: /text: must equal the
  concatenated text-delta events ("Hello from OpenAI.")`; a temporary invalid

  `contracts/fixtures/expected/provider-errors.json: /cases/0/error/code: must
