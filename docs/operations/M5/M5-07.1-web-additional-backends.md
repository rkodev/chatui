# M5-07.1 - Web Azure Blob, GCS, Google Drive, and WebDAV adapters

- Milestone: M5
- Status: Complete
- Order: 21
- Depends on: M5-03.1, M5-04.1
- Parallel-safe: yes, with `M5-07.2` and `M5-07.3`
- Owns: `web/src/features/backup/storage/`, `web/src/features/settings/`
- Read first: [M5 plan](../M5-backup-and-sync-implementation-plan.md) sections 3.4 and 5.3; spec section 13.6

## Goal

Add the remaining storage backends on web behind the existing `StorageAdapter`
interface: Azure Blob, Google Cloud Storage, Google Drive, and WebDAV. Enable
them in the backup settings UI. The adapters must only ever receive encrypted
bytes.

## Preconditions

- `M5-03.1` and `M5-04.1` are `Complete`.
- The `StorageAdapter` interface and typed errors exist.
- Do not add a cloud SDK; use `fetch` and the documented REST APIs.
- Do not add a server proxy.

## Deliverables

- `web/src/features/backup/storage/azure.ts`:
  - Account name + key or SAS token.
  - Block blob PUT/GET/HEAD/DELETE.
  - ETag/`If-Match` conditional writes.
  - Connectivity test.
- `web/src/features/backup/storage/gcs.ts`:
  - Service account JSON (JWT -> OAuth2 token) initially.
  - JSON or XML API PUT/GET/HEAD/DELETE.
  - Generation/`If-Match` conditional writes where available.
  - Connectivity test.
- `web/src/features/backup/storage/google-drive.ts`:
  - OAuth access token; use the app data folder or a user-selected folder.
  - Drive v3 file create/update/get/delete; no ETag/`If-Match`.
  - Treat weak consistency conservatively; re-read after write and retry on
    conflict.
  - Connectivity test.
- `web/src/features/backup/storage/webdav.ts`:
  - URL + username + password (Basic auth).
  - PUT/GET/HEAD/DELETE and `PROPFIND` for list.
  - Treat weak consistency conservatively; re-read after write.
  - Connectivity test.
- Backup settings UI: enable the four backends with backend-specific fields.
- Tests with mocked `fetch`:
  - Auth header construction.
  - PUT/GET/HEAD/DELETE for each backend.
  - Conditional write conflict handling.
  - Connectivity test success and typed errors.
  - No plaintext is passed to any adapter.

## Implementation steps

1. Read the `StorageAdapter` interface, S3 adapter, and backup settings UI.
2. Implement Azure Blob:
   - Build the request with `x-ms-version`, `x-ms-date`, and the signature.
   - Use block blob PUT.
   - Parse `ETag` and send `If-Match` on rewrite.
3. Implement GCS:
   - Build and sign a JWT with the service account key.
   - Exchange it for an OAuth2 access token.
   - Use the JSON API for object operations.
   - Use generation preconditions for conditional writes.
4. Implement Google Drive:
   - OAuth access token; app data folder or user-selected folder.
   - Drive v3 file create/update/get/delete.
   - No ETag/`If-Match`; re-read after write and retry on conflict.
5. Implement WebDAV:
   - Basic auth header.
   - PUT/GET/HEAD/DELETE.
   - `PROPFIND` for list, or document that list is unsupported and use HEAD.
   - Re-read after write; never assume read-after-write.
6. Update the backup settings UI to show backend-specific fields and enable the
   options.
7. Add tests with mocked `fetch`. Use synthetic encrypted bytes only.
8. Run the web gates.

## Handoff notes

- The shared `BackupBackend` union in `web/src/domain/settings.ts` and the
  export schema in `web/src/features/settings/exportService.ts` were extended
  with `google-drive`. The task requires Google Drive in the UI, and the
  existing union did not include it.
- Azure uses Shared Key signing when an account key is present; a SAS token is
  used only when no account key is supplied.
- GCS uses the JSON API with service-account JWT exchange. User OAuth remains a
  later preference.
- Google Drive uses the file `version` field for optimistic concurrency because
  Drive v3 has no ETag/`If-Match` preconditions. Writes are re-read after
  completion.
- WebDAV lists with `PROPFIND` Depth 1 and filters client-side; pagination
  options are accepted but WebDAV has no standard continuation token.
- All adapters reject non-`Uint8Array` bodies before sending a request.
