# M2-01.3 - Web discovery, fallback, capabilities, reasoning, and provider UI

- Status: Complete
- Parent task: M2-01
- Order: 5
- Depends on: M2-01.2
- Parallel-safe: yes, with M2-05.3
- Owns: `web/src/features/providers/`, `web/src/providers/`, provider/model tests
- Read first: [M2 plan](../M2-providers-and-content-implementation-plan.md) sections 3.2, 3.8, and 4.3; spec sections 7.5, 7.8, 7.9, 11.5

## Goal

Make discovery, fallback models, capability inference, reasoning display, and provider management usable for every enabled OpenAI-compatible preset.

## Preconditions

- M2-01.2 preset enablement is complete.
- Expected catalog vectors from M2-00.2 are available.

## Deliverables

- Per-preset discovery using the preset's discovery path and format.
- Per-preset cache keys, TTL, forced refresh, and last-known-good behavior.
- Fallback model selection when discovery is blocked or unavailable.
- Capability inference for missing modalities, capabilities, context, and supported parameters.
- Reasoning normalization for OpenAI-compatible `reasoning_content` and other supported fields.
- Provider list/detail UI for enabled presets and Custom providers.
- Tests for catalog mapping, fallback, capabilities, reasoning, and provider UI state.

## Implementation steps

1. Read the expected catalog vectors and the M1 model service.
2. Generalize discovery by preset format while keeping OpenRouter's cache semantics.
3. Add fallback model selection from the shared fallback rule.
4. Add capability inference at the catalog-to-model boundary.
5. Normalize reasoning in the OpenAI-compatible stream.
6. Update provider list/detail UI for multiple presets and Custom providers.
7. Add tests for discovery failure, stale cache, missing fields, and reasoning separation.
8. Run web gates.

## Acceptance criteria

- [x] Discovery works for every enabled OpenAI-compatible preset in tests.
- [x] A blocked discovery path yields fallback models and a non-blocking warning.
- [x] Missing modalities/capabilities are inferred per the shared rule.
- [x] Reasoning appears separately from answer text and is not replayed.
- [x] Provider management lists enabled presets and Custom providers.
- [x] OpenRouter catalog and free badge behavior are unchanged.
- [x] Web gates pass.

## Verification

```bash
make web-lint && make web-typecheck && make web-test && make web-build
```

## Out of scope

- Native adapters.
- Attachment filtering by capability.
- Conversation settings and data controls.

## Handoff notes

- Discovery: `loadCatalog` continues to use each preset's `modelDiscovery.path`,
  format, `cacheTtlSeconds`, and the provider record id in the cache key. Added
  `discovery.test.ts` iterating every `M2_ENABLED_PRESET_IDS` entry plus TTL,
  forced refresh, last-known-good, and missing-snapshot cases.
- Fallback behavior: added `web/src/providers/fallbackModels.ts` with the shared
  fallback lists (`openai`, `anthropic`, `google`, `ollama`), the contract
  `defaultModelId` for every other non-OpenRouter preset, and the shared
  `selectFallbackModel` rule. `ModelService.refreshModels` now returns cached
  models with `degraded: true` and a non-blocking notice when discovery fails,
  or persists fallback rows (marked `metadata.fallback`) when no cache exists.
  `selectDefaultModel` creates fallback rows when needed and applies the fixture
  notices. OpenRouter intentionally keeps no fallback list so its M1
  empty-catalog onboarding failure and catalog behavior remain unchanged.
- Capability inference defaults: `inferOpenAIModelMetadata` in
  `openaiCatalog.ts` follows `contracts/fixtures/expected/capability-inference.json`.
  Raw `inputModalities`/`input_modalities`, output modalities, capabilities,
  supported parameters, and context/output limits win; missing modalities and
  supported parameters use preset defaults; missing limits are `null`; missing
  capabilities are derived in the order `text`, `vision`, `files`, `tools`,
  `reasoning`, `streaming`. OpenAI-format discovery now receives per-preset
  defaults for Anthropic, Gemini, and Ollama.
- Reasoning fields handled: `delta.reasoning_content` (DeepSeek and other
  OpenAI-compatible providers), `delta.reasoning`, and `delta.reasoning_details`.
  Reasoning deltas stay separate from text deltas. Repeated identical chunks are
  preserved for generic OpenAI-compatible presets; the OpenRouter reference
  keeps its M1 de-duplication so `reasoning` plus `reasoning_details` still emit
  once. `buildChatRequest` continues to drop reasoning parts, so reasoning is
  never replayed.
- Provider UI: the list shows each configured provider's preset label and keeps
  enabled/disabled/coming-later availability plus Custom creation. The detail
  screen now shows the preset label, uses the preset `docsUrl` for a
  provider-neutral documentation link, uses OpenRouter-specific routing copy
  only for OpenRouter, and renders a degraded refresh notice instead of an
  error.
- Verification: `make web-lint && make web-typecheck && make web-test && make web-build`
  passed. `web-test` ran 73 files / 617 tests.
