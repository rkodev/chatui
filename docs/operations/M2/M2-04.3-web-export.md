Implement per-conversation JSON/Markdown export and a full `chatui.export` archive with secrets excluded by default.

## Preconditions

- M2-00.2 export fixture exists.
- M2-03.4 settings data entry is available.

## Deliverables

- Per-conversation JSON export.
- Per-conversation Markdown export.
- Full data archive export matching `contracts/schema/chat-export.schema.json`.
- Secrets excluded by default; plaintext warning.
- Optional attachment byte inclusion.
- Preservation of IDs, ordering, provider/model snapshots, and attachment references.
- Download and validation tests.

## Implementation steps

1. Read the export schema and shared export fixture.
2. Add a repository-level export reader that collects conversations, messages, attachments, providers, models, and settings.
3. Exclude secrets by default and never include plaintext keys.
4. Add per-conversation JSON and Markdown formatters.
5. Add optional attachment payload inclusion.
6. Add download behavior and plaintext warning.
7. Validate generated archives against the schema.
8. Add round-trip and preservation tests.
9. Run web gates.

## Handoff notes

- Export service entry points: `ExportReader` in `web/src/storage/ExportReader.ts` reads IndexedDB snapshots (all data or one conversation). `ExportService` in `web/src/features/settings/exportService.ts` builds `chatui.export` JSON, per-conversation JSON, and Markdown. `createExportService()` in `exportServiceFactory.ts` wires IndexedDB, settings, and `AttachmentStore`. `/settings/data` renders `DataExportPanel` for full-archive and per-conversation downloads; `downloadTextFile()` owns the Blob/anchor download.
- Attachment inclusion policy: attachment metadata (`id`, `name`, `mimeType`, `sha256`, `size`) is always included for referenced attachments. `dataBase64` is omitted unless `includeAttachmentBytes` is true; Markdown never embeds bytes. The Data screen checkbox defaults to off.
- Archive validation evidence: `exportService.test.ts` loads the real `contracts/schema/chat-export.schema.json`, checks the checked-in fixture validates, and validates generated full and per-conversation archives against the same schema. `ExportReader.test.ts` covers ordering, per-conversation scoping, and secret exclusion. `DataExportPanel.test.tsx` and `download.test.ts` cover the UI warning/options and download behavior.
- Ordering decision: conversations export by `createdAt` then id, messages by `sequence`, attachments/providers by `createdAt` then id, and models by provider/remoteId. This is deterministic and preserves round-trip history order. Provider `secretId` values remain opaque references; the reader never opens the `secrets` store, so key material cannot enter an archive.
- Scope note: import and clear-data controls remain for M2-04.4/M2-04.5. The existing disabled per-conversation export button in the chat conversation settings screen was left untouched because `web/src/features/chat/` is outside this task's scope; `/settings/data` is the export entry point for now.
