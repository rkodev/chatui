## Goal

Implement a provider-agnostic SSE reader that handles real-world line endings, multi-line `data:` fields, comments, bounded buffering, final flush, and cancellation. The reader must not parse provider JSON.

## Preconditions

- M1-02.1 is complete.
- Use `ReadableStream` fixtures and existing Vitest setup.

## Deliverables

- `readSse(response, { signal, onEvent })` or an equivalent async iterator.
- CRLF and lone-CR normalization.
- Multi-line `data:` concatenation with a single newline.
- Comment and empty-line handling, including `: OPENROUTER PROCESSING`.
- Bounded buffer that errors with a normalized parse/transport error instead of growing without limit.
- Final-buffer flush when the stream ends without a trailing blank line.
- Abort support that stops reading promptly.
- Tests for chunk boundaries split inside CRLF, inside a `data:` line, inside JSON, and at the final buffer.

## Implementation steps

1. Read spec 21.1 and the OpenRouter keep-alive fixture.
2. Implement a decoder loop using `response.body.getReader()`.
3. Normalize line endings before event splitting.
4. Split events on blank lines; for each event, collect only `data:` lines, strip one optional leading space, and join with `\n`.
5. Ignore comment lines and unknown SSE fields.
6. Enforce a maximum buffer size and throw a typed error when exceeded.
7. On stream end, process any remaining complete event in the buffer.
8. Wire `AbortSignal` checks before and after reads.
9. Add tests against hand-built `ReadableStream` chunks and the real `openrouter-keepalive.sse` fixture.

### Public transport API

```ts
readSse(response: SseResponse, options: ReadSseOptions): Promise<void>

interface SseResponse {
  readonly body: ReadableStream<Uint8Array> | null
}

interface ReadSseOptions {
  onEvent: (data: string) => void
  signal?: AbortSignal
  maxBufferChars?: number
}
```

`SseResponse` is structural, so a real `Response` can be passed directly.
`onEvent` receives the raw concatenated `data:` value. The transport does not
parse JSON. `data: [DONE]` is passed through as a normal data event; adapters
must stop on it. Empty data values are not emitted, so keep-alive comments never
produce blank messages.

### Error types

- `SseTransportError` - base class for normalized transport failures.
- `SseMissingBodyError` - the response has no readable body.
- `SseBufferOverflowError` - an incomplete event exceeded the buffer limit;
  exposes `maxBufferChars`.
- `SseAbortError` - reading was stopped by the signal; `name` is `AbortError`.
- Underlying `reader.read()` failures are wrapped in `SseTransportError` with
  the original error in `cause`.

### Buffer limit

`DEFAULT_MAX_SSE_BUFFER_CHARS = 1024 * 1024` characters (UTF-16 code units).
The limit applies to data retained for an incomplete event. Complete events are
drained as soon as their terminating blank line arrives, so a stream of many
small events does not accumulate. Tests can override the limit with
`maxBufferChars`.

### Cancellation

An abort listener calls `reader.cancel()`, which resolves a pending read with
`done: true`; the loop then observes `signal.aborted` and throws
`SseAbortError`. An already-aborted signal throws before reading. The reader
lock is released in `finally`.

### Decisions

- `[DONE]` is emitted as data rather than filtered in the transport. This keeps
  the reader provider-agnostic; the OpenRouter adapter will stop on it.
- The buffer limit is measured in characters because the reader operates on
  decoded strings. For ASCII SSE payloads this matches bytes.
- `web/src/providers/index.ts` was not changed because it is outside this
  task's `Owns` list. Downstream code can import `readSse` from
  `web/src/providers/sse` directly.
