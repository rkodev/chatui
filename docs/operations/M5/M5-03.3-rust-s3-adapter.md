# M5-03.3 - Rust S3-compatible adapter and conditional writes

- Milestone: M5
- Status: Not started
- Order: 11
- Depends on: M5-02.3
- Parallel-safe: yes, with `M5-03.1` and `M5-03.2`
- Owns: `rust/crates/chatui-backup/`
- Read first: [M5 plan](../M5-backup-and-sync-implementation-plan.md) sections 3.4 and 5.3; spec section 13.6; `contracts/schema/backup-envelope.schema.json`

## Goal

Implement the S3-compatible storage backend in Rust with SigV4, conditional
writes, a connectivity test, and typed errors. The adapter must only ever
receive encrypted bytes.

## Preconditions

- `M5-02.3` is `Complete` and the manifest/payload code exists.
- Rust is conditional. If Rust is not shipping, mark this task `Cancelled`.
- Use `reqwest`; do not add a cloud SDK or a server proxy.

## Deliverables

- `rust/crates/chatui-backup/src/storage/mod.rs`:
  - `StorageAdapter` trait: `test_connection`, `get_object`, `put_object`,
    `head_object`, `delete_object`, `list_objects`.
  - `StorageObject`, `StorageError` with typed variants.
- `rust/crates/chatui-backup/src/storage/sigv4.rs`:
  - Canonical request, string to sign, signing key, `Authorization` header.
  - Support `GET`, `PUT`, `HEAD`, `DELETE`.
- `rust/crates/chatui-backup/src/storage/s3.rs`:
  - `S3StorageAdapter` with path-style and virtual-hosted-style URLs.
  - `If-Match`/`If-None-Match` conditional writes.
  - ETag capture and return.
  - Conservative eventual-consistency handling.
- Tests:
  - SigV4 known-answer test.
  - Adapter tests with a local mock server (`wiremock` or `httpmock`).
  - Conditional write conflict returns `conflict`.
  - Connectivity test returns typed errors.
  - No plaintext is passed to the adapter in tests.

## Implementation steps

1. Read the envelope codec, manifest/payload code, and the desktop `reqwest`
   setup.
2. Define the `StorageAdapter` trait and error types.
3. Implement SigV4 with `hmac`, `sha2`, and `hex`.
4. Implement `S3StorageAdapter` with `reqwest`:
   - Build the URL from endpoint, bucket, and key.
   - Sign every request.
   - Send `If-Match` on manifest rewrite and `If-None-Match: *` on create.
   - Parse `ETag` and map HTTP status to typed errors.
5. Implement `test_connection` with a `HEAD` on the bucket or a small probe
   object. Do not write plaintext.
6. Add tests with a local mock server. Use synthetic encrypted bytes only.
7. Run the Rust gates.

## Acceptance criteria

- [ ] `StorageAdapter` and typed errors exist.
- [ ] SigV4 signing passes a known-answer test.
- [ ] GET/PUT/HEAD/DELETE work against a local mock server.
- [ ] Conditional writes use `If-Match`/`If-None-Match` and surface conflicts.
- [ ] ETags are captured and returned.
- [ ] Connectivity test returns typed errors and writes no plaintext.
- [ ] No cloud SDK or server proxy is added.
- [ ] The adapter only receives encrypted bytes.
