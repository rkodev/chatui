# M3.5-07.1 - OpenAI-compatible preset adapters

- Milestone: M3.5
- Status: Complete
- Order: 24
- Depends on: M3.5-06.4
- Parallel-safe: none; unblocks native adapters
- Owns: `rust/crates/chatui-providers/src/openai_compatible.rs`, `rust/crates/chatui-providers/src/openai_catalog.rs`, OpenAI-compatible conformance tests
- Read first: [M3.5 plan](../M3.5-rust-desktop-implementation-plan.md) sections 3.5 and 4.9; spec sections 7.3, 7.5, 7.6, 7.9

## Goal

Generalize the OpenRouter transport into a preset-driven OpenAI-compatible adapter for OpenAI, Groq, Mistral, DeepSeek, xAI, Together, Fireworks, LM Studio, llama.cpp, and Custom.

## Preconditions

- The OpenRouter conformance gate is complete.
- Do not add Anthropic, Gemini, or Ollama native behavior in this task.
- Do not duplicate preset metadata.
- Do not modify `web/`, `android/`, or `contracts/`.

## Deliverables

- Preset-driven OpenAI-compatible adapter that consumes contract preset data.
- Base URL, auth headers, default headers, attribution headers, and discovery format from the preset.
- Request serialization matching OpenAI request vectors.
- Streaming normalization matching OpenAI expected vectors.
- OpenAI-format `/models` mapping to the shared `Model` shape.
- Preset enablement that does not hardcode provider names.
- Tests for text, reasoning, usage, errors, retry, cancellation, protected fields, and discovery.

## Implementation steps

1. Read `web/src/providers/openaiCompatible.ts`, `openaiCatalog.ts`, and `presets.ts`.
2. Reuse the OpenRouter transport modules where they are already provider-neutral. Extract shared logic instead of copying it.
3. Add a preset-to-transport conversion that carries:
   - base URL;
   - auth type/header/scheme;
   - default and attribution headers;
   - discovery path/format/TTL;
   - key validation path;
   - extra namespace and passthrough behavior.
4. Implement OpenAI `/models` mapping. Use preset defaults when the provider omits modalities, capabilities, context, or parameters.
5. Serialize requests using the shared OpenAI request vectors.
6. Normalize text, `reasoning_content`, usage, and errors.
7. Verify unsupported controls are omitted.
8. Add tests for every enabled OpenAI-compatible preset that has vectors, plus a representative custom preset.
9. Run the OpenRouter suite again to prove no regression.

## Handoff notes

- Preset-to-transport mapping: `OpenAiCompatiblePreset::from_contract` carries
  the contract preset plus the derived extra namespace, extra mode, and
  reasoning style. `ModelDiscoveryFormat::Openrouter` selects curated advanced
  JSON and OpenRouter reasoning deduplication; every other format selects
  all-safe-key passthrough and OpenAI `reasoning_effort`.
- Enabled presets: `openai`, `groq`, `mistral`, `deepseek`, `xai`, `together`,
  `fireworks`, `lmstudio`, `llamacpp`, and `custom`. `openrouter` remains on
  `OpenRouterAdapter`. `anthropic`, `google`, and `ollama` remain
  `UnsupportedAdapter`.
- Discovery: `openai_catalog::map_models` maps `{data: [...]}` or a bare array
  into `CatalogModel`, which converts to the shared `Model` with
  `CatalogModel::to_model`. Missing modalities, capabilities, and supported
  parameters fall back to `defaults_for_preset`; missing limits stay `None`;
  embedding models are hidden.
- Test names: `registry_enables_openai_compatible_presets`,
  `every_openai_request_vector_matches_through_the_adapter`,
  `unsupported_controls_are_omitted`,
  `every_openai_stream_vector_matches_through_the_adapter`,
  `every_openai_http_error_vector_matches_through_the_adapter`,
  `openai_in_stream_error_matches_the_shared_vector`,
  `openai_catalog_maps_the_shared_vector`,
  `capability_inference_uses_preset_defaults`,
  `custom_preset_uses_the_same_transport`,
  `credentials_stay_in_headers_and_never_in_urls`,
  `synthetic_network_and_quota_errors_match_the_shared_vectors`,
  `cancellation_before_first_token_returns_cancelled`,
  `cancellation_after_first_token_preserves_partial_text`,
  `retry_allowed_before_partial_output`, and
  `retry_not_allowed_after_partial_output`.
- Provider-specific deviations: none. The OpenAI-compatible transport uses the
  contract's base URL, auth header/scheme, default and attribution headers,
  discovery path/format/TTL, and key-validation path. Query-parameter auth is
  rejected before any request. The shared error mapper now maps OpenAI
  `type: server_error` to status 500 for in-stream errors and maps HTTP 400
  content-filter messages to `content_filter`; OpenRouter vectors still pass.
- Files touched beyond the two new modules: `adapter.rs`, `lib.rs`,
  `registry.rs`, `openrouter/errors.rs`, `openrouter/request.rs`, and
  `openrouter/stream.rs` to wire the preset-driven adapter and extract shared
  logic. `openrouter_adapter.rs` was updated only to reflect the newly enabled
  presets.
