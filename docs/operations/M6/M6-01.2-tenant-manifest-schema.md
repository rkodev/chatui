# M6-01.2 - Tenant manifest schema and fixtures

- Milestone: M6
- Status: Not started
- Order: 2
- Depends on: M6-01.1
- Parallel-safe: yes, with `M6-01.3`
- Owns: `contracts/schema/hosting-tenant.schema.json`, `contracts/fixtures/hosting/`, `scripts/validate-contracts.mjs`
- Read first: [M6 plan](../M6-managed-hosting-implementation-plan.md) sections 2.1, 3.1 (T-01, T-05, T-06), and 4; `contracts/schema/backup-manifest.schema.json`; the schema and fixture loading code in `scripts/validate-contracts.mjs`

## Goal

Define the strict, public-safe tenant deployment manifest that an operator stores
outside the app bundle. The manifest describes subdomain, region, custom domain
and TLS state, release pin, public config hash, health, support links, and
rollback target. It must never contain credentials or secrets.

## Preconditions

- `M6-01.1` is `Complete` and `DEC-M6-04` and `DEC-M6-05` are recorded.
- Do not add this schema to the served app config. It is an operator-side
  deployment record, not runtime browser configuration.
- Do not add fields for provider keys, storage credentials, passphrases, or
  support credentials.

## Deliverables

- `contracts/schema/hosting-tenant.schema.json`:
  - `schemaVersion` integer, initially `1`.
  - `tenantId` non-empty string.
  - `subdomain` constrained string, with a documented length and character set.
  - `region` non-empty string; the allowed list is documented by M6-01.4.
  - `customDomain` object or `null` with `hostname`, `status`, and
    `lastCheckedAt`. Suggested statuses: `unconfigured`, `pending_dns`,
    `pending_tls`, `active`, `failed`.
  - `release` object with immutable `version` and `artifactDigest`.
  - `publicConfig` object with `path` and `sha256`.
  - `health` object with `status`, `lastCheckedAt`, and optional `message`.
    Suggested statuses: `unknown`, `healthy`, `degraded`, `unhealthy`.
  - `rollback` object with `releaseVersion`, `artifactDigest`, and
    `configSha256`.
  - `support` object with `docsUrl` and optional `contactUrl`.
  - `createdAt` and `updatedAt` as ISO 8601 / RFC 3339 UTC strings.
  - `additionalProperties: false` at every object level.
- `contracts/fixtures/hosting/`:
  - `tenant-full.json` valid fixture with a custom domain and rollback target.
  - `tenant-minimal.json` valid fixture with `customDomain: null`.
  - `tenant-invalid-unknown-field.json` with an unknown property.
  - `tenant-invalid-missing-release.json` missing a required release field.
  - `tenant-invalid-secret-field.json` with a forbidden field such as
    `accessKeyId`. The value may be a redacted placeholder, never a real key.
- `scripts/validate-contracts.mjs`:
  - Compile the new schema with the existing schema-loader path.
  - Validate every fixture.
  - Add broken-vector self-tests that assert the invalid fixtures fail for the
    expected reason.
  - Print a clear error naming the fixture path and JSON pointer.

## Implementation steps

1. Read the existing backup schema and its fixture registration.
2. Find how `validate-contracts.mjs` compiles schemas and loads fixtures.
3. Write the schema with strict objects and explicit enums/patterns.
4. Add the valid and invalid fixtures.
5. Register the schema and fixtures in the validator.
6. Add negative self-tests for unknown fields, missing release fields, and
   forbidden secret-bearing fields.
7. Run the contracts gate and fix any validation or fixture mismatch.

## Acceptance criteria

- [ ] `contracts/schema/hosting-tenant.schema.json` exists and compiles.
- [ ] Valid full and minimal fixtures pass.
- [ ] Unknown fields, missing required release data, and forbidden secret fields
      fail with clear errors.
- [ ] The schema contains no credential, token, passphrase, or storage-secret
      field.
- [ ] `make contracts-check` passes.
- [ ] No real or realistic secret value is committed in a fixture.

## Verification

```bash
make contracts-check
```

Confirm the output includes the new tenant schema and fixtures, and that the
broken-vector self-tests ran.

## Out of scope

- Public app `config.json` templates (`M6-01.3`).
- The tenant config validator CLI (`M6-01.4`).
- Storing or enforcing tenant records in a real control plane.
