## Goal

Complete the web OpenRouter adapter with streaming, normalized events, reasoning, usage, errors, retry, cancellation, routing, and protected-field enforcement.

## Preconditions

- SSE transport and key/catalog methods are complete.
- Expected vectors and request vectors exist.

## Deliverables

- `streamChat(ctx, request, signal, onEvent)` using the SSE transport.
- Request body construction: model, system message, messages, `stream: true`, `stream_options.include_usage`, supported sampling parameters, `reasoning.effort` when supported, and curated `provider` options.
- Attribution headers from config.
- Mapping for text deltas, reasoning deltas, `finish_reason`, usage, and in-stream errors.
- Reasoning deduplication per the M1-01.1 rule.
- Usage and cost normalization, with `estimated: true` only when usage is absent.
- Error mapping for 401, 402, 403, 404, 429, 400 context length, 503, network before/after first token, and cancellation.
- Retry policy: at most 3 attempts, jittered exponential backoff starting at 800 ms, cap 8 s, honor `Retry-After`, retry only before the first token.
- Advanced JSON guard that rejects `model`, `messages`, `stream`, and `stream_options` overrides.
- Tests using the shared expected vectors, fake timers, and abort signals.

## Implementation steps

1. Read expected vectors and request vectors.
2. Build the OpenRouter request body in one small function so tests can assert exact JSON.
3. Send `POST /chat/completions` with bearer auth and attribution headers.
4. Feed SSE data into an event mapper. Ignore comments and unknown fields.
5. Convert content arrays defensively by concatenating text fields.
6. Apply reasoning precedence and deduplication.
7. Track `receivedText`; never retry after it becomes true.
8. Implement `Retry-After` parsing from headers and from the fixture metadata.
9. Normalize errors into `ChatError` with provider ID, status, retryable, retryAfterSeconds, requestId when available, and redacted details.
10. Add tests for every fixture and every error code. Add a test that protected advanced fields are rejected before fetch.
11. Verify no key appears in thrown errors or logs.

## Acceptance criteria

- [ ] Streaming emits the expected event order for text, keep-alive, reasoning, and usage fixtures.
- [ ] Reasoning appears once.
- [ ] In-stream error preserves partial text and does not retry.
- [ ] 402, 429, 503, auth, model-not-found, context-length, network, and cancellation map correctly.
- [ ] Retry stops after the first token and honors `Retry-After`.
- [ ] Curated routing serializes correctly.
- [ ] Protected fields cannot be overridden.
- [ ] Web gate passes.
