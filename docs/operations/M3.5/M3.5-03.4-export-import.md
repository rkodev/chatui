## Goal

Implement `chatui.export` read/write with schema validation, merge-by-default import, attachment-byte opt-in, and safe handling of untrusted files.

## Preconditions

- Repositories and contract types are complete.
- Do not implement the export/import UI.
- Do not include secrets in exports.
- Do not trust file names, IDs, sizes, or attachment paths from an import.

## Deliverables

- Export service that produces a schema-valid `chatui.export` document with:
  - conversations, messages, attachments, providers, models, and settings;
  - optional attachment bytes as base64;
  - no secrets;
  - deterministic ordering.
- Per-conversation JSON export and Markdown export where the milestone requires it. If Markdown is deferred to the UI task, document that.
- Import service that:
  - validates with `jsonschema` before any write;
  - enforces archive and attachment size limits;
  - rejects duplicate IDs, dangling references, and unsafe attachment names;
  - merges by default without deleting local data;
  - restores attachment bytes only when present and valid;
  - is transactional or leaves local data unchanged on failure.
- Tests for round-trip, merge, invalid input, duplicates, dangling references, unsafe names, oversized input, and secret exclusion.

## Implementation steps

1. Read `web/src/features/settings/exportService.ts`, `importService.ts`, and `contracts/fixtures/expected/chatui-export.json`.
2. Implement export using repositories. Keep IDs, ordering, model snapshots, and attachment references intact.
3. Use the shared `ChatExport` types from `chatui-contracts`. Do not invent a second export shape.
4. Set `format = "chatui.export"`, `formatVersion`, `exportedAt`, and a semantic `appVersion`.
5. Include attachment bytes only when explicitly requested. Base64-encode bytes and preserve `sha256`, `size`, `name`, and `mimeType`.
6. Implement import validation before writes:
   - parse JSON with a bounded size limit;
   - validate against the export schema;
   - validate unique IDs and cross-record references;
   - validate attachment names against path traversal and control characters;
   - validate SHA-256 values and decoded byte limits.
7. Implement merge-by-default. Existing conversations with the same ID must not be silently overwritten in a destructive way. Choose and document a deterministic conflict policy consistent with web/Android.
8. Make the import transactional. On failure, no partial local state or orphan files remain.
9. Restore attachment bytes through the attachment store when present. Skip missing bytes safely and record a summary.
10. Exclude secret records, keys, and secret headers from exports, including provider metadata.
11. Add a plaintext warning string/constant for the UI task to display.

## Handoff notes

- Export API: `ExportService::new(conversations, messages, attachments,
  providers, models, settings)` takes `Arc<dyn ...Repository>` traits.
  `with_attachment_store` enables opt-in bytes and `with_app_version` overrides
  the default crate version. `export_all`, `export_conversation`,
  `export_all_json`, `export_conversation_json`, and `list_conversations` are
  the public entry points. `encode_export` serializes pretty JSON with a
  trailing newline. `EXPORT_PLAINTEXT_WARNING` is the UI warning string.
- Import API: `ImportService::new(pool, attachment_store)` with
  `with_limits(max_bytes, max_attachment_bytes)`. `import_bytes`, `import_text`,
  and `import_archive` return `ImportSummary`. `validate_import_archive` is
  public for callers that already have a `serde_json::Value`. `ImportMode`
  defaults to `Merge`; `Replace` is explicit.
- Conflict policy: merge upserts by ID and never deletes local records. Local
  providers keep `enabled`, `secretId`, and `createdAt`; local models keep
  `hidden`, `pinned`, a manual `source`, and `createdAt`. Models are matched by
  `(providerId, remoteId)` and imported references are remapped to the local
  model ID. Merge fills only missing settings keys, matching the web client.
  A local model ID with a different provider/remote identity, or a local
  message sequence occupied by a different message ID, is rejected as a
  conflict and the transaction rolls back. Replace clears only the imported
  data stores (conversations, messages, attachments, providers, models,
  settings, FTS); secrets, backup configuration, and the sync queue are
  untouched.
- Size limits: `MAX_IMPORT_BYTES = 50 MiB`,
  `MAX_IMPORT_ATTACHMENT_BYTES = 20 MiB`,
  `MAX_IMPORT_ATTACHMENT_NAME_LENGTH = 255`, and
  `MAX_IMPORT_ID_LENGTH = 256`. The declared attachment size is checked even
  when bytes are absent. Base64 must be standard padded encoding.
- Validation: the raw JSON value is validated against
  `chat-export.schema.json` before deserialization, then checked for unique
  IDs, model identity uniqueness, message sequence uniqueness, provider/model/
  conversation/attachment/settings references, unsafe attachment names, and
  SHA-256 format. Attachment bytes are decoded and checked for size, declared
  size, and SHA-256 before any write. Every attachment must be referenced by a
  message because the SQLite schema requires `attachments.message_id NOT NULL`.
- Secrets: exports never read the secret repository. Provider headers named
  `Authorization`, `Proxy-Authorization`, `X-Api-Key`, `X-Goog-Api-Key`,
  `Api-Key`, `Apikey`, or `Api_Key` are removed, and metadata keys with those
  names plus `secret`, `password`, `access_token`, `refresh_token`,
  `credential`, and `credentials` are removed recursively. The bare metadata
  key `key` is preserved because OpenRouter uses it for a non-secret `/key`
  label. Provider `secretId` is an opaque reference and is preserved.
- Transactionality: attachment bytes are written before the SQLite
  transaction. Newly created byte files are deleted if the transaction fails.
  The transaction covers providers, models, conversations, messages, FTS,
  attachments, and settings. Replace mode cleans orphan attachment files after
  a successful commit.
- Markdown: per-conversation Markdown export is deferred to the UI/Markdown
  tasks (M3.5-09.4 and M3.5-10.2). This task provides per-conversation JSON
  export only.
- Integration changes outside the listed `Owns` paths: `src/lib.rs` declares
  and re-exports the new modules; `Cargo.toml` adds `base64` and
  `chatui-contracts`; `repositories/conversations.rs` adds
  `ConversationRepository::list_all`; `repositories/messages.rs` adds
  `MessageRepository::list_all_including_deleted` and makes
  `refresh_conversation_stats` crate-visible; `repositories/attachments.rs`
  adds `AttachmentRepository::list_all_unbounded`. These are read helpers for
  export and the transactional import writer. No UI or provider crate was
  touched.
- Tests: `export::tests` covers round-trip IDs/ordering/snapshots, opt-in
  bytes, missing store rejection, secret header/metadata exclusion,
  per-conversation filtering, deterministic ordering, and newest-first
  listing. `import::tests` covers round-trip, merge preservation, model ID
  remapping, missing attachment bytes, invalid JSON, schema violations,
  duplicate IDs, dangling references, unsafe names, oversized archive,
  oversized attachment, invalid base64, size mismatch, hash mismatch,
  transactional rollback on conflict, replace mode, and settings merge.
