## Implementation steps

1. Read spec sections 7.4, 10.12, 15.1, and 15.2.
2. Run the full Rust suite:
   ```bash
   make contracts-check
   make rust-fmt
   make rust-lint
   make rust-nextest
   make rust-conformance
   make rust-build
   make rust-deny
   make rust-audit
   ```
3. Run the provider conformance suites for every enabled adapter.
4. Execute the OpenRouter checklist and record each item with a test name or manual evidence.
5. Walk the section 15.2 list and mark each case `pass`, `N/A`, or `blocked`. Include the test name or procedure.
6. Run the process-death procedure on the available OS. Use the release or debug build consistently and record which.
7. Verify partial content survives cancellation and failure.
8. Verify export/import round-trip and clear-data behavior.
9. Verify no secrets appear in logs, exports, or crash output.
10. Record results in `conformance.md` and `M3.5-verification.md`.

### What changed

- Added `rust/tests/conformance/tests/process_death.rs` and
  `rust/tests/conformance/src/bin/process_death_child.rs`. The test spawns a
  child, commits a `streaming` message, kills the child with `SIGKILL` (or
  `TerminateProcess`), reopens the database, and proves recovery marks the
  message `cancelled` while preserving partial text and reasoning.
- Added `chatui-storage`, `tokio`, and `tempfile` to the conformance package so
  the process-death test can use the real storage layer.
- Updated the OpenRouter checklist in `conformance.md` to mark the previously
  deferred display and persistence items as passing, with the UI test names.
- Added the full run, fixture coverage, provider suites, critical-case table,
  process-death procedure, secret-handling evidence, and blockers to
  `conformance.md`.
- Added section 13 to `M3.5-verification.md`.
