### 10.2 Redaction evidence

The default `Redactor` policy redacts `Authorization`, `x-api-key`,
`x-goog-api-key`, `anthropic-dangerous-direct-browser-access`, custom secret
headers, registered exact values, bearer tokens, API-key-shaped strings, and
sensitive query parameters. `RedactingFormat` formats the complete tracing event
and then redacts it, so structured fields and span attributes are covered.

Tests:

- `redaction::tests::redacts_authorization_header`
- `redaction::tests::redacts_required_api_key_headers`
- `redaction::tests::redacts_custom_secret_header`
- `redaction::tests::redacts_json_style_header`
- `redaction::tests::redacts_bearer_tokens_anywhere`
- `redaction::tests::redacts_api_key_shaped_strings`
- `redaction::tests::redacts_sensitive_query_parameters`
- `redaction::tests::redacts_registered_secret_values`
- `redaction::tests::preserves_ordinary_text`
- `redaction::tests::preserves_line_endings`
- `redaction::tests::redactor_debug_does_not_print_registered_values`
- `redaction::tests::redacting_format_redacts_event_fields`

### 10.3 Panic evidence

`install_panic_hook` redacts the panic payload with the same policy, truncates it
to 512 characters, and keeps the source location. Tests:

- `panic::tests::panic_message_redacts_headers_and_tokens`
- `panic::tests::panic_message_redacts_registered_values`
- `panic::tests::panic_message_truncates_long_payloads`
- `panic::tests::panic_report_writes_redacted_output`
- `panic::tests::panic_message_keeps_location_context`

Limitation: the panic runtime owns the payload buffer, so the hook prevents
printing but cannot zeroize that buffer.

### 10.4 Release logging policy

`filter_for(false)` returns `WARN` and `filter_for(true)` returns `DEBUG`.
`redaction::tests::release_filter_is_not_verbose` asserts both. Release builds
therefore do not configure verbose request or response logging. The crate adds
no telemetry, analytics, or remote logging.

### 10.5 Zeroization evidence

`SecretValue` uses `Zeroizing<String>` and implements `Zeroize`;
`store::tests::secret_value_can_be_zeroized_explicitly` proves explicit
zeroization. Derived keys, decrypted plaintext, and serialized plaintext use
`Zeroizing`. `EncryptedFileStore::load` wraps each plaintext value in
`Zeroizing<String>` before validating the ID, so an early return still zeroizes
the remaining values. `SessionStore` clears its map on lock and drop. The full
audit is in [security.md](security.md) section 4.

### 10.6 Backup exclusion

| OS | Result | Evidence |
| --- | --- | --- |
| Linux | Documented procedure; no standard OS-level per-file exclusion | `security.md` section 5 gives `rsync` and `tar` exclusion examples for `~/.local/share/chatui/secrets.enc`. |
| macOS | Documented procedure; not yet wired into Rust | `security.md` section 5 specifies `NSURLIsExcludedFromBackupKey` and `tmutil addexclusion` for `~/Library/Application Support/chatui`. |
| Windows | Documented procedure; explicit limitation | `security.md` section 5 records the `%APPDATA%\chatui\data` path, OneDrive Known Folder Move behavior, and the lack of a standard per-file cloud-backup exclusion. |

The SQLite conversation database is not encrypted at rest in phase 1; the same
directory-level exclusion should cover it. Backup/sync implementation remains
M5 scope.

### 10.7 Source audit

The audit commands and results are in [security.md](security.md) section 6. No
`std::env` usage, URL construction, secret-bearing filename, or secret-bearing
error message was found in `chatui-secrets`. `expose()` is used only for keyring
writes, Argon2id input, JSON serialization, and tests. Secret-bearing `Debug`
implementations are custom and redacted; `FallbackChoice` derives `Debug` but its
passphrase field is a `SecretValue` and prints `SecretValue([REDACTED])`.

### 10.8 Limitations

- macOS and Windows backup exclusion is documented, not implemented in Rust.
- The panic payload is redacted before printing but is not zeroized.
- The OS credential-store backend may copy a secret internally; the crate
  zeroizes its own buffers and never logs the value.
- Release logging is limited to `WARN`; request and response bodies are never
  logged by this crate.
