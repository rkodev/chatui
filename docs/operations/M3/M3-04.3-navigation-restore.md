# M3-04.3 - Navigation and last-active restore

- Milestone: M3
- Status: Complete
- Order: 20
- Depends on: M3-04.2, M3-02.2
- Parallel-safe: no; shares startup and navigation files
- Owns: `android/app/src/main/java/dev/chatui/shell/`, `MainActivity`, navigation tests, `M3-verification.md` (restore evidence)
- Read first: [M3 plan](../M3-android-depth-implementation-plan.md) sections 3.3 and 4.5; spec sections 9.3, 9.4, and 11.1

## Goal

Restore the practical navigation location after a cold start without overriding deep links or onboarding.

## Preconditions

- M3-04.2 and M3-02.2 are complete.
- Do not persist secrets, provider keys, or transient dialog state.
- Do not auto-open a deleted conversation.

## Deliverables

- Last-active conversation is persisted when a chat is opened and restored on cold start.
- Navigation Compose saved state is used for practical back-stack restoration.
- Missing/deleted last-active conversation falls back safely.
- Deep links take precedence over last-active restore.
- Onboarding still wins when setup is incomplete.
- Tests for each case.

## Implementation steps

1. Read `shellStartDestination`, `ShellNavHost`, `ChatUiApp`, `MainActivity`, `ConversationService.setLastActiveConversation`, `getLastActiveConversation`, and the deep-link handler.
2. Confirm `ShellNavHost` uses a `rememberNavController` backed by saved state. Keep that behavior.
3. Ensure opening a chat writes `lastActiveConversationId`. Do not write it for providers/settings unless M3-00.2 explicitly requires it.
4. On cold start:
   - if onboarding is incomplete, start onboarding;
   - else if a pending deep link exists, route the link first;
   - else if the last-active conversation exists, open it;
   - else open the conversation list.
5. Handle a missing or deleted last-active conversation by clearing the pointer and opening the list. Do not show a permanent not-found screen for a stale pointer.
6. Add tests for:
   - last-active conversation restore;
   - deleted conversation fallback;
   - deep link precedence over last-active;
   - onboarding precedence over both;
   - no duplicate navigation on recreation.
7. Record the cold-start restore evidence in `M3-verification.md`.

## Handoff notes

- Cold-start routing now goes through `resolveShellStartDestination` in
  `ShellNavHost.kt`. It checks onboarding first, then a pending external intent
  (deep link or share), then `ConversationService.getLastActiveConversation()`.
  The service clears a stale pointer when the conversation no longer exists, so
  a deleted last-active conversation falls back to the list without a
  not-found screen.
- `ChatUiApp` resolves the start destination once per activity creation and
  only starts the external-intent collector after that resolution. This keeps a
  cold-start deep link from being raced by last-active restore. The collector
  still restarts when onboarding completes so a link held during onboarding is
  handled afterwards.
- `rememberNavController()` remains the back-stack owner, so Navigation Compose
  saved state still restores the practical back stack on recreation. A consumed
  deep link is not re-delivered by `ExternalIntentRouter`, which prevents
  duplicate navigation on recreation.
- Opening a chat still writes `lastActiveConversationId` from the chat
  destination. The write is now guarded so a deep link to a missing
  conversation renders the existing not-found state instead of throwing.
- No new persistence was added. Only the existing non-secret
  `lastActiveConversationId` setting is used; provider keys, secrets, and
  transient dialog state are untouched.
- Tests: `ShellNavigationTest` covers restore, deleted fallback and pointer
  clearing, deep-link precedence, onboarding precedence, and consumed-link
  recreation. `FakeConversationService.getLastActiveConversation` now mirrors
  the production stale-pointer clearing.
- Verification: `make android-lint`, `make android-test`, and
  `make android-assemble` pass; `:app:connectedDebugAndroidTest` passes on
  `Medium_Phone_API_36.1(AVD) - 16` (10 tests, 2 skipped manual phases).
- Evidence is recorded in `M3-verification.md` section 15.
