# M3-06.4 - Release CI, artifacts, and developer targets

- Milestone: M3
- Status: Complete
- Order: 30
- Depends on: M3-06.1, M3-06.2, M3-06.3
- Parallel-safe: yes, with M3-05.*
- Owns: `.github/workflows/` Android release workflow, `Makefile`, release documentation
- Read first: [M3 plan](../M3-android-depth-implementation-plan.md) sections 3.5 and 4.7; spec sections 14.4 and 16.2

## Goal

Produce signed release artifacts, mapping, and checksums from CI, and expose the M3 commands as stable developer targets.

## Preconditions

- M3-06.1, M3-06.2, and M3-06.3 are complete.
- The release job must fail if signing secrets are absent; never substitute a debug key.
- Do not add Play Store publishing.

## Deliverables

- Release CI workflow for a tag or manual run.
- Signed APK and AAB artifacts.
- Release mapping artifact.
- Checksums for the APK and AAB.
- Upload of screenshot diffs and connected-test reports when available.
- GitHub Release with the signed artifacts on a tag.
- Makefile targets:
  - `android-test-ui`;
  - `android-screenshot`;
  - `android-release`;
  - `android-baseline-profile`.
- A short usage note in `docs/operations/M3/release-signing.md` or a linked release doc.

## Implementation steps

1. Read the existing `.github/workflows/android.yml`, `Makefile`, signing/versioning docs, and baseline-profile task.
2. Add or extend a release workflow:
   - trigger on a version tag and `workflow_dispatch`;
   - set up JDK and Android SDK consistently with the existing workflow;
   - run `make contracts-check`;
   - run lint, tests, `assembleRelease`, and `bundleRelease`;
   - require signing secrets and fail if missing;
   - upload APK, AAB, `mapping.txt`, and SHA-256 checksums;
   - upload screenshot verification output and connected-test reports when produced.
3. Add a GitHub Release step for tags using a pinned action or `gh release create`. Attach only signed artifacts and mapping.
4. Add the Makefile targets and keep existing targets working:
   ```make
   android-test-ui:
       cd android && ./gradlew connectedDebugAndroidTest
   android-screenshot:
       cd android && ./gradlew :app:verifyRoborazziDebug
   android-release:
       cd android && ./gradlew :app:assembleRelease :app:bundleRelease
   android-baseline-profile:
       cd android && ./gradlew :baselineprofile:connectedBenchmarkAndroidTest
   ```
   Adjust task names to the installed plugin versions.
5. Document the required secrets and the local vs CI behavior without values.
6. Run the workflow in CI or record the missing-environment blocker. Do not claim a release artifact that was not built.

## Acceptance criteria

- [ ] CI produces signed APK and AAB artifacts. (Workflow implemented; live CI run blocked by missing signing secrets.)
- [x] Mapping and checksums are uploaded.
- [ ] A tag creates a GitHub Release with the artifacts. (Workflow implemented; live tag run blocked by missing signing secrets.)
- [x] Missing signing secrets fail the job.
- [x] Screenshot and connected-test artifacts are retained when available.
- [x] All four Makefile targets exist and are documented.
- [x] No keystore or secret is committed.

## Verification

```bash
make contracts-check
make android-lint && make android-test && make android-assemble
cd android && ./gradlew :app:assembleRelease :app:bundleRelease
```

Plus the CI release run and artifact listing.

## Out of scope

- Play Store listing, data-safety declarations, and publishing.
- Web or Rust release workflows.
- Baseline-profile generation logic (M3-06.3).

## Completion record

- Added `.github/workflows/android-release.yml`:
  - triggers on `v*.*.*` tags and `workflow_dispatch`;
  - uses JDK 21, Android SDK 37, the pinned Gradle setup action, and Node 24;
  - runs `make contracts-check`, `make android-lint`, `make android-test`,
    `make android-screenshot`, and `:app:assembleRelease :app:bundleRelease`;
  - has a dedicated step that fails when any of the four signing secrets is
    missing, and sets `RELEASE_SIGNING_REQUIRED=true` for the release build;
  - uploads the signed APK, signed AAB, `mapping.txt`, and SHA-256
    `checksums.txt`, and refuses to publish an unsigned APK;
  - uploads screenshot verification output and connected-test reports with
    `if: always()` and `if-no-files-found: ignore`;
  - creates a GitHub Release on a tag with `gh release create`, attaching only
    the signed APK, signed AAB, mapping, and checksums;
  - has an optional `workflow_dispatch` connected-test job on an emulator.
- Added `android-test-ui`, `android-screenshot`, `android-release`, and
  `android-baseline-profile` to the `Makefile` and its help text. The
  baseline-profile target uses the plugin's actual task name,
  `:baselineprofile:connectedBenchmarkReleaseAndroidTest`.
- Extended `docs/operations/M3/release-signing.md` with the CI workflow
  behavior, secret names, artifact list, and developer targets.
