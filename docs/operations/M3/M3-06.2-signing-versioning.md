# M3-06.2 - Signing and version policy

- Milestone: M3
- Status: Complete
- Order: 28
- Depends on: M3-06.1, M3-00.2
- Parallel-safe: yes, with M3-05.*
- Owns: `android/app/build.gradle.kts`, signing/version docs, CI secret-name documentation
- Read first: [M3 plan](../M3-android-depth-implementation-plan.md) sections 3.5 and 4.7; spec sections 14.4 and 16.5

## Goal

Make release signing depend only on CI secrets and make versioning monotonically increasing and semantic.

## Preconditions

- M3-06.1 minified release build works.
- M3-00.2 records whether signing secrets are available.
- Never commit a keystore, password, or base64 secret.

## Deliverables

- Env-driven release signing configuration.
- A release build that fails loudly when signing is required but secrets are absent.
- Monotonic `versionCode` and semantic `versionName` policy.
- `docs/operations/M3/release-signing.md` listing secret names and the local-build behavior.
- No committed signing material.

## Implementation steps

1. Read `android/app/build.gradle.kts`, `gradle.properties`, `.gitignore`, and the release workflow plan.
2. Add a `signingConfigs.release` block that reads, without printing values:
   - `ANDROID_KEYSTORE_PATH` or `ANDROID_KEYSTORE_BASE64`;
   - `ANDROID_KEYSTORE_PASSWORD`;
   - `ANDROID_KEY_ALIAS`;
   - `ANDROID_KEY_PASSWORD`.
   If a base64 secret is used, decode it to a temporary file outside the repository and delete it after use.
3. Apply the release signing config only when all required values exist. If `RELEASE_SIGNING_REQUIRED=true` and they are missing, fail the build with an actionable message.
4. Define versioning:
   - `versionCode` from `ANDROID_VERSION_CODE` when set, otherwise a monotonic git commit count or the existing local value;
   - `versionName` from `ANDROID_VERSION_NAME` or a semantic tag, otherwise `0.1.0-dev`;
   - record the policy in `release-signing.md`.
5. Confirm the debug variant still uses the debug signing config and no release secret is needed for local debug work.
6. Add a repository scan to CI or the task handoff:
   ```bash
   rg -n --hidden -g '!*.lock' -g '!**/build/**' "keystore|storePassword|keyPassword" .
   ```
   No committed secrets may be found.
7. Document the secret names and expected local behavior in `release-signing.md`.

## Acceptance criteria

- [x] Release signing reads only environment/CI values.
- [x] Missing required secrets fail the release build with clear copy.
- [x] Debug builds remain unaffected.
- [x] `versionCode` policy is monotonic.
- [x] `versionName` follows semantic versioning.
- [x] No keystore or password is committed.
- [x] `release-signing.md` lists secret names only, never values.

## Completion record

- `android/app/build.gradle.kts` now reads release signing only from
  `ANDROID_KEYSTORE_PATH` or `ANDROID_KEYSTORE_BASE64`,
  `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, and `ANDROID_KEY_PASSWORD`.
  No value is printed.
- A base64 keystore is decoded to a temporary file outside the repository,
  restricted to the current user, and deleted by the `cleanupReleaseKeystore`
  finalizer, `buildFinished`, and `deleteOnExit`.
- `RELEASE_SIGNING_REQUIRED=true` fails configuration with an actionable
  message naming the missing values. A debug key is never substituted.
- `versionCode` uses `ANDROID_VERSION_CODE` when set, otherwise
  `git rev-list --count HEAD`, otherwise `1`. `versionName` uses
  `ANDROID_VERSION_NAME`, otherwise an exact semantic tag, otherwise
  `0.1.0-dev`.
- Debug builds keep the default debug signing config and need no release
  secret.
- Added `docs/operations/M3/release-signing.md` with secret names only, local
  behavior, version policy, and the secret-hygiene scan.

## Handoff notes

- Verification:
  - `cd android && ./gradlew :app:assembleDebug` -> BUILD SUCCESSFUL.
  - `RELEASE_SIGNING_REQUIRED=false ./gradlew :app:assembleRelease` ->
    BUILD SUCCESSFUL; output is `app-release-unsigned.apk`.
  - `RELEASE_SIGNING_REQUIRED=true ./gradlew :app:help` -> fails with the
    expected missing-secret message and exit code 1.
  - A throwaway keystore outside the repository was used to verify the signed
    path: `assembleRelease` produced a signed `app-release.apk`, `apksigner
    verify` passed, `versionCode=4242` and `versionName=1.2.3` were applied,
    and the decoded temporary keystore was removed.
- Secret scan: `rg` is not installed in this environment, so the equivalent
  `grep -rn --exclude-dir=.git --exclude-dir=build --exclude-dir=.gradle
  --exclude-dir=node_modules --exclude='*.lock' -E
  "keystore|storePassword|keyPassword" .` was run. Matches are documentation,
  build-script references, and existing Keystore test identifiers only. No
  keystore, password, or base64 value is committed; `git ls-files` shows no
  signing-material extensions.
- CI signing secrets remain unavailable per `M3-decisions.md`. The signed CI
  release gate is still owned by M3-06.4 and must set
  `RELEASE_SIGNING_REQUIRED=true` plus the four secret names.
- Shallow CI clones report a commit count of `1`; release CI must set
  `ANDROID_VERSION_CODE` explicitly or fetch full history for a monotonic
  `versionCode`.
