- Status: Not started

- Depends on: M1-02.1
- Parallel-safe: yes, with M1-02.2 and M1-06.3
- Owns: `web/src/providers/openrouter.ts` key/catalog portion, `web/src/providers/openrouterCatalog.ts`, catalog cache tests, fixtures under `contracts/fixtures/models/`
- Read first: [M1 plan](../M1-openrouter-core-implementation-plan.md) section 4.3; spec sections 3.1, 3.3, 3.4, 7.4 model catalog and key introspection, 7.8

## Goal

Implement OpenRouter `GET /key` and `GET /models` with normalized catalog mapping, a 24-hour cache, manual refresh, and last-known-good behavior.

## Preconditions

- M1-02.1 registry is available.
- Do not implement `POST /chat/completions` in this task.

## Deliverables

- `validateKey(context, signal)` returning `ProviderKeyInfo`.
- `listModels(context, signal)` returning normalized `ModelInfo`.
- Mapping for `id`, `canonical_slug`, `name`, `context_length`, `top_provider.*`, `architecture.*`, `pricing.*`, `supported_parameters`, `default_parameters`, `per_request_limits`, and unknown non-secret metadata.
- Price conversion from USD per token to USD per million, preserving raw strings in metadata.
- Free-model detection using zero effective pricing and the `:free` suffix.
- Capability inference for text, vision, files, tools, reasoning, and streaming.
- Catalog cache with 24-hour TTL, manual refresh, and last-known-good snapshot on failure.
- Attribution headers from runtime config.
- Tests against `contracts/fixtures/models/openrouter-models.json`, `openrouter-key.json`, and synthetic malformed responses.

## Implementation steps

1. Read the catalog mapping table in spec 7.4 twice; implement it field by field.
2. Use decimal-safe conversion for price strings. Do not parse binary floats directly for per-million display.
3. Treat unknown fields as ignorable and copy only small non-secret values into metadata.
4. Implement cache read/write. Store `fetchedAt` and the last successful normalized catalog.
5. On network or parse failure, return the last-known-good catalog with a refresh error flag.
6. Implement key validation mapping including `label`, usage, limit, free-tier, and rate limit.
7. Ensure the API key is never placed in a URL or log.
8. Add fixture tests for paid, free, vision, reasoning, tool, long-context, unusual pricing, and unknown-field models.
9. Add tests for cache hit, expiry, refresh, and failure fallback.

## Acceptance criteria

- [ ] A valid key maps label, usage, limit, free-tier, and rate-limit metadata.
- [ ] Every required catalog field is mapped correctly.
- [ ] Prices display per million tokens and free models are marked.
- [ ] Unknown fields do not break mapping.
- [ ] Cache lasts 24 hours, manual refresh works, and failure keeps the last good catalog.
- [ ] No chat streaming is added.
- [ ] Web gate passes.
