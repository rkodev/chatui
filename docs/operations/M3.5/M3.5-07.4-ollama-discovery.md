## Goal

Implement Ollama's native NDJSON chat and `/api/tags` discovery, plus shared fallback-model selection and capability inference for presets whose discovery is missing or degraded.

## Preconditions

- OpenAI-compatible preset behavior exists.
- Do not fork provider logic per OS.
- Do not use the OpenAI-compatible path as the only Ollama implementation; native NDJSON is primary.
- Do not modify `web/`, `android/`, or `contracts/`.

## Deliverables

- Ollama native adapter:
  - `POST /api/chat` with NDJSON;
  - system prompt as the first message;
  - text/file concatenation;
  - image base64 arrays;
  - `options` for sampling controls;
  - `num_predict` for max output tokens;
  - final usage from `prompt_eval_count` and `eval_count`.
- Ollama discovery at `/api/tags` mapped into the shared `Model` shape.
- A documented OpenAI-compatible fallback for custom local servers.
- Shared discovery fallback selection:
  - use the preset default model when present in the catalog;
  - otherwise select the first non-hidden text model by `remoteId`;
  - when the catalog is empty, use the first fallback preset model;
  - emit the exact shared unavailable/fallback notices.
- Capability inference from preset defaults when the provider omits modalities, capabilities, context, or supported parameters.
- Tests against Ollama request, stream, error, tags, fallback, and capability vectors.

## Implementation steps

1. Read `web/src/providers/ollama.ts`, `fallbackModels.ts`, `openaiCatalog.ts`, and the shared fallback/capability vectors.
2. Implement Ollama native base URL handling: strip the trailing `/v1` from the contract base URL when using `/api/*`.
3. Implement `POST /api/chat` with NDJSON. Parse each line as JSON in the adapter, not the transport.
4. Map `message.content` to text deltas, `done` and `done_reason` to finish, and `prompt_eval_count`/`eval_count` to usage.
5. Map images to the message `images` array as base64. Concatenate file parts with the shared file header.
6. Map sampling controls under `options`; `maxOutputTokens` maps to `num_predict`; `stop` maps to `stop`.
7. Implement `/api/tags` discovery and map names to models with preset defaults.
8. Implement fallback selection and notices exactly as the request-vector README specifies.
9. Implement capability inference in the shared order `text`, `vision`, `files`, `tools`, `reasoning`, `streaming`.
10. Add tests for NDJSON completion, usage, errors, tags, fallback present/missing/no-text cases, and capability inference.
11. Run the shared conformance suite.

## Acceptance criteria

- [ ] Ollama native chat streams correctly from NDJSON.
- [ ] Usage and finish reasons map correctly.
- [ ] `/api/tags` discovery maps into the shared `Model` shape.
- [ ] Images and file parts serialize correctly.
- [ ] Fallback selection and notices match the shared vectors.
