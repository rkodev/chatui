## Goal

Create synthetic, replayable fixtures for every provider path that later clients must normalize. Fixtures are contracts and must not contain real keys, prompts, personal data, or live API captures.

## Preconditions

- Provider presets and schemas exist.
- Do not implement stream parsers or client adapters.

## Deliverables

### Stream fixtures under `contracts/fixtures/streams/`

- `openrouter-text.sse`
- `openrouter-reasoning.sse` with both `reasoning` and `reasoning_details`
- `openrouter-usage.sse` with final usage and cost
- `openrouter-error-200.sse` with an error object inside an HTTP 200 stream
- `openrouter-keepalive.sse` containing `: OPENROUTER PROCESSING` comments and unknown fields
- `openai-text.sse`
- `openai-reasoning.sse`
- `anthropic-text.sse`
- `gemini-text.sse`
- `ollama-ndjson.txt`
- `error-429.sse`

Each file must be non-empty UTF-8, use the provider's real wire syntax, and be usable as raw bytes without post-processing.

### Catalog fixtures under `contracts/fixtures/models/`

- `openrouter-models.json`: provider-shaped catalog with paid, `:free`, vision, reasoning, tool-capable, long-context, unusual pricing strings, unknown fields, and canonical slugs.
- `openrouter-key.json`: key metadata with label, usage, limit, free-tier flag, and rate-limit information.
- `openai-models.json`
- `anthropic-models.json`
- `gemini-models.json`
- `ollama-tags.json`

### Error fixtures under `contracts/fixtures/errors/`

- `openrouter-402.json`
- `openrouter-429.json`
- `openrouter-503.json`

### Fixture rules

- Use only fake identifiers such as `sk-or-v1-example`, never a realistic secret.
- Keep prompts generic and non-personal.
- Preserve free-model `:free` suffixes and OpenRouter pricing strings exactly.
- Do not add expected normalized event snapshots in M0. Record that this is deferred to M1 conformance in the handoff notes.

## Implementation steps

1. Read spec 7.4, 7.5, and 7.6 for wire shapes.
2. Create the stream fixtures first. Keep each scenario small enough for a human to read.
3. Create the catalog fixtures. Include at least one entry that exercises each required capability and pricing edge case.
4. Create the three error envelopes.
5. Check every file is non-empty and valid UTF-8.
6. Search the fixture tree for obvious secret patterns and remove anything that resembles a real key.

```bash
jq empty contracts/fixtures/models/*.json contracts/fixtures/errors/*.json
file contracts/fixtures/streams/* contracts/fixtures/models/* contracts/fixtures/errors/*
grep -RniE 'sk-[a-z0-9]{20,}|api[_-]?key|bearer [a-z0-9]{20,}' contracts/fixtures || true
```

The first command must print nothing. The grep command is a review aid, not a guarantee.

## Handoff notes

- Expected normalized event snapshots are intentionally deferred to M1 conformance. M0 delivers raw provider wire fixtures only.
- `openrouter-key.json` is key introspection metadata, not a model catalog. The validator must special-case it instead of treating every JSON under `fixtures/models/` as a catalog envelope.
- `error-429.sse` is an OpenAI-style SSE error payload used for stream error handling. The OpenRouter HTTP error envelope is `fixtures/errors/openrouter-429.json`.
- The OpenRouter free fixture has a `:free` ID and a canonical slug without the suffix to exercise deduplication without rewriting the selectable ID.
- The OpenRouter catalog includes synthetic-only unknown fields (`experimental_routing`, `x_provider_note`, `future_capability_flags`) and unknown pricing/usage fields so clients prove they ignore unknown data safely.
- All identifiers, digests, names, and content are synthetic. No live API captures are present.
- Fixtures are contracts. Future changes to them must be deliberate and reviewed, not incidental edits while implementing adapters.
