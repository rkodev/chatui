# M3.5-02.1 - Domain entities, IDs, time, errors, and stream events

- Milestone: M3.5
- Status: Complete
- Order: 6
- Depends on: M3.5-01.1
- Parallel-safe: yes, with M3.5-01.2, M3.5-01.3, and M3.5-04.1
- Owns: `rust/crates/chatui-domain/`
- Read first: [M3.5 plan](../M3.5-rust-desktop-implementation-plan.md) sections 3.2 and 4.4; spec sections 6.1, 6.2, 7.2, and 15.2

## Goal

Implement the Rust domain model with the exact shared JSON shapes so exports, imports, fixtures, and provider events interoperate with web and Android.

## Preconditions

- The workspace exists.
- Do not add network, storage, UI, or OS dependencies to `chatui-domain`.
- Do not invent field names or a second serialization shape.
- Do not modify `web/`, `android/`, or `contracts/`.

## Deliverables

- Serde structs/enums for:
  - `Provider`, `Model`, `Conversation`, `ChatParams`, `Message`, `ContentPart`, `Attachment`, `Usage`, `ChatError`, `Settings`, `BackupConfig`, `SyncMeta`.
  - `StreamEvent`, `FinishReason`, `ChatErrorCode`, `MessageRole`, `MessageStatus`, `ProviderKind`, `ProviderAuthType`, `BrowserCors`, `ModelCapability`, `InputModality`, `OutputModality`, `ModelSource`, `Theme`, `Density`, `ChatFontSize`, `SendKey`, `ReasoningEffort`.
- Exact JSON field names matching section 6 and the export schema. Use `#[serde(rename_all = "camelCase")]` only where it matches the shared JSON.
- UUIDv7 generation and validation helpers.
- RFC 3339 UTC timestamp helpers with a `Z` suffix.
- Unit tests for serialization, enum values, IDs, timestamps, and content-part round-trips.

## Implementation steps

1. Read `docs/IMPLEMENTATION.md` sections 6.1, 6.2, and 7.2, plus `web/src/domain/*` and the Android entities for reference.
2. Add dependencies: `serde` with `derive`, `serde_json`, `uuid` with the `v7` feature, and `time` or `chrono` with serde support. Keep the dependency set minimal.
3. Create modules such as `provider.rs`, `model.rs`, `conversation.rs`, `message.rs`, `attachment.rs`, `settings.rs`, `errors.rs`, `stream.rs`, `ids.rs`, and `time.rs`.
4. Model `ContentPart` as a tagged enum:
   ```rust
   #[serde(tag = "type", rename_all = "kebab-case")]
   pub enum ContentPart {
       Text { text: String },
       Image { attachment_id: String, mime_type: String, alt: String },
       File { attachment_id: String, mime_type: String, name: String },
       Reasoning { text: String },
       ToolCall { id: String, name: String, arguments_json: String },
       ToolResult { tool_call_id: String, content: String },
   }
   ```
   Use `#[serde(rename = "attachmentId")]` etc. where the shared JSON is camelCase.
5. Model `StreamEvent` as a tagged enum with `start`, `text-delta`, `reasoning-delta`, `tool-call-delta`, `usage`, `finish`, and `error`.
6. Model `ChatError` with every shared code and field. Keep `details` as `Option<serde_json::Value>`.
7. Implement UUIDv7 helpers using `uuid::Uuid::now_v7()`. Reject non-v7 UUIDs in validation tests.
8. Implement RFC 3339 helpers using `time::OffsetDateTime` or `chrono::DateTime<Utc>` and serialize with a `Z` suffix.
9. Add round-trip tests for every entity and content part. Include nulls, empty arrays, and unknown provider metadata.
10. Add a dependency test or source review proving `chatui-domain` has no I/O crates.

## Handoff notes

### Result (2026-11-07)

Implemented the domain crate with modules `attachment`, `conversation`, `errors`,
`ids`, `message`, `model`, `provider`, `settings`, `stream`, and `time`.

Public types:

- Entities: `Provider`, `Model`, `ModelPricing`, `Conversation`, `ChatParams`,
  `Message`, `ContentPart`, `Attachment`, `Usage`, `ChatError`, `Settings`,
  `BackupConfig`, `SyncMeta`.
- Enums: `ProviderKind`, `ProviderAuthType`, `BrowserCors`, `ModelCapability`,
  `InputModality`, `OutputModality`, `ModelSource`, `MessageRole`,
  `MessageStatus`, `FinishReason`, `ChatErrorCode`, `AttachmentKind`,
  `ReasoningEffort`, `SyncState`, `Theme`, `Density`, `ChatFontSize`, `SendKey`,
  `BackupBackend`, `BackupEncryption`, `BackupKdf`.
- Events: `StreamEvent` with `start`, `text-delta`, `reasoning-delta`,
  `tool-call-delta`, `usage`, `finish`, and `error`.
- Helpers: `new_id`, `is_uuid_v7`, `validate_uuid_v7`, `UuidV7Error`,
  `Timestamp`, `now_rfc3339`, `format_rfc3339`, `parse_rfc3339`,
  `is_rfc3339_utc`.

Serialization uses `#[serde(rename_all = "camelCase")]` on structs and explicit
renames where the shared JSON is not a simple case conversion. `ContentPart` and
`StreamEvent` are internally tagged with `type` and kebab-case variant names.
`ModelPricing` omits absent optional fields instead of emitting `null`, matching
the export schema. `Timestamp` normalizes to UTC and always serializes RFC 3339
with millisecond precision and a `Z` suffix.

Tests cover every entity, every content part, every stream event, all
`ChatErrorCode` values, UUIDv7 generation/validation, RFC 3339 round-trips,
nulls, empty arrays, unknown provider metadata, and the shared
`contracts/fixtures/expected/chatui-export.json` fixture. A manifest test
asserts that `chatui-domain` has no network, storage, UI, or OS crates.

Verification results:

- `cargo fmt --all --check` passed.
- `cargo clippy -p chatui-domain --all-targets -- -D warnings` passed.
- `cargo nextest run -p chatui-domain` passed: 37 tests.
- `cargo tree -p chatui-domain` shows only `serde`, `serde_json`, `time`, and
  `uuid` (plus their transitive support crates such as `getrandom`/`libc` for
  UUIDv7 randomness and `time-core`/`time-macros`).

`cargo-nextest` was not installed in the environment; it was installed locally
with `cargo install --locked cargo-nextest` to run the required verification.
No repository artifact was added for the tool.

Deviation: `SyncMeta` is the provisional shape already used by the web and
Android clients (`state`, `lastSyncedAt`, `remoteRevision`). The spec references
`SyncMeta` without defining it; M5 owns the final shape. No provider presets or
provider metadata were copied into the domain.
