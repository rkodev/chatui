## Handoff notes

- Search strategy: bounded cursor scan instead of a full-text index. Titles are
  checked over the newest 500 conversations; message text over the newest 2,000
  messages. Results are capped at 20 conversation groups and 3 snippets per
  group. Searches are case-insensitive and whitespace-normalized. A result is
  marked `truncated` when a scan or result cap stopped the search early; the UI
  explains that only the most recent matches are shown. This keeps per-query
  work bounded and pairs with the debounce so the store is never scanned per
  keystroke. If M2-04.2+ needs full-history matching, replace this with a
  maintained token index in a later schema migration.
- Result grouping: one group per conversation, newest conversation first, with
  a `Title match` badge when the title matched and up to three message snippets
  ordered newest sequence first. Each snippet includes role and surrounding
  text context. Clicking a group title or snippet selects the conversation and
  clears the search query.
- Performance observations: unit tests confirm that a bounded scan reports
  `scannedConversations`/`scannedMessages` caps and truncation. The sidebar only
  invokes search after debounce, and stale requests are ignored by request id.
- Out-of-scope note: the small update to
  `web/src/features/providers/managementService.test.ts` is only the interface
  conformance needed by `ConversationStore`; no provider behavior changed.
