# M6-02.1 - Deployment template tree and edge configuration

- Milestone: M6
- Status: Not started
- Order: 5
- Depends on: M6-01.4
- Parallel-safe: yes, with `M6-03.1` and `M6-05.1`
- Owns: `deploy/chatui/README.md`, `deploy/chatui/edge/`, `deploy/chatui/templates/tenant.example.json`, `deploy/chatui.md`, `docs/hosting/overview.md`, `docs/operations/M4/deployment.md`
- Read first: [M6 plan](../M6-managed-hosting-implementation-plan.md) sections 1.1, 2.1, 3.5 (D-01 through D-04), and 4; [M4 deployment](../M4/deployment.md); `deploy/Caddyfile`; `deploy/chatui.md`; `contracts/schema/hosting-tenant.schema.json`

## Goal

Create the reproducible `deploy/chatui/` template tree and edge configuration
that serve the same static bundle with the same SPA fallback, cache rules,
security headers, CSP, and `/healthz` behavior as the M4 container. Consolidate
the old single-file recipe and remove out-of-scope managed-storage claims.

## Preconditions

- `M6-01.4` is `Complete` and the tenant manifest and public config contracts are
  frozen.
- The edge configuration must not change the section 14.1 header or cache
  contract.
- Do not add a server component, proxy, or tenant backend.

## Deliverables

- `deploy/chatui/README.md`:
  - Purpose and repository/external-operator boundary.
  - Build and upload steps for `web/dist`.
  - Link to `deploy/chatui/templates/config.full.json` and
    `config.minimal.json`.
  - Link to `deploy/chatui/templates/tenant.example.json`.
  - Link to the edge configuration, health/status definitions, custom-domain
    runbook, rollback runbook, BYO storage docs, privacy docs, and export path.
  - Explicit statement: BYO storage only; no managed storage partner in M6.
  - Explicit statement: no server-side prompt proxy, key custody, plaintext
    storage, or backup-passphrase access.
- `deploy/chatui/edge/Caddyfile`:
  - Tenant example that matches `deploy/Caddyfile` semantics: SPA fallback,
    `no-cache` for shell/config/worker/manifest and deep routes, immutable
    `/assets/*`, exact security headers and CSP, and static `/healthz`.
  - Comments show where the tenant origin/domain is configured if the operator
    uses Caddy.
- `deploy/chatui/edge/headers.md`:
  - Copy the exact header and cache table from `docs/operations/M4/deployment.md`
    so an operator using a non-Caddy edge can reproduce it.
  - State that the CSP must not gain third-party script origins.
- `deploy/chatui/templates/tenant.example.json`:
  - Valid against `hosting-tenant.schema.json`.
  - Uses example values only: subdomain, region, custom domain, release version,
    artifact digest, config hash, health, support, and rollback target.
  - Contains no credentials, keys, tokens, passphrases, or private endpoints.
- `docs/hosting/overview.md`:
  - One-page overview of the hosting flow, audiences, boundary, and links.
- Update `deploy/chatui.md`:
  - Replace the standalone recipe with a short pointer to
    `deploy/chatui/README.md`, or keep the file as a compatibility pointer.
  - Remove or qualify the "optional managed storage partner" sentence.
  - Update references in `docs/operations/M4/deployment.md` and any other files
    that link to `deploy/chatui.md`.

## Implementation steps

1. Read the existing `deploy/chatui.md` and `deploy/Caddyfile`.
2. Create the `deploy/chatui/` directories and README.
3. Copy the header/cache/SPA/health behavior into the edge template without
   loosening CSP or adding third-party origins.
4. Create the tenant example and validate it against the new schema.
5. Add the headers reference document.
6. Write the hosting overview and link every section.
7. Replace the old recipe with a pointer or update every reference.
8. Search the repository for `deploy/chatui.md` and `managed storage` and fix
   stale or out-of-scope links/claims.
9. Run contract validation and a local static smoke test.

## Acceptance criteria

- [ ] `deploy/chatui/` exists with a README, edge template, headers reference,
      and tenant example.
- [ ] The edge template reproduces the M4 SPA fallback, cache, header, CSP, and
      `/healthz` contract.
- [ ] The tenant example validates against the tenant schema.
- [ ] The old recipe no longer advertises a managed storage partner.
- [ ] Every reference to `deploy/chatui.md` resolves or is updated.
- [ ] `docs/hosting/overview.md` exists and links the real files.
- [ ] No backend, proxy, key custody, or server-side storage path is added.
- [ ] No secrets are present in templates or docs.
