## Goal

Implement the web Gemini adapter with header-based auth, SSE streaming, usage metadata, system instructions, inline data, and correct finish mapping.

## Preconditions

- M2-00.1 Gemini expected vectors exist.
- M2-01.1 generic transport is available.

## Deliverables

- Gemini model discovery from the shared catalog fixture.
- Chat streaming with `alt=sse` and `x-goog-api-key`.
- `systemInstruction` handling.
- Text and `inlineData` image request serialization.
- `usageMetadata` mapping.
- Finish reason mapping: `STOP` to `stop`, `MAX_TOKENS` to `length`, `SAFETY`/`RECITATION` to `content_filter`.
- Gemini error mapping, retry, and cancellation.
- Fixture tests and adapter registration.

## Implementation steps

1. Read the Gemini fixture and expected vector.
2. Implement the discovery and chat URL construction without putting the key in the query string.
3. Map SSE candidates and parts to normalized text deltas.
4. Map usage metadata and finish reasons exactly.
5. Serialize system instructions and inline image data.
6. Add tests for text, finish mapping, usage, errors, retry, cancellation, and protected fields.
7. Register the adapter without regressing other providers.
8. Run web gates.

## Acceptance criteria

- [ ] Gemini text fixtures pass.
- [ ] `MAX_TOKENS`, `SAFETY`, and `RECITATION` map correctly.
- [ ] Usage metadata is persisted and mapped.
- [ ] API key is sent in the header only.
- [ ] System instructions and inline data serialize correctly.
- [ ] Retry, cancellation, and errors behave like the shared contract.
- [ ] Web gates pass.
