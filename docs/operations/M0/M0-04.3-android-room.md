# M0-04.3 - Room schema, DAOs, FTS, migrations

- Status: Not started
- Parent task: M0-04
- Order: 16
- Depends on: M0-04.2
- Parallel-safe: yes, with M0-02.3
- Owns: `android/core/database/**`, its module build file, `android/core/database/schemas/**`, corresponding tests
- Read first: [M0 plan](../M0-foundations-implementation-plan.md) sections 3.3 and 4.5; spec sections 6, 9.5, 15.1

## Goal

Implement the Room database, entities, DAOs, full-text search, schema export, and migration tests. No UI may access Room directly.

## Preconditions

- Domain models exist.
- Room, KSP (or kapt), Robolectric, and AndroidX test dependencies are configured.

## Deliverables

- Room entities matching spec 9.5:
  - `ConversationEntity`
  - `MessageEntity`
  - `AttachmentEntity`
  - `ProviderEntity`
  - `ModelEntity`
  - `SecretEntity`
  - `BackupConfigEntity`
  - `SyncQueueEntity`
- Indexes:
  - `messages(conversationId, sequence)`
  - unique `models(providerId, remoteId)`
  - `attachments(sha256)`
- DAOs for every entity with focused queries:
  - conversation list/update/delete
  - last 50 messages plus older-page pagination
  - attachment metadata
  - provider and model CRUD
  - ciphertext-only secret CRUD
  - backup config and sync queue placeholders
- `messages_fts` FTS table over message text using FTS4 unless FTS5 is proven reliable at minSdk 26. Keep it synchronized through Room triggers or repository writes, and prove search finds inserted text.
- `ChatUiDatabase` version 1 with `exportSchema = true` and a committed schema JSON.
- Migrations:
  - every change gets a Room migration
  - `MigrationTestHelper` test for the current migration path
  - destructive migration is not enabled in release builds
  - export/import uses a separate format version, not the Room version
- Tests that run under `testDebugUnitTest`, using Robolectric where needed:
  - in-memory DAO tests
  - migration test using `MigrationTestHelper`
  - FTS search test
  - unique model constraint test
  - pagination test

## Implementation steps

1. Add Room KSP configuration and the database module dependencies.
2. Create entities and DAOs.
3. Add the FTS table and synchronization mechanism.
4. Add database version 1 and schema export.
5. Add migration test infrastructure even if version 1 is the only version, so future migrations are trivial to add.
6. Write DAO, FTS, uniqueness, and pagination tests.
7. Run the database module tests and the app build.

## Acceptance criteria

- [ ] All spec 9.5 entities exist with the required fields.
- [ ] Required indexes and the unique model constraint exist.
- [ ] FTS search returns inserted message text.
- [ ] Schema export is committed.
- [ ] A migration test runs successfully under `testDebugUnitTest`.
- [ ] Destructive migration is absent from release configuration.
- [ ] Message reads default to 50 and paginate older pages.
- [ ] Database module tests and `:app:assembleDebug` pass.

## Verification

```bash
cd android && ./gradlew :core:database:testDebugUnitTest
cd android && ./gradlew :app:assembleDebug
find android/core/database/schemas -type f
```

## Out of scope

- DataStore, secret encryption, repositories above the DAO layer, design system, and UI.
- Backup/sync behavior. The entities exist only as schema placeholders.

## Handoff notes

Record the FTS version, synchronization mechanism, schema version, and any migration test that requires Robolectric or instrumentation.
