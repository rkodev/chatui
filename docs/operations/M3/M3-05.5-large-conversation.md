- Milestone: M3

## Goal

Keep the proven bounded-composition behavior after the adaptive-shell and lifecycle changes.

## Preconditions

- M3-05.2 is complete.
- `ChatMessageListTest` currently has a 10,000-message test; reuse it.
- Do not rewrite the message list unless the test exposes a regression.

## Deliverables

- The 10,000-message test still passes after M3 changes.
- A bounded-composition assertion (fewer than a documented threshold of rows composed).
- Assertion that the newest message is visible and stable keys/content types are used.
- A short performance note in the handoff.

## Implementation steps

1. Run the existing `ChatMessageListTest` and record the result.
2. Keep or extend the 10,000-message test:
   - build 10,000 deterministic messages;
   - count composed rows;
   - assert the count is less than a bounded threshold (the current test uses <100);
   - assert the newest message is visible.
3. Add a case with an active streaming row to prove history rows do not all recompose when a token arrives.
4. Add a case with duplicate-prone keys/ids to prove stable identity.
5. If a shell change regressed composition, fix the list/shell with stable keys and content types; do not remove the test.
6. Record the result and any device performance note in the handoff.

## Acceptance criteria

- [ ] The 10,000-message bounded-composition test passes.
- [ ] The newest message is visible.
- [ ] History rows do not recompose on streaming token updates.
- [ ] Stable keys/content types remain in `LazyColumn`.
- [ ] No product behavior is removed to satisfy the test.
