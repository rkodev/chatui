## Goal

Deliver the Android first-run flow: BYOK/on-device explanation, OpenRouter preselected and recommended, key entry, inline testing, actionable errors, and transition to a new chat.

## Preconditions

- Provider/model services and Hilt graph are available.
- Other presets are gated to disabled/coming later.
- Do not build provider management or model picker in this task.

## Deliverables

- Onboarding ViewModel with one immutable `UiState` and intents.
- Welcome screen with BYOK/on-device copy and OpenRouter Recommended.
- Provider picker with OpenRouter enabled and other presets disabled.
- Key entry with optional label, Connect, inline testing, error area, and preserved input.
- Public catalog load before key validation; sending disabled until validation succeeds.
- On success, store provider/key, refresh models, select a default, set onboarding complete, and navigate to chat.
- Compose/unit tests for first run, invalid key, valid key, and preserved form.

## Implementation steps

1. Read `OnboardingPlaceholder`, shell navigation, and service APIs.
2. Build the ViewModel with state for welcome, form, testing, catalog loading, and error.
3. Build composables using Material 3 and existing design tokens.
4. Start catalog loading when the screen opens.
5. On Connect, disable the action, validate, and keep the form on error.
6. On success, update settings and navigate to the new chat flow.
7. Wire the shell start destination or onboarding redirect.
8. Add tests for the three critical onboarding cases.
9. Run the Android gate.

## Acceptance criteria

- [ ] First run shows onboarding and preselects OpenRouter.
- [ ] Invalid key shows an actionable error, preserves input, and stores nothing.
- [ ] Catalog models are visible before validation, but sending remains disabled.
- [ ] Valid key creates the provider, loads models, selects a default, and opens chat.
- [ ] No other provider can be connected.
- [ ] Android gate passes.
