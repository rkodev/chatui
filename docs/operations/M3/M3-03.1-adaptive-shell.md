# M3-03.1 - Adaptive shell with permanent sidebar and drawer

- Milestone: M3
- Status: Complete
- Order: 10
- Depends on: M3-00.2
- Parallel-safe: yes, with M3-01.* and M3-06.1
- Owns: `android/app/src/main/java/dev/chatui/shell/`, `android/feature/conversations/`, app/version-catalog dependencies for window sizing, shell tests
- Read first: [M3 plan](../M3-android-depth-implementation-plan.md) sections 3.2 and 4.3; spec sections 9.3, 11.1, 11.9, and M3-00.2 adaptive-navigation decision

## Goal

Make the shell adaptive: a permanent conversation sidebar at width >= 840 dp and a modal drawer below it, while keeping every existing destination reachable.

## Preconditions

- M3-00.2 records the adaptive-navigation decision.
- Do not add new conversation features, search behavior, or provider behavior.
- Do not remove access to providers, settings, data, or backup.

## Deliverables

- A width-aware shell that selects permanent sidebar or drawer at the 840 dp boundary.
- Sidebar/drawer content containing conversations, new chat, search, providers, settings, and any other existing destination.
- Main content area that keeps the current chat or destination.
- Compose/Robolectric tests at compact and expanded widths.
- No duplicate bottom-navigation behavior that conflicts with the chosen design.

## Implementation steps

1. Read `ChatUiApp.kt`, `ShellScaffold`, `ShellNavHost`, `ShellDestination`, `ConversationRoute`, `ConversationListScreen`, and `ChatScreen`.
2. Add the chosen width source to `libs.versions.toml` and the app module:
   - preferred: `androidx.compose.material3:material3-window-size-class`; or
   - use `BoxWithConstraints` if adding the dependency is not justified.
   Do not hard-code a library version in a module build file.
3. Introduce an `AdaptiveShell`/`ShellLayout` composable that accepts:
   - a sidebar slot;
   - a main-content slot;
   - a boolean for expanded width.
   At `>= 840.dp`, render the sidebar permanently. Below it, use `ModalNavigationDrawer`.
4. Wire the sidebar to the existing conversation state. Reuse `ConversationListScreen`/`ConversationRoute` and the existing `ConversationService`; do not duplicate grouping, search, pin, archive, or delete logic.
5. Keep the top app bar and destination content working. If bottom navigation is removed or retained, follow M3-00.2 exactly.
6. Add navigation tests that open providers, settings, data, backup, and a conversation from the sidebar/drawer.
7. Add width tests:
   - `@Config(qualifiers = "w411dp-h891dp")` must show the drawer or compact path;
   - `@Config(qualifiers = "w840dp-h1280dp")` must show the permanent sidebar.
8. Run the existing M1/M2 navigation tests and fix regressions.

## Acceptance criteria

- [x] Widths below 840 dp use the compact navigation path.
- [x] Widths at or above 840 dp show a permanent sidebar.
- [x] Every existing destination remains reachable.
- [x] Conversations, search, new chat, providers, and settings are available from the sidebar/drawer.
- [x] No M2 feature logic is duplicated.
- [x] Compact and expanded Compose tests pass.

## Verification

```bash
make android-lint && make android-test && make android-assemble
```

Plus a tablet/foldable device check when available.

## Out of scope

- Window insets and IME handling (M3-03.2).
- Predictive back (M3-03.3).
- Hardware shortcuts (M3-03.4).
- New conversation or navigation features.
