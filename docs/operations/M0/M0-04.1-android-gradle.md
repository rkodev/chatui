## Goal

Create a buildable Android Gradle project with the required module graph and version catalog. The app may render a minimal placeholder, but feature work belongs to later tasks.

## Preconditions

- Contracts validate.
- JDK and Android SDK are available. Locally, set `ANDROID_HOME` or create an uncommitted `android/local.properties`.
- Gradle is not required on PATH; commit a wrapper so all builds use the same Gradle version.

## Deliverables

- Gradle wrapper with `gradlew`, `gradlew.bat`, wrapper JAR, and properties. Mark `gradlew` executable.
- Root Gradle Kotlin DSL setup with a version catalog at `gradle/libs.versions.toml`.
- `build-logic` convention plugins or shared build configuration so modules do not duplicate Android/Kotlin setup.
- Modules:
  - `app`
  - `core:model`
  - `core:common`
  - `core:designsystem`
  - `core:database`
  - `core:datastore`
  - `core:network`
  - `feature:onboarding`
  - `feature:chat`
  - `feature:conversations`
  - `feature:providers`
  - `feature:settings`
  - `feature:backup`
- `minSdk = 26` and the latest stable compile/target SDK installed at implementation time. Record the selected values in the catalog.
- Dependencies included for later M0 tasks:
  - Kotlin serialization, Hilt, Navigation Compose, Coil, WorkManager, SplashScreen, Activity Compose, Lifecycle, Paging
  - Room and KSP for the database task
  - DataStore, Tink, OkHttp/SSE declarations only if they do not add provider implementations
  - JUnit4, Truth, MockK, Turbine, Robolectric, AndroidX test core
- Minimal `app` manifest and `MainActivity` that assemble and launch a placeholder.
- Namespace/application ID: use `dev.chatui` unless the repository owner has already chosen another; keep all modules under that prefix.
- `.gitignore` already covers build outputs and `local.properties`; do not commit either.

## Implementation steps

1. Inspect the installed SDK and choose the latest stable compile/target levels.
2. Bootstrap or download Gradle to generate the wrapper, then use only the wrapper afterward.
3. Create settings, root build, version catalog, and build logic.
4. Create every module with the correct plugin and minimal build file.
5. Add the minimal app manifest and entry point.
6. Run `./gradlew projects` and `:app:assembleDebug`.
7. Confirm `gradlew` is executable and `local.properties` is untracked.

## Acceptance criteria

- [ ] `./gradlew projects` lists every required module.
- [ ] `./gradlew :app:assembleDebug` succeeds.
- [ ] `minSdk` is 26.
- [ ] Compile/target SDK and dependency versions are pinned and recorded.
- [ ] The Gradle wrapper is committed and executable.
- [ ] `local.properties`, build outputs, and signing material are not committed.
- [ ] No provider implementation or feature screen exists.

## Verification

```bash
cd android && ./gradlew projects
cd android && ./gradlew :app:assembleDebug
cd android && git status --short
```

## Out of scope

- Domain models, Room, DataStore, secrets, design system, and navigation shell.
- Release signing, baseline profiles, Play Store packaging, and screenshots.
