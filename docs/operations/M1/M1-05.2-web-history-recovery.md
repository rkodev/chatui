## Goal

Deliver the conversation sidebar, date grouping, last-active restore, safe new chat, delete/undo, and startup recovery for interrupted streams.

## Preconditions

- Conversation service is complete.
- Chat screen route is wired enough to open a conversation.

## Deliverables

- Sidebar/history surface with New chat and grouped sections: Today, Yesterday, Previous 7 days, Previous 30 days, Older.
- Conversation item with title, timestamp, and a delete action; rename where the surface allows.
- Delete confirmation and a 5-second undo toast where feasible.
- Root `/` redirect to last active conversation or a new chat.
- Safe new-chat behavior that does not reuse a sending conversation.
- Startup recovery invoked before chat interaction: scan messages with status `streaming`, mark `cancelled`, preserve partial content, add an interruption explanation.
- Offline state: history readable and sending disabled.
- Tests for grouping, delete/undo, restore, and recovery.

## Implementation steps

1. Read the conversation service and chat route.
2. Build a pure date-grouping helper and tests with fixed timestamps.
3. Build the sidebar using existing primitives and design tokens.
4. Implement delete confirmation and undo buffering for 5 seconds.
5. Implement root redirect using typed settings.
6. Add a repository query or scan for `streaming` messages. Keep it bounded to the active/last conversations if necessary.
7. Implement recovery and mark the message cancelled with an explanation.
8. Add offline detection and disable send.
9. Add tests and run the gate.

## Acceptance criteria

- [ ] History groups match the required date buckets.
- [ ] New chat and last-active restore work.
- [ ] Delete requires confirmation and supports undo where feasible.
- [ ] A reload during streaming marks the message interrupted and preserves partial text.
- [ ] Offline disables sending while history remains readable.
- [ ] Search, pin, and archive are not added.
- [ ] Web gate passes.
