## Goal

Implement the Android Anthropic adapter with native headers, top-level system prompts, thinking separation, image blocks, and error mapping.

## Preconditions

- M2-00.1 Anthropic vectors exist.
- M2-05.1 generic transport is available.

## Deliverables

- Anthropic discovery and key validation where supported.
- Streaming with `x-api-key` and `anthropic-version`; no web-only browser header required.
- Top-level system prompt.
- Thinking/text separation.
- Base64 image blocks.
- Usage, finish, error, retry, and cancellation mapping.
- Fixture tests and adapter registration.

## Implementation steps

1. Read the Anthropic fixture and expected vector.
2. Implement headers and request body from the shared vectors.
3. Map all Anthropic stream events.
4. Keep thinking separate and do not replay reasoning.
5. Serialize image blocks.
6. Add tests for text, thinking, usage, errors, retry, and cancellation.
7. Register the adapter.
8. Run Android gates.

## Handoff notes

- Adapter registration: `AnthropicAdapter` implements the new `CatalogAdapter`
  surface. `ProviderAdapterRegistry` maps `ProviderKind.ANTHROPIC` to it, and
  `RoutingProviderAdapter` / `RoutingProviderGateway` dispatch by
  `context.provider.kind`. `AppModule` binds the registry, routing adapter, and
  routing gateway. `anthropic` is enabled in `M2_ENABLED_PRESET_IDS`, so the
  provider UI can create and validate Anthropic providers.
- Android headers omit the web-only
  `anthropic-dangerous-direct-browser-access` header even though the contract
  lists it in `defaultHeaders`. `x-api-key` and `anthropic-version` are always
  sent; the key never appears in a URL.
- Error mapping: HTTP 400 context messages map to `context_length`, 403 to
  `permission` unless the message is moderation-related, 429 to `rate_limit`
  with `Retry-After`, and 529 to retryable `provider`. In-stream
  `overloaded_error` maps to status 529 with `retryable = false`.
- Deferred cases: `ModelService.refreshModels` still passes no API key to
  discovery, so Anthropic discovery falls back to the shared fallback models
  until secret plumbing is added to the model service. OpenAI-compatible
  providers still use the M1 OpenRouter transport; per-preset dispatch is a
  later task. Gemini and Ollama remain disabled.
