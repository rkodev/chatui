## Goal

Turn OpenRouter SSE events into normalized `StreamEvent` values, with reasoning deduplication, usage and cost mapping, in-stream error handling, and the no-retry-after-partial rule.

## Preconditions

- HTTP client, SSE parser, retry/watchdog, and request serialization exist.
- Do not add other providers.
- Do not auto-retry after text or reasoning has been emitted.
- Do not log keys or raw response bodies in release.
- Do not modify `web/`, `android/`, or `contracts/`.

## Deliverables

- OpenRouter streaming call using the shared HTTP client and SSE parser.
- Normalized mapping for:
  - `start` with response ID;
  - `text-delta`;
  - `reasoning-delta` from `reasoning` and `reasoning_details` without duplication;
  - `usage` with input, output, total, cost, and estimated flag;
  - `finish` reason;
  - `error`.
- In-stream error handling for HTTP 200 error envelopes.
- HTTP error mapping for 401, 402, 403, 404, 429, 503, and 5xx.
- `Retry-After` extraction and retryability.
- Partial-output tracking so no retry happens after text or reasoning.
- Tests against every OpenRouter expected stream and error vector.

## Implementation steps

1. Read every `contracts/fixtures/expected/openrouter-*.json`, `openrouter-errors.json`, and the raw stream fixtures.
2. Implement the streaming call. Send the request, check status, and hand the body to the SSE parser.
3. Ignore `: OPENROUTER PROCESSING` and other comments. The SSE parser already does this; verify end to end.
4. Map `choices[0].delta.content`:
   - string content appends text;
   - array content concatenates text defensively.
5. Map reasoning:
   - prefer structured `reasoning_details` when present;
   - fall back to `reasoning`;
   - never emit duplicate text for both.
6. Map `finish_reason` values to the shared `FinishReason`. Unknown values become `unknown`.
7. Map final usage and cost. Mark `estimated: true` only when usage is absent and estimated locally.
8. Map HTTP errors to `ChatError`. Use the section 7.4 table and preserve request/generation IDs in `details`.
9. Map in-stream error objects to the same normalized error, preserve partial content, stop, and do not retry.
10. Track first-token and latency timing for the message layer.
11. Add tests:
    - text;
    - keep-alive;
    - reasoning;
    - usage/cost;
    - in-stream error;
    - 402, 429, 503;
    - cancellation before and after first token;
    - retry allowed only before partial output.
12. Document any deviation from the expected vectors.

## Handoff notes

- Streaming API: `openrouter::stream::stream_chat` sends a prepared body and
  attribution headers through the shared `HttpClient`, checks the status, and
  hands the body to `read_sse`. `stream_chat_completions` is the convenience
  wrapper that joins `/chat/completions` through the shared URL policy.
  `StreamDecoder` is the pure incremental decoder; `StreamSummary` carries the
  response ID, text, reasoning, usage, finish reason, error, partial-output
  state, retryability, first-token time, and total latency.
- Event mapping: `start` is emitted on the first parsed chunk with its `id`.
  String `delta.content` is appended directly; array content concatenates its
  text fields. `reasoning_details` wins over `reasoning`, and repeated or
  incremental reasoning text is deduplicated against the text already emitted.
  `finish_reason` maps to the shared `FinishReason`; unknown values become
  `unknown`. Final `usage` maps `prompt_tokens`, `completion_tokens`,
  `total_tokens`, and `cost` with `estimated: false`.
- Estimated usage: the adapter does not add an extra `usage` event when the
  provider omits usage, because the shared keep-alive vector has no usage event.
  `StreamSummary::estimated_usage` returns reported usage unchanged, or a local
  `ceil(characters / 4)` estimate marked `estimated: true` for the message layer.
- Error mapping: `openrouter::errors::map_http_error` and `map_stream_error`
  share `map_error_object`. HTTP statuses map to `auth`, `quota`, `permission`
  or `content_filter`, `model_not_found`, `context_length`, `rate_limit`, and
  `provider`; 429/5xx are retryable and `Retry-After` is preserved. In-stream
  errors take their status from the envelope `code`, preserve the response ID as
  `requestId`, copy non-secret metadata into `details` with `provider_name` and
  `retry_after_seconds` renamed to camelCase, and are never retryable.
- Partial output and cancellation: the decoder marks text and reasoning as they
  are emitted. `retry_allowed` is true only for a retryable error with no partial
  output. Cancellation returns a `cancelled` error while keeping the partial
  text and reasoning in the summary.
- Tests: `tests/openrouter_stream.rs` covers every OpenRouter stream vector,
  keep-alives, reasoning deduplication, usage/cost, in-stream errors, 402/429/503
  HTTP errors, 401 key redaction, cancellation before and after the first token,
  and retryability before and after partial output. Unit tests in `stream.rs` and
  `errors.rs` cover finish-reason mapping, array content, reasoning dedup,
  estimated usage, metadata renaming, and secret-free messages.
- Expected-vector deviations: none. All `openrouter-*.json` stream vectors and
  `openrouter-errors.json` cases match exactly.
- Verification: `make contracts-check` passed; `cargo fmt --all --check` passed;
  `cargo clippy -p chatui-providers --all-targets -- -D warnings` passed;
  `cargo nextest run -p chatui-providers` passed (206 tests).
