# M3-01.5 - Cleartext warning and certificate-validation guard

- Milestone: M3
- Status: Not started
- Order: 9
- Depends on: M3-01.4
- Parallel-safe: yes, with M3-01.2 and M3-01.3
- Owns: `android/core/providers/src/main/kotlin/dev/chatui/core/providers/ProviderCreation.kt`, `android/feature/providers/`, network-security tests, M3 evidence notes
- Read first: [M3 plan](../M3-android-depth-implementation-plan.md) sections 3.1 and 4.2; spec sections 9.6, 11.8, and 12.3

## Goal

Make the local-HTTP warning explicit to the user and add regression guards that certificate validation and redacted logging remain intact.

## Preconditions

- M3-01.4 is complete and the allowed-host policy exists.
- Do not weaken the policy or add an allow-all trust manager.

## Deliverables

- A user-visible warning when a provider base URL uses cleartext to an approved local host.
- Validation that refuses cleartext to non-approved hosts with actionable copy.
- A static/source test proving the shared OkHttp client has no custom trust manager, hostname verifier, or logging interceptor.
- Tests for the warning and refusal paths.

## Implementation steps

1. Read `ProviderCreation.kt`, `ProviderListScreen.kt`, `ProviderListViewModel.kt`, `ProviderDetailScreen.kt`, and `AppModule.kt`.
2. Add a pure validation/warning helper that returns one of:
   - `allowed local cleartext` with warning copy;
   - `refused cleartext` with error copy;
   - `secure HTTPS` with no warning.
3. Surface the warning in the Custom provider form and provider detail without preventing the user from reviewing the URL. If confirmation is required, use an explicit acknowledgment; do not hide the warning in a log.
4. Ensure the warning does not display secrets and does not put the URL in an exported intent or log.
5. Add a static test that inspects `AppModule.provideOkHttpClient()`:
   - no `interceptors` or `networkInterceptors`;
   - no custom `sslSocketFactory`;
   - no custom `hostnameVerifier`;
   - default certificate validation remains in effect.
6. Add tests for the validation/warning helper and the UI warning text.
7. Record the result in `M3-verification.md`.

## Acceptance criteria

- [ ] Approved local HTTP produces an explicit user warning.
- [ ] Non-approved cleartext is refused with actionable copy.
- [ ] HTTPS produces no cleartext warning.
- [ ] No custom trust manager or hostname verifier exists.
- [ ] No logging interceptor is installed.
- [ ] Warning tests pass and contain no real keys.
