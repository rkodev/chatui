# M3.5-10.2 - Data controls and export/import UI

- Milestone: M3.5
- Status: Not started
- Order: 38
- Depends on: M3.5-10.1, M3.5-03.4
- Parallel-safe: yes, with M3.5-10.3
- Owns: `rust/crates/chatui-ui/src/data/`, data route/state, data UI tests
- Read first: [M3.5 plan](../M3.5-rust-desktop-implementation-plan.md) sections 3.6 and 4.12; spec sections 3.7, 11.5, 15.2, 21.4

## Goal

Implement data/storage usage, export/import UI, clear-data confirmation, per-key deletion, attachment-byte opt-in, and plaintext warnings.

## Preconditions

- Settings layout and the export/import service exist.
- Do not silently include attachment bytes or secrets in exports.
- Do not delete data without explicit confirmation.
- Do not modify `web/`, `android/`, or `contracts/`.

## Deliverables

- Data settings screen with:
  - storage usage for database, attachments, and secrets metadata;
  - export-all and per-conversation export;
  - JSON and Markdown export where supported;
  - attachment-byte opt-in;
  - plaintext warning;
  - import with merge-by-default and optional explicit replace;
  - import validation errors shown clearly;
  - clear-all with typed confirmation;
  - per-key deletion;
  - backup placeholder link.
- Export/import progress and result summaries.
- Tests for usage display, export options, import merge/replace, invalid import, clear confirmation, and per-key deletion.

## Implementation steps

1. Read spec sections 3.7, 15.2, and 21.4, plus `web/src/features/settings/DataExportPanel.tsx`, `DataImportPanel.tsx`, `DataClearPanel.tsx`, and `DataUsagePanel.tsx`.
2. Build the data view model over storage usage, export, import, and clear-data services.
3. Implement storage usage with a clear breakdown and refresh.
4. Implement export options. Default to no attachment bytes. Show the plaintext warning before export.
5. Implement per-conversation JSON and Markdown export where supported.
6. Implement import with merge-by-default. Require explicit confirmation for replace. Show validation errors without partially changing local data.
7. Implement clear-all with typed confirmation and per-key deletion.
8. Add tests for every option and failure state.
9. Document what is exported, what is excluded, and the plaintext risk.

## Acceptance criteria

- [ ] Storage usage is displayed and refreshable.
- [ ] Export includes conversations, messages, providers, models, and settings.
- [ ] Attachment bytes are opt-in.
- [ ] Secrets are never exported.
- [ ] Markdown and per-conversation export work where supported.
- [ ] Import merges by default and is explicit for replace.
- [ ] Invalid imports are rejected without data loss.
- [ ] Clear-all requires typed confirmation.
- [ ] Per-key deletion works.
- [ ] Tests pass.
