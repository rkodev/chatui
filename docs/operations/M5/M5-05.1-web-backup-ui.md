# M5-05.1 - Web backup/restore UI and settings

- Milestone: M5
- Status: Not started
- Order: 15
- Depends on: M5-04.1
- Parallel-safe: yes, with `M5-05.2` and `M5-05.3`
- Owns: `web/src/features/settings/`, `web/src/app/`, `web/src/features/backup/`
- Read first: [M5 plan](../M5-backup-and-sync-implementation-plan.md) sections 3.6 and 5.3; spec sections 13.7 and 21.5; `web/src/features/settings/BackupSettingsScreen.tsx`

## Goal

Replace the web backup placeholder with a working settings and restore flow:
configure a backend, test connectivity, enable backup, show status, back up now,
restore, and delete the remote backup with typed confirmation.

## Preconditions

- `M5-04.1` is `Complete` and the sync engine works.
- `M5-03.1` provides the S3 adapter and connectivity test.
- Do not add a new design system or redesign settings.

## Deliverables

- `web/src/features/settings/BackupSettingsScreen.tsx`:
  - Backend selector (`s3` first; other backends disabled until `M5-07.1`).
  - Endpoint, region, bucket, prefix, access key, secret key, passphrase fields.
  - "Test connection" button with typed success/error feedback.
  - "Enable backup" toggle.
  - Status: last backup time, pending changes, last error, storage usage.
  - "Back up now", "Restore from backup", "Delete remote backup".
  - Typed confirmation for delete and for replace-on-restore.
  - Clear statement that credentials and the passphrase stay client-side.
  - Warning that losing the passphrase means losing access.
- `web/src/features/settings/backupSettingsService.ts`:
  - Load/save `BackupConfig`.
  - Store credentials through the existing `SecretStore`.
  - Never store the passphrase.
- `web/src/features/backup/useBackupStatus.ts`:
  - Poll or subscribe to sync status.
- Tests:
  - Form validation and save.
  - Connectivity test success and failure.
  - Enable/disable.
  - Back up now calls the sync engine.
  - Restore defaults to merge; replace requires typed confirmation.
  - Delete remote requires typed confirmation and does not delete local data.
  - Credentials are stored as secrets; passphrase is not persisted.
  - Status renders last backup, pending, error, and usage.

## Implementation steps

1. Read the placeholder screen, `settingsService`, `SecretStore`, router, and the
   sync engine API.
2. Add a `backupSettingsService` that reads/writes `BackupConfig` and stores
   credentials via `SecretStore`. Do not persist the passphrase.
3. Build the form with existing settings primitives. Keep the existing route.
4. Wire "Test connection" to the S3 adapter's `testConnection`.
5. Wire "Enable backup" to save the config and start the sync engine.
6. Wire "Back up now" to `backupNow()` and show progress/result.
7. Wire "Restore from backup" to `restore()` with merge as the default. Add a
   separate replace action behind typed confirmation.
8. Wire "Delete remote backup" to `deleteRemote()` behind typed confirmation.
9. Add the client-side statement and passphrase-loss warning.
10. Add tests and run the web gates.

## Acceptance criteria

- [ ] The placeholder is replaced with a working settings screen.
- [ ] Backend, endpoint, region, bucket, prefix, credentials, passphrase, test,
      and enable controls exist.
- [ ] Connectivity test shows success and typed errors.
- [ ] Status shows last backup, pending changes, errors, and storage usage.
- [ ] Back up now, restore, and delete remote work.
- [ ] Restore merges by default; replace requires typed confirmation.
- [ ] Delete remote requires typed confirmation and keeps local data.
- [ ] Credentials are stored as secrets; the passphrase is never persisted.
- [ ] The client-side statement and passphrase-loss warning are visible.
- [ ] Existing settings tests still pass.
