# UX-04.2 - Reachable model management

- Phase: UX-04 - Setup, providers, and models
- Status: Not started
- Order: 21
- Depends on: UX-04.1
- Output folder: `docs\operations\android-minimalist-design-plan`
- Parallel-safe: No with ProviderRoutes/ProviderDetail/ShellNavHost edits.

## Goal

Connect provider Models/Manage models to the existing management component so
hidden models can be recovered through a real production entry point.

## Read first

Read the [execution contract](README.md), source-plan sections 2, 5.4,
and 5.5, `Providers\ManageModelsScreen.kt`,
`Providers\ModelPickerViewModel.kt`, `Providers\ProviderRoutes.kt`,
`Providers\ProviderDetailScreen.kt`, `Shell\ShellNavHost.kt`, and existing
provider route/picker/navigation tests.

## Owns

- Provider-scoped management route adapter in `Providers\ProviderRoutes.kt`
  or a private sibling, existing management UI call sites.
- Models action in `ProviderDetailScreen.kt` and canonical app navigation.
- Focused `ProviderRoutesTest`, `ModelPickerViewModelTest`,
  `ModelPickerContentTest`, and `ShellNavigationTest` cases.

## Deliverables

A provider-scoped management destination/host backed by
`ModelPickerTarget.Manage(providerId)` with hidden models included.

## Implementation steps

1. Verify that `ManageModelsScreen` currently has no production caller.
   Reuse it and the existing model-management service; do not build a parallel
   catalog editor.
2. Add a labeled Models/Manage models action to provider detail and pass its
   provider ID through the route to app-owned navigation.
3. Construct the existing picker ViewModel with Manage target and hidden
   models included; key state by provider ID. Reuse UX-04.1's presentation
   where applicable and preserve existing route names/restore behavior.
4. Keep search, manual ID, refresh, pin/unpin, hide/unhide, warnings, and
   error/retry available. Selecting a management row must not change a chat
   or global default merely because the same ViewModel class is reused.
5. Preserve Back/Up and initiating focus. Handle missing/deleted providers
   safely; do not fall back silently to another provider.
6. Add a route-level test opening Models from provider detail, recovering a
   hidden model, and observing refreshed picker availability. Assert that
   defaults and conversation model IDs remain untouched.

## Acceptance criteria

- [ ] A real provider-detail action reaches existing model management.
- [ ] Hidden models can be found and unhidden without raw database edits.
- [ ] Provider scope and nonselection semantics are correct after reopen.
- [ ] Manual/refresh/pin/hide behavior and Back remain intact.
