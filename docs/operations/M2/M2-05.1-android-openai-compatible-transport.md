## Goal

Extract a preset-driven OpenAI-compatible transport from the Android OpenRouter adapter while preserving OpenRouter behavior.

## Preconditions

- M2-00.2 expected and request vectors are complete.
- Do not add Custom provider UI in this task.

## Deliverables

- Generic OpenAI-compatible transport for validation, discovery, and streaming.
- Preset-driven base URL, auth, default headers, attribution, and discovery format.
- Request serialization from shared vectors.
- Existing retry, SSE, cancellation, usage, and error behavior preserved.
- Tests for OpenAI fixtures and OpenRouter regression.
- No key in URLs, logs, or provider records.

## Implementation steps

1. Read `OpenRouterAdapter`, `OpenRouterStream`, `SseTransport`, and `ProviderRegistry`.
2. Introduce a generic OpenAI-compatible adapter using preset configuration.
3. Keep OpenRouter-specific routing and in-stream behavior behind configuration.
4. Build requests from shared vectors and supported parameters.
5. Add OpenAI fixture tests and rerun M1 OpenRouter tests.
6. Run Android gates.

## Acceptance criteria

- [ ] OpenAI-compatible transport is preset-driven.
- [ ] OpenAI text, usage, error, retry, and cancellation fixtures pass.
- [ ] OpenRouter behavior is unchanged.
- [ ] Protected fields cannot be overridden.
- [ ] No native adapters or UI are added.
- [ ] Android gates pass.

```bash
make android-lint && make android-test && make android-assemble
```
