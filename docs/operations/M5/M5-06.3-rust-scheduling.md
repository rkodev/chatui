## Goal

Provide a desktop scheduling equivalent for backup. Document when backup runs,
how the user can force it, and what happens when the app is closed.

## Preconditions

- `M5-05.3` is `Complete` and the backup UI can enable backup.
- Rust is conditional. If Rust is not shipping, mark this task `Cancelled`.
- Do not add an OS service or a background daemon.

## Deliverables

- `rust/apps/desktop/src/services/backup_scheduler.rs`:
  - A `tokio` interval-based scheduler while the app is running.
  - `schedule()`, `cancel()`, and `run_if_due()`.
  - Respect the user's enable/disable setting.
- `docs/operations/M5/rust-scheduling.md`:
  - When backup runs (app open, interval, manual).
  - What happens when the app is closed.
  - How the user can force a backup.
  - Platform limitations.
- Tests:
  - Scheduler runs when due and skips when not due.
  - Disable cancels the schedule.
  - No plaintext path is introduced.

## Implementation steps

1. Read the backup UI, sync engine, and desktop service wiring.
2. Implement `backup_scheduler.rs` with `tokio::time::interval`.
3. Wire enable/disable in the backup settings flow.
4. Write `rust-scheduling.md` with honest behavior and limitations.
5. Add tests with a fake clock or short intervals.
6. Run the Rust gates.

## Handoff notes

- Added `rust/apps/desktop/src/services/backup_scheduler.rs` with
  `BackupScheduler` (`schedule()`, `cancel()`, `run_if_due()`), a
  `BackupRunOutcome` result, and `ScheduledBackupService`, which wires
  enable/disable to schedule/cancel and keeps the passphrase in memory for the
  session only.
- `BackupScheduler` uses `tokio::time::interval_at` on the shared desktop
  runtime and runs the blocking `BackupService::backup_now` call through
  `tokio::task::spawn_blocking`. It never reads content or talks to a storage
  adapter, so no plaintext path is introduced.
- Added `ServiceRuntime::handle()` so the scheduler reuses the single desktop
  runtime. No second runtime, OS service, or background daemon was added.
- Added `docs/operations/M5/rust-scheduling.md` documenting the 5-minute tick,
  15-minute due window, manual backup, app-closed behavior, and the
  passphrase/sleep/timer limitations.
- Tests use a fake clock and short intervals: due/not-due runs, disable/cancel,
  missing passphrase, failure retry, idempotent schedule, and a check that only
  the encrypted `backup_now` entry point is called.
- The desktop composition does not yet mount the backup settings screen, so
  `ScheduledBackupService::from_runtime` is the intended wiring point when that
  screen is added. `start_if_enabled()` should be called when the screen loads.
