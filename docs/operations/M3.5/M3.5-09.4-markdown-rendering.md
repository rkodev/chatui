- Parallel-safe: yes, with M3.5-09.3 and M3.5-09.5

- Read first: [M3.5 plan](../M3.5-rust-desktop-implementation-plan.md) sections 3.6 and 4.11; spec sections 11.6, 11.7, 12.1

## Goal

Render assistant content safely with GFM Markdown, code highlighting and copy, tables, task lists, links, math fallback, blocked raw HTML, and blocked remote images by default.

## Preconditions

- The message list exists.
- Do not execute raw HTML, scripts, or untrusted links.
- Do not bundle a browser engine.
- Do not modify `web/`, `android/`, or `contracts/`.

## Deliverables

- `pulldown-cmark` GFM renderer with:
  - headings, lists, tables, task lists, links, inline/fenced code;
  - safe link allowlist (`http`, `https`, `mailto`, in-app anchors);
  - raw HTML rendered as text, not HTML;
  - remote images blocked by default;
  - incomplete fenced code during streaming rendered as a code block.
- `syntect` or equivalent highlighting with a bounded theme and language set.
- Code block language label, copy exact text, and wrap/scroll toggle.
- Math handling:
  - render math if a safe Rust-compatible renderer is chosen;
  - otherwise show bounded raw source with a clear fallback.
- Tests for XSS payloads, raw HTML, unsafe links, remote images, incomplete fences, copy text, and math fallback.

## Implementation steps

1. Read spec sections 11.6 and 11.7, plus `web/src/features/chat/MarkdownRenderer.tsx`, `CodeBlock.tsx`, and `MathRenderer.tsx`.
2. Add `pulldown-cmark` and a bounded `syntect` setup.
3. Implement safe rendering. Never enable raw HTML. Render HTML source as text.
4. Allowlist link schemes. Open external links with an explicit action and no secret-bearing URL.
5. Block remote images unless `settings.loadRemoteImages` or a per-message action allows them.
6. Render incomplete code fences during streaming as code blocks.
7. Implement code copy using the exact source text, not highlighted markup.
8. Implement math fallback. If no safe Rust renderer is chosen, show bounded raw source and do not break the message.
9. Add tests with XSS payloads, script tags, `javascript:` links, remote images, tables, task lists, and incomplete fences.
10. Document the renderer's safety boundaries and math decision.

## Acceptance criteria

- [ ] GFM Markdown renders correctly.
- [ ] Raw HTML is inert and rendered as text.
- [ ] Unsafe link schemes are rejected.
- [ ] Remote images are blocked by default.
- [ ] Incomplete fences render as code blocks.
- [ ] Code copy returns exact source.
- [ ] Syntax highlighting is bounded.
- [ ] Math renders safely or falls back to raw source.
- [ ] Tests cover XSS, links, images, fences, and math.
- [ ] No browser engine or script execution is introduced.
