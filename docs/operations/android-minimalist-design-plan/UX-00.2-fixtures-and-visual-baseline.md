## Goal

Capture a reproducible pre-redesign visual/test baseline using invented data
and the real production shell, not just standalone screen fixtures.

## Read first

Read the [execution contract](README.md), source-plan sections 2, 7, and
10, and UX-00.1's ledger. Inspect `Screenshots\ScreenshotTest.kt`,
`android\app\src\sharedTest\kotlin\dev\chatui\testing\TestFixtures.kt`,
`AppTests\ShellNavigationTest.kt`, and the existing app instrumentation tests.
Existing `ScreenshotSidebar` and standalone chat are not production-shell
coverage.

## Owns

- Test-only fixtures/harness under `android\app\src\test`,
  `android\app\src\sharedTest`, and existing `android\app\src\androidTest`.
- Baseline screenshots/reports and a seeding/capture recipe linked from this
  task's Handoff notes; keep large artifacts outside Git.
- No production UI redesign or shipping test-data entry point.

## Deliverables

Deterministic fixtures, actual-shell baseline captures, baseline command
results, and an identified baseline build/revision for later device comparison.

## Implementation steps

1. Reuse existing fakes and fixtures. Cover empty/populated/archived history,
   long titles, model filters/hidden models, code/tables/reasoning, attachment
   warnings, missing configuration, and recoverable errors with fake content.
2. Provide a deterministic local dataset/stream recipe for 10,000 messages
   and representative supported images. Reuse it for UX-00.3 and UX-06.4;
   do not require a paid provider or depend on external catalog latency.
3. Extend the test harness to compose actual shell/navigation surfaces with
   injected services. Capture the current placeholder and closed drawer as
   findings; do not accidentally fix them in a baseline test.
4. Record representative small-window light/dark captures, including 320 dp
   width/large text and one expanded sidebar. Label existing standalone
   goldens separately and preserve them where useful.
5. Run baseline app/design-system checks and screenshot verification. Record
   existing failures separately instead of changing unrelated expectations.
6. Record exact seeding/reset steps, fixture identity, build configuration,
   and baseline revision/artifact checksum for UX-00.3. Keep secret-free
   baseline artifacts available even after UI implementation starts.

## Acceptance criteria

- [ ] Captures identify actual shell versus standalone fixtures correctly.
- [ ] Fixtures are deterministic, contain no real secrets/content, and support
      the later long-history/image/stream scenarios.
- [ ] Baseline failures and unavailable environments are stated factually.
- [ ] The same baseline dataset/build can be used on reference devices.
