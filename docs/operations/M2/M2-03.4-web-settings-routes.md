- Status: Complete
- Parent task: M2-03

- Depends on: M2-01.3
- Parallel-safe: yes, with M2-04.1

## Goal

Complete the web settings surfaces and wire every setting that affects user-visible behavior.

## Preconditions

- M2-01.3 provider/model settings exist.
- M2-03.1 remote-image setting contract exists.

## Deliverables

- Appearance settings: theme, density, chat font size, reduced motion behavior.
- Chat defaults: default provider/model, system prompt, parameters, send key, token usage, remote images.
- Providers/models entry points to existing management screens.
- Data settings entry point reserved for M2-04.5.
- Backup placeholder and about/privacy screens.
- Behavior wiring for send key, token usage, remote images, defaults, remember-keys-on-web, and last-active conversation.
- Tests for route reachability and settings persistence.

## Implementation steps

1. Review placeholders in `web/src/app/routes/placeholders.tsx` and settings service.
2. Replace appearance, backup, about, and data placeholders with real screens or entry points.
3. Add chat default controls and persist them through `SettingsService`.
4. Wire remote-image, send-key, usage, and default prompt/params behavior.
5. Add navigation links between settings sections.
6. Add tests for each route, persistence, and behavior changes.
7. Run web gates.

## Acceptance criteria

- [x] Appearance, chat defaults, providers/models entry, data entry, backup placeholder, and about/privacy are reachable.
- [x] Settings persist and survive reload.
- [x] Remote images, send key, token usage, and default prompt/params affect behavior.
- [x] Remember-keys-on-web and last-active behavior remain correct.
- [x] No data export/import implementation is added in this task.
- [x] Web gates pass.

## Handoff notes

- Routes added: `/settings/chat` (chat defaults). `/settings/appearance`, `/settings/data`,
  `/settings/backup`, and `/settings/about` now render real screens instead of placeholders.
  `/settings` renders a shared `SettingsLayout` with navigation to every settings section, and
  the shell header links to `/settings`.
- Settings behavior matrix:
  - theme/density/chat font size -> `SettingsProvider` loads persisted values at startup and
    applies them through `ThemeProvider`, so they survive reload.
  - send key -> chat service -> `useChatSession` -> `Composer` keyboard handling.
  - token usage -> chat service -> `useChatSession` -> `MessageList`/`MessageItem`.
  - remote images -> chat service `getLoadRemoteImages` -> `MessageList` -> `MessageItem`/
    `StreamingMessage` -> `MarkdownRenderer`.
  - default provider/model/system prompt/params -> `ConversationService.createConversation`
    (existing behavior) with the new `/settings/chat` controls persisting through
    `ProviderManagementService.setDefaults`.
  - remember-keys-on-web -> persisted global preference exposed on `/settings/chat`; per-provider
    remember/session choices remain authoritative for each secret.
  - last active conversation -> unchanged existing `ConversationService` behavior; settings
    service tests still cover persistence.
- Deferred settings: data export/import/storage usage/clear-data (M2-04.5), backup controls
  (post-M2), and attachment settings beyond remote images.
- Verification: `make web-lint && make web-typecheck && make web-test && make web-build` passed
  (83 test files, 763 tests).
