# UX-02.1 - Reusable history presentation

- Phase: UX-02 - Navigation and entry points
- Status: Not started
- Order: 9
- Depends on: UX-01.5
- Output folder: `docs\operations\android-minimalist-design-plan`
- Parallel-safe: Yes with transcript work; no with other history-screen edits.

## Goal

Make the existing history list usable in a full-screen root or sidebar/drawer,
with explicit title/New chat ownership and lighter rows.

## Read first

Read the [execution contract](README.md), source-plan sections 4 and 5.3,
`History\ConversationListScreen.kt`, `History\ConversationRoute.kt`,
`History\ConversationGrouping.kt`, and the existing conversation-list,
grouping, search, and Back tests.

## Owns

- `History\ConversationListScreen.kt` and `History\ConversationRoute.kt`.
- Focused cases in `ConversationListScreenTest.kt`,
  `ConversationSearchTest.kt`, and `ConversationListBackTest.kt`.
- Grouping/service/storage implementations remain read-only.

## Deliverables

A host-configurable history presentation that reuses the current state/service,
suppresses duplicate chrome, and preserves every row operation.

## Implementation steps

1. Add explicit host configuration/callbacks for title and New chat ownership.
   Keep defaults compatible until UX-02.2 adopts the new host variants.
2. Render lighter rows: title, existing preview/model information, time, pin/
   selected state, and visible overflow. Remove unnecessary chevrons/cards;
   do not query messages or change schema to manufacture previews.
3. Keep search, highlighted matches/snippets, active/archive selection, pinned
   and every existing date group. Preserve stable keys/lazy rendering.
4. Keep open, rename, delete confirmation/undo, pin/unpin, archive/unarchive,
   and labeled alternatives to swipe. Do not remove archive access on narrow
   screens or rely on gesture discovery.
5. Hoist/retain lightweight search/tab/scroll state as needed for host changes.
   Do not instantiate a second independent history collector in a reusable
   content component; UX-02.2 will decide which host is active.
6. Add tests for one New chat with host-owned CTA, standalone CTA compatibility,
   long titles/large text, search/archive transitions, and preserved overflow/
   undo actions.

## Acceptance criteria

- [ ] A host can suppress embedded title/CTA without losing functionality.
- [ ] Search, all grouping, active selection, archive and row actions remain.
- [ ] Rows wrap/grow at 320 dp/200% fonts with 48 dp actions.
- [ ] No new message scans, storage fields, or duplicate list state holders.

## Out of scope

changing deletion/undo timing.
