# UX-05.7 - Backup overview and recovery safeguards

- Phase: UX-05 - Settings, data, and backup
- Status: Blocked
- Order: 35
- Depends on: UX-05.6
- Output folder: `docs\operations\android-minimalist-design-plan`
- Parallel-safe: No with BackupSettingsScreen/ViewModel or setup call sites.

## Goal

Make encrypted backup status-first, separate configuration and destructive
recovery, and preserve the existing backup/restore/scheduler semantics.

## Read first

Read the [execution contract](README.md), source-plan sections 5.7 and
6, `BackupUI\BackupSettingsScreen.kt`, `BackupUI\BackupViewModel.kt`,
`BackupUI\BackupStatus.kt`, `BackupUI\BackupSettingsService.kt`,
`BackupUI\work\BackupScheduler.kt`, UX-05.6's configuration entry,
and existing backup screen/ViewModel/scheduler tests.

## Owns

Overview/recovery presentation and narrowly required state routing in the
backup screen/ViewModel, plus focused tests. Scheduler/adapters/sync engine/
confirmation constants stay authoritative and unchanged.

## Deliverables

Configured status overview, unconfigured setup state, secondary Configuration/
Restore, and clearly separated advanced recovery/remote deletion.

## Implementation steps

1. When unconfigured, show Set up encrypted backup and a short explanation.
   When configured, lead with actual last backup/pending count and one primary
   Back up now action. Do not fabricate success/counts for unknown status.
2. Link Configuration to UX-05.6's real form. Keep current enable/disable and
   test workflows available and distinguish committed config from pending edits.
3. Expose storage usage/last error/details without competing full-width primary
   buttons. Preserve actionable failure and pending states, not decorative polling.
4. Keep Restore merge as the default. Put Replace local data and Delete remote
   backup in a clearly named advanced recovery/destructive area, not beside
   Back up now as equivalent primary actions.
5. Preserve exact current typed confirmation constants/consequences and
   passphrase/validation before commit. No destructive preselection/autofocus;
   cancel must not invoke the service.
6. Preserve manual/enable backup behavior and WorkManager connected-network +
   battery-not-low constraints, unique six-hour periodic cadence, and existing
   exponential backoff starting at 30 seconds. Do not make it Wi-Fi-only.
7. Add cases for unconfigured/configured/disabled/busy/failure, configuration
   return, merge/replace differences, incorrect/correct typed phrases, passphrase
   absence, remote-delete cancellation, one outcome, and large-font access.

## Acceptance criteria

- [x] Overview is status-first with truthful data and one primary action.
- [x] Configuration/test/enable/manual backup and all recovery paths remain.
- [x] Typed destructive/passphrase gates and merge default are unchanged.
- [x] Scheduler/network/battery and credential semantics are untouched.
