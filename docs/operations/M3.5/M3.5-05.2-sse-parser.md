## Goal

Implement a provider-agnostic SSE transport that matches the shared fixtures and never parses provider JSON.

## Preconditions

- Domain and conformance scaffold exist.
- Do not parse provider payloads in this module. The adapter owns JSON.
- Do not use an unbounded buffer.
- Do not modify `web/`, `android/`, or `contracts/`.

## Deliverables

- A bounded SSE reader over an async byte stream.
- CRLF, LF, and lone-CR normalization, including a CR split across chunks.
- Event separation by a blank line.
- Multi-line `data:` concatenation.
- Comment/keep-alive tolerance.
- Final event flush when the stream ends without a trailing blank line.
- Abort/cancellation support.
- A configurable maximum buffer size with a clear overflow error.
- Tests against every raw stream fixture and property tests for chunk boundaries.

## Implementation steps

1. Read `web/src/providers/sse.ts` and spec appendix 21.1.
2. Define an async API such as `read_sse(stream, on_event, cancel, max_buffer)`.
3. Normalize line endings before splitting. Hold a trailing `\r` until the next chunk so CRLF split across chunks is handled.
4. Accumulate only `data:` fields. Ignore comments beginning with `:` and unknown fields.
5. Join multiple `data:` lines with `\n`.
6. Emit only non-empty data values. Keep-alive comments must not produce events.
7. Flush the final event when the stream ends.
8. Enforce a maximum incomplete-event buffer. Return a typed overflow error, never an unbounded allocation.
9. Support cancellation promptly. Do not read further after cancellation.
10. Add tests that feed every fixture through the parser and compare the raw `data:` event sequence. Do not parse JSON in the parser.
11. Add property tests or chunk-boundary tests for CRLF splits, lone CR, multi-line data, empty data, comments, and overflow.

## Acceptance criteria

- [x] The parser handles CRLF, LF, and lone CR.
- [x] Multi-line data is joined with a single newline.
- [x] Comments and keep-alives are ignored without producing events.
- [x] The final event flushes at end of stream.
- [x] The buffer is bounded and overflow is a typed error.
- [x] Cancellation stops reading promptly.
- [x] No JSON parsing exists in the SSE module.
- [x] Fixture and property tests pass.

## Handoff notes

- Completed 2026-11-07.
- Public API: `chatui_providers::sse::read_sse(stream, on_event, cancel, max_buffer)` where `stream` is any `futures_util::Stream<Item = Result<B, E>>` with `B: AsRef<[u8]>`, `on_event` is `FnMut(&str)`, `cancel` is a `tokio_util::sync::CancellationToken`, and `max_buffer` is the incomplete-event byte limit. Re-exported from the crate root as `read_sse`, `SseError`, and `DEFAULT_MAX_SSE_BUFFER_BYTES`.
- Buffer limit: `DEFAULT_MAX_SSE_BUFFER_BYTES = 1024 * 1024` (1 MiB). The limit applies only to an incomplete event; complete events are drained before the check, so a complete event larger than the limit is still delivered. Overflow returns `SseError::BufferOverflow { max_bytes }`.
- Error type: `SseError::{BufferOverflow, Cancelled, Stream, InvalidUtf8}`. `Stream` carries the underlying error's display message; `InvalidUtf8` is returned for a complete event that is not valid UTF-8.
- Framing: CRLF, LF, and lone CR are normalized at the byte level. A trailing `\r` is held across chunks so a split CRLF pair is one line ending. Events are separated by a blank line. Only `data:` fields are collected; comments (`:`) and unknown fields are ignored. Multiple `data:` lines are joined with `\n`; empty data values are not emitted. The final event is flushed at end of stream. `[DONE]` is passed through as raw data; adapters own the sentinel.
- Cancellation: checked before every read and raced against the pending stream read with `tokio::select!` (`biased`), so a cancelled token returns `SseError::Cancelled` without polling the stream again.
- Fixture tests: `rust/crates/chatui-providers/tests/sse.rs` loads every `.sse` fixture through `chatui_conformance::ConformanceFixtures` and compares the raw `data:` event sequence against an independent oracle. It also runs every fixture with CRLF and lone-CR line endings.
- Chunk-boundary tests: every split point of every `.sse` fixture, one-byte chunks for every fixture, and 7-byte chunks for the OpenRouter keep-alive fixture. Additional cases cover CRLF split across chunks, multi-line data, empty data, comments, unknown fields, UTF-8 split across chunks, final flush, overflow, complete-event-larger-than-limit, cancellation, and stream errors.
- Verification: `cargo fmt --all --check` passed; `cargo clippy -p chatui-providers --all-targets -- -D warnings` passed; `cargo nextest run -p chatui-providers` passed 62/62 (31 SSE tests).
- Decisions: the parser accepts a generic byte stream rather than a `reqwest::Response` so it stays transport-agnostic and testable; `CancellationToken` is required rather than optional so callers cannot accidentally ignore cancellation; the buffer limit is measured in bytes (stricter than the web implementation's character count for non-ASCII data).
- Known framing edge case: a complete event larger than `max_buffer` is allowed because the limit is on the incomplete-event buffer, matching the web transport. A single stream chunk can therefore allocate up to the chunk size before the post-chunk overflow check; the HTTP client's chunking bounds this in practice.
- No `web/`, `android/`, or `contracts/` file was modified. `Cargo.toml` gained `futures-util`, `tokio-util`, and the `tokio` `macros` feature; `lib.rs` declares and re-exports the module.
