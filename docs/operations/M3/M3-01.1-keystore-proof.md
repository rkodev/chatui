# M3-01.1 - Real Android Keystore and ciphertext-only proof

- Milestone: M3
- Status: Not started
- Order: 5
- Depends on: M3-00.2, M3-05.1
- Parallel-safe: yes, with M3-01.4 and M3-02.3
- Owns: `android/app/src/androidTest/` security tests, `android/core/datastore/src/main/kotlin/dev/chatui/core/datastore/secret/`, `docs/operations/M3/M3-verification.md` (security evidence section)
- Read first: [M3 plan](../M3-android-depth-implementation-plan.md) sections 3.1 and 4.2; spec sections 9.7 and 12.3

## Goal

Prove that the production Tink path uses the Android Keystore, writes only ciphertext, and survives a new cipher instance without exposing plaintext.

## Preconditions

- M3-05.1 test infrastructure is complete.
- Do not change the encryption format or weaken the cipher.
- Use a synthetic sentinel value only; never a real API key.

## Deliverables

- An instrumentation or device procedure proving `TinkSecretCipher.androidKeystore` encrypts and decrypts a sentinel.
- A second cipher instance can decrypt the stored value, proving the keyset is loaded from persistent Keystore-backed storage.
- Evidence that Room stores only ciphertext and that the keyset preferences file does not contain the sentinel.
- A source/log audit result for raw secret logging.
- Case evidence recorded in `M3-verification.md`.

## Implementation steps

1. Read `TinkSecretCipher.kt`, `SecretStore.kt`, `SecretEntity.kt`, and the existing `TinkSecretCipherTest`/`SecretStoreTest`.
2. Add an instrumentation test under `android/app/src/androidTest/java/dev/chatui/security/`:
   - get the application context;
   - build `TinkSecretCipher.androidKeystore(context)`;
   - encrypt a sentinel such as `m3-sentinel-not-a-real-key`;
   - create a second cipher instance and decrypt the ciphertext;
   - assert the result equals the sentinel.
3. Add a ciphertext-only check:
   - build an in-memory or temporary `ChatUiDatabase` on the device;
   - store the sentinel through `SecretStore`;
   - read the `SecretEntity` directly;
   - assert `ciphertext` does not equal and does not contain the sentinel.
4. Check the keyset preferences file is not readable as plaintext:
   - locate the `chatui_secret_keyset_prefs` file through the test application context;
   - assert its bytes do not contain the sentinel.
5. Add a manual/device note for a true process restart: install, store a sentinel, force-stop, relaunch, decrypt, and record the result. Do not claim a process restart from an in-process test.
6. Audit all app and module sources for `Log`, `println`, exception messages, and HTTP interceptors that could contain secret headers. The only current startup log should remain content-free.
7. Record results in `docs/operations/M3/M3-verification.md` under a security subsection.

## Acceptance criteria

- [ ] `TinkSecretCipher.androidKeystore` is exercised on an Android runtime.
- [ ] A second cipher instance decrypts the persisted ciphertext.
- [ ] Room contains ciphertext only for the sentinel.
- [ ] The keyset preferences file does not contain the sentinel.
- [ ] A process-restart procedure is recorded separately from the in-process test.
- [ ] No raw key or secret header appears in code logs or test output.
- [ ] The evidence section contains no real key.
