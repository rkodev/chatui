## Handoff notes

- Math approach: no math typesetting library is bundled. Standalone `$$` blocks and fenced `math`/`latex`/`tex` blocks render their exact source in a bounded `ChatMath` block; inline `$...$` math stays in the Markdown flow as raw text. Unterminated or invalid math remains raw text, so streaming-incomplete math cannot break the message. This is the documented raw-source fallback allowed by the task.
- Remote-image policy: `ChatMarkdown` and `ChatMessageItem` accept `loadRemoteImages` and default to `false`. Only absolute `http`/`https` image sources are eligible; `data:`, `javascript:`, `mailto:`, relative, and protocol-relative sources never load. Blocked images show alt text, a note, a per-message "Load image" action, and an "Open image" link. Enabled images load off the main thread and fall back to "Image unavailable." on failure.
- Deferred cases: the settings screen and `ChatRoute`/`ChatMessageList` plumbing that supplies `loadRemoteImages` from `AndroidSettings` are deferred to M2-06.5, which owns behavior wiring. Inline images use the same blocked/load contract as block images. No math typesetting, image proxying, or CSP changes are added here.
