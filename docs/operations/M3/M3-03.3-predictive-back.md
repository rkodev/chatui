# M3-03.3 - Predictive back ordering

- Milestone: M3
- Status: Not started
- Order: 12
- Depends on: M3-03.1, M3-03.2
- Parallel-safe: no; shares shell and chat files
- Owns: `android/app/src/main/java/dev/chatui/shell/`, `android/feature/chat/ChatScreen.kt`, dialog/sheet call sites, back-navigation tests
- Read first: [M3 plan](../M3-android-depth-implementation-plan.md) sections 3.2 and 4.3; spec sections 9.3, 9.10, and 3.8

## Goal

Make back always close the topmost layer before leaving the screen, with predictable ordering and no double navigation.

## Preconditions

- M3-03.1 and M3-03.2 are complete.
- Android predictive-back callback is already enabled in the manifest; keep it enabled.
- Do not change the destination graph or introduce new screens.

## Deliverables

- A single ordered back policy: dialog or sheet -> drawer -> keyboard -> navigation.
- Explicit handlers for every overlay and for the drawer.
- Tests proving each layer closes before the next.
- No double pop or accidental app exit when a dialog/sheet is open.

## Implementation steps

1. Read `AndroidManifest.xml` (`enableOnBackInvokedCallback`), `ShellNavHost`, `ShellScaffold`, `ConversationListScreen`, `ChatScreen`, `ConversationSettingsSheet`, `ModelPickerSheet`, and chat dialogs.
2. Define the priority order explicitly in the shell/chat:
   - confirmation/dialog;
   - modal bottom sheet;
   - conversation drawer;
   - keyboard (let the system IME consume it where applicable);
   - navigate back.
3. Use `BackHandler` (and `PredictiveBackHandler` only if the Compose version supports it without an experimental opt-in that breaks the build) with `enabled` conditions tied to state.
4. Ensure a sheet/dialog `onDismissRequest` and the back handler share the same close function so they cannot both pop navigation.
5. Add tests that open each layer, invoke back, and assert only that layer closes. Cover:
   - delete/rename dialog;
   - conversation settings sheet;
   - model picker sheet;
   - conversation drawer;
   - plain navigation back.
6. Run on a device/emulator with gesture back if available and record the result.

## Acceptance criteria

- [ ] Back closes a dialog before a sheet, drawer, or navigation.
- [ ] Back closes a sheet before a drawer or navigation.
- [ ] Back closes the drawer before navigating.
- [ ] Keyboard back is not intercepted by the app.
- [ ] No double pop or app exit occurs with an overlay open.
- [ ] Predictive-back callback remains enabled.
