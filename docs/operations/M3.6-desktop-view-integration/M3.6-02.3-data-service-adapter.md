## Goal

Implement the production `chatui_ui::data::DataService` over SQLite, export,
import, attachments, and the secret repository so the Data screen shows real
usage and performs safe exports, imports, clears, and key removal.

## Preconditions

- `M3.6-02.1` is complete and exposes `ServiceRuntime`.
- Exports must exclude secrets and attachment bytes unless explicitly opted in.
- The plaintext warning must remain visible in the view model.
- Clear-all must require the exact typed confirmation from the view model.
- Do not modify `web/`, `android/`, or `contracts/`.

## Deliverables

- `SqliteDataService` implementing `chatui_ui::data::DataService`:
  - `usage`, `list_conversations`;
  - `export_all`, `export_conversation` for JSON and Markdown;
  - `import_text` with merge and replace modes;
  - `clear_all`;
  - `list_provider_keys`, `remove_provider_key`.
- Reuse `ExportService`, `ImportService`, `AttachmentStore`, and the
  repositories rather than issuing SQL in the adapter.
- Tests against an in-memory or temporary database covering usage, export
  contents, import modes, clear-all, and key removal.

## Implementation steps

1. Reuse `ServiceRuntime` and construct `ExportService`, `ImportService`, and
   the attachment store.
2. Implement usage from repository counts and attachment sizes.
3. Implement `list_conversations` newest-first.
4. Implement export with the existing `ExportOptions`; never include secret
   values.
5. Implement import with the existing `ImportMode`; validate the archive and
   report summaries.
6. Implement clear-all with the same data scope used by tests.
7. Implement provider key listing and removal through the secret repository.
8. Map storage and import errors to `DataError` with user-safe messages.
9. Add tests, including negative cases for missing conversations and invalid
   archives.

## Handoff notes

- `SqliteDataService::from_runtime(&ServiceRuntime)` is the constructor for
  `M3.6-06.1`. It depends on the shared `SyncBridge`, `SqlitePool`, conversation,
  message, attachment, provider, model, settings, and secret repositories, and
  the shared `AttachmentStore`. `SqliteDataService::new(...)` accepts the same
  dependencies explicitly for tests.
- Export/import behavior differs from `MemoryDataService` in these ways:
  - JSON exports are sanitized by `chatui_storage::ExportService`, so secret
    headers and secret-bearing metadata keys are removed; provider `secretId`
    references are preserved.
  - Import uses `chatui_storage::ImportService`, which validates the archive
    before writing, applies merge/replace in one transaction, and restores
    attachment bytes when present. Replace clears the data stores represented by
    the archive but does not delete unrelated secret rows.
  - Markdown export is per-conversation only and never includes attachment
    bytes or settings.
  - Clear-all also removes attachment byte files, which the in-memory service
    does not model.
