# M5-00.1 - Preflight, decisions, and cross-client test vectors

- Milestone: M5
- Status: Complete
- Order: 1
- Depends on: none
- Parallel-safe: no; blocks all M5 work
- Owns: `docs/operations/M5/`, `contracts/fixtures/backup/`
- Read first: [M5 plan](../M5-backup-and-sync-implementation-plan.md) sections 1.2, 4, and 5.3; [M5 milestone](../../milestones/M5-backup-and-sync.md) "Entry criteria" and "Risks and decisions to confirm"; spec sections 6.2, 13, and 21.5

## Goal

Freeze the backup format, product decisions, and cross-client test vectors before
any client code is written. This task creates no product behavior. It exists so
web, Android, and Rust cannot invent different envelopes, manifests, or conflict
rules.

## Preconditions

- M4 is `Complete` and phase 1 is released.
- The user has explicitly confirmed phase 2 scope. If not, keep this task
  `Blocked` and do not start later tasks.
- Do not change application source in this task.

## Deliverables

- `docs/operations/M5/M5-decisions.md` with confirmed answers for:
  - Phase 2 scope authorization and the milestone start date.
  - Backup format version (`formatVersion` and envelope `v`).
  - KDF v1 parameters and whether Argon2id is implemented now or only documented.
  - Compression rule (gzip conversations, never attachments).
  - AAD encoding (object type + object key, length-prefixed).
  - Conversation object key format (128-bit random hex `storageKey`).
  - Revision model and tombstone retention.
  - Restore default (merge) and replace/delete confirmation rules.
  - First backend (S3-compatible) and second backend choice.
  - Rust scope: shipping or not shipping.
  - Web scheduling constraints and Android WorkManager constraints.
- `contracts/fixtures/backup/vectors.json` with deterministic cross-client
  vectors:
  - Envelope header parse and serialize.
  - AAD construction for `manifest`, `conversation`, and `attachment`.
  - IV and salt lengths.
  - Gzip round trip for a conversation payload.
  - Wrong passphrase failure.
  - Tampered header, IV, ciphertext, and AAD failure.
- `docs/operations/M5/M5-baseline.md` with the current `make contracts-check`
  and per-client test results.
- An entry-gate checklist with pass/fail and owner for each item.

## Implementation steps

1. Read the M5 milestone, the M5 plan, and spec sections 6.2, 13, and 21.5.
2. Confirm phase 2 scope with the user. Record the confirmation date and scope
   in `M5-decisions.md`. If not confirmed, stop and leave the task `Blocked`.
3. Record every decision in the table in plan section 4. Do not leave a decision
   implicit. For each decision, write the chosen value and a one-line rationale.
4. Define the exact envelope byte layout in `M5-decisions.md`:
   - offset 0: ASCII `CHATUI1\n` (8 bytes);
   - offset 8: big-endian `uint32` header length;
   - offset 12: UTF-8 JSON header;
   - next 12 bytes: random IV;
   - remainder: AES-256-GCM ciphertext with the 16-byte tag appended.
5. Define the exact header JSON fields: `v`, `formatVersion`, `alg`, `kdf`,
   `iterations`, `salt`, `objectType`, `objectKey`. Use base64 for `salt`.
6. Define the AAD byte string precisely, for example
   `objectType + "\n" + objectKey` encoded as UTF-8. Write it down so every
   client produces identical bytes.
7. Create `contracts/fixtures/backup/vectors.json` with synthetic data only.
   Include a fixed passphrase, salt, IV, plaintext, and expected ciphertext for
   at least one vector so clients can compare byte-for-byte. Never use real
   user data.
8. Add a short `contracts/fixtures/backup/README.md` explaining that these are
   known-answer vectors and must not be regenerated casually.
9. Run the baseline commands and record the results in `M5-baseline.md`:
   ```bash
   make contracts-check
   make web-lint && make web-typecheck && make web-test
   make android-lint && make android-test
   make rust-check && make rust-test
   ```
10. Record the Rust decision. If Rust is not shipping, state that Rust tasks are
    optional and do not block the web/Android gate.
11. Write the entry-gate checklist and update the `README.md` status if the
    phase 2 gate is still blocked.
