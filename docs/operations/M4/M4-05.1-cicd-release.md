- Milestone: M4
- Status: Complete
- Order: 6
- Depends on: M4-03.1, M4-04.1
- Parallel-safe: no; packages the measured build and deploy artifacts
- Owns: `.github/workflows/` (all four release pipelines and their shared behavior), `Makefile` release targets and help text, `docs/operations/M4/release.md`, `docs/operations/M4/release-notes.md`, `docs/operations/M4/evidence/ci/`
- Read first: [M4 milestone](../../milestones/M4-polish-and-release.md) workstream 4 (CI/CD) and section 6; spec sections 16.1-16.5, 14.4, 14.5, 10.10, 10.12, and 12; existing `.github/workflows/*.yml` and `Makefile`

## Goal

Make the release pipelines complete and least-privilege: web, Android, Rust desktop (if shipping), and contracts. Produce signed/attributable artifacts with versioning and release notes, and fail closed when secrets or checks are missing.

## Preconditions

- `M4-03.1` and `M4-04.1` are `Complete`; the measured build and deployment container are the inputs.
- Rust workflow work is required only if `M4-00.1` says `shipping`.
- Signing secrets live only in CI secret stores; never echo, commit, or log them.
- Do not publish the Play Store listing or store data-safety forms.

## Deliverables

- Web workflow: frozen-lockfile install, contracts check, lint, typecheck, tests with coverage, build, Playwright against the built app with mocked providers, artifact upload, and tag-based container publishing with semver and `latest` tags.
- Android workflow: JDK/SDK setup, Gradle cache, lint, unit tests, debug assemble, optional emulator instrumented tests, and tag-based signed AAB/APK using CI secrets.
- Rust desktop workflow (only if shipping): pinned toolchain, Cargo cache, fmt, clippy, tests, release build, cross-platform matrix, tag-based signed desktop artifacts and update manifests, and scheduled `cargo-deny`/`cargo-audit`.
- Contracts workflow: schema validation, fixture conformance across enabled clients, and failure on any OpenRouter fixture regression or schema/parity mismatch.
- Least-privilege `permissions`, concurrency groups, caching, artifact retention, and no secrets in logs.
- Versioning per spec 16.5: app semver, contract integer, backup format integer, and per-platform DB versions.
- `release-notes.md` with upgrade and migration notes, known issues, and the release artifact list.
- `release.md` documenting secrets (names only), how to cut a release, and what each workflow produces.
- Evidence under `docs/operations/M4/evidence/ci/`: workflow run summaries or a recorded environment blocker per pipeline.

## Implementation steps

1. Read every existing workflow and the `Makefile` release targets. Identify what is already implemented versus missing.
2. Web workflow:
   - ensure `pnpm install --frozen-lockfile` (with the repo's `--trust-lockfile` convention if required);
   - run `make contracts-check`, lint, typecheck, test with coverage, build;
   - run Playwright against the built app with mocked providers;
   - upload the build and reports with a bounded retention;
   - on a version tag, build and publish the container from `M4-04.1` with semver and `latest` tags.
3. Android workflow:
   - confirm JDK/SDK setup and Gradle cache;
   - run contracts, lint, unit tests, debug assemble;
   - keep the optional emulator instrumented job;
   - require the four signing secrets, fail if missing, and produce signed APK/AAB, mapping, and checksums on a tag.
4. Rust workflow (only if shipping):
   - use the pinned toolchain from `rust/rust-toolchain.toml`;
   - run fmt, clippy, tests, conformance, deny, and audit;
   - build the cross-platform matrix and sign artifacts/update manifests on a tag using CI secrets;
   - schedule `cargo-deny` and `cargo-audit`.
   If not shipping, do not present Rust as a release deliverable; leave the workflow as-is and mark it post-preview in the docs.
5. Contracts workflow:
   - confirm schema validation and fixture conformance run for every enabled client;
   - fail on any OpenRouter fixture regression or schema/parity mismatch.
6. Add or fix `permissions`, `concurrency`, caching, and retention across workflows. Ensure secrets are referenced only through `${{ secrets.* }}` and never printed.
7. Versioning:
   - set the app semver and tag format from `M4-decisions.md`;
   - confirm the contract integer, backup format integer, and per-platform DB versions;
   - ensure CI derives version code/name deterministically and monotonically.
8. Write `release-notes.md`:
   - what changed since the previous release;
   - upgrade/migration notes, including Android DB/version and (if shipping) Rust update-manifest notes;
   - known issues and the blocker list (must be empty at final release);
   - artifact list with names and where to find checksums.
9. Write `release.md`: each workflow trigger, required secret names, artifacts, and the manual steps to cut a release.
10. Run the workflows where the environment allows; otherwise record the exact blocker (missing secrets, runner, device) without claiming a produced artifact.
