## Goal

Confirm that M2 is actually complete, capture the current Android baseline, and make environment blockers explicit before implementation starts.

## Preconditions

- Do not change application code, build files, manifests, or tests in this task.
- Do not record API keys, signing material, prompts, or personal data.

## Deliverables

- A new `docs/operations/M3/M3-verification.md` file with:
  - environment section (host, JDK, Gradle, Android SDK, adb/emulator availability);
  - baseline command results;
  - current Android test count and debug APK size;
  - known blockers and their owners.
- A short handoff note in this task file listing missing tools, devices, or CI access.

## Implementation steps

1. Read `docs/operations/M2/M2-verification.md` and `contracts/parity.md`. Record the M2 completion date and any M2 deferrals that target M3.
2. Run the baseline commands from the repository root and record exact results:
   ```bash
   make contracts-check
   make android-lint
   make android-test
   make android-assemble
   ```
3. Record the Android unit-test count from the Gradle output and the debug APK size:
   ```bash
   ls -l android/app/build/outputs/apk/debug/app-debug.apk
   ```
4. Check device availability without installing anything:
   ```bash
   command -v adb || true
   adb devices || true
   command -v emulator || true
   ```
   If no device or emulator is available, record every device-dependent task as blocked pending hardware or a managed device.
5. Check whether the release environment exists, without printing secret values:
   - Are CI signing secrets provisioned?
   - Is a keystore path available outside the repository?
   - Is a baseline-profile/benchmark device or emulator available?
   Record only `available`, `unavailable`, or `unknown`.
6. Create `docs/operations/M3/M3-verification.md` with sections for environment, baseline commands, baseline measurements, and blockers. Keep it factual and evidence-oriented.
7. Update this task's `Handoff notes` with the results and any blocker.
