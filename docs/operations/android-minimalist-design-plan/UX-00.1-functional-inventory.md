## Implementation steps

1. Record the revision and any existing local modifications. Do not revert
   them or use an old operations pack's completion status as current proof.
2. For each capability in section 6, record its present entry path, source
   owner, important consent/confirmation, proposed entry path, implementation
   task ID from the index, and required regression/evidence.
3. Distinguish reachable behavior from unused components and disabled
   placeholders. Explicitly record the Conversations placeholder, the model
   callback that opens Providers, unwired Manage models/curated routing, and
   duplicated attachment warnings.
4. Record the fixed placement rules: no bottom bar, full-screen compact Chats,
   840 dp permanent-sidebar breakpoint, one New chat per history host, model
   picker in the header, and secondary actions in More.
5. Record settings/theme propagation gaps and the `loadRemoteImages` true
   default versus contradictory copy/spec. Assign truthful copy to UX-05.5;
   leave any default change outside this program.
6. List platform precedence and confirmation invariants: onboarding/pending
   share or deep link/last-active restore, one-layer Back, import/restore modes,
   key removal, and clear-all/remote-delete exact confirmations.
7. Link every ledger row to an implementation owner and a UX-06 evidence
   owner. Do not declare an unused component or unperformed manual check done.

### Fixed design decisions

These are already decided by the source plan/execution contract, not new
product choices:

1. **Placement:** no persistent bottom bar; full-screen compact Chats when no
   chat is open; history drawer from chat; permanent sidebar at **840 dp**.
   One labeled New chat per history host, including empty states; optional
   gestures do not replace visible actions. Owners: [UX-02.1], [UX-02.2].
2. **Toolbar:** compact stable title bar, header title/model picker and direct
   Send/Stop. Conversation settings, separate text/Markdown sharing, New chat
   and keyboard help belong in **More**. Chats More exposes Providers, App
   settings and help; drawer footer exposes canonical Providers/Settings.
   Back/Up replaces the menu on hierarchical destinations. Owners:
   [UX-01.3], [UX-02.3], [UX-02.4].
3. **Integration boundary:** `app` owns cross-feature presentation, explicit
   conversation/default picker targets and canonical routes. Reuse existing
   services/state/components; no chat-to-provider-UI dependency, new UI module,
   navigation framework, dependency upgrade or database migration.
4. **Preservation:** no silent change to selected models, generation/extras,
   routing/privacy/costs, stored preferences, draft/attachment limits,
   scheduling, minimum SDK 26, either density or any chat font size.
   Quiet presentation must preserve warnings, failure states and recovery.
5. **Truthful privacy, not a default change:** `AndroidSettings.loadRemoteImages`
   is **true**; DataStore uses that value when absent, and `ChatRoute` forwards
   it. `SettingsScreens.kt` says blocked by default/blocked until allowed;
   `IMPLEMENTATION.md` section 3.6 also requires blocked-by-default. Correct
   misleading current copy in [UX-05.5], preserve both persisted values and
   per-image controls, and bound loading in [UX-03.5]. Changing the default or
   migrating/resetting preferences is separately approved product work.
6. **Evidence:** screenshots must exercise production shell integration;
   isolated components and historical goldens do not prove reachability.
   [UX-06.1] owns integrated visual evidence, [UX-06.2] accessibility/focus/
   insets, [UX-06.3]/[UX-06.4] profile/performance, [UX-06.5] actual device and
   usability flows, and [UX-06.6] final ledger/parity reconciliation. Focused
   regressions remain the implementation owner's responsibility, not deferred
   wholesale to UX-06. No such checks have been executed by UX-00.1.
