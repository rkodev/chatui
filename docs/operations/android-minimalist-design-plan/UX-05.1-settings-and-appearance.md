# UX-05.1 - Settings root and appearance

- Phase: UX-05 - Settings, data, and backup
- Status: Not started
- Order: 29
- Depends on: UX-02.4
- Output folder: `docs\operations\android-minimalist-design-plan`
- Parallel-safe: No with SettingsScreens/SettingsRoute/ShellNavHost edits.

## Goal

Keep Settings as the concise home for secondary tools and make Appearance
compact without dropping any preference or creating duplicate destinations.

## Read first

Read the [execution contract](README.md), source-plan sections 4 and 5.7,
`SettingsUI\SettingsScreens.kt`, `SettingsUI\SettingsRoute.kt`,
`SettingsUI\SettingsViewModel.kt`, `Shell\ShellNavHost.kt`,
UX-01.4's theme wiring, `SettingsScreensTest.kt`, `SettingsViewModelTest.kt`,
and `AppTests\SettingsRouteTest.kt`.

## Owns

Settings root/Appearance/About layout in the named settings files, narrowly
required canonical navigation callbacks, and focused settings/app-route tests.
Leave chat-default controls and feedback/copy changes to their named tasks.

## Deliverables

Concise root rows and a compact accessible Appearance screen with one live
preview and all existing options.

## Implementation steps

1. Retain the grouped-list foundation and root entries: Appearance, Chat
   defaults, Providers, Data & storage, Encrypted backup, About/privacy.
   Use one screen-title owner and concise row descriptions/current values.
2. Make Providers point to the existing canonical provider destination.
   Keep both backup entry paths connected to the real backup feature in app;
   do not route production to the similarly named settings fallback/stub.
3. Keep light/dark/system, comfortable/compact, every current chat font size,
   haptic feedback, and dynamic color. Reduced motion continues to follow OS.
4. Use one compact live preview instead of repeated large examples. Make
   choices wrap/use a selector at 320 dp/200% fonts without shrinking targets.
5. Preserve immediate preference writes and the applied theme behavior from
   UX-01.4. Do not change defaults or add a staged Save button.
6. Simplify About layout with existing information available; UX-05.5 owns
   privacy/obsolete-copy reconciliation. Keep Back/Up and focus restoration.
7. Test every root destination, appearance persistence/live application,
   compact/large-font layouts, and canonical Providers/real-backup navigation.

## Acceptance criteria

- [ ] Root is concise and all secondary tools remain reachable.
- [ ] Every appearance setting persists and applies without a new Save step.
- [ ] One preview/title; accessible options in both densities.
- [ ] No duplicate provider/settings/backup implementation or placeholder route.
