## Goal

Implement the production onboarding service adapters so first-run onboarding can
load the public OpenRouter catalog, validate a key, persist the provider and
models, and record onboarding completion.

## Preconditions

- `M3.6-02.1` and `M3.6-02.2` are complete.
- Tests must not call the network; inject fake catalog and validator sources.
- The key is passed only to the validator and the secret store.
- Do not log or render the key.
- Do not modify `web/`, `android/`, or `contracts/`.

## Deliverables

- Production implementations of:
  - `onboarding::CatalogSource` backed by the OpenRouter catalog;
  - `onboarding::KeyValidator` backed by the provider validation functions;
  - `onboarding::ProviderStore`, `onboarding::ModelStore`, and
    `onboarding::SettingsStore` backed by SQLite.
- A constructor that wires `OnboardingService` over the adapters.
- Tests with fake catalog/validator plus a temporary database for persistence
  and completion.

## Implementation steps

1. Reuse the provider/model adapters from `M3.6-02.2` where the trait shapes
   match; otherwise add thin wrappers.
2. Implement the catalog source with the shared HTTP client and a bounded
   timeout.
3. Implement the key validator with the same mapping used by
   `providers::ProviderKeyValidator`.
4. Implement provider and model persistence with upsert semantics.
5. Implement settings completion persistence through `SqliteSettingsRepository`.
6. Add tests for catalog errors, validation errors, provider/model persistence,
   completion, and a skipped onboarding path.
7. Document network boundaries, timeouts, and error copy.

## Acceptance criteria

- [x] Onboarding can load a catalog through the production source.
- [x] Key validation returns non-secret metadata and never exposes the key.
- [x] Provider and model records persist across reopen.
- [x] Completion persists and reloads.
- [x] Catalog and validation failures produce user-safe copy.
- [x] Tests are offline and use temporary databases.
- [x] No key material appears in logs or tests.

- Decisions:
  - Added `rust/apps/desktop/src/services/onboarding.rs` with
    `OpenRouterCatalogSource`, `PresetKeyValidator`, and the SQLite-backed
    `ProviderStore`, `ModelStore`, and `SettingsStore`.
  - `build_onboarding_service(runtime, preset, secrets)` wires the production
    `OnboardingService` over one shared `HttpClient` and the shared SQLite
    repositories.
  - `OpenRouterCatalogSource` calls the public `chatui-providers` OpenRouter
    `/models` loader on the shared runtime with `DEFAULT_NETWORK_TIMEOUT`
    (30 seconds). `PresetKeyValidator` delegates to the existing
    `services::providers::ProviderKeyValidator`, so validation uses the same
    per-preset adapter and error mapping.
  - The onboarding service saves the catalog before the provider record, but
    `models.provider_id` has an immediate foreign key to `providers`. The model
    adapter therefore buffers catalog writes and the provider adapter flushes
    them after the provider upsert succeeds. Rollback clears the buffer.
  - `providers.secret_id` also has a foreign key to the `secrets` metadata
    table. The provider adapter inserts a non-secret metadata row with empty
    ciphertext when the referenced row is missing; the actual key remains only
    in the injected `SecretStore`.
  - Model persistence uses `get_by_remote_id` plus `upsert`, preserving the
    existing local ID, `pinned`, `hidden`, and `created_at` on refresh.
  - Added `chatui-contracts` as a direct `chatui-desktop` dependency and
    declared `pub mod onboarding;` in `services/mod.rs`. Both are required
    wiring outside the owned file.
  - Tests use temporary SQLite databases, `SessionStore`, and fake catalog and
    validator sources. The production network adapters are exercised offline
    through the shared URL policy (public cleartext is rejected before any
    request).

## Handoff notes

- Constructor for `M3.6-06.1`:
  `services::onboarding::build_onboarding_service(&runtime, &preset, secrets)`
  returns `Result<OnboardingService, ChatError>`. It needs the selected
  `Arc<dyn SecretStore>` from `M3.6-02.1`.
- Concrete adapter constructors:
  - `OpenRouterCatalogSource::from_runtime(&runtime, &preset)` and
    `OpenRouterCatalogSource::with_client(bridge, client, &preset)`.
  - `PresetKeyValidator::from_runtime(&runtime, &preset)` and
    `PresetKeyValidator::with_client(bridge, client, &preset)`.
  - `ProviderStore::from_runtime(&runtime, models)` where `models` is the
    shared `Arc<ModelStore>`.
  - `ModelStore::from_runtime(&runtime)`.
  - `SettingsStore::from_runtime(&runtime)`.
- Network-blocking trait methods:
  - `CatalogSource::load_catalog` blocks on the shared runtime for at most
    `DEFAULT_NETWORK_TIMEOUT` (30 seconds).
  - `KeyValidator::validate_key` blocks on the shared runtime for at most
    `DEFAULT_NETWORK_TIMEOUT` (30 seconds) through `ProviderKeyValidator`.
  - Neither may be called on the Slint thread. `M3.6-06.1` must run onboarding
    on a worker task and marshal results back with `upgrade_in_event_loop`.
- Default model selection is owned by `chatui_ui::onboarding::OnboardingService`
  and uses the shared fallback rule. The adapter only persists the selected
  models. When no usable text model exists, the service returns
  `OnboardingError::NoModel` and rolls back the secret, provider, models, and
  settings. For OpenRouter, a catalog failure with no cached models and no
  preset fallback also fails onboarding with a user-safe network error.
- The provider adapter writes an empty-ciphertext `secrets` metadata row for
  the provider's `secret_id` so the foreign key is satisfied. The key itself is
  never written to SQLite by this adapter.
