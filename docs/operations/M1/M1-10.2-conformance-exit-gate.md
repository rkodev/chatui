## Goal

Prove the M1 exit gate, record fixture conformance and critical-case evidence on both clients, and update parity and milestone status truthfully.

## Preconditions

- All implementation tasks are complete or explicitly deferred.
- CORS evidence exists.

## Deliverables

- Final `docs/operations/M1/M1-verification.md` containing:
  - command results for contracts, web, and Android gates;
  - OpenRouter conformance checklist per platform;
  - fixture conformance results for text, keep-alive, reasoning, usage, in-stream error, 402, 429, 503, retry, cancel, and routing;
  - critical-case mapping for cases 1-10, 15-18, 20-21, and 28;
  - manual two-minute onboarding-and-chat smoke records;
  - CORS matrix result and any release-stop note.
- Updated `contracts/parity.md` with an evidence-backed M1 implementation status that does not claim M2 features.
- Updated milestone status tables.
- Any accepted deferral recorded with an owner and target milestone.

## Implementation steps

1. Run the full contract, web, and Android gates from the repository root.
2. Run the fixture conformance suites on both clients and capture output.
3. Map each critical case to a test name or manual evidence row.
4. Record the OpenRouter 7.4 checklist with pass/fail per platform.
5. Record the manual two-minute flow for web and Android. Use disposable keys and redact them.
6. Update `contracts/parity.md` carefully. Keep the required table intact; add an implementation-status section or notes below it. Do not add a second pipe table unless the validator is updated to support it.
7. Update milestone status only when all evidence exists.
8. Run `make contracts-check` again after documentation changes.
9. Review the diff for secrets and accidental M2 scope.

## Acceptance criteria

- [ ] `make contracts-check` passes.
- [ ] Web lint, typecheck, test, and build pass.
- [ ] Android lint, test, and assemble pass.
- [ ] Fixture conformance is green on both clients.
- [ ] Critical cases 1-10, 15-18, 20-21, and 28 have evidence.
- [ ] The CORS result is recorded, and a blocker blocks the web release.
- [ ] Parity reflects what actually works.
- [ ] No secrets, real prompts, or personal data appear in evidence.
- [ ] No M2 feature is claimed or implemented.
