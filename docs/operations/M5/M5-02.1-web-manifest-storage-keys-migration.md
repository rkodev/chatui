# M5-02.1 - Web manifest, storage keys, and DB v2 migration

- Milestone: M5
- Status: Complete
- Order: 6
- Depends on: M5-01.2
- Parallel-safe: yes, with `M5-02.2` and `M5-02.3`
- Owns: `web/src/domain/`, `web/src/storage/`, `web/src/features/backup/`
- Read first: [M5 plan](../M5-backup-and-sync-implementation-plan.md) sections 3.3 and 5.3; spec sections 6.1, 6.4, and 13.3; `contracts/schema/backup-manifest-body.schema.json`

## Goal

Add the durable data needed for sync on web: a random conversation `storageKey`,
a monotonic `revision`, tombstones with `deviceId`, a manifest writer/reader, and
a self-contained conversation payload. Migrate existing IndexedDB data without
loss.

## Preconditions

- `M5-01.2` is `Complete` and the envelope codec exists.
- `M5-01.1` schemas are the source of truth for manifest and conversation shapes.
- Do not change export/import behavior.

## Deliverables

- Domain updates in `web/src/domain/conversation.ts`:
  - `storageKey: string` (128-bit random hex).
  - `revision: number` (monotonic, starts at 1).
  - Keep `sync` metadata; document the final shape.
- Domain updates for tombstones in `web/src/domain/`:
  - `Tombstone { conversationId, messageId?, deletedAt, deviceId }`.
- Storage updates in `web/src/storage/db.ts` and `migrations.ts`:
  - Bump `DB_VERSION` to 2.
  - Add a `tombstones` object store keyed by `id` with indexes on
    `conversationId` and `deletedAt`.
  - Backfill `storageKey` and `revision` for existing conversations in the v2
    migration.
- New `web/src/storage/TombstoneRepository.ts`.
- New `web/src/features/backup/manifest.ts`:
  - `buildManifest(snapshot)` from `ExportReader`.
  - `parseManifest(bytes)` with schema validation.
  - `mergeManifestIndexes(local, remote)` by revision.
- New `web/src/features/backup/conversationPayload.ts`:
  - `buildConversationPayload(conversation, messages, attachments)`.
  - `parseConversationPayload(bytes)`.
- Tests:
  - Migration v1 -> v2 preserves data and backfills fields.
  - `storageKey` is 32 hex chars and unique.
  - Manifest round trip and schema validation.
  - Conversation payload round trip.
  - Tombstone repository CRUD.

## Implementation steps

1. Read `web/src/domain/conversation.ts`, `web/src/storage/db.ts`,
   `migrations.ts`, `ExportReader.ts`, and the new schemas.
2. Add `storageKey` and `revision` to the `Conversation` interface. Update
   `ConversationRepository` create/update paths to set them:
   - `storageKey` = 16 random bytes as 32 lowercase hex chars.
   - `revision` = 1 on create, increment on every local mutation.
3. Add the `Tombstone` type and `tombstones` store. Add indexes.
4. Write the v2 migration:
   - Create the `tombstones` store and indexes.
   - Iterate existing conversations and add `storageKey`/`revision` if missing.
   - Do not delete or rewrite unrelated records.
5. Add `TombstoneRepository` with `add`, `listByConversation`, `listAll`, and
   `delete`.
6. Implement `buildManifest` from `ExportReader`:
   - Include conversation index, attachment index, revisions, tombstones, and
     `deviceId`.
   - Use the schema field names exactly.
7. Implement `parseManifest` with the schema validator or a hand-written
   validator that matches the schema. Reject unknown `formatVersion`.
8. Implement `mergeManifestIndexes` by revision. Do not implement full sync here;
   only the index merge used by `M5-04.1`.
9. Implement the conversation payload builder/parser. Include metadata, all
   messages, and attachment references. Exclude secrets.
10. Add tests and run the web gates.

## Completion record

- Added `Conversation.storageKey` (32 lowercase hex chars) and
  `Conversation.revision` (starts at 1). `newStorageKey()` generates 128 random
  bits with WebCrypto.
- `ConversationRepository` assigns both on create and increments `revision` on
  update. `MessageRepository` increments it on append and truncate mutations.
- Bumped IndexedDB to v2, added the `tombstones` store with `conversationId`
  and `deletedAt` indexes, and backfilled existing conversations in place.
- Added `Tombstone`, `TombstoneRepository`, `manifest.ts`, and
  `conversationPayload.ts` with schema validation and revision-based index
  merge.
- Export keeps its existing contract by stripping the new sync-only fields;
  import backfills them through `toConversationRecord`.
- Verification: `make web-lint && make web-typecheck && make web-test` passed
  (105 files, 919 tests). `cd web && pnpm exec vitest run src/storage
  src/features/backup` passed (9 files, 86 tests).

## Handoff notes

- `mergeManifestIndexes` is only the index merge. Full sync, upload/download,
  and conflict resolution remain in `M5-04.1`.
- Tombstone retention and hard-delete after 30 days remain in the sync engine.
- `ConversationRepository.delete` still hard-deletes; tombstone creation is
  deferred to the sync engine because it needs the configured `deviceId`.
