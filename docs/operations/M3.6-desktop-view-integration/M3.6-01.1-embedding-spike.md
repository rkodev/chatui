# M3.6-01.1 - Embedding spike and decision

- Milestone: M3.6
- Status: Not started

- Depends on: none
- Parallel-safe: yes, with M3.6-02.1

## Goal

Determine whether the existing feature `Window` components can be embedded into
`ShellWindow` through `ComponentContainer` and `ComponentFactory`, and record a
go/no-go decision with evidence. This decision gates every UI integration task.

## Preconditions

- Slint 1.18.1 is pinned by the workspace.
- Do not modify production crates in this task. Add the spike only.
- Do not modify `web/`, `android/`, or `contracts/`.
- Do not add dependencies to the main workspace for the spike.

## Deliverables

- A self-contained spike at `rust/spikes/ui-embedding/` containing:
  - a host component with two `ComponentContainer`s and `component-factory`
    properties;
  - an embedded component whose root is a `Window`, with at least one
    property, one callback, and one `Text`;
  - a Rust entry point that creates the embedded component with `::new()`,
    installs factories that return the same handles, and updates a property
    after embedding.
- A runnable or test assertion proving:
  - the embedded content renders inside the host;
  - a callback fires from the embedded content while embedded;
  - a setter called through the controller handle updates the embedded UI;
  - two containers can be toggled with `visible` without losing their handles;
  - dropping the host does not panic.
- `embedding-decision.md` recording the result, the exact Slint APIs used, and
  the fallback plan if embedding is unsupported.

## Implementation steps

1. Read `shell.rs` to capture how `ShellWindow` is created, synced, and tested.
2. Read the Slint `ComponentContainer` and `ComponentFactory` sources or docs.
3. Create the spike crate with its own `Cargo.toml`, `Cargo.lock`, and
   `src/main.rs`.
4. Declare the host component with `ComponentContainer { component-factory:
   root.left-factory; }` and a second container.
5. Create the embedded `Window` component with a label, a text property, a
   count property, and a `clicked` callback.
6. From Rust, build both components with `::new()`, set factories with
   `slint::ComponentFactory::new`, and run a short event-loop smoke or a
   headless test.
7. Call a setter on the embedded handle after embedding and assert the text
   property changed.
8. Invoke the embedded callback and assert it reached the Rust handler.
9. Toggle container visibility and assert both handles remain usable.
10. Record the decision, limitations (window chrome, sizing, focus, nested
    windows), and the fallback.

## Acceptance criteria

- [ ] The spike builds with the pinned toolchain.
- [ ] Embedded content renders inside the host container.
- [ ] Callbacks from the embedded component reach Rust while embedded.
- [ ] Setters on the controller handle update the embedded UI.
- [ ] Visibility toggling does not invalidate the embedded handles.
- [ ] `embedding-decision.md` states go or no-go with evidence.
- [ ] If no-go, the decision lists the concrete fallback and blocking issues.
- [ ] No production crate or workspace dependency is modified.
