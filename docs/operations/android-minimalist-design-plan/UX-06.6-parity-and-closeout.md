## Implementation steps

1. Verify every preceding task is genuinely `Complete`, with task/index status
   agreement, valid dependencies, and evidence in its Handoff notes.
   Keep this closeout task `In progress` until its own review is finished.
   Missing manual measurements cannot be waived by changing a status label.
2. Map each source-plan definition-of-done item and preservation-ledger family
   to implementation changes, focused regressions, screenshots, and applicable
   physical/manual evidence. Check actual production entry points.
3. Reconcile intentional presentation changes in `contracts\parity.md` under
   its existing process. Confirm per-change parity updates were not deferred
   wholesale and no functionality/cost/privacy/default drift is hidden.
4. Run integrated candidate checks below after focused lane checks. Investigate
   failures with the owning task; do not regenerate all goldens or weaken
   assertions as a closeout shortcut.
5. Review UX-06.2/UX-06.4/UX-06.5 device, accessibility, performance, and anonymous
   usability results. Confirm the tested build/fixtures match the final UI.
6. Keep unrelated pre-existing modifications untouched. Record any separately
   scoped product/default discrepancy, such as remote-image default policy,
   without pretending it was changed or silently resetting existing users.
7. Update source-plan progress/status with links to this evidence only when
   the definition of done is met. Preserve its original proposal/review context;
   do not rewrite old target values as if they were measured then.
8. If any gate is incomplete, mark this task `Blocked`, identify the exact
   owner/remaining evidence, and leave the program unfinished. Otherwise
   record the final reviewed result and synchronize statuses.
