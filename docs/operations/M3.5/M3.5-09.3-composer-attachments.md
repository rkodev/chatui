## Goal

Implement the composer with auto-grow, send-key behavior, persistent drafts, attachment selection, drag-and-drop, clipboard paste, chips, capability warnings, and failure-safe text preservation.

## Preconditions

- The chat runner and attachment store exist.
- Do not lose typed text on send failure.
- Do not store attachment bytes in the database.
- Do not modify `web/`, `android/`, or `contracts/`.

## Deliverables

- Composer:
  - auto-grow from 1 to 8 lines, then scroll;
  - Enter/Shift+Enter or Mod+Enter behavior from settings;
  - send and stop controls;
  - disabled states while streaming or offline;
  - text preservation on failure.
- Per-conversation drafts persisted through the repository.
- Attachment flow:
  - native file picker;
  - drag-and-drop;
  - clipboard paste;
  - image/text validation;
  - image downscale to 2048 px longest edge with metadata stripping;
  - content-addressed storage;
  - chips with size and remove action;
  - capability warnings when the selected model cannot accept an attachment.
- Tests for send keys, drafts, attachment validation, downscale, chips, and failure preservation.

## Implementation steps

1. Read spec sections 3.6, 11.4, and 11.6, plus `web/src/features/chat/Composer.tsx`, `attachmentRules.ts`, `imageProcessing.ts`, and Android equivalents.
2. Build the composer state. Auto-grow up to 8 lines, then scroll.
3. Implement send-key behavior from settings. Preserve text when sending fails or is cancelled.
4. Implement persistent drafts keyed by conversation. Restore on open, clear on send/discard.
5. Implement attachment selection through native dialogs and drag-and-drop. Clipboard paste should accept images where the framework supports it.
6. Validate MIME types and sizes. Downscale images with the `image` crate and strip metadata. Store through the attachment store.
7. Show chips with name, size, and remove action. Keep the send button disabled when empty and no attachments or when streaming/offline.
8. Show capability warnings when the model lacks vision/file support.
9. Add tests for send keys, draft restoration, attachment validation, downscale bounds, chip removal, and text preservation on failure.
10. Document attachment limits and failure behavior.

## Handoff notes

- Composer state: `ComposerState` owns the draft text, send-key mode, streaming/offline/sending flags, selected model capabilities, pending attachments, and attachment error. `ComposerController` binds it to the Slint `ComposerWindow`. `begin_send` snapshots and clears text/attachments; `restore_after_failure` restores both for send failures and cancellations; `discard` clears the draft.
- Auto-grow: `line_count`, `visible_lines`, `scrolls`, and `textarea_height` implement the 1-to-8-line policy. The Slint window uses `editor-height` and `editor-content-height` inside a `ScrollView`, so the editor grows to 8 lines and then scrolls.
- Send keys: `handle_key` implements `enter` (Enter or Ctrl/Cmd+Enter sends, Shift+Enter newlines) and `mod-enter` (only Ctrl/Cmd+Enter sends, Enter newlines). `send_key_hint` exposes the current mode to the view.
- Drafts: `DraftStore` is the synchronous cache used by the composer. `MemoryDraftStore` is the in-process implementation. `PersistentDraftStore` adds a dirty set and async `load`/`flush`; `SettingsDraftPersistence` stores non-secret draft text under `draft:<conversationId>` in the typed settings repository. Drafts are bounded to 50 conversations and 32,000 characters, evicting the least recently updated entry.
- Attachments: `validate_attachment_file` mirrors the web/Android rules (20 MB images, 2 MB text, PNG/JPEG/WebP/GIF plus text/source extensions). `process_image` decodes with the `image` crate, applies EXIF orientation, downscales the longest edge to 2048 px, and re-encodes to JPEG (opaque photos) or lossless WebP (everything else), which strips EXIF and other metadata. Undecodable images keep their original bytes.
- Storage: `store_pending_attachment` writes bytes through `AttachmentStore::put`, so storage keys are SHA-256 content hashes and identical bytes deduplicate. `PendingAttachment::to_attachment` builds the metadata row after the message exists; the schema requires a non-null message ID, so the composer does not insert metadata before send.
- Chips and warnings: `chips()` returns name, size, and kind for the Slint chip rows. `capability_warning()` and `unsupported_attachment_ids()` compare attachment kinds against the model's input modalities and vision/files capability flags.
- Input paths: `validate_files` covers picker, drag-and-drop, and paste input. `dropped_files` accepts every file and lets validation reject unsupported types; `clipboard_images` accepts images only. The Slint window exposes `attach` and `paste-image` callbacks. Native file dialogs, OS drag-and-drop, and clipboard access are wired by M3.5-10.3, which owns desktop integration.
- Tests: `enter_mode_sends_on_enter_and_shift_enter_inserts_newline`, `mod_enter_mode_sends_only_with_modifier`, `send_is_disabled_when_empty_streaming_or_offline`, `auto_grow_stops_at_eight_lines_and_scrolls`, `drafts_are_keyed_by_conversation_and_restore`, `send_failure_restores_text_and_attachments`, `cancelled_send_restores_text_and_attachments`, `chips_show_name_size_and_remove`, `capability_warning_for_unsupported_attachments`, `model_capabilities_fall_back_to_capability_flags`, `slint_window_renders_composer_state`, `slint_window_invokes_send_and_remove_handlers`, `validates_supported_images_and_text`, `rejects_empty_oversized_and_unsupported_files`, `sanitizes_file_names`, `scaled_dimensions_never_upscales`, `process_image_downscales_to_2048_and_strips_metadata`, `process_image_returns_original_bytes_when_undecodable`, `store_pending_attachment_uses_content_addressed_storage`, `clipboard_paste_accepts_images_only`, `format_attachment_size_is_human_readable`, `drafts_are_bounded_and_evict_oldest`, `drafts_are_truncated_to_the_maximum_length`, `empty_text_clears_the_draft`, `persistent_drafts_load_and_flush_through_persistence`, `settings_draft_persistence_round_trips`.
- Framework limitation: Slint has no native file-dialog or clipboard API in the UI crate. The composer exposes callbacks and framework-independent validation; the desktop integration task supplies the OS dialogs, drop target, and clipboard reader.
- Wiring and dependencies: the new modules are registered in `chat/mod.rs` and re-exported from `lib.rs`. `chatui-ui/Cargo.toml` adds `image` (png, jpeg, webp, gif) for downscaling and `tempfile` as a dev-dependency for synthetic attachment-store tests. `Cargo.lock` records those feature additions.
